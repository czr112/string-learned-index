### 1.2 "分项之和等于合计可能是循环验证"

**成立，且已确认。** 原代码：

```
model_other = total − blocks − overflow − tables
再校验 blocks + overflow + tables + model_other == total
```

等式按定义成立，无符号回绕后仍成立，不构成独立校验；原报告"9/9 对账 OK"无效。

修订后的口径（`bench_e8.cpp` 中新增 `Space` 结构）：

| 要求 | 实现 |
|---|---|
| 同一布局状态下取全部快照 | 每个变体在其自身布局状态下一次取齐 |
| 减法前检查已知分项之和不大于总量 | 每个分项先与合计比较，回绕立即违反 |
| 尽可能独立累计，而非只由差额定义 | 八个分项各自累加；合计取自 `Index::memory()`（逐区域求和的另一条路径） |
| 检查加法本身没有溢出 | 分项之和以 128 位累加 |

对账失败即抛出并中止运行，不写汇总行。

**关于"不访问目录"还是"不分配目录"**：答案是**不访问**。`index.hpp` 的构造函数无条件分配并填充 `off_`，`memory_breakdown()` 也无条件计入 `off_/sg_/bb_` 三张表；`offset_directory=false` 只切换 `base_of(g)` 的寻址方式。JSON 中 V1 的 `tables` 与 V2 完全相同（298,026 / 282,794 / 307,456）即为直接证据。新增断言 `v1.overflow_count() == uniform_overflow` 作为交叉检查。

**空间结论的适用范围**（按审阅意见收紧）：

> 在本轮固定数据、构建过程和空间统计口径下，需求容量分配在保持主块预算不变的情况下，减少了溢出记录及其存储开销。

以下均属**不受计时噪声影响**的结论，但容器容量与对象大小仍可能随构建历史、标准库或平台改变，不扩展为"跨环境都固定"；本报告的"确定性"仅指与本次测量重复无关。

## 5. 结论与适用边界

### 5.1 结论

1. **空间（结构化收益，本报告的主要结论）**：在本轮固定数据、构建过程和空间统计口径下，需求容量分配在保持主块预算不变的情况下，减少了溢出记录及其存储开销——溢出减少 21.9%–62.1%，估算总空间降低 11.1%–20.6%。该结论**不受计时噪声影响**，但不扩展为跨环境固定。
2. **时间（仅方向）**：本次交错测量中，需求布局在三个数据集上均观察到更低的查询延迟；跨独立运行的稳定性尚未建立。
3. **V1 与 V2 空间相同是预期结果**：目录照常分配、只切换寻址。

| 运行 | 处置 | 证据位置 |

> 归档观测包含不同平台和协议版本，不合并计算胜率。各次结果存在方向及幅度变化；当前预热协议下的独立重复证据仍不足。

### 5.4 平台

E8 前半段（v1–v3）与 E5–E7 相同：Windows 11 + MinGW-w64 g++ 15.2.0。**v4 迁移到 WSL2 Ubuntu 24.04 + g++ 13.3.0**，理由是 g++ 13.3 与原前三轮（Linux x86-64 + g++ 13.3 + taskset）一致，也符合课题环境的 Ubuntu 要求。

- **绝对值不可拼接**：本次绝对耗时比归档的 v3（Windows）高约 34%–49%，不得与 E5–E7 或 E8-v3 拼接。
- **迁移不足以消除波动**：同平台同二进制的两次运行离散度分别为 26.8% 与 11.8%。**具体来源尚未隔离**，不能归因于任何单一因素。

## 6. 遗留项

1. **端到端测量的稳定性验证**（按审阅归入后续正式评估）：需在更安静的机器上以更多配对批数进行。本机的 3 种子×1 批，离散度与效应同量级。
2. 更新负载下的容量漂移与再平衡。
3. 偏移目录与溢出策略的单独消融（若要测目录的**空间**代价，需另做一个真正不分配目录的变体）。
4. sanitizer 补测——Windows 工具链与 WSL 侧均未提供 ASan/UBSan。

**E9 第一版的范围**（保持模型与逻辑组号不变）：
