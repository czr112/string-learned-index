## 2. 严格等预算与空间对账

### 2.1 对账口径（v4 重写）

v3 把 `model_other` 定义为 `total − blocks − overflow − tables`，随后再"校验" `blocks + overflow + tables + model_other == total`。**这是同义反复**：等式按定义成立，且无符号整数回绕后仍会成立，因此它没有证明任何东西；v3 报告的"9/9 对账 OK"不构成独立校验。

v4 改为：

- 八个分项（主块、模型、前缀、溢出、容量表、区域自身、栅栏、索引自身）**各自独立累加**；
- 合计取自 `Index::memory()`，它逐区域求和，**走的是另一条代码路径**；
- 每个分项在相减之前先与合计比较，任何无符号回绕会立刻违反该条件（v3 的 uint64 下溢正是原检查看不见的失败模式）；
- 分项之和以 128 位累加，加法本身不可能回绕；
- 对账失败即抛出并中止运行，不写汇总行。

### 3.1 协议

### 3.3 判定（收紧后）

1. **需求布局的收益（V3−V2）**：三组中位数之差均为负（−119.7 / −27.6 / −82.2 ns），配对方向一致度 3/3、2/3、3/3。
2. **V2 的延迟中位数高于 V1（V2−V1）本次运行三组均为正**（+50.9 / +20.6 / +20.3 ns，配对一致度 2/3、2/3、2/3），但归档的 Windows 运行中该差值为负。该对照估计的是**寻址实现变化在完整查询路径中的影响**，不能把差值完全解释成"读取一次目录的成本"：V1 与 V2 空间虽相同，但代码布局、编译结果与运行状态都可能影响耗时，空间相同并不意味着耗时应当接近，也不意味着固定步长寻址必然更快。因此**不单独声明目录成本**。
3. **协议弱点如实声明**：3 种子×1 批、同进程、同机器、非独立重复；本次种子离散度最高 11.8%，仍与待测效应同量级。**只做轮内同批查询的变体间比较，不做跨运行比较**；不同平台与协议版本的运行不合并计算胜率。

## 4. E9 可行性：理想化容量估算

| 数据 | 配置 48 槽的组 | 其中全占 48 槽 | 封顶组内剩余溢出 | 现预算内可收回 | 占比 |
|---|---:|---:|---:|---:|---:|
| 混合字符串 | 229 | 229 | 37,971 | 29,706 | 78.2% |
| 重复前缀 | 585 | 585 | 96,236 | 79,115 | 82.2% |
| 百万域名 | 1,461 | 1,461 | 55,567 | 44,013 | 79.2% |

口径：逐组取溢出后缀长度升序，在**该组自身空闲后缀字节**内贪心装箱，每条记录预留 17 B（新槽的 Entry 16 B ＋ 指纹 1 B）。

**这是理想化容量估算，不是多块组已经能够兑现的回收率**：未计入多块组的块头、64 B 对齐与子块定位元数据（这些只会降低可收回数）；各组空闲字节不可互相借用已隐含在逐组计算中；"组内多块"的定位结构本身可能引入额外访存。它足以支持设计 E9 小原型，尚不足以预告实际收益。

## 5. 平台变更、被排除的运行与重复性

### 5.1 平台

E8 前半段（v1–v3）与 E5–E7 相同：Windows 11 + MinGW-w64 g++ 15.2.0。**v4 迁移到 WSL2 Ubuntu 24.04 + g++ 13.3.0**，理由是 g++ 13.3 与原前三轮（Linux x86-64 + g++ 13.3 + taskset）一致，也符合课题环境的 Ubuntu 要求。

必须注意：

- **E8-v4 的绝对值不能与 E5–E7（Windows）拼接**，也不能与前一轮 E8-v3 拼接。本次绝对耗时比归档的 v3（Windows）高约 34%–49%：mixed 442 对 330、skew 713 对 503、tranco 389 对 261 ns。
- **迁移不足以消除波动**。WSL2 是与 Windows 共享同一宿主的虚拟机，宿主侧调度抢占、频率调节与热降频会穿透进去；它给不了 `isolcpus` 式的隔离（那需要独占物理核）。同平台同二进制的两次运行离散度分别为 26.8% 与 11.8%，**具体来源尚未隔离**，不能归因于任何单一因素。

## 6. 结论与下一步

1. **空间上结论稳固**：在本轮固定数据、构建过程和空间统计口径下，需求重分配把溢出减少 21.9%–62.1%，估算总空间降低 11.1%–20.6%（对账后合计）。该结论**不受计时噪声影响**，但不扩展为跨环境固定——容器容量与对象大小仍可能随构建历史、标准库或平台改变。对账已改为非循环口径。
2. **V1 与 V2 空间相同是预期结果**：目录照常分配，只切换寻址。v3 的"—（无目录）"与 34B 差额均已撤回。
3. **时间上只报方向**：*本次交错测量中，需求布局在三个数据集上均观察到更低的查询延迟；跨独立运行的稳定性尚未建立。*"重分配收益是最稳健信号"的表述撤回。
4. **E9 就绪**：在逐组计算、每新增记录计入后缀与 17 B 元数据、尚未计入多块额外开销的模型下，约 78%–82% 的剩余溢出具有回收可能。实现方式为"逻辑组内多物理块"（模型与映射不变），需设计子块定位并把块头/对齐/定位元数据计入可行性；与"组分裂"（改变映射）分开命名与评估。第一版范围见修订报告的 §6。
5. 其余待办：更新负载下的容量漂移与再平衡；偏移目录与溢出策略的单独消融；sanitizer 补测；**端到端测量的稳定性验证（按审阅意见归入后续正式评估，需在更安静的机器上以更多配对批数进行）**。
