## E19-1 审阅边界与落实（2026-09-16）

| 审阅边界 | 落实 |
|---|---|
| **先做 R1，不自称"整个流程只预测一次"** | R1 只消除构造内部的第二次预测；\`RESULTS_E19.md\` 与 \`E19_TABLES.md\` 一律写 **3 次／键 → 2 次／键** |
| **核实需求遍历与放置遍历各算了什么** | 计数器显示 \`fingerprint_calls\` = 1／键（全在放置里），\`demand_pass\` **只算组号不算指纹**。因此只宣称省一次组号预测，**指纹时间一分不计** |
| **"纯函数"要升级为"同一组参数下的同一映射"** | 复用条件写成 \`cfg.multiblock && config_.reuse_group_ids && group_of.size() == sorted.size()\`；前缀／模型／**逻辑组数**／路由在同一个 \`Region\` 内完全相同。文档明确区分**逻辑组数**与**物理子块数** |
| **临时数组按区域，不必全量** | id 数组**按区域**分配（≤ `region_keys` 项 ≈ 8 KiB），随构造函数释放。实测峰值 **+0.01 MB**、额外分配**恰好每区域一次** |
| **正确性依据要写对** | 审阅指出：**数组长度相同不代表键与组号对应正确**。正确性依据是「同一构造函数内生成与消费、键序与模型不变」；长度检查只是快速筛选，**不能保证将来任意改动都安全回退** |
| **不量化不同分母的落差** | 审阅指出：「构造阶段 20%+」与「完整流程 3.5%–8.6%」**分母不同**，不能相减当作阶段估计失效的定量证据。结论（阶段比例不是加速界）保留，**量化说法删除** |
| **"18%–28% 上界"改为收益潜力估计** | 文档一律称 E18 的相位比例是**优化潜力指示，不是界**；实测节省明显小于"比例除以二"，并把这当作"阶段比例不能当加速界"的直接证据 |

**R2 本轮不做**：跨统计与构造的复用要另行核对区域划分、公共前缀、模型状态、逻辑组数与路由模式的一致性。

## E19-2 实现（2026-09-16）

1. \`Config\` 增加 \`bool reuse_group_ids = false\`（**默认关闭**，默认路径不变）。
2. 需求遍历把组号写进**按区域**的 \`std::vector<std::uint32_t>\`。
3. 放置遍历读它而不是再调 \`canonical_group\`；\`E18_PREPASS\` 诊断分支同样尊重该开关。
4. **条件复用 + 退回**：任何不满足都走旧路径，避免将来改动破坏对应关系时**静默错放**。
5. 新增 \`check_e19_reuse.cpp\`（验收门）与 \`bench_e19.cpp\`（同进程 A/B）。

## E19-3 事故（2026-09-16）

1. **组装出的 \`bench_e19.cpp\` 缺 \`Sha256\` 类。** 我的切片从 \`structure_digest\` 开始，把前面的 \`Sha256\` 类切掉了，诊断目标编译失败（\`'Sha256' was not declared\`）。**由构建闭环拦下**（失败即不产生可执行文件）。改为从 \`class Sha256\` 开始切。
2. **缺 \`<malloc.h\>`。** 诊断目标用 \`malloc_usable_size\`，而组装进去的头文件里没有该包含。同一闭环拦下。补上。
3. **一次编译失败会阻断同一命令行里后续目标**（\`tools_build.py\` 在失败时 \`sys.exit(1)\`），所以第一次跑三个目标时第三个根本没被尝试。重跑即可，但值得记住：**批量构建要用"先全部构建、再逐个核对记录"的方式看结果**。

## E19-5 结论与下一步（2026-09-16）

1. **R1 成立**：结构、方案、查询全部未变（96 组配置、38,400 次查询对照），预测次数恰好减一／键，最终构造流程缩短 **3.5%–8.6%**，临时内存代价 **+0.01 MB**。
2. **收益明显小于 E18 相位比例所暗示的量级。** E18 给出 `grp_prep` + `demand_pass` 占**构造** 42.7%／42.1%／26.7%，实测降幅是**完整流程**的 3.5%–8.6%。**两者分母不同，不能相减来量化落差**——能说的只是方向性结论：**阶段比例是优化潜力指示，不是加速界**（它包含循环、数组访问与容量状态更新）。要量化落差，需要把两者放进同一个计时范围。
3. **没有引入隐蔽的预测调用**：门逐配置核对构造阶段的预测次数**恰好**少一次／键（单块时**一次不少**），而不是"大约少"。
4. **下一步二选一，都不预设结果**：
   * **R2**（跨统计与构造复用）：潜在收益是再省一次／键，但要把 id 数组的生命周期延长到全量（512 KB／1 MB），并核对区域划分、前缀、模型、逻辑组数、路由五个一致性条件。**收益是否值得，要靠同进程 A/B 测，不能靠推算。**
   * **子块选择**：重复前缀上探测 7.11 次／键（E18 计数），是另一个方向，但改动更大。
5. **ART 对照仍停在 E15 轮**，本系列（E16–E19）都未补。
