# E19 结果：R1——构造内部复用组号

日期：2026-09-16。目录：`validation_e19_20260916`（继承 E18）。平台：WSL2 Ubuntu 24.04 + g++ 13.3.0，单核绑定。

**E18 定位到最终路径上每个键的组号被算了三次，并选定了"算一次并复用"。本轮实现其中的 R1：构造内部复用——需求遍历把组号记下来，放置遍历读它，而不是再问模型一次。**

---

## 0. 结论摘要

| 验收项 | 结果 |
|---|---|
| 结构与查询 | **未受影响**：96 组配置下摘要一致、**38,400 次查询逐条一致**、容量方案一致 |
| 预测次数 | **3 次／键 → 2 次／键**（构造阶段 2.00 → 1.00） |
| 最终流程时间 | **0.9145×–0.9646×**（干净构建，同进程 A/B，5 进程） |
| 临时内存峰值 | **+0.01 MB**（24.54 → 24.54，可忽略） |
| 额外分配 | **恰好每区域一次**（64／64／128 次，即那个 id 数组本身） |

**R1 把最终构造流程缩短约 3.5%–8.6%。** 混合与重复前缀在 5 个进程上**全部低于 1**；百万域名有 1 个进程高于 1（最大值 1.0104），所以它的点估计要带着这一点读。

**并且 R1 并没有把流程变成"只预测一次"**——它是 **3 次／键降到 2 次／键**。指纹本来就只算一次，本轮**没有**声称省掉任何指纹时间。

---

## 1. 改了什么

`Config` 增加一个开关，**默认 false**，所以默认路径不变、既有门继续通过：

```cpp
bool reuse_group_ids = false;   // 仅对 multiblock 有意义（需求遍历在那里才跑）
```

构造函数里：

* 需求遍历把算出的组号写进一个 **按区域** 的 `std::vector<std::uint32_t>`（最多 `region_keys` 项，即约 8 KiB／区域），随构造函数一起释放；
* 放置遍历读它，而不是再调一次 `canonical_group`；
* **复用是有条件的**：`cfg.multiblock && config_.reuse_group_ids && group_of.size() == sorted.size()`。任何不满足都退回原路径。

  **这个条件保证了什么、没保证什么，必须写清楚**：数组的**生成与消费在同一个构造函数内**，键序与模型都没有变化——**这才是正确性的依据**。长度检查只是廉价的快速筛选，它能发现部分异常，**不能保证将来任意改动下都能安全回退**：若有人让数组在别处生成、或让键序在两者之间改变，长度仍可能相等而对应关系已经错了。

**为什么在这里复用是安全的**：前缀、模型、**逻辑组数**、路由模式在这个 `Region` 内部完全相同，组号数组与放置遍历走的是同一份键序列。**逻辑组数与物理子块数是两回事**——调整后者保持组号不变，前者的变化才会改变预测结果，而这两者在同一个构造函数里都没有变化。

**没有采用跨阶段复用（R2）**：那需要核对统计与构造之间的区域划分、公共前缀、模型状态、逻辑组数与路由模式，是另一件事，本轮不做。

`check_e19_reuse`（`-DE18_COUNT`）在区域规模 × 槽数 × 块字节 × 路由 × 模型 × 单块/多块共 **96 组配置**上对照开关 off／on：

## 3. R1 没有省掉什么

* **指纹。** 它本来就只算一次，在放置遍历里。计数器显示构造阶段 `fingerprint_calls` = 1／键、`group_calls` = 2／键，所以省掉的**恰好是一次组号预测**，`grp_prep` 里的指纹时间**一分都不计入**。
* **统计阶段的那次预测。** 跨阶段复用是 R2，本轮不做。
* **`demand_pass` 的其余工作。** 它还要填两个按组的累加器、走一遍键数组；消失的只是它的模型调用。
* **E18 的 `grp_prep` + `demand_pass` 比例（42.7%／42.1%／26.7%）是"优化潜力指示"，不是界。** 它里面包含循环、数组访问与容量状态更新，R1 都不消除。

  **但不能拿两个不同分母的数字相减来量化落差**：前者是**构造阶段**内部的占比，后者是**完整流程**的降幅，两者计时范围不同。这里成立的只是方向性结论——**阶段比例不是加速界**；**要量化落差，需要把两者放进同一个计时范围再比**，本轮没有做。

## 4. 适用边界

1. **只做 R1，不做 R2。** 跨统计与构造的复用需要另行核对区域划分、公共前缀、模型状态、逻辑组数与路由模式的一致性，本轮未做。
2. **默认关闭。** `Config::reuse_group_ids` 默认 false，既有门与既有数字不变；本轮所有收益数字来自显式打开的变体。
3. **只对 `multiblock` 有效**；单块配置下开关必须**完全没有影响**（门已断言）。
4. **逻辑组数 ≠ 物理子块数。** 本轮复用建立在"同一 `Region` 内、逻辑组数不变"之上；改变物理子块数不影响该结论，改变逻辑组数会。
5. **时间来自干净构建的同进程 A/B**；内存与分配次数来自带包装的诊断构建，**不得用于任何时间比较**。
6. **百万域名的跨进程离散跨过 1**（0.8794–1.0104，4/5 低于 1），其点估计要带着这一点读。
7. **摘要不是物理字节相等的证据**（边界同 E15 §1.2）。
8. **只覆盖静态批量构建**；增量路径逻辑未改。
9. **不含 ART 对照**（`native.hpp` 的包装与"零仪器"相冲）。
