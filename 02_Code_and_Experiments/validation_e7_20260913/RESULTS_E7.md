# E7 结果：同样的溢出记录，能不能查得更便宜？

日期：2026-09-13（v2，按评审意见修正比例口径、Tranco 结论、协议表述，并补充分类成本分解与比较字节数证据；修订记录见 LOG.md E7-5）。目录：`validation_e7_20260913`（继承 E6→E5→E3 存储实现）。范围（评审定向）：**模型、物理分组、主块布局全部不变，只改变溢出区的点查算法**。环境同前轮（`-O3 -march=x86-64-v2 -static`，进程内绑核，构建经 `tools_build.py` 记录哈希）。

先行证据对照：第一轮 `overflow_probe` 曾以固定 32 条阈值做"大列表二分替换"，结论为无可靠改善。本轮差异：阈值由**调参查询选定并冻结**（非固定 32）；采用**短线性＋长二分的 Hybrid**（不是整表替换）；增加命中分类与比较字节数计数；调参与测试查询身份分离。

## 0. 正确性门槛

`check_ov.cpp`：**32,000 次差分操作**（5 个布局 trial）＋**9,202 次策略一致性断言**（同索引同键，Linear/Binary/Hybrid 各阈值的 found/value/source 逐项相等）＋source 预言机（4096B 键必报溢出命中、不存在键必报 source=0）。一次通过。**功能差分门通过；本环境缺少 sanitizer，内存安全检查待补。**存储门（E5 check.cpp）同参数重跑通过。

## 1. 协议（两段流程，无独立验证集）

**本协议是两段流程：调参 → 冻结 → 测试；没有独立验证集**（与 E3 的三段身份不同，如实区分）：
1. 调参查询＝排序名次 %4==0 的键（32,768 条，50% 命中，未命中为 `~missing~` 且计时外核实不存在）；在其上扫描 T∈{4,8,16,32,64,128,256}＋Linear＋Binary；
2. 选出 Hybrid 阈值并写 `frozen_ov_<kind>.json` 冻结（mixed=128、skew=64、tranco=128）；
3. 冻结之后才生成测试查询（其余 3/4 键，131,072 条×3 种子），只对冻结策略集计时。

数据与布局：mixed 131072 / skew 131072 / tranco 262144；固定叶 context16＋B=1024＋S=16；溢出键 78,861 / 123,171 / 146,551。策略挂在查询 Mode 上，三种策略测量**同一批溢出记录**。正式计时 3 方法×3 种子×5 轮乱序（15 批），预热 20000，批校验和；分类统计来自独立诊断运行（8192 条测试身份查询，`-DE7_COUNT_BYTES` 构建，不进入计时二进制）。百分比＝**逐批配对百分比差的中位数**；15 批非独立实验。

| 数据 | 溢出命中／全部查询 | 溢出命中／成功查询 | **溢出进入率**（实际访问溢出区的查询占比，8192 条实测） |
|---|---:|---:|---:|
| mixed | 30.1% | 60.4% | **80.2%** |
| skew | 46.7% | 93.9% | **96.8%** |
| tranco | 27.5% | 55.3% | **77.8%** |

（v1 中"47%–47%–28%"为笔误，应为 46.7%–30.1%–27.5%。）两个口径必须区分：**溢出命中比例 ≠ 溢出区访问比例**——未命中查询同样进入溢出区查找。溢出进入率远高于命中比例：即便混合数据也有约 80% 的查询要碰溢出结构，这是溢出成本如此显著的根本原因。（进入率在实现上具有结构性：主块未命中必然进入溢出查找；实测值与该结构一致。）

## 4. 分类成本分解与比较字节数（8192 条测试身份查询/数据集）

| 数据 | 策略 | 类别 | 字符串比较/查询 | 记录接触/查询 | 比较字节/查询 |
|---|---|---|---:|---:|---:|
| mixed | linear | 主块命中 / 溢出命中 / 未命中 | 1.02 / 1.47 / 0.55 | 0 / 112.4 / 143.1 | 72.8 / 96.8 / 12.3 |
| mixed | binary | 同上 | 1.02 / **7.31** / 5.63 | 0 / **6.27** / **4.76** | 73.5 / **261.9** / 117.2 |

| tranco | binary | 同上 | 1.00 / **6.78** / 5.54 | 0 / 5.78 / 4.68 | 11.3 / **49.6** / 30.3 |
| tranco | hybrid | 同上 | 1.00 / 2.34 / 1.13 | 0 / 21.6 / 31.0 | 11.2 / 22.0 / 7.3 |

三个机制结论（均有数字直接支撑）：
1. **二分更贵的原因不只是"比较次数多"，而是"每次比较走的字节多"**：二分探测收敛到与查询字典序相近的后缀，mixed/skew 上每次比较要走 262–270 字节，而线性路径的 tag 过滤使全比较落在随机碰撞记录上（89–97 字节）、未命中碰撞甚至 1–17 字节即分出差异。**一次完整比较调用不等于扫描了完整字符串**——因此补充了字节数证据。
2. **线性的代价是记录接触数**（未命中必须扫全表：mixed 143、skew 276 次；溢出命中也要 112–140 次），tag 过滤使其实际字符串比较极少。
3. **hybrid 的收益来源可以按类拆开**：溢出命中类省下百次级记录接触（代价是比较字节 2–3 倍化）；未命中类省下全表扫描（mixed 143→12 次）。tranco 上 hybrid 各类收益与代价接近抵消，与端到端"未观察到明确收益"一致。

## 5. 判定（收紧后）

1. **Hybrid 在 mixed、skew 上表现出较一致的改善方向（−10.25%/−8.35%，各 14/15 批胜出）；Tranco 的配对指标与总体中位数方向不同（中位数 298.8 对 297.5 略差，配对 −4.13% 仅 8/15 胜），当前未观察到明确收益。**因此 Hybrid **进入候选集可以，成为统一默认方案还不合适**；按数据选阈值/策略的选型框架是必要的。
2. **纯二分不稳健**：tranco 0/15 胜（+11.42%），mixed 2/15 胜；只有溢出列表极大且命中/未命中都以长列表为主的 skew 才有正收益。**"二分访问记录更少"不等于"更便宜"**——比较字节数证据见 §4。
3. 与第一轮 overflow_probe 结论差异的来源：固定 32＋整表替换 → 调参阈值＋短线性长二分；调参表显示阈值敏感性真实存在（mixed：T=4 时 886.7ns 劣于线性 703.2，T=128 最优 374.7）。
4. **结论边界**：15 批为同进程重复计时；两段流程无独立验证集；50% 命中率；未测更新负载下溢出长度分布漂移；阈值 7 档粗网格。**溢出进入率 78%–97% 表明：让每次查溢出更便宜只解决了半个问题——减少需要进入溢出区的查询次数（分组质量与容量分配）是 E8 的主题。**
