## 改造记录

### E7-1 溢出点查策略进 Mode（2026-09-13）
设计决定：策略挂在**每次查询的 Mode**（`OvSearch ov`＋`ov_thr`），不改 Config、不改溢出内容与排序——三种策略测量的是**同一批溢出记录的不同查法**，天然隔离"记录相同、查法不同"这个问题；同一已建索引即可测量全部变体，也便于逐查询策略一致性断言。
`Result` 增加 `str_cmps`（本次查找的完整字符串比较次数，主块与溢出都计）与 `source`（0 未命中 / 1 主块命中 / 2 溢出命中）。原 `overflow_checks` 语义保留（线性=扫描记录数，二分=探测次数）。
三种策略：Linear＝现状（tag 过滤＋线性，命中即停）；Binary＝有序后缀二分（每探测一次全比较，不用指纹——指纹过滤与有序探测不兼容）；Hybrid＝`size()≥阈值` 时二分否则线性。
insert 的去重 find、update、erase、scan 路径未触碰（范围外）。

### E7-2 策略正确性门 check_ov.cpp（2026-09-13）
- 对抗键池（空串、前缀链、嵌入零字节、0xFF、4096B 长键、8 字节边界族）＋随机键，多个布局 trial（含 S=8/32 与极小 region_keys 强制大溢出列表）；
- **策略一致性**：同一索引、同一键，Linear/Binary/Hybrid(各阈值) 的 found/value/source/str_cmps 逐项断言一致（str_cmps 允许不同——只断言 found/value/source 一致，str_cmps 差值被记录而非断言）；
- **差分**：每种策略的 insert/update/upsert/erase/scan 与 `std::map` 对账；
- 输出 JSON：各策略查找数、不一致数（必须为 0）。

### E7-3 基准 bench_ov.cpp（2026-09-13）
固定叶（context16/B=1024/S=16，与 E5/E6 参考布局一致）。查询身份两段分离（无独立验证集）：**调参查询＝排序名次 %4==0 的键，测试查询＝其余键**（身份不重叠）。流程：
1. 建索引（一次）；生成调参查询（32768 条，50% 命中，未命中 `~missing~` 计时外核实不存在）；
2. 阈值扫描 T∈{4,8,16,32,64,128,256}＋Linear＋Binary：每变体 3 轮计时取中位数 → **选定 T\* 并写出 frozen_ov.json（冻结后不得更改）**；
3. 冻结后才生成测试查询（131072 条×3 种子）；正式方法＝Linear/Binary/Hybrid(T\*)，3 种子×5 轮乱序计时、预热、批校验和；
4. 采样诊断（每方法 4096 条测试查询）：主块命中/溢出命中/未命中三类占比、平均 str_cmps、平均溢出探测次数、平均模型步数。
所有构建经 `tools_build.py` 记录。

### E7-4 运行与结果（2026-09-13）
三组数据正式运行完成（阈值冻结：mixed=128、skew=64、tranco=128；全部批校验和通过）。要点：
1. **Hybrid 全胜**：端到端配对差 vs 线性基线 mixed −10.25%（14/15 胜）、skew −8.35%（14/15 胜）、tranco −4.13%（8/15 胜）。
2. **纯二分不稳健**：mixed +8.68%（2/15 胜）、tranco +11.42%（0/15 胜）——其字符串比较（4.8–8.6 次/查询）超过线性 tag 过滤（0.64–1.29 次），只有溢出列表极大的 skew（线性接触 201 次/查询）才值得。
3. 分类统计：溢出命中占比 skew 47%、mixed 30%、tranco 28%；未命中约 50%。E7 让"每次查溢出更便宜"，未减少"需要查溢出的次数"。
4. 与第一轮 overflow_probe 结论差异的来源：固定 32 阈值＋整表替换 → 调参阈值（64–128）＋短线性长二分混合；调参表显示阈值敏感性真实存在（mixed 上 T=4 劣于线性、T=128 最优）。
5. 建议：Hybrid 作为默认候选进入选型框架；"减少溢出本身"（分组质量/装载率/热组）仍是更大的未动杠杆。
详见 `RESULTS_E7.md`。
