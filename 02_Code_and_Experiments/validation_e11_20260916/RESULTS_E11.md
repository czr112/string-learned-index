# E11 结果：多块组的子块范围定位

日期：2026-09-16。目录：`validation_e11_20260916`（继承 E10→E9→…→E3）。平台：WSL2 Ubuntu 24.04 + g++ 13.3.0。

范围：**保持 D／M／S 的布局与记录放置不变，只替换组内主块的查找方式**。

---

## 0. 摘要

1. **发现并修复了 E9 遗留的扫描正确性缺陷**（§2.1）。它在多块组的中间子块被清空时**静默丢键**。最小复现在 E10 与 E11 上输出逐字相同，证明是 E9 引入、E10 继承，**不是本轮引入**。
2. **实现了子块范围定位**：多块组建立边界目录，查找时**至多检查一个候选主块**（§1）。
3. **定位的代价本轮未测**。按项目指令先做基线比较，"S ＋ 子块范围定位"作为后续新增变体，`bench_e11` 推迟（§3）。

## 1. 实现

### 1.1 边界目录

多块组建立非空子块的边界目录：每条 = `{该子块最小后缀, 子块编号}`，按子块顺序。**单块组不建目录**，连外层槽位都不付。

边界**拥有自身存储**（拷贝而非指向块内的视图），因此压缩不会留下悬空引用——这是审阅建议的"初版用自有存储更容易验证"。

**目录空间全部计入**，不再是"零新增元数据"：

| 项 | 计入位置 |
|---|---|
| 外层槽位 `groups_ × sizeof(vector)` | `memory_breakdown().directory` |
| 每条边界的字符串缓冲 | 同上 |
| 描述符 `{string, uint32}` | 同上 |

混合数据约 21,000 个组，外层槽位本身约 0.5 MB。单块布局该项为零。

### 1.2 定位

`locate_subblock(g, s)` 在目录上二分，取"不大于 s 的最后一个边界"对应的子块；**小于所有边界时返回 `NO_SUBBLOCK`**。

M1 保证这个候选是**唯一**的：更早子块的键都小于该子块的最小键，更晚子块的键都更大。因此**至多一个主块需要检查**。

`find_impl` 只改子块循环的起止（`lo_blk..hi_blk`），**标签筛选与精确比较的代码一行未动**——只改"访问哪些子块"。

### 1.3 关键正确性条件

**`NO_SUBBLOCK` 不等于"本组未命中"。** M1 只约束主块之间的顺序，**不保证溢出记录落在某个主块的 min/max 之间**。因此定位失败后必须继续原有 Hybrid 溢出查找——代码中 `if (result.found) return result;` 之后的溢出段**完全未改**，两条路径共用同一段。

### 1.4 维护

目录随子块最小键变化重建：前端插入（`p == 0`）、删除第 0 条（最小键变了或该块空了）、整组压缩（重放会逐条前端插入，用抑制标志避免逐条重建，**末尾重建一次**）。计数 `dir_rebuilds` / `dir_entries_built` 供后续代价测量。

### 1.5 默认路径不变

`Mode::locate` 默认 **false**。三个继承门在本轮**数字逐字不变**，即默认路径与 E10 完全一致；定位是显式开启的变体。

## 2. 正确性

### 2.1 发现的缺陷：多块扫描在中间空子块处丢键

`Region::scan` 的归并循环中，`blk` **只在"取走当前子块最后一条"时前进**。若中间存在**空子块**（`count == 0`），`have_a` 恒为假；此时若溢出也取完，`break` 结束该组，**后面所有子块的记录被静默丢弃**。`g == first && matches` 的预推进只覆盖第一个组。

**最小复现**（`probe_scan.cpp`，本轮保留）：

```
regions=35 multiblock_groups=182 max_subblocks=23
static scan sweep OK
FULL SCAN MISMATCH step=1996 got=1935 want=1937     ← E10 与 E11 修复前，输出逐字相同
```

**修复**：把"跳过空／取尽的子块"提到归并循环顶部，作为唯一的推进点。修复后复现 **6000 步动态 + 全量静态扫描全部通过**。

**对既有结论的影响**：**E9／E10 的正式数字不受影响**。它们的 bench 只构建不删除，布局中不存在空中间子块；三个继承门在修复后数字逐字不变，也印证它们从未走到该路径。缺陷是潜伏的，不是已污染结果的。

**处置**：E9／E10 是冻结的已交付轮次，本轮**不擅自回改**；缺陷、复现与修复一并记录，是否回补由项目决定。

### 2.2 针对性门 check_e11_locate.cpp

在同一索引上对照 `locate` 开／关两条路径，逐查询要求 `found/value/source` 完全一致。按键族构造（随机测试到不了关键位置）：

| 键族 | 次数 |
|---|---:|
| 各子块的最小键与最大键 | 1,516 |
| 两子块之间的不存在键 | 523 |
| 小于全部主块键、大于全部主块键 | 469 |
| 溢出区的每条记录 | 331 |

外加动态段 12,000 步（插入／更新／删除／扫描／查找）全程对照。

**结果**：

```
comparisons = 112,366    mismatches = 0
queries_below_every_primary   = 996      ← 走无候选块路径
queries_answered_from_overflow = 13,893  ← 溢出答案
目录结构校验 26,626 组次（条目数==非空子块数、编号有序、边界严格递增、
                        边界就是该子块真实最小键）
scans = 2,084   dynamic_ops = 12,000
```

**一处如实报告**：强制构造的"**低于所有主块键且存在于溢出区**"这一双重条件，本轮只产出 **1 例**（未强制时天然 0 例）。原因清楚——**溢出记录绝大多数是大键**，很少落到边界之下。该情形被触发并通过，但覆盖薄；无候选块路径本身覆盖 996 次、溢出答案 13,893 次是厚实的。

### 2.3 继承门

`check.cpp`、`check_e8_hetero.cpp`、`check_e9_multiblock.cpp` 三个门在 E11 上**数字逐字不变**。

## 3. 本轮明确未做

**定位代价未测。** 按项目指令，先做基线比较（E12），子块范围定位作为后续新增变体。推迟的内容：

| 对照指标 | 要回答的问题 |
|---|---|
| 边界比较次数与逻辑比较字节 | 是否重新引入了昂贵的长前缀比较？ |
| 候选主块检查数、SIMD 批次 | 实际省下多少遍历？ |
| 溢出进入率与探测数 | 原有溢出查找是否保持一致？ |

**本轮不给出"定位是否划算"的结论**。已建立的只是：**它正确地做到了"至多一个候选主块"**。

## 4. 边界

1. **不计时**，也不声称定位会更快。特别地：定位本身要读边界、比字符串，重复前缀数据上省下 SIMD 遍历后可能重新付出较长的边界比较——**这需要测量，本轮没有测**。
2. **目录空间是真实的**（外层槽位 + 边界串），已计入 `memory()`；单块布局为零。
3. **双重条件覆盖薄**（1 例），见 §2.2。
4. **S 分配器在预算不足时的候选取舍仍未验证**（E9 遗留项）。
5. **扫描缺陷在 E9／E10 中仍存在**，本轮未回补（§2.1）。
6. 单一平台、合成与固定快照数据。
