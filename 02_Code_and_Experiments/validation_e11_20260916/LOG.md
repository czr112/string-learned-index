## 本轮最重要的事：发现并修复 E9 遗留的扫描缺陷

### E11-1 缺陷（2026-09-16）
新写的 `check_e11_locate.cpp` 在第三组参数（`block_bytes=1024, slots=48, region_keys=64`）上以 `FAILED range scan` 失败。

**最小复现**（`probe_scan.cpp`，本轮保留为证据）：同一份复现编译进 **E10 与 E11 两个目录**，结果逐字相同——

```
regions=35 multiblock_groups=182 max_subblocks=23
static scan sweep OK
FULL SCAN MISMATCH step=1996 got=1935 want=1937
```

**E10 与 E11 输出完全相同 → 这是 E9 引入、E10 继承的缺陷，不是 E11 引入的。**

### E11-2 根因（2026-09-16）
`Region::scan` 的归并循环：

```cpp
while (out.size() < limit) {
    const bool have_a = blk < nb && a < header(g, blk).count;   // ← 空块时 a<count 为假
    const bool have_b = o && b < o->size();
    if (!have_a && !have_b) break;                              // ← 直接结束整组
    ...
    if (take_a) { ...; if (++a == header(g, blk).count) { ++blk; a = 0; } }  // ← 唯一的推进点
    else { ...; ++b; }
}
```

`blk` **只在"取走当前子块最后一条"时前进**。若中间有一个**空子块**（`count == 0`），`have_a` 恒为假；此时若溢出也取完，`break` 结束该组——**后面所有子块的记录被静默丢弃**。

`g == first && matches` 的预推进只覆盖第一个组，`g > first` 的组没有跳过空块的机制。

**这是丢键**：`idx.size()` 与参照一致，但扫描少返回记录。中间空子块由 `erase` 清空某个子块产生；构建期按序填充不会产生，所以 E9/E10 的 bench（只建不删）与 E9 的门（参数下未出现空中间块）都没有触发。

### E11-3 修复（2026-09-16）
把"跳过空/取尽的子块"提到归并循环顶部，作为**唯一**的推进点：

```cpp
while (out.size() < limit) {
    while (blk < nb && a >= header(g, blk).count) { ++blk; a = 0; }
    const bool have_a = blk < nb;
    ...
    if (take_a) { ...; ++a; } else { ...; ++b; }
}
```

验证：复现程序在 E11 上 **6000 步动态 + 全量静态扫描扫过全部键 → ALL OK**；E10 上仍失败（对照组）。

**对既有结论的影响**：E9／E10 的正式数字**不受影响**——它们的 bench 只构建不删除，布局中不存在空中间子块。三个继承门在修复后**数字逐字不变**，也印证它们从未走到该路径。缺陷是潜伏的，不是已污染结果的。

**处置**：E9／E10 是已交付的冻结轮次，本轮**不擅自回改**；缺陷与本复现一并记录，是否回补由项目决定。

## 其余改造

### E11-4 边界目录（2026-09-16）
为**多块组**建立非空子块的边界目录：每条 = `{该子块最小后缀（自有拷贝）, 子块编号}`，按子块顺序。单块组不建目录。

- 边界**拥有自身存储**（拷贝而非指向块内的视图），因此压缩不会留下悬空引用。
- 目录空间（外层槽位 + 每条边界串 + 描述符）**全部计入** `memory_breakdown().directory` 与 `memory()`——**不再声称"零新增元数据"**。
- 单块布局 `dirs_` 为空，连外层槽位都不付。

### E11-5 范围定位（2026-09-16）
`Mode` 增加 `locate`（默认 **false**，因此默认路径与 E10 逐字相同）。

`locate_subblock(g, s)` 在边界目录上二分，返回"不大于 s 的最后一个边界"对应的子块；**小于所有边界时返回 `NO_SUBBLOCK`**。

`find_impl` 只改循环的起止：`lo_blk..hi_blk`。标签筛选与精确比较的代码**一行未动**——只改"访问哪些子块"，最小风险。

**关键正确性条件**：`NO_SUBBLOCK` **不等于**"本组未命中"。M1 只约束主块之间的顺序，不保证溢出记录落在某个主块的 min/max 之间。因此定位失败后**必须**继续原有 Hybrid 溢出查找——代码里 `if (result.found) return result;` 之后的溢出段**完全未改**。

### E11-6 目录维护（2026-09-16）
目录必须跟着子块最小键变化。触发点：
- `insert_into` 在 `p == 0`（前端插入）时重建该组目录；
- `erase` 在删除的是第 0 条时重建（该块最小键变了，或该块空了）；
- `compact` 重放整组会逐条前端插入 → 用 `suppress_dir_rebuild` 抑制，**末尾重建一次**。

计数：`dir_rebuilds`、`dir_entries_built`（供后续代价测量）。

### E11-7 针对性门 check_e11_locate.cpp（2026-09-16）
**在同一索引上**对照 `locate` 开／关两条路径，逐查询要求 `found/value/source` 完全一致。随机测试到不了关键位置，因此按键族构造：

| 键族 | 覆盖 |
|---|---|
| 各子块的最小键与最大键 | 1,516 次 |
| 两子块之间的不存在键（前块最大键 + `\0`） | 523 次 |
| 小于全部主块键（组最小键的严格前缀）、大于全部主块键（末键 + `\xff`） | 469 次 |
| 溢出区的每一条记录 | 331 次 |
| **强制构造**：逐个清空前导非空子块，使溢出记录落到边界之下 | 见下 |
| 动态段：插入／更新／删除／扫描／查找 12,000 步，全程对照 | ✓ |

同时结构化校验目录本身：条目数 == 非空子块数、子块编号有序、边界严格递增、**边界就是该子块的真实最小键**（49,000+ 组次）。

**结果**：

```
comparisons=112366  mismatches=0
boundary_keys=1516  between_subblock_keys=523  outside_all_primary_keys=469
overflow_records_queried=331
queries_below_every_primary=996        ← 无候选块的路径
queries_answered_from_overflow=13893   ← 溢出答案
dir_groups_struct_checked=26626
dynamic_ops=12000  scans=2084
```

**一处如实报告**：强制构造的"低于所有主块键**且**存在于溢出区"这一双重条件，本轮只产出 **1 例**（未强制时天然出现 0 例）。原因清楚——**溢出记录绝大多数是大键**，很少落到边界之下。双重条件因此是稀有情形；它被触发并正确通过，但覆盖薄。无候选块路径本身覆盖了 996 次、溢出答案 13,893 次，是厚实的。

### E11-8 结论与边界（2026-09-16）
- **至多一个候选主块**已实现并通过检查（`candidate_blocks` 在 locate 路径下 ≤ 1；`queries_below_every_primary` 时可为 0）。
- **定位代价本轮未测**。按用户指令，先做基线比较（E12），"S ＋ 子块范围定位"作为后续新增变体；`bench_e11` 的定位代价诊断（边界比较次数与逻辑比较字节、候选块检查数、溢出进入率、目录容量与维护成本）**推迟**。
- 目录占用是真实的：外层槽位 `groups_ × sizeof(vector)`，混合数据约 21,000 组。它已计入空间，不是免费的。
