# E6 实验改造日志（validation_e6_20260913）

开始日期：2026-09-13。本目录继承 `validation_e5_20260913`（其继承 E3）的存储实现；目标是对**外层路由**做第一阶段的实现与消融：基线（fence 二分）→ A（前 8 字节大端整数辅助二分）→ B（同样前缀元数据＋Eytzinger 排列）。学习路由/ART 路由（C）按评审意见延后到第二阶段。

范围声明（对应评审 2026-09-13）：
- 固定路由保证叶方案在**同一控制变量**下比较；更换路由后**必须重测叶方案端到端**，不得预设叶排序不变；路由优化不是必然纯收益。
- E4 的 ART 是完整索引对照，E5 的 locate_only（172–268ns）与 E4 ART 数字（365.7ns）**属不同轮次不同协议，不做跨轮定量对比**。
- 最终验收以**端到端收益**为主；locate_only 微基准只用于解释原因。locate_only 与"端到端−区域内部"是不同测量，分别报告，不要求相等。
- 第一版允许分裂后整体重建辅助目录，但**必须记录更新次数与成本**。

环境：与 E5 相同（Windows 11 / Core Ultra 9 275HX / g++ 15.2.0 MinGW-Builds），编译 `-std=c++17 -O3 -march=x86-64-v2 -static`，进程内绑 CPU 0。sanitizer：本工具链无 libasan/libubsan（E5 已探测），clang++ 亦不可用（2026-09-13 复查）；路由正确性以**逐条区域编号差分**为主要手段并在下文如实注明。

### E6-2 RouterA：前 8 字节大端整数辅助二分（2026-09-13）
新增 `route_aux.hpp`。`prefix_u64`：前 8 字节按**大端序**构造整数（首字节在最高位），不足 8 字节尾部补零，空串安全（避免移位 64 位 UB）。性质：该映射保序——两值不同时，整数大小关系与无符号字节字典序完全一致（补零等价于虚拟 0x00 后缀，与"短串在前"规则相容，嵌入零字节亦正确）；**两值相等时不作任何判定，回退完整字符串比较**；总长度不作排序键（评审例 `abcdefghz`/`abcdefghaa` 由等值回退处理）。查询前缀整数每次 `locate` 只计算一次。
结构：fence 的 U 值非递减数组；二分求严格小于 U_key 的个数 c1；等值块内按 fence 全比较二分求 ≤key 个数 c2；`locate = c1+c2-1`（下限 0）。元数据在 `structure_version` 变化时整体重建，重建次数与耗时分别记账。
验证：check_router.cpp 逐条差分（见 E6-5）。

### E6-3 RouterB：同前缀元数据＋Eytzinger 排列（2026-09-13）
动机（评审）：分清收益来自"前缀比较"还是"目录排列"。Eytzinger（层序）排列本身不保证无分支也不保证更快，故只作为独立变体实测。
实现：标准中序构造把 fence（按原序）放入 1-based 层序数组（`ue_`＋`orig_` 反查表）；下降过程每层比较 U，**等值时用 fence 全比较决定左右**（`ge = u>uk || (u==uk && compare(fence,key)<=0)`），记录首个 ≥key 的位置；按"该 fence 是否等于 key"区分 `locate=fence序号` 或 `序号-1`（下限 0；全部 fence<key 时为 m-1）。元数据同 E6-2 版本机制。
验证：同上，与基线逐条差分（含全部 fence 键本身、fence±1 字节变体、空串、高位字节、8 字节边界对）。

### E6-4 基准程序 bench_e6.cpp（2026-09-13）
固定叶（context16/B=1024/S=16），方法：`locate_baseline/locate_A/locate_B`（微基准）与 `end_baseline/end_A/end_B`（端到端）。纪律与 E5 相同：独立查询副本、50% 命中、`~missing~` 未命中核实不存在、3 种子×5 轮、乱序、预热 20000、批校验和（locate 方法的校验和=区域序号和；find 方法=结果校验和）。每个种子计时前先逐条断言 A/B 与基线路由一致。输出 fence 前 8 字节碰撞诊断（不同 U 数、与前驱同 U 占比、最大等值游程）、辅助元数据字节数、路由重建耗时。

### E6-8 结果汇总（2026-09-13）
三组数据（mixed 131072 / skew 131072 / tranco 262144）正式运行完成，每方法 15 批，全部批校验和通过。要点：
1. fence 前 8 字节区分度决定 A/B 收益：tranco 0% 碰撞 → locate −24%/−32%、端到端配对 −3.5%（11/15 胜）/−5.9%；mixed 71.9% 碰撞 → 配对差 ≈0；skew 100% 碰撞 → A≈基线、B 劣化。评审"长公共前缀使 A 失效"的预判被数据证实。
2. 元数据：A 512B–1KB、B 1–2KB；构建期重建 9–23μs；动态 2146 次重建共 7.0ms。
3. 路由总收益受当前规模限制（64–128 区域，locate 总盘子 50–270ns）；端到端主导成本仍是溢出扫描（E5 证据）。
4. 决定：A 保留为可开关组件进入选型框架；B 暂不默认；C（学习/ART 路由）延后，其评估上限由本阶段量化；E7 建议转向分组质量与溢出访问，更大区域规模时再复测路由。
详见 `RESULTS_E6.md`。
