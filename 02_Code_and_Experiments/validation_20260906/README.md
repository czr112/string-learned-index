# 字符串学习型索引自主验证包

验证日期：2026-09-06。此包包含可运行的 C++17 机制原型、正确性检查、原始计时结果及复现脚本。它不是 LITS/CARMI 的复现，也不是完成的项目产品。

## 查看结果

- `VALIDATION.md`：本轮发现、结果边界和下一步判断。
- `RESULTS_TABLE.md`、`summary.json`：由原始 CSV 自动计算的汇总。
- `QUERY_COPY_TABLE.md`、`OVERFLOW_PROBE_TABLE.md`：两个后续定向实验的独立汇总；单位均为 7 轮批次平均 ns/op 的中位数。
- `results/main/`：9 个主要配置；每种方法 7 轮，完整记录。
- `results/diagnostic/`：两个缩小区域的定向对照；每种方法 7 轮。
- `overflow_probe/results/`：针对线性溢出查找与二分溢出查找的独立对照。
- `query_copy_probe/results/`：百万长键及百万真实域名，查询字节使用独立副本的补充对照；用于检查有序数组基线的别名优势。
- `update_events.csv`：12000 次动态混合操作的逐操作记录。
- `correctness.json`、`overflow_probe/correctness.json`：两套实现的差分检查结果。
- `environment.json`：编译器、CPU、缓存及运行限制。
- `MANIFEST.sha256`：交付文件校验值。

试跑放在 `results/pilot/`，不用于主结论。其短键文件目前只保留 3 轮，原请求为 5 轮，且终端摘要与保留 CSV 不一致；原因未确定。保留原文件并在 `summary.json` 标记，没有补造缺失行。主实验与定向实验均完成全部 7 轮。

## 实现范围

`index.hpp` 实现：无符号字节字典序；共享前缀；区域内归一化整数条件模型；块号确定条件；64 字节对齐、固定步长的真实内存块；紧凑条目及块内后缀字节；属于原组的溢出容器；find/insert/update/upsert/erase/scan；区域重建及分裂。

模型使用 16 个上下文行，每行 257 个符号（EOS＋256 个字节），累计概率量化为 2^16；位置尺度为 2^47。每个训练键最多采集前 16 个后缀字节，查询仍可按该模型继续计算。这个简化模型可能产生严重分组偏斜；不能据此推断正式 LITS 或更强字符串模型的性能。

每块含 64 字节块头、16 个 16 字节条目，以及剩余后缀区。长后缀及容量冲突进入组内溢出容器。块数按条目数量与后缀字节的平均容量估计，装载率 0.75；尚未实现按实际最大组占用选择模型、自动迁移阈值或后台重建。外层使用有序区域分隔键二分查找，不是经过完整优化的学习树。

第一套实现的点查在有序溢出容器中逐条筛选。`overflow_probe/` 是独立的后续版本：溢出容器超过 32 条时，增加精确二分查找选项；保留原版源码和原实验，避免覆盖证据。两套代码都只实现单线程安全性，没有并发发布、锁、epoch 或稳定返回引用的 API。

## 方法名称

| CSV 名称 | 含义 |
|---|---|
| full | 完整数值模型计算；区间宽度为零时允许终止；不预取 |
| full_pf | 同上，在剩余指纹计算前预取块头 |
| interval | 两端点确定同一块号时终止；不预取 |
| interval_early_pf | 提前停止后、剩余指纹计算前预取块头 |
| interval_late_pf | 提前停止后，先完成指纹，再发出预取 |
| interval_direct | 提前停止，但不使用指纹筛选，直接精确比较 |
| residual / residual_pf | 剩余影响低于一块时停止的参照函数；有／无预取；使用按此函数独立构建的布局 |
| sorted_array | 完整字符串有序数组＋二分查找；是合理简单基线，不是 SOTA 字符串索引 |
| overflow_linear / overflow_binary32 | 后续独立版本中的线性溢出查找／大溢出区二分查找，其余条件相同 |

`residual` 参考已有提前停止思想，属于自建整数参照，不等于原版 LITS。`end` 包含外层区域定位；`local` 预先知道所属区域，用于隔离区域内部工作，不能作为完整索引延迟。各方法返回结果均参与校验和，避免被编译器消除；预热查询还逐项核对答案。

## 数据与计时

- 合成 `short` 实际是 37 字节的用户键（固定前缀＋两个十六进制字段）；称为“短”是相对于长字符串。
- 合成 `long` 为 156 字节，含共享 URL 形式前缀、唯一字段和随机后缀。
- 合成 `skew` 为 156 字节，含不同长度的重复 `a` 段、唯一字段和尾部字符；不是通用 Zipf 数据或真实 URL。
- Tranco 使用固定列表 XN6XN，共 100 万域名，生成于 2026-09-05。域名不是完整 URL，不替代项目的 dblp/wiki/URL 数据。原始排名不作为访问热度，查询按均匀抽样生成。[列表来源](https://tranco-list.eu/list/XN6XN)

Tranco 数据未重新打包；下载地址、CSV SHA-256 和版本保存在 `tranco_source.json`。引用：Victor Le Pochat et al., “Tranco: A Research-Oriented Top Sites Ranking Hardened Against Manipulation,” NDSS 2019，DOI 10.14722/ndss.2019.23386；聚合数据的来源与许可见 [Tranco 官方说明](https://tranco-list.eu/)。

性能程序使用单线程并绑核，10% 未命中查询（在已存在 ASCII 键后附加零字节生成），每轮打乱方法运行顺序，每个方法先预热至多 20000 个查询，再计时完整批次。主实验和定向实验各方法均 7 轮；结果报告批次平均耗时的中位数，并保留最小／最大值。指纹在本机使用 SSE4.2 CRC32；代码也保留软件回退，但不同实现的速度不能直接比较。

`index_bytes` 是按块、模型、容器容量和字符串容量估计的结构及数据大小；不是 RSS，未包含分配器元数据。小字符串内联容量可能保守重复计入。基准进程还保存生成键、查询和第二套参照索引，不能把该字段当作进程峰值内存。

`mean_model_bytes` 和 `mean_overflow_checks` 来自额外的 4096 查询采样，不是性能计时器的时间分解。主 CSV 中 `p50_sample_ns` / `p99_sample_ns` 是随后对同一子集再次访问的暖缓存样本，含时钟开销；不用于总体尾延迟结论。维护实验的逐操作时钟同样有开销，其与重建同时出现的大延迟只代表观测结果，没有最坏界保证。

环境为共享虚拟化主机，没有硬件缓存计数；不能把延迟差异直接解释为缓存命中率变化。跨配置诊断来自不同进程，存在系统噪声；未做完整显著性检验或跨硬件复现。

基准审查发现：主实验、区域诊断及溢出对照中的命中查询引用生成键，而有序数组基线直接保存生成键；查询与基线记录的字节存在别名，可能有利于该基线。完整计算、提前停止及预取之间的布局隔离仍成立，但跨结构速度比较有此限制。因此另保留 `query_copy_probe/`，给所有命中／未命中查询创建独立字符串副本，再比较完整计算、区间停止、提前预取和有序数组。比较这四种方法时优先看该补充对照，不能将其与原进程结果直接拼接。

## 复现

需要 Linux、Python 3、支持 C++17 的 g++、`taskset`，完整实验另需网络下载 Tranco。建议在交付包的副本中运行，保留原始结果。

```bash
python3 reproduce.py
```

上面会重新编译并运行两套正确性检查及动态操作检查。

```bash
python3 reproduce.py --full
```

上面继续下载并核对固定数据，运行主实验、区域诊断、溢出对照及独立查询副本对照，重新生成汇总。百万级实验需要数 GB 可用内存及数分钟运行时间；耗时取决于硬件。

原容器中的 LeakSanitizer 结束扫描因进程可见性限制失败，因此复现脚本明确使用 `detect_leaks=0`，保留 AddressSanitizer 和 UndefinedBehaviorSanitizer。这里的通过结果不包含泄漏检查；可在支持的本地环境另行开启。

## 工作记录

先实现区域与真实块存储，再执行差分和内存检查；小规模试跑发现预取波动及溢出过多，随后完成 9 个主配置；根据结果追加两个区域大小对照，再针对有序溢出容器补做二分查找对照；最终代码审查发现查询别名问题，又补做百万级独立查询副本对照。保留负结果与所有版本，没有为了获得加速比而删改主实验样本。

本包未运行 ART、HOT、原版 LITS/LIT+ 的正式基准，未证明发表新颖性，也未完成动态性能最优策略。这些是后续项目验收内容。
