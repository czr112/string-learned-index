## E17-1 设计（2026-09-16）

### 三条路径

| 路径 | 内容 |
|---|---|
| B | `probe.bulk_load` → `group_stats()` → 规划 → `bulk_load` + 逐区域 `rebuild_with_caps` |
| A | 同 B 的探针与规划 → `bulk_load_with_plan` |
| C | `demand_profile` → 规划 → `bulk_load_with_plan` |

### 轮换顺序 + 配对比值

每个重复里三条路径按 `{B,A,C}`／`{A,C,B}`／`{C,B,A}` 轮换执行，所以"第几个跑"不固定落在同一条路径上。**比值在单次重复内配对计算**（`A_r/B_r`、`C_r/A_r`、`C_r/B_r`），再跨重复、跨进程取中位数。5 个重复 × 5 个进程。

### 零仪器

**没有任何分配器包装，没有任何记账。** 这是 E16 的直接教训：记账开在计时区里会**不成比例地放大探针路径**（它的分配次数远多于统计路径）。本轮的时间数字必须来自不带任何仪器的构建。内存诊断仍以 E16 的独立构建为准。

### 先比结构

每次运行内部先比对三条路径建出的 S 摘要，**不一致直接抛异常**，不产生记录。摘要串行化沿用 E14／E15／E16，因此还能与 E15 记录的**值**直接比。

## E17-2 事故（2026-09-16）

1. **脚本生成的 `tools_build.py` 丢了 `SRC` 定义。** 我用整段替换清掉了 E16 的目标配置，连带把 `SRC = {...}` 一起删掉，构建时报 `NameError: name 'SRC' is not defined`。**由构建闭环拦下**（失败即不产生可执行文件，`build/` 里没有留下半成品）。补回空字典。
2. **组装脚本用了自己的目录做相对路径**，`HERE/../validation_e16_...` 解析成了 tmp 目录下的路径，`FileNotFoundError`。改成从命令行显式接收两端路径。
3. **heredoc 里的引号把 shell 提前截断**（组装 `bench_e17.cpp` 的那条命令）。改为**先把脚本写成文件再执行**——这类组装脚本本来就该是文件，而不是一次性命令串。

## E17-3 结果（2026-09-16）

5 个进程 × 3 数据集，先热身再测量。完整表见 `E17_TABLES.md`。

**结构**：三条路径的摘要**本轮内一致，且与 E15 记录的值逐字符相同**（三个数据集全部）。

**时间（ms，跨进程中位数）**：

| 路径 | 混合字符串 | 重复前缀 | 百万域名 |
|---|---:|---:|---:|
| B（原始） | 137.76 | 152.84 | 243.89 |
| A（E15） | 78.60 | 93.51 | 154.73 |
| **C（最终）** | **69.24** | **80.85** | **109.28** |

**比值**（逐进程比值的中位数）：

| 比值 | 混合字符串 | 重复前缀 | 百万域名 |
|---|---:|---:|---:|
| **A / B** | **0.576×** | **0.577×** | **0.630×** |
| **C / A** | **0.863×** | **0.875×** | **0.713×** |
| **C / B** | **0.496×** | **0.526×** | **0.453×** |

跨进程离散（`C/B`）：混合 0.444–0.528、重复前缀 0.498–0.536、百万域名 0.422–0.456。三个数据集方向一致。

**与前两轮各自报的数对照**：A/B 类前两轮报 0.617×–0.657×、本轮 0.576×–0.630×；C/A 类前两轮报 0.732×–0.884×、本轮 0.713×–0.875×。量级一致但**不是同一个数**（分母定义与机器状态都不同）——**这正是不能用乘积的原因**：本轮把三者放进同一进程后 `C/B` 落在 0.453×–0.526×，乘积会给出 0.48×–0.55×，两者接近但不等，而**只有前者是可复现的定义**。

## E17-4 结论与下一步（2026-09-16）

1. **合计成果已直接测得**：两处改造使完整构建流程降至 **0.453×–0.526×**，即约 **1.9–2.2 倍**。**总报告中跨轮相乘的"合计"已删除，替换成这个直测值。**
2. **三处验证一致**：三条路径同结构（跨轮摘要逐字符相同）、四个继承门与 E12 逐字相同、两个新门 `passed`。
3. **下一步是拆 `place`**：E14 测它占 Region 构造 45%–66%，**但那是 E14 的运行与旧构建过程**，当前路径已改过两处，**占比需在当前路径上重测**。要拆四段：组号与指纹计算／主块选择与容量检查／描述符移动与后缀复制／溢出容器插入与分配。
4. **ART 对照本轮没补**：`bench_e17` 不链接 libart（`native.hpp` 自带包装，与"零仪器"相冲）。若要把"最终实现 ÷ ART"补齐，需要单独一轮把 libart 与本轮 C 路径放进同一个干净程序。
