# E17 结果：三条构建路径的同轮直接比较

日期：2026-09-16。目录：`validation_e17_20260916`（继承 E16）。平台：WSL2 Ubuntu 24.04 + g++ 13.3.0，单核绑定。

**E15 与 E16 各自只与其替代掉的那条路径比过，两处改造从未在同一次运行里同时对过。本轮把三条路径放进同一个干净计时程序，直接测出 `C / B`。**

---

## 0. 结论摘要

| 路径 | 内容 |
|---|---|
| **B** | 完整探针 + 规划 + 先构建再重建（原始完整流程） |
| **A** | 完整探针 + 规划 + 直接构建（E15） |
| **C** | 轻量统计 + 规划 + 直接构建（E16，最终实现） |

| 比值 | 混合字符串 | 重复前缀 | 百万域名 |
|---|---:|---:|---:|
| **A / B**（隔离 E15） | **0.576×** | **0.577×** | **0.630×** |
| **C / A**（在 E15 路径上隔离 E16） | **0.863×** | **0.875×** | **0.713×** |
| **C / B（两项合计）** | **0.496×** | **0.526×** | **0.453×** |

**两处改造合计使完整构建流程的时间降至原来的 0.453×–0.526×，即约 1.9–2.2 倍。**

**这个数是直接测出来的，不是把前两轮的比值相乘。** §3 说明了为什么不能相乘。

| 验证项 | 结果 |
|---|---|
| 三条路径建出的结构 | **摘要一致**，且**与 E15 记录的值逐字符相同** |
| 四个继承正确性门 | 输出与 E12 **逐字相同** |
| `check_e15_plan`／`check_e16_probe` | 均 **passed** |

## 1. 为什么需要这一轮

E15 报的是"两遍构建 → 一遍构建"（在其自身运行中：完整流程 0.617×–0.657×）。
E16 报的是"探针 → 轻量统计"（在其自身运行中：完整流程 0.732×–0.884×）。

两者都不能单独回答"原始流程 → 最终流程是多少"，因为：

- E15 测得的中间量 A（探针 + 规划 + 一遍构建）与 E16 测得的 A **不是同一次观测**，不能消去；
- 而且**两个比值中位数的乘积通常也不等于总比值的中位数**，即使在同一环境。

所以此前版本里用乘积给出的"合计 0.48×–0.55×"**已经被移除**。本轮直接测。

---

## 2. 方法

### 2.1 三条路径

```cpp
B: Index probe(c); probe.bulk_load(keys);  …group_stats()…  plan
   Index x(cm); x.bulk_load(keys);
   for (i) x.rebuild_with_caps(i, x.region(i).all(), plan…);      // 原始完整流程

A: 同 B 的探针与规划，但
   Index x(cm); x.bulk_load_with_plan(keys, plan…);               // E15

C: Index stats_only(c); auto demand = stats_only.demand_profile(keys);  plan
   Index x(cm); x.bulk_load_with_plan(keys, plan…);               // E16
```

相同键、相同 `Config`、相同规划。**每个重复里三条路径按轮换顺序执行**（`{B,A,C}`、`{A,C,B}`、`{C,B,A}` 循环），所以"第几个跑"不会固定落在同一条路径上；**比值在单次重复内配对计算**（`A_r/B_r`、`C_r/A_r`、`C_r/B_r`），再跨重复、跨进程取中位数。

### 2.2 干净计时

**没有任何分配器包装，没有任何记账。** E16 已经证明：把记账开在计时区里会**不成比例地放大探针路径**（它的分配次数远多于统计路径）。本轮所有时间数字都来自不带任何仪器的构建。内存诊断仍以 E16 的独立构建为准。

### 2.3 先比结构，再报时间

每次运行内部先比对三条路径建出的 S 摘要，**不一致直接抛异常**，不产生记录。摘要串行化与 E14／E15／E16 相同（含 SHA-256 自检），因此还能与 E15 记录的**值**直接比。

| 数据 | 本轮内三条路径一致 | 与 E15 记录的摘要相同 |
|---|---|---|
| 混合字符串 | 是 | **是** |
| 重复前缀 | 是 | **是** |
| 百万域名 | 是 | **是** |

**三条路径建出的是同一个结构，而且就是前几轮记录的那个。**

摘要覆盖的边界与 E15 §1.2 相同，此处不重复；支持的说法仍是「规范化结构摘要一致，测试查询结果一致，现有功能检查未观察到回归」。

## 3. 结果

完整表见 `E17_TABLES.md`。中位数（ms，5 进程）：

| 路径 | 混合字符串 | 重复前缀 | 百万域名 |
|---|---:|---:|---:|
| B（原始） | 137.76 | 152.84 | 243.89 |
| A（E15） | 78.60 | 93.51 | 154.73 |
| **C（最终）** | **69.24** | **80.85** | **109.28** |

比值**同时给两种口径**（本项目已记录的失效模式）：

| | 混合字符串 | 重复前缀 | 百万域名 |
|---|---:|---:|---:|
| **A / B**，逐进程比值的中位数 | **0.576×** | **0.577×** | **0.630×** |
| A / B，中位数之比 | 0.571× | 0.612× | 0.634× |
| **C / A**，逐进程比值的中位数 | **0.863×** | **0.875×** | **0.713×** |
| C / A，中位数之比 | 0.881× | 0.865× | 0.706× |
| **C / B**，逐进程比值的中位数 | **0.496×** | **0.526×** | **0.453×** |
| C / B，中位数之比 | 0.503× | 0.529× | 0.448× |

**跨进程离散（`C / B`，5 个进程）**：混合 0.444–0.528、重复前缀 0.498–0.536、百万域名 0.422–0.456。三个数据集的方向在 5 个进程上一致。

**池化全部 25 个重复样本**：`C / B` = 0.506／0.513／0.438（`A/B` = 0.575／0.603／0.627，`C/A` = 0.880／0.850／0.700）。

### 3.1 与前两轮各自报的数对照

| | 前两轮各自报的 | 本轮同轮实测 |
|---|---|---|
| A / B 类（E15 的收益） | 0.617×–0.657×（完整流程口径） | **0.576×–0.630×** |
| C / A 类（E16 的收益） | 0.732×–0.884× | **0.713×–0.875×** |

量级一致，但**不是同一个数**——分母不同（前两轮的"完整流程"含各自那轮的探针/构建定义），机器状态也不同。**这正是不能用跨轮比值相乘的原因**：本轮把三者放进同一进程之后，`C / B` 落在 **0.453×–0.526×**，而乘积会给出 0.48×–0.55×；两者接近但不等，而且**只有前者是可复现的定义**。

## 4. 对 ART

**本轮不含 ART 对照。** `bench_e17` 不链接 libart（`native.hpp` 自带 `calloc`/`free` 包装，与本轮"零仪器"的要求相冲）。ART 的数字仍以 E15 轮为准：完整流程 ÷ ART = 2.12×／1.76×／4.88×，**那是 E15 路径的对照，不含 E16**。

若要把"最终实现 ÷ ART"也补齐，需要单独一轮把 libart 与本轮的 C 路径放进同一个干净程序——**本轮没做**。

---

## 5. 现在还剩什么

`C / B` 已经是"构建流程"这一层的完整答案。**下一步是把 `place` 拆开。**

**E14 测出 `place` 占 Region 构造 45%–66%，是最大的一项；但那是 E14 的运行与当时的构建过程**，当前路径已经改过两处，**具体占比需要在当前路径上重测**。要测的是四段：

* 组号计算与指纹计算；
* 主块选择与容量检查；
* 描述符移动、后缀复制；
* 溢出容器插入与分配。

之后才谈优化。`dir`／`layout`／容量规划按 E14 的分解不动（合计不到 4% 与约 2%）。

---

## 6. 适用边界

1. **只覆盖静态批量构建。** 增量路径（`insert`／`erase`／`rebuild`／分裂）逻辑未改，也没有被重新计时。
2. **`C / B` 是"完整构建流程"的比值**，不是端到端查询性能，也不是空间。
3. **摘要不是物理字节相等的证据**（§2.3，边界同 E15 §1.2）。
4. **比值同时给两种口径**（逐进程比值的中位数／中位数之比），两者最多相差约 0.015。
5. **绝对耗时跨进程漂移约 10%**；结论建立在 5 进程一致的方向上。
6. **各轮绝对值不可拼接**（E12–E17 机器状态不同）；**本轮的价值恰恰在于消除跨轮拼接**。
7. **不与 E4 拼接**（另一台机器、另一套 `-march`）；**无 sanitizer**（工具链与 WSL 侧均不可用）。
8. **不含 ART 对照**（§4）。
