# E4 实现与自主验证结果

2026-09-11。已经实现跨区域候选测量、独立验证集选择和原生 ART 对照。**本轮支持“保留简单配置回退”的工程方案，但不支持“跨区域联合选择一定更好”或“当前原型已经胜过成熟 ART”的结论。**

## 1. 这次实际增加了什么

| 模块 | 已实现行为 |
|---|---|
| 跨区域成本矩阵 | 每个候选构建全数据索引；随机交错区域查询，计入完整外层路由，再按实际访问区域归集耗时 |
| 同条件局部代理 | 在同一候选索引上连续查询单个叶，保留上一轮暖访问思路作对照 |
| 独立验证选择 | 所有预算可行的统一配置与两类代理产生的联合／回退配置竞争，验证后冻结配置，再生成测试查询 |
| 相同配置去重 | 区域配置向量相同就复用一个索引和一组计时，不把不同名称当作不同算法 |
| 原生基线适配 | 接入固定版本 armon/libart；LITS 适配与两项边界修复保留，因后续检查失败而排除正式计时 |
| 结果完整性门槛 | 校验源代码摘要、CSV 行数、字段、完整末行；不完整尝试整体归档，不补造数据 |

代码在 `selector.hpp`、`native.hpp` 与 `bench.cpp`。存储和字符串模型仍使用 E3 的实现，没有在本轮性能实验中改写其底层布局。`Registry::validate` 输出所选索引，后续查询直接调用 `SelectedIndex::find`。它是离线选型流程，尚未处理在线漂移和并发切换。

## 2. 如何避免再次用测试结果选参数

按排序后的键序号 `% 8` 分为三类查询身份：0/1 调参，2/3 验证，4–7 测试。索引正常装载所有键；隔离的是访问键及其衍生未命中查询。每组验证完成后写出 `frozen.json`，随后才生成测试查询。它保证本轮内隔离，不代表历史实验从未访问过这些键。

本轮共同接口为不含 NUL 的 ASCII 字符串；命中率固定 50%，未命中查询在源键后追加 `~missing~`，事先查明不存在。所有查询拥有独立字符串内存。上一轮命中率约 90%，且负例追加 NUL；LITS 的 C 字符串 API 无法沿用那个协议，所以**不能把两轮绝对耗时直接拼成加速比**。

最终每组 262144 条查询、3 个种子、每种子 5 轮，方法次序随机。总计 420 条正式批次计时，计时外完成 **22020096 次逐查询核对**，计时内再核对结果汇总。新选择器检查覆盖 49152 条分区查询，并验证身份隔离、命中比例、配置去重及预算；ASan+UBSan 通过。ART 另外通过 10000 次随机操作与 33330 次查找核对，也通过 ASan+UBSan。此前 E3 的 70000 次动态操作证据继续保留，不写成本轮重新做过。

CPU 0 串行运行；共享虚拟机，三组固定数据分别为重复前缀长键 131072、混合字符串 262144、Tranco 域名 1000000。下文数字是 15 个批次平均耗时的中位数，不是单次请求中位延迟或 P99，也不代表多台机器上的统计显著性。

## 3. 正式测试结果

单位 ns/op，越低越好；名称相同的冻结配置复用计时。

| 方法 | 重复前缀 | 混合字符串 | 百万域名 |
|---|---:|---:|---:|
| 默认 context16／1024 | 806.88 | 696.66 | 756.32 |
| 局部暖代理联合选择 | 593.54 | 537.21 | 642.25 |
| 跨区域代理联合选择 | 625.72 | 591.98 | 649.54 |
| 局部暖代理＋有序叶回退 | 557.36 | 541.63 | 632.01 |
| 跨区域代理＋有序叶回退 | 564.53 | 588.92 | 647.70 |
| 验证集最佳统一配置 | 636.01 | 601.45 | 650.05 |
| **验证集最终选择** | **564.53** | **537.21** | **650.05** |
| 全部前缀压缩有序叶 | 558.59 | 693.68 | 686.20 |
| 全字符串有序数组 | 722.88 | 828.06 | 729.95 |
| **原生 armon/libart** | **509.02** | **376.47** | **365.71** |

冻结策略分别为：重复前缀选跨区域代理＋回退，混合数据选暖代理联合配置，域名选统一 position16／512。相对默认，查询时间减少 30.0%、22.9%、14.1%；相对验证最佳统一配置，减少 11.2%、10.7%、0%。**三组最终策略仍分别比 ART 慢 10.9%、42.7%、77.7%。** 三个查询种子的中位数都保持了 ART 更快的方向。

ART 采用的是 [armon/libart 固定提交](https://github.com/armon/libart/tree/301046804af165269e37da6725f5a4aec9ecc881) 的 C99 实现，不代表 ART-OLC 或所有 ART 实现。其完整空间尚未按本原型相同口径计量，所以这里只作同查询语义下的时间对照，不能声称 ART 满足本原型空间预算。

验证选择也并非测试集“预言机”：重复前缀最终策略比已测可行配置中的测试最佳慢 1.29%，域名慢 2.85%，混合数据恰好选中测试最佳。这是事后诊断，**没有据此重选配置或重跑以优化排名**。较小差异可能受负载采样与主机波动影响。

## 4. 跨区域测量为什么仍没有兑现预期

最清楚的反例在混合数据。跨区域代理给它自己的联合配置估计 498.95 ns，给暖代理产生的联合配置估计 571.95 ns，预测前者更快；最终测试却是 **591.98 对 537.21 ns**，排序仍然反转。

本轮跨区域代理测量的是“所有区域使用同一候选”时的成本，然后将区域成本相加；最终异质索引的布局组合与访问相互影响并未被直接测量。调参查询仅抽样访问部分键，逐查询时钟也会扰动访问节奏；本机空时钟中位数为约 20 ns。三轮重复与随机交错不能消除这些结构性偏差。没有 PMU 与相应消融，不能把失败归咎于某一项缓存因素。

因此，**跨区域访问是一个已实现、但尚未可靠改进排序的成本代理；独立验证是评估与工程选择机制，两者目前都不应单独包装成已证实的论文创新。** 原文的主线仍应是分层模型如何降低预测与定位成本，以及物理布局如何减少真实内存访问。

## 5. 空间与选择成本揭示了另一处问题

| 数据 | 最终选择估计占用 | 最佳统一配置估计占用 | 选型额外成本量级 |
|---|---:|---:|---:|
| 重复前缀 | 38.54 MiB | 37.53 MiB | 6.44 秒 |
| 混合字符串 | 65.01 MiB | 62.07 MiB | 6.31 秒 |
| 百万域名 | 90.84 MiB | 90.84 MiB | 12.95 秒 |

预算约束最终索引的叶容量估计，外层路由另计；不是 RSS，也不约束整个选型过程的峰值。选型期间保留多个配置，峰值内存可能明显超过单个最终索引。表中成本包含候选测量、全部待验证配置构建、验证与记录开销，并减去直接建默认索引的成本，属于研究工具的实测量级。

按本轮相对默认的时间节约粗估，约需 2660 万、3960 万、1.22 亿次后续静态查询才摊平这项成本；没有计入未来更新、重新调参，也不能对更快的 ART 使用这种摊平说法。

重复前缀数据尤其值得警惕：最终选择 25／64 个有序叶，占 38.54 MiB；暖代理回退选择 62／64 个有序叶，占 16.06 MiB，测试还略快。全部有序叶仅 15.19 MiB，测试 558.59 ns。验证阶段最终选择与全部有序叶仅相差约 0.22%，却选了远大的结构。后续版本可预先规定“接近最快时优先更小、更简单”的容差规则，再独立验证；本轮不事后套规则改结果。

## 6. LITS 的接入进度和阻塞证据

取得并固定 [LITS 提交](https://github.com/schencoding/lits/tree/6f4793dff0dcf66daada49e2f4ae1b1838bfa9cc/LITS)，封装原生 bulkload、lookup、upsert、remove 与显式 destroy。无修改发布构建通过本轮返回值核对，但检查依次暴露：

1. PMSS 插值达到表格上界后仍读取下一列，越界。补丁夹紧行／列上界。
2. 补丁后 HPT::getCdf 在 gcpl=0 时读 key[-1]。补丁在起点使用上下文 0，与训练约定一致，并同步修改 getPos。
3. 双补丁后 UBSan 停在其内嵌 HOT 的未对齐 uint64_t 读取。本轮没有继续改写该路径，也没有关闭对齐检查来宣称通过。

因此，本轮**不报告 LITS 的正式性能数值**。三次失败日志、原始摘要、补丁脚本与重新下载入口都已保留，见 `NATIVE_STATUS.md`。这是具体提交与该输入下的检查结果，不代表论文主张被推翻。下一次可在明确完成修复和验证后恢复该基线。

## 7. 对课题实现路线的修正

当前值得保留的是“可替换后缀模型＋预测分组布局＋有序叶回退＋独立验证”的接口，但必须把它当作待优化原型。下一步应把工作重点从更复杂的选型算法转回实际索引结构：

- **可变条目槽数与字节容量。** E3 已证明域名默认溢出主要是槽不足，长键主要是后缀字节不足。把当前固定 16 槽改成显式布局参数 S，候选如 8／16／32；有效后缀空间按 `B − sizeof(Header) − S × sizeof(Entry)` 计算，只保留能容纳目录的组合。查询、插入、垃圾回收与重建必须共同使用布局描述，不能只改容量估计。仍用相同键与字节语义检查正确性，再独立选参数。
- **先量化定位与溢出开销，再加预取。** 将外层路由、后缀预测、主块与溢出验证分别做必要消融；跨区域代理失败说明仅看局部 ns 不够。预取应继续保留关闭选项，不能用未经测量的“提高命中率”作结论。
- **控制维护与选型成本。** 预先固定小候选集、复杂度／空间容差及重调参触发条件，再测试分布变化。选型器应逐步改成能释放不需要的候选，记录峰值与摊平条件。在线预算、模型／布局原子发布与安全回收仍需单独实现。

这些是下一轮的具体待实现项，本轮没有宣称完成可变槽、在线调参、并发、SIMD 标签比较或最终新颖性证明。
