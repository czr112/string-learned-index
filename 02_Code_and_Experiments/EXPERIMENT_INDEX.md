## 0. 阅读纪律（先看这一节）

1. **不要跨轮拼接绝对值。** 各轮的平台、编译器、预热与协议不同。**平台迁移本身就让绝对值不可比**：E8 的 v4 修订从 Windows 迁到 WSL2 后，同一份测量的绝对值高了约 34%–49%（E8 §5）。要跨轮看，只看**同一轮内部**的比值。
2. **每一轮都是自足的。** 结论只在"该轮的数据集、协议、样本量"内成立；轮次自己的 `RESULTS_EN.md` §"适用边界"列出该轮不能外推的部分。
3. **"通过正确性门"不等于"任意输入都正确"。** 早期轮次的环境**没有 sanitizer**（E5–E8 的 Windows 工具链与 WSL 侧都缺 ASan/UBSan），内存安全检查是**待补**项，不是已通过项。
4. **每轮的入口是 `RESULTS_EN.md`（结论）+ `LOG.md`（逐条过程、事故与更正）。** 更正大多追加在 `RESULTS_EN.md` 顶部而不改原文，**先读顶部的更正块**。
5. **E9 引入、E11 修复过一个扫描正确性缺陷**（多块组中间子块被清空时静默丢键）。读到 E9/E10 的扫描结论时注意这一点。

## 2. 三条线索怎么连起来

**构建成本**：E14 分解 → E15 去掉重复构建 → E16 去掉探针 → E17 同轮合计（**C/B 0.453×–0.526×**）→ E18 三段分解（构造仍占 66%–79%）→ E19/E20 复用组号。**最终仍慢于 ART（E20：1.34×–3.77×）。**

**查询成本**：E5（布局与 SIMD）→ E6（路由消融）→ E7（溢出查找策略）→ E8（容量分配）→ E9/E10（多块与访问代价交换）→ E11/E13（子块范围定位）→ E12（完整点查基线）→ **E21（冻结版本：胜有序数组、负于 ART）**。

**空间**：E8（容量重分配，溢出容器与后缀容量缩减）→ E22（更新负载下不复存在容量回退，代价改走溢出增长）→ **E24（两层分解：垃圾只在替换后出现；溢出容器元素余量 22%–30%；合法迁回几乎为零且卡在字节上）**。

**更新路径**：E24 量出 `update`／`erase` 走的是**慢路径**——这是 E25 的对象。**注意这一条的代价与布局退化是两件事**：E24 的 `update_only` 与 `initial` 逐位相同。

**维护**：E26 的 C1 证明**压缩的主要成本不在哈希**（哈希砍掉 2/3–19/20，时间只快 0.9%–6.7%）；C2 证明**压缩几乎从不促成触发它的那次放置**（0%–3.5%），跳过"腾不出足够字节"的那些是净收益。

**扫描**：E27 先测四项再选一项；**空组位图在本状态上没有目标**，改的是结果物化。

**长期替换下的空间（E28–E31，冻结之后）**：E28 诊断（**碎片，不是组预算**）→ E29 放宽触发（**能恢复空间、回不了本**，12 格一致更慢）→ E30 把判据的尺子直接测掉（**原地收紧 6–11 ns/记录，门槛 70 ns，机制被许可**）→ E31 实现并端到端对照（**开关默认关闭、冻结版本未改动**）。**这条线只做回收，不改模型、逻辑映射与主块预算。**

**功能评估已完整**（E20 冻结）：构建、点查（E21）、更新负载（E22）、范围扫描（E23）。**E24 起转入优化前的定位诊断**；E25–E27 是四项改造并已冻结；**E28–E31 是冻结之后对长期替换的追加诊断与一个候选机制**（默认关闭，采用与否见那一轮）。
