# E20 结果：R2 与 R1 与 ART 的同轮比较

日期：2026-09-16／17。目录：`validation_e20_20260916`（继承 E19）。平台：WSL2 Ubuntu 24.04 + g++ 13.3.0，单核绑定。

**E19 做了 R1（构造内部复用组号）。本轮做 R2——把统计阶段已经算出的组号交给最终构造，使构造阶段一次预测都不做；并在同一轮补上落后数轮的 ART 对照。**

> **修订记录**
> **① 映射身份**：审阅指出守卫只覆盖"长度相同、组数不同"，还会放行**"前缀与组数相同、但模型或输入不同"**。已加**模型表摘要**。
> **② 键序列检查**：审阅进一步指出——**映射相同不等于缓存的逐键组号仍然对应当前输入**。模型表是数据的摘要，不同键集可能训练出同一张表。
> **③ 生命周期收紧与表述更正**：审阅指出**首尾字节摘要只是辅助检查、不是键序列身份**（`aaba` 与 `abba` 长度、首字节、尾字节全同，混合之前就分不开；源地址与长度也看不见原地修改）。因此**不再要求弱摘要承担它给不了的保证**——上下文的生成与消费收进**一个内部调用**，不向调用方暴露可复用的入口。**这是正确性修复，不是继续扩展构建优化。**
> 全部时间数字在 ③ 之后重跑。

> **本轮结论中的默认版本是 R1。** R2 的构建成绩只作为**可选路径结果**引用。

## 0. 结论摘要

三个方案在**同一个干净计时程序**里对照，**计时起止边界统一**（各自必须做的准备工作全部计入）：

| 方案 | 内容 | 混合字符串 | 重复前缀 | 百万域名 |
|---|---|---:|---:|---:|
| **V1 / R1（冻结默认）** | 统计 → 规划 → 构造（构造内部复用） | 86.13 | 97.52 | 138.36 |
| V2 / R2（可选） | 同一路径，跨阶段传入组号 | 91.99 | 99.11 | 127.05 |
| V3 / ART | 本环境的 armong/libart | 52.94 | 75.77 | 36.46 |

**冻结默认路径相对 ART**（`T_R1 ÷ T_ART`，>1 表示原型更慢）：

| | 混合字符串 | 重复前缀 | 百万域名 |
|---|---:|---:|---:|
| **T_R1 ÷ T_ART（冻结默认）** | **1.68×** | **1.34×** | **3.77×** |
| 跨进程范围 | 1.57–1.82 | 1.26–1.38 | 3.63–4.39 |
| T_R2 ÷ T_ART（**可选路径，不作默认成绩**） | 1.56× | 1.24× | 3.58× |

**经过全部构建优化，两条路径都仍慢于 armong/libart。** 这一点不因选 R1 或 R2 而改变。

| 验收项 | 结果 |
|---|---|
| 统计 / 方案 / 结构 / 查询 | **全部一致**（48 组配置、19,200 次查询对照） |
| **映射与序列守卫** | **四类错配/失效全部被拒**：组数 48、模型 48、**另一份键集 16**、**原地改键序 48** |
| **整条路径的预测次数** | **2 次／键 → 1 次／键**（构造阶段 1 → **0**） |
| 缓存空间 | 峰值 **+0.52／+0.53／+1.05 MB**（本轮观察，见 §4） |
| 分配次数 | **不变**（数组只是换了生存期） |
| 同轮完整流程有无净收益 | **有，但幅度已缩小**：4.3%–6.0%，且非全部进程成立 |

**本轮最重要的外部结论**：**经过全部构建优化，最终流程仍比当前 ART 构建更慢**——`skew` 最近（1.23×），`tranco` 最远（3.45×）。

## 1. 改了什么

### 1.1 只复用组号

上下文带：统计结果、**组号数组**、**前缀**、**逻辑组数**、**模型表摘要**、**键序列摘要**，以及**来源键数组的身份**。**R1 保留为独立开关与回退路径。**

**探针阶段的"是否进入溢出"标记没有被带过去**：组号是从带标记的数组里**去掉最高位**得到的。

### 1.2 映射身份：前缀与组数**不够**

**审阅指出的第一个缺口**：前缀相同、逻辑组数相同，**但模型类型不同**时映射仍可能不同。修法不重新预测键——上下文携带一个**映射身份**：对**训练后的模型表**（连同逻辑组数、路由模式）做摘要。

> 映射 = （前缀，训练后的表，逻辑组数，路由模式）。四者相同，**映射就按构造相同**。

**摘要只在真的有预设传入时才计算**，默认路径与 R1 路径一分不付。

### 1.3 键序列：**映射相同仍不等于缓存可用**，但摘要不是身份

**审阅指出的第二个、也是更根本的缺口**：

$$\text{摘要相同} \Rightarrow f_{\text{旧}} = f_{\text{新}} \quad\text{但缓存里是}\quad ids[i] = f_{\text{旧}}(keys_{\text{旧}}[i])$$

而构建需要 $f_{\text{新}}(keys_{\text{新}}[i])$。**模型表是数据的统计摘要——不同键集完全可能训练出同一张表**。

**加了两条便宜的检查**：源数组身份（地址+长度，O(1)）与键序列摘要（每键一步 FNV，混入长度与首尾字节）。

**但审阅指出——这两条都不是身份，只是辅助检查。** 这**不是"理论上的哈希碰撞"**：

* `aaba` 与 `abba`：**长度相同、首字节相同、尾字节相同**——摘要在混合之前就已经分不开；
* 源地址与长度**看不见原地修改**。

**所以不再要求弱摘要承担它给不了的保证。** 正确性改由**受控的数据生命周期**承担：

> **上下文在一个内部调用中生成并消费，不向调用方暴露可跨调用复用的入口。**

`Index::bulk_load_reusing_ids(pairs, stats_cfg, plan_for)` 是**唯一文档化的用法**——统计、规划、构造在**一次调用**内完成，`ctx` 是普通局部变量，不会逸出，因此**无法被存下来、复制出去、或对着另一份数据重放**。原先那种"调用方拿到上下文再传给构造"的入口已经取消。

那几条检查保留为**纵深防御**（能发现明显的误用），但它们**不是**正确性的来源。原有那个把上下文传进来的重载改名为 `bulk_load_with_context` 并标注 **INTERNAL**，仅供验收门构造反例使用。

**容量表与物理子块数仍不参与校验**（它们不改变映射）。

### 1.4 护栏的成本被量到了

第一版 `model_identity` 每个表项做 8 次混合，实测约 **3 ms／次构建**（两遍）——**这正好是 R2 全省下来的量**。改成**逐字节** FNV（每字节一次乘法）后降到约 0.6 ms。**护栏不能比它保护的对象还贵。**

## 2. 验收（`check_e20_r2`）

| 检查 | 规模 |
|---|---|
| **单次调用入口 `bulk_load_reusing_ids` 与 R1 一致**（结构、扫描、预测次数） | **48** |
| R1 与 R2 的结构摘要、前缀、逻辑组数一致 | 48 组配置 |
| 容量方案一致 | 48 |
| 查询结果一致（locate + scan + 全量扫描） | **19,200** 次逐条比对 |
| 构造阶段预测次数：R1 每键 1 次 → **R2 恰好 0 次** | 48 |
| **错配 / 失效上下文必须被拒** | **48 + 48 + 16 + 48** |
| 与 E15 记录的摘要逐字符比对 | 三个数据集全部一致 |

**表格第一项是本轮唯一文档化的用法**：`bulk_load_reusing_ids` 在 48 组配置上产出的结构与 R1 完全相同、扫描结果相同、**预测次数恰好 1 次／键**。

**四类，逐类都有针对性反例**：

| 类别 | 构造方式 | 被哪一层拦下 | 结果 |
|---|---|---|---|
| (i) 组数不同 | 同一份键、换槽数 → 组数变、**id 个数不变** | 组数检查（长度检查会放行） | **48/48** |
| (ii) **模型不同** | 同一份键、**同一前缀与组数**，换模型类型 | 模型表摘要（前缀+组数会放行） | **48/48** |
| (iii) **键集不同** | **另一份键集** | 源数组身份 | **16/48**（其余被更早的检查拦下） |
| **(iv) 同一向量、原地改键序** | 交换两个中间键：**模型表不变**（训练按多重集累加，与顺序无关）、**前缀不变**（首尾键未动）、**组数不变**（长度多重集未变），**只有键序列变了** | **键序列摘要** | **48/48** |

**case (iv) 是前三类都覆盖不到的那一个**：映射完全相同、上下文仍指向同一个向量，只有键序变了。测试本身还断言了"设置必须真的做到映射不变、序列变"，**不让它因为设置没做到而悄悄通过**。

四类被拒之后，**退回路径建出的结构都与正确结构逐字节相同**。

另外，ART 每次运行用同一批抽样查询（20,000 条）与原型逐条对照 `found`/`value`，全部一致。

## 3. 时间

完整表见 `E20_TABLES.md` §3。中位数（ms，5 进程，干净构建）：

**冻结默认路径（R1）**：86.13／97.52／138.36 ms，相对 ART 慢 **1.68×／1.34×／3.77×**。

**可选路径（R2）**，只在可选路径结果中引用：

| 数据 | 最小 | 中位 | 最大 | 低于 1 的进程 | 降幅 |
|---|---:|---:|---:|---:|---:|
| 混合字符串 | 0.8612 | 0.9790 | 1.1235 | **3/5** | **2.1%** |
| 重复前缀 | 0.8728 | 0.9413 | 0.9528 | **5/5** | **5.9%** |
| 百万域名 | 0.9207 | 0.9226 | 0.9791 | **5/5** | **7.7%** |

**R2 的降幅 2.1%–7.7%，且 `mixed` 上只有 3/5 个进程低于 1。** 它在若干轮测量中的幅度与方向都随机器状态摆动（更早的一轮是 4/5、4/5、4/5；再早是 5/5、5/5、5/5）。**这个稳定性不足以替换默认路径。**

> **降幅变小有多少是护栏成本，无法分离。** 护栏估算约 1 ms／次构建（≈1%），其余与机器状态混在一起——这几次运行期间 ART 自己的时间波动达 44%，而 `ART/R1` 基本不变。**没有数据把两者分开，就不声称哪个占多少。**

## 4. 缓存空间与分配次数

| | 混合字符串 | 重复前缀 | 百万域名 |
|---|---:|---:|---:|
| 峰值，R1（MB） | 27.06 | 26.74 | 29.04 |
| 峰值，R2（MB） | 27.59 | 27.27 | 30.09 |
| **R2 − R1（MB）** | **+0.52** | **+0.53** | **+1.05** |
| 分配次数，R1 → R2 | 136,913 → **136,913** | 146,998 → **146,998** | 79,333 → **79,333** |

**峰值增加一个 `uint32`／键。这是本轮的观察，不是通用保证**——它来自"数组在哪分配、何时释放"这条单线程路径上的具体安排；**换成更早释放、或区域并行构建，峰值会不同**。可推广的是机制（**生存期变长**），不是那个数字。

**分配次数不变也不是巧合**：R1 在构造里每区域分配一个 id 数组；R2 在统计阶段每区域分配一个、构造里一个都不分配。**数组只是换了生存期。** 独立探针验证：两个入口 473 → 537 次（+64 = 每区域一次），id 总数 131,072 = 每键一个。

## 5. R2 预期与实际的边界

* 预期整条流程的组号预测 2 次／键 → 1 次／键 —— 实测正是如此（构造阶段 1 → 0）。
* **不消除重复的模型训练**——两个阶段仍各自 `train` 一次；没有把任何训练收益计入。
* **不复用指纹**——指纹只在构造里算一次。
* **R2 只优化初始构建。** 它**不能**让旧查询结果当作最终版本已重测的结果，**也不能期待更新（插入／删除／扫描／重建）自动获得同样收益**。

## 6. 适用边界

1. **正确性的来源是受控的生命周期，不是那几条检查。** 唯一文档化的用法是 `bulk_load_reusing_ids`：上下文在**一次调用内**生成并消费，不会逸出，因此无法被存下来或对着另一份数据重放。源数组身份、键序列摘要、前缀+组数、模型表摘要四项是**纵深防御**，**能发现部分误用，不能验证所有原地修改**（`aaba`/`abba` 就是反例）。
2. **因此本轮的结论是**：在**已测配置下未观察到结构与查询差异**。**不宜写成"可复用上下文已经完整保证映射对应正确"**；若将来要在**不同构建**之间复用，需要另外校验完整的键序列身份，并把成本计入。
3. **R2 的限定必须与它一起引用**：**只在输入键序列保持不变的同一次构建流程内使用。**
4. **校验有成本**（键序列摘要两遍 + 模型表摘要两遍），已计入本轮时间。
5. **探针的溢出归属标记没有被带过去**，也不应该被带过去。
6. **时间来自干净构建**；峰值与分配来自带包装的诊断构建，**不得用于任何时间比较**。
7. **ART 只接受无 NUL 的 ASCII 键**（该守卫是承重的），只在 ASCII 子集上被评估；**ART 的空间数字本轮未测**。
8. **摘要不是物理字节相等的证据**（边界同 E15 §1.2）。
9. **只覆盖静态批量构建**；增量路径逻辑未改，也未被重新计时。

## 7. 冻结建议

**审阅同意冻结 R1，并停止继续扩展构建优化。**

> **冻结轻量统计、直接构建与构造内部组号复用（R1）为默认实现；跨阶段复用（R2）保留为有明确输入不变前提的实验选项。**

定时成绩的引用规则，**本轮起生效**：

* **默认版本的构建成绩一律引用 R1**（相对 ART 慢 **1.68×／1.34×／3.77×**）；
* **R2 的 1.56×／1.24×／3.58× 只能放在"可选路径结果"里，不得作为冻结默认版本的成绩。**

**R2 的限定必须与它一起引用**：

> **只在输入键序列保持不变的同一次构建流程内使用；现有检查可以发现部分误用，但不能验证所有原地修改。**

这条限定现在由**接口**保证（上下文在 `bulk_load_reusing_ids` 内部生成并消费），而不靠调用方自觉。

**下一步（按审阅给的顺序，以冻结的 R1 产物为主）**：

| 阶段 | 比较对象 | 重点 |
|---|---|---|
| 完整点查 | 冻结 R1、ART、全局有序数组、原 S | 同轮端到端耗时；命中／未命中分别看 |
| 动态负载 | 冻结 R1 与支持对应操作的基线 | 更新成本、查询退化、溢出增长、压缩与重建 |
| 范围扫描 | 冻结 R1 与提供相同扫描语义的基线 | 相同起点与返回条数下的正确性与耗时 |

动态测试尤其要观察**需求布局经过更新后是否回退为统一容量、以及回退发生多频繁**——这可能比继续省几毫秒初始构建时间更影响实际使用价值。
