## 已实现与尚未实现

模型候选为 context16、position16、unigram，均为本项目机制原型，不是 LITS 原版。前两者各 16 行概率表，后者 1 行；采用真实动态表分配并计入容量。相比前轮内联表，模型存储形态已有变化，因此应比较本轮内部方法，不直接把跨轮时间差解释为联合选择收益。

有序叶也共享区域前缀，在同一个外层路由中运行，避免把前缀收益只分配给模型叶。模型和布局重配置整体替换；动态操作已差分验证。选择在 bulk load 前完成，普通更新沿用所选配置并支持同步重建／分裂；没有在线重新调参，初始容量预算也不覆盖后续无限插入。

选择器使用局部暖缓存时间代理，最终查询包含外层路由和全体区域访存。离散拉格朗日搜索只保证返回可行候选并保留不差于初始方案的代理目标，不保证全局最优。100 个小型随机预算问题还与穷举最优值比较，差距保留在正确性 JSON，不能把这部分通过写成最优性证明。

逐组统计将当前溢出记录按主块剩余资源分为“仅槽不足、仅字节不足、两者不足、当前已能装入”；超长后缀另外计数，与上述分类可能重叠。它描述采样时的布局，不是每条记录插入时的历史原因；删除留下的空洞单独计入 garbage_bytes。

内存数值是同一容量计数方法下的估计，包含模型、块、容器及字符串容量，未包括分配器元数据，SSO 容量可能重复计入。进程另保留输入、查询、多个政策索引；不能将某个索引估计容量当成进程 RSS 或峰值。调参期间每次仅保留一个候选区域，其选型时间包括候选构建、测量、统计写出和求解。

## 复现

需要 Linux、Python 3、g++（C++17）、taskset。原机编译使用 `-march=native`，查找指纹采用硬件 CRC；其他机器结果会不同。请在压缩包的副本中运行，因为脚本会替换该副本中的结果。

```bash
python3 reproduce.py
```

编译并执行新实现的正确性检查。延续原容器的进程可见性限制，明确使用 `detect_leaks=0`，ASan／UBSan 保持启用；这不包括泄漏检查。

```bash
python3 reproduce.py --full
```

继续下载并核对 Tranco XN6XN，执行三组正式实验和汇总。已有固定 CSV 时可添加 `--tranco /absolute/path/tranco_XN6XN.csv`。需数 GB 可用内存；本机三组正式运行合计约一至数分钟，选型／动态检查和硬件差异会影响总耗时。

Tranco 数据不随包重新分发。[固定来源](https://tranco-list.eu/list/XN6XN)。真实域名不等于完整 URL；mixed 和 skew 均为合成数据。没有 ART／HOT／LITS 正式性能基线、硬件缓存事件或并发验证。本轮不声称新颖性，也不能把局部收益外推为最终项目成绩。
