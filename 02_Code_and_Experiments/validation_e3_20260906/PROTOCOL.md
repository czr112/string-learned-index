# E3：离线模型与块布局联合选择

本协议在读取 E3 正式计时结果前写定。原型基于上一轮代码另建目录，前轮原始结果及源码保留。

## 研究问题

在相同区域边界和同一总容量上限下，每区域同时选择后缀模型和块大小，能否优于统一配置及先模型后块大小的两阶段选择？加入有序叶回退是否带来额外收益？不预设联合选择一定有效。

## 固定条件

- 区域目标大小 2048，按全量键的连续字典序划分；本轮不自动选择区域边界。
- 三类简化整数模型：原型上下文 16 行、位置 16 行、单行 unigram。均训练每键前 16 个后缀字节，非正式 LITS 模型。
- 三个块大小：512、1024、2048 字节；每块 16 条目、块头和条目区共 320 字节，装载参数 0.75。
- 9 个模型／块组合，另加共享前缀压缩的有序叶候选。所有叶在同一外层路由和所有权框架下运行。
- 查询使用区间停止、硬件 CRC 指纹、精确比较；预取固定关闭，溢出沿用原型线性指纹筛选。
- 固定配置为 context16＋1024 字节块。该配置实构建的叶容量总量定义所有选择器共同预算；外层目录开销另计。该预算是容量估计，非 RSS。
- 构建需要全量索引键，所有方法相同。调参查询只使用排序名次模 4 为 0 的键；最终评估使用其余键，键身份不重叠。两种查询均独立拥有字符串，含 10% 添加零字节的未命中查询。

## 选择器与对照

每区域 512 个调参查询，每候选 3 轮、每轮 4 遍查询，取批次 ns/op 中位数。候选构建顺序按区域打乱，候选测量时该区域主要处于暖缓存。因此这一代选择器使用局部成本代理，最终必须看独立查询上的端到端时间。

全局目标为按区域键数加权的局部查询耗时，约束为叶容量总和不超过预算。实现拉格朗日乘子搜索，保存可行初始方案；是离散近似算法，不承诺背包问题最优解。

| 方法 | 选择方式 |
|---|---|
| fixed_context1024 | 固定原型模型与 1024 字节块 |
| uniform_tuned | 在预算内，从 9 个组合选一个所有区域统一使用 |
| sequential | 先固定 1024 字节块按区域选模型，再固定各区域模型选块大小 |
| joint_learned | 每区域直接考虑 9 个模型／块组合，受同一全局预算限制 |
| joint_with_leaf | 在 joint_learned 基础上，允许有序叶回退 |
| sorted_leaves | 所有区域均使用共享前缀压缩的有序叶 |
| sorted_array | 完整字符串有序数组及二分查询 |

后两个为额外基线，显式记录是否满足同一总预算；若超出不隐藏结果，也不宣称等预算获胜。选型计时含候选构建、局部测量、统计写出和求解，最终构建另计。维护期间保留当前选择，显式重配置会连同模型和布局整体替换；本轮不在线重新学习配置，也不保证更新后仍满足初始快照预算。

## 数据与运行计划

先运行 mixed 8192 键的连通性试跑（两轮、一份查询），不用于性能结论。正式配置为重复前缀 skew 131072 键、mixed 262144 键、固定 Tranco XN6XN 1000000 域名。mixed 以约各三分之一的短键、随机长键、重复前缀键构成，并以一个类别字节和斜线形成连续区域；用于检验已知分布异质性，不充当真实数据。

正式配置每方法使用 3 个独立评估查询随机种子（20260920–20260922），每种子 5 轮。skew 和 mixed 每批 262144 查询，Tranco 每批 524288 查询。各轮方法顺序随机，计时前预热至多 20000 查询，返回结果逐项预热核对及整批校验和核对。单线程绑核，各进程顺序运行。

报告各种子的中位数、汇总中位数与范围、容量、溢出原因、选型成本、候选分布及相同选择签名。不同方法若配置选择相同，不能将计时差当成算法收益。保留负结果，不以正式评估查询重新选参。共享虚拟机、多轮同一环境及局部暖缓存代理的限制必须注明。

## 验证与交付

新检查覆盖 10 个候选、异质区域、动态操作、模型与有序叶互相迁移、空串与二进制键、前缀变化、扫描和分裂。容量统计检查记录守恒。选择器通过随机小问题的可行性、初始方案不退化及枚举下界检查，但不要求近似算法等于最优解。ASan／UBSan 启用，延续原环境的 LeakSanitizer 限制并明确关闭泄漏扫描。

原始 candidates.csv 保留局部三轮测量和溢出原因，selections.csv 保留每方法每区域的选择，joint_groups.csv 保留 joint_learned 的逐组占用，timings.csv 保留每次端到端计时。查询代码、协议、分析脚本及数据 SHA 与结果一并交付。
