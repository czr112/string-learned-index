# A2 入口诊断：设计（经对抗性审查修正）

日期：2026-09-24。目录：`validation_e25_20260918`。前置：`OPTIMIZATION_PLAN_V2.md` §6 的 A2 条目。

**本文只是设计，尚未实现。** 实施与结果另见 `RESULTS_A2_ENTRY.md`。

---

## 0. 为什么要先设计

**候选是 A2（相邻子块重分配）**，入口条件（计划 §6）是：

> 「P1 跑完后看 `reclaim_widest` 仍失败的**残余事件**里，有多少是『**组内总容量够但两块分界不对**』」

**在动手之前，这份设计经过一次四视角对抗性审查**（草案 → 独立反驳 → 逐条验证）：
**12 条发现，8 条被反驳掉，4 条存活，而存活的每一条都会改变结论**。修正写在下文，
**审查推翻的版本（直接按「最终进溢出的插入事件」采样）不能照做**。

---

## 1. 上一轮的同型错误（本设计要防的那一类）

我此前写过「`reclaim_widened_blocks_examined − reclaim_widened_helped = 110`，所以有 110 个残余失败」。
**这是单位错误**：前者是 `E25_ADD(..., count)`，**一次加的是「本次搜索里候选块的个数」**；
后者是 `E25_INC`，**每次搜索成功时加 1**。**两个单位，不能相减**。

**A2 的分母会直接决定它是开还是关**，所以本文对每一个记录字段都写明**单位与行单位**。

---

## 2. 修正一：采样 population 必须有唯一指代

`put_overflow` **有五个调用点**（`index.hpp`）：

| 行 | 调用者 | 是不是「A1′ 之后的残余插入事件」 |
|---|---|---|
| **`:3640`** | `place_with_ctx` | **是**——增量插入终点，A1′／compact／drain 都试过 |
| **`:3730`** | `insert_slow` | **是**——同上 |
| `:2531` | `Region` 构造（`E18_PREPASS` 分支） | **否**——那条路径上 `subblock_reclaim`／`reclaim_widen`／`compact`／`drain` **从不运行** |
| `:2548` | `Region` 构造（`#else` 分支） | **否**——同上 |
| `:1945` | `drain_overflow_bounded` 的重新存入 | **否**——不是新插入；`put_primary` 从未被调用，`F2` 无定义，`F5` 会**重复计数一条已在本组容器里的记录** |

**所以「最终进溢出的插入事件」这句话在代码里没有唯一指代**，照它采样会把构造期放置与 drain 重存算成 A2 的机会。

**设计**：
- **只在 `:3640` 与 `:3730` 两个终点埋点**，**每次事件一行**。
- **构造期与 drain 两个桶单独计数并显式打印**，写明「**已排除，不是因为数目小，而是它们不是 A1′ 之后的残余事件**」——**不默认为 0**。
- **行单位 ＝ 一次事件，不是一次 `put_primary` 失败**：一次插入事件最多产生 **8 次** `put_primary` 失败
  （原始 1 次 ＋ `reclaim_widen` 预算 4 次 ＋ `compact` 之后 1 次 ＋ `drain` 之后 1 次……），
  按失败计数会把分母放大近一个数量级。**F2 只在事件的终点记录一次**（记录的是**终点时刻**的状态）。

## 3. 修正二：必须跑两个负载，X 按负载分别报

长期替换（`same`／`grow` 到 200%）**正是 A1′ 把问题消掉的那个负载**：
WIDE 臂的残余溢出是 **748／950／1,924**（相对 S0 降 98.5%–99.4%）。
**在那上面量出来的 X，是「A1′ 之后剩下的硬化尾巴」的性质，不是结构的性质。**

**设计**：
- **W1 ＝ 长期替换到 200%**（计划 §6 的负载，好与 G3 的 748／950／1,924 并列）；
- **W2 ＝ 纯插入对照**（计划本来就写了「另加一个纯插入负载做对照」，**P1 从没跑过**）——
  纯插入下**没有垃圾**，`reclaim_widen` 的失败原因与 W1 **本质不同**。
- **X 按 (负载, 语料) 分别报，绝不合成一个数。**
- **分母用「事件数」，不是 G3 的「200% 检查点的溢出条数」**——后者是**存量**，不是本设计采样的**流量**。

## 4. 修正三：F5 的成本单位

**代码里没有增量目录更新。** `rebuild_dir` 是 `dir.clear()` 之后**为每个非空子块重建一个 `std::string`**；
`dir_entries_built` 数的是**建了多少项**，不是**改了多少项**。任何保持 M1 的边界移动都至少改动一个**最小值**，
而 `locate_subblock` 恰好对这些最小值做二分——**所以整组重建是正确性必需的**。

**设计**：F5 的第三个字段改成 **「会被重建的目录项数」＝ 被触及组的非空子块数**，
并**显式写明这是一次完整的 `rebuild_dir`（clear ＋ 每非空子块一个分配），不是逐项编辑**。
这一成本**在 A2 想针对的那种「拥挤、多子块」的组上最大**——所以它必须进分母旁边的成本侧，不能被「改动项数≈1」掩盖。

## 5. 修正四：F2／F3 不必重新实现

**已经有**：`trial_place`（`index.hpp`）只读地算出
- `TrialPlace::refused_by_slots` / `refused_by_bytes` —— **F2** 的拒绝原因；
- `f2_budget_suffices`／组级空闲字节与槽位 —— **F3** 的「组总量够不够」。

经 `diag_trial` 调用。**本设计复用它们，只新做 F4／F5。**

## 6. 最终的记录字段

**一次事件一行**，字段与单位：

| 字段 | 内容 | 单位 |
|---|---|---|
| `kind` / `workload` | 语料；**`replace`（W1）或 `insert`（W2）** | — |
| `state` | 采样时的检查点 | — |
| `group` | 目标逻辑组 | 组号 |
| **F2** `refuse_slots` / `refuse_bytes` | 排名选中子块拒绝的原因 | **布尔**（本次事件） |
| **F3** `group_slots_suffice` / `group_bytes_suffice` | 组的**总**空闲槽位与**总**空闲字节是否够 | **布尔**（本次事件） |
| **F4** `adjacent_move_fits` | 只移动**相邻两块边界**、保持 M1 与每块字节预算后能否放下（**只读模拟**） | **布尔** |
| **F5a** `moved_records` | 该移动要搬的记录条数 | **记录数** |
| **F5b** `copied_bytes` | 该移动要复制的后缀字节数 | **字节** |
| **F5c** `dir_entries_rebuilt` | 被触及组的**非空子块数**（＝ 一次完整 `rebuild_dir` 的项数） | **目录项数** |

**外加三个被排除桶的计数**：`excluded_build_placements`、`excluded_drain_restores`、`excluded_other`。

**配置随记录写死**：`subblock_reclaim=1`、`reclaim_widest=1`、`overflow_migrate=0`——
**population 是「在哪些开关下幸存的插入事件」，换开关就不是同一个分母，必须随记录声明。**

## 7. 判定（计划 §6 的停止条件，按负载分别判）

| 结果 | 处置 |
|---|---|
| F4 为真的事件占比**很小** | **记录负结果并关闭 A2** |
| 占比**明确**且 F5 的**记录数／字节／目录项数都有界** | 进入**单开关原型 ＋ 同轮计时** |
| 两个负载给出**相反**的画像 | **按负载分别记录**，不取平均；原型只对占比明确的那个负载做 |

**计数只能定位候选，不能换算时间收益。** 本轮不做计时。
