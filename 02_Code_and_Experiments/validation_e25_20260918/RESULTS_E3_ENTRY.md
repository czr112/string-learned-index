# E3 入口诊断：写路径的时间预算与工作普查

日期：2026-10-10。目录：`validation_e25_20260918`。
前置：`OPTIMIZATION_PLAN_V2.md` §6 的 E3 行——「**分配、复制与临时工作区**」，
进入条件写明要「**先区分**后缀真实写入／描述符移动／容器扩容／短命临时对象／输出物化的**占比**」，
判据是「E32 §4 的溢出成本诊断**扩到写路径全段**」。

**本文只做分解，不做对照、不宣称加速**：没有翻转任何开关，每一格都是这份构建对自己写路径的拆分。

---

## 0. 结论

**进入条件不成立：写路径上没有一样东西叫"分配是大头"。**

| 计划的五类 | 实测（替换负载，每 1,000 次操作） | 判断 |
|---|---|---|
| (a) 后缀真实写入 | 主块 **239 / 55 / 6,783 B**（mixed/skew/tranco）；溢出记录 **80,016 / 76,655 / 5,679 B** | 溢出侧才是真实写入发生的地方 |
| (b) 描述符移动 | 主块 **0 次**（新键都追加）；**溢出容器搬移 68,087 / 123,980 / 11,811 条记录** | **字节质量在这里**：约 **3.3 / 6.0 / 0.57 KB 每次操作** |
| (c) 容器扩容 | **55.8 / 3.1 / 27.3 次**、**17,925 / 1,933 / 11,058 B** | 小 |
| (d) 短命临时对象 | **995 / 999 / 443 次** `std::string` 构造 | 每次插入约一次，量级 80 B/op |
| (e) 输出物化 | 替换负载 **0**；纯插入 **2,450–5,344 条/1,000 op**（区域分裂的 `all()`） | 只在分裂路径上出现，且那里是**第一**大项 |

**时间侧的答案同样是这两块，不是分配**：替换负载里，插入侧是**区域内检索**（`find_located` 26–49%）＋**放置**（40–50%），
删除侧是**区域 erase**（60–81%，其中溢出容器 8–29%）；**纯插入**负载里第一项是**区域分裂重建**（44–66%）。
**分配（临时对象＋扩容）在任何一格都不是首位。**

**因此 E3 按其原定判据关闭**；证据指向的是两处**已在册**的方向：溢出记录搬移（O1／`overflow_stable_store`）
与插入路径上的检索／放置，而不是"减少分配"。

## 1. 装置与两条必须写明的限制

`diag_write_cost.cpp`（`-DE25_DIAG -DE18_COUNT -DE30_TIME -DE30_WRITE`）：`Index::insert`/`Index::erase` 整体计时，
并对其内部的每一段**嵌套**计时（区域 locate、`Region::find_located`、`place_with_ctx`、`rebuild`、`all()`、
`repack_subblock`、`compact`、溢出容器的 lookup/构造/移动/删除）。**嵌套项各自对父项取比，不相加。**

**限制一：空计时器是测出来的，而且它很贵。** 本机一次"读钟＋写回"配对实测 **51.3–62.4 ns**（多次运行），引用的这一次是 **52.53 ns**，
分析器按 `调用次数 × 校准值` **逐项扣除**，并把原始值一并打印以便核对。**扣除是保守的**：紧循环是读钟最便宜的情形，
真实调用点只会更贵，所以扣除后的数字是**上界**。

**限制二：有些相位就落在这把尺子的下面。** 区域 `locate` 每个负载测到的原始值常低于它自己的校准地板
（mixed 16.1 ms 对地板 13.5 ms，1.2×），**这类格子只能读作"不高于地板"，不能读成"0%"或"占 7%"**。
能被分辨的是 `find_located`（约 3× 地板）、`place`、`rebuild`、`Region::erase`、溢出各段。

**本文数字来自最后一次重建之后的重跑**（`index.hpp` 在测量后又补了一处"无时钟构建的空宏"，按本项目的纪律重跑，使记录身份与磁盘一致）。

**负载**：与 `bench_long`/`diag_ov_cost` 逐字相同的长期替换（冻结配置，活跃键环、本键原位替换、
25/50/100/200% 检查点，`same` 与 `grow` 两种模式），**外加纯插入对照**（装载一半、再插入另一半，
检查点 25/50/75/100%）。N=262144，reps=1（这是份额分解，不是 A/B）。

**输出**：`results/main/write_cost_diag_20261010.jsonl`（28 行）、
汇总 `results/main/write_cost_analysis.txt`。

## 4. 判定

1. **E3 按其原判据关闭。** 「先证实分配是大头」这一步**没有通过**：短命临时对象约一次插入一个（80 B 量级）、
   容器扩容 3–91 次/千次操作（2–18 B/op），两者在任何一格里都不是首位。
2. **写路径的字节质量是"搬移"**：溢出的记录移位 **68–124 条/次替换**（×48 B ≈ **3.3–6.0 KB/op**），
   而真实写入是 **~80 B/op**——**相差 40–77 倍**。这条正是 `overflow_stable_store`（O1）针对的对象，
   **已作为候选存在**，不需要新候选。
3. **时间的第一位随负载而变**：替换负载是"区域内检索＋放置＋区域 erase"，纯插入负载是"区域分裂重建"。
   **分配不在其中任何一位上。**
4. 若要继续沿写路径做结构改动，**先看那两处已在册的方向**；本轮不提出新候选，也不改默认。

## 5. 本轮修掉的装置缺陷（全部由本轮自己的数字暴露）

1. **用错宏**：`E30_ADD` 的第二个参数是**时间戳**（它做的是 `+= now_ns() - arg`），
   我却拿它累加**记录数**，于是"`all()` 物化记录数"读出 **4.15e11** —— 一个不可能的数。
   改用直接 `+=`。**这个错误只有在对量级有预期时才会被发现**，所以它值得单独记一笔。
2. **时钟包错了范围**：`Index::erase` 的内层时钟本意只包 `locate`，却把整条
   `nodes_[locate(key)].region->erase(key)` 都包了进去，于是 `locate` 一度读出 **91%**。
   已改为只包 `locate`。
3. **检查点表越界**：纯插入对照复用了替换负载的检查点表（含 200%），
   而 `pending` 的 200% 不存在——**构造出的区间是越界的**。行数（3 而非 4）是唯一症状。已换成独立的表。

三条都在**同一轮**发现并修复，修复后重跑全部测量；本文数字来自**修复后**的构建。
