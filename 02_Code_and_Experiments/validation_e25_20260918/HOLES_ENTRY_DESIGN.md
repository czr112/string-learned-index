# 本块空洞复用：入口诊断设计（方法由用户指定）

日期：2026-09-27。目录：`validation_e25_20260918`。候选出处：总计划 §7 的可进入条件表
「局部整理有效，但重复复制活跃后缀占主导 → 小型块内空洞复用表」。
**本文只是设计，尚未成文结论。** 结果另见 `RESULTS_HOLES_ENTRY.md`。

---

## 0. 候选是什么

`insert_into`（`index.hpp:1772`）的字节判据是

```
if (s.size() > h.bottom - start_of(g)) { place_fail_bytes; return false; }
```

**这是「连续空闲段」的判据，不是「容量」的判据。** 后缀区的实际形状是

```
[ start_of | 连续空闲 contig | 活跃后缀（按插入顺序排列） | 死区 garbage | bb_ ]
```

`bottom` 是活跃后缀的最低偏移。所以**死区完全不在这条判据的视野里**：一个块可以带着几千字节死区，
却因为底部连续空闲不够而拒绝一条记录。这就是候选的全部立足点——**把新后缀写进死区，不搬任何活跃字节**。

---

## 1. 配对必须按子块，不能按全索引

**这是本轮方法上最重要的一条，也是用户直接指定的：**

> 请直接按发生插入失败的目标块配对统计"可用空洞尺寸"和"待写后缀长度"……
> **仅比较全索引的两张尺寸分布会高估可复用量。**

理由是结构性的：**子块 X 的洞装不下属于子块 Y 的后缀**——放置是逐块的，且不变式 M1
使各子块键域互不相交。全索引地拿「洞尺寸直方图」对「新后缀长度直方图」，会把洞和
**根本到不了它的请求**配在一起，把匹配率抬高。所以本轮的每一个数都在**拒绝发生的那一刻、
在那一个块上**产生。

**而且「块级拒绝」与「插入级溢出」不是同一个量。** `put_primary` 会依次试探多个块，
所以**一次插入可以产生多次块级拒绝**。两者的距离本轮直接测量（见结果文档）。

---

## 2. 键序**不是**这条判据的一部分（这是布局的性质，不是本轮的假设）

`insert_into` 把新后缀写在 `bottom - s.size()`，**不是按键序位置**——所以**后缀的物理顺序是插入顺序**。
`Entry::offset` 全代码只被三处读：

| 位置 | 用途 | 是否要求偏移单调 |
|---|---|---|
| `suffix()`（`index.hpp:1563`） | 按偏移取字节 | 否 |
| `repack_subblock()`（`:1850`） | **自己重新推导顺序**再重排 | 否 |
| 同上的断言 | `offset >= start_of(g) && offset + length <= bb_[g]` | 否，只要求落在块内 |

**没有任何地方要求偏移按键序单调。** 键序活在 **`entries[]` 的数组下标 `p`** 里；字节放在哪与之无关。
所以死区**在哪一段都可以用**，不需要为「键序」建模任何约束——**这一条是本轮读代码确认的，不是假定**。

## 3. 逐事件要检查的三件事（用户点名的：键序、槽位、边界条件）

| 项 | 检查方式 | 结果如何记录 |
|---|---|---|
| **键序** | 见 §2：不约束字节位置 | 不需要建模；在报告里写明理由 |
| **槽位** | `insert_into` 先判 `h.count >= slots_of(g)` 并提前返回，所以走到字节分支时**槽位按构造必有空** | 每个事件仍记 `slots_free`，**记录而不是假定** |
| **边界** | 洞由 `[bottom, bb_)` 内活跃区间**之间的补集**定义，所以 `offset ≥ start_of`、`offset+len ≤ bb_` 按构造成立 | 由扫描的恒等式间接保证（见 §5） |

**槽位这一条对候选是硬约束**：空洞复用**只释放字节、不产生槽位**。所以**槽位不足的拒绝，
候选一概够不着**——本轮把 `place_fail_slots` 与 `place_fail_bytes` 分开报。

## 4. 同一个事件上做两个测试，因为候选的立论是一次对照

| 测试 | 定义 | 代价 |
|---|---|---|
| `fits_hole` | 本块**某一段死区 ≥ 本次后缀长度** | **不搬任何字节** |
| `fits_repack` | **连续空闲 + 本块死区 ≥ 本次后缀长度** | 这就是 `repack_subblock` 今天做的事，**要搬全部活跃后缀** |

分开报，才使「与紧凑化单独对照」成为**同一事件上的配对比较**，而不是两个不同总体上的两个比率。

**并且必须写明一件配置事实**：**发布配置里 `subblock_reclaim` 与 `reclaim_widest` 都是 `false`**。
所以 `fits_repack` 是**反事实对照**（「若开启会怎样」），不是实测对照。
`subblock_reclaims` 在两轮运行里恒为 0，**那是配置导致的零，不是没有机会的零**——
两者必须能被读者分开，所以把它一并报出来。

---

## 5. 扫描的恒等式：死区之和必须等于该块自己报的 garbage

扫描把 `[bottom, bb_)` 内的活跃区间排序后取补集。它的和**必须**等于该区域自己的账目
`occupied − suffix_live`。**不一致就说明扫描写错了**，而写错的扫描会让下游每一个比率都变得毫无意义
却依然看着合理。所以本轮**逐事件比较两者并计数不一致**（预期为 0）。

## 6. 两个负载

| 负载 | 形状 | 为什么必须有 |
|---|---|---|
| **W1 长期替换到 200%** | 删除 + 插入 | **候选自己的工况**：erase 切出死区，insert 想用回来 |
| **W2 纯插入** | 载入偶数下标的一半，插入奇数下标的一半 | **对照**：没有任何删除，所以**几乎切不出死区**。用它区分「匹配率是工作负载的性质还是结构的性质」 |

W2 用**真实的键、真实的键域**（交错取半），不是把新键全堆到尾部——否则插入流会偏到最后一个区域，
量出来的东西与索引结构无关。

## 7. 判定

| 结果 | 处置 |
|---|---|
| **两个负载都够不着**（纯插入上没有洞，替换上被已有机制覆盖） | **记录负结果并关闭** |
| **替换上匹配率高、且搬移确为主导成本**（进入条件第二半成立） | 进入单开关原型 ＋ 同轮计时 |
| **两个负载给出相反画像** | **按负载分别记录**，不取平均 |

**进入条件的原文是两句**：「局部整理有效」**且**「重复复制活跃后缀占主导」。**两句都要成立**；
只成立前一句，候选就只是把一个**已经实现**的机制换个更省拷贝的写法，而不是补一个缺口。

**计数只能定位候选，不能换算时间收益。** 本轮不取任何计时。

**并且**：任何以容量或搬移为目标的改动，**验收表必须有 `query_ms` 与 `scan`，且在同一轮**（沿用 A3 登记）。
