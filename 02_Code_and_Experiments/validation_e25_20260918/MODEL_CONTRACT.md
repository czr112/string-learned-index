# MODEL_CONTRACT：参考模型与未来模型的最小接线契约

日期：2026-09-23。依据：总计划 §3「测试后端与未来模型交付的最小契约」。

**这是一份边界文档，不是设计文档。** 它写的是：**模型组把模型交过来时，索引侧已经替你保证什么、你必须保证什么、以及哪一条由谁看守**。本阶段只把已有接线整理成稳定接口，不建设新的模型框架，不重新设计预测算法。

当前有两个后端标识，都是**实验标签**，不据此翻转项目默认：

| 标识 | 是什么 | 默认 |
|---|---|---|
| **M_ref** | 当前固定的 LITS-HPT 适配及区域回退组合（`model/lits_hpt_adapter.hpp`） | 否 |
| **M_old** | `Context16`，自研表驱动参考模型 | **是** |

模型组交付 M_team 后，复用本文的门与 §7 的 2×2 对照。

## 0. 契约总表

| # | 接口事项 | 约束 | 当前实现 | 看守它的门 |
|---|---|---|---|---|
| 1 | **输入** | 完整键、区域前缀、长度与字节域；由**适配器**统一坐标，布局代码不猜"是否已剥离前缀" | `Region::canonical_group(full_key)` **只接完整键**，内部自接后缀 | **减少**误用入口：`canonical_group` 只接一个参数，`canonical_group(后缀, 完整键)` 编不过。**但它不是编译期保证**——两个都是 `std::string_view`，**把后缀当完整键传仍然编得过**（见下方"挡不住什么"） |

| 4 | **生命周期** | 训练结果的所有者、只读共享、区域重建/分裂时的重校准与失效规则 | `shared_ptr<const SharedModel>` 全索引一份、只读、删拷贝；重建时重新校准 | `check_lits_index` 的前缀重建/分裂计数断言 |

| 6 | **回退** | 按活跃区域、记录、查询**分别**计数；**区域内映射一旦确定，单次查询内不得临时换模型** | `Index::lits_coverage()`（按活跃区域走，带回退原因分项）；非有限的预测**拒绝**而不是中途换后端 | `check_lits_model` 的六条拒绝路径、`check_lits_index` |

| 8 | **边界** | 空索引、单键、`G=1`、前缀关系、域外输入有明确语义与**有触发证明**的用例 | `sorted.size() < 2` → `boundary(NoKeys / TooFewKeys)`，组 0 | `check_lits_index` 的空索引/单键/`G=1`、`check_lits_model` 的 37 个边界区 |
| 9 | **模型替换** | 改变映射**必须重建或按有证明的方式迁移记录**，不能只换模型指针保留旧位置 | 换后端时 `preset_ok` 恒假 → 整区重建 | `check_e20_r2`（四个 guard case）、`check_lits_index`（前缀重建非空性） |

## 1. 输入：坐标由适配器统一

**约束**：模型只接收**完整键**与**区域前缀长度**，由适配器决定怎么切。**布局代码不得自行猜测"传进来的字符串是否已经剥掉前缀"**。

**当前实现**：`Region::canonical_group(std::string_view full_key)` 只接**一个**参数，内部 `full_key.substr(prefix_.size())`。LITS 的 `gcpl` 与我们的区域前缀 `p` 是同一量（源码三处一致：`lits_node.hpp:347/365/292`），所以 `size = G`、`group = clamp(getPos(key, G, p, α, β), 0, G-1)`。

**为什么签名只接一个参数——以及它挡不住什么**：两个同型参数**不能**保证坐标正确——`canonical_group(suffix, full_key)` 一样编得过，所以**参数个数确实去掉了一类误用**。

**但这只是减少误用入口，不是编译期保证。** `std::string_view` **不携带"这是完整键还是后缀"的信息**，编译器无法识别字符串的语义，**把后缀当完整键传仍然编得过**——这正是本契约想防的那一类错误。

**要真正的编译期保证，需要引入区别于后缀的强类型**：把完整键与后缀分别包成两个不同的类型，只让前者能进 `canonical_group`，让"传后缀"变成类型错误。**在该强类型引入之前，这一条按「受控调用链 ＋ 有触发证明的边界检查」来守**，**不按「编译错误」来声称**。

**字节域**：LITS 适配器**拒绝**字节 ≥ 128 与嵌入 NUL（`unsupported_reason`）；M_old 的承诺更宽。**性能对照限定在无 NUL ASCII 域**（ART 适配器的边界），原型的功能检查另列。

## 2. 输出：饱和必须在转换**之前**

**约束**：返回 `[0, G)` 内的合法组号。**浮点有限性、饱和与整数转换的次序是契约的一部分。**

**当前实现**（`predict_group`）：

```text
1. 非有限 -> 拒绝（不中途换后端）
2. c <= 0        -> 0
3. c >= G - 1    -> G - 1
4. 否则           -> static_cast<std::uint32_t>(c)     <-- 转换在最后
```

**为什么不能靠区域最长键兜底**：源码的 `getPos` 内部就做了 `static_cast<int>(c)`，**在返回值上夹紧修不了它**；而 `1e300` 是有限的，所以只查 `isfinite` 也不够。`1e9` 的上界**降级为额外的保守准入策略**（静态、逐区域一次的判定），**不是**运行时量的唯一保护。

**"被保守数值界拒收"不是"模型分辨不出键"**：局部线性校准本来就在放大小跨度。这两个说法不能互换。

## 3. 同一映射：五个阶段必须解释同一个组号

**约束**：统计、容量规划、构造、查询、更新，必须在**同一个有效模型状态**下解释组号。换后端时 **`preset_ok` 恒假** → 回退为整区重建；`Index` 侧另有源地址+长度与逐区域 `key_digest` 复核。

**当前实现**：全索引**一份** `shared_ptr<const SharedModel>`；两处训练点（Region 构造 `index.hpp:2036`、需求探针 `:2715`）共用它。

**必须一起读的不对称**：发布配置里**放置走 `Route::Full`、查询走 `Route::Interval`**。两条 route 会选不同的组函数。`check_g1_contract` C 就是为这条而写的——**6,144 个缺席键、两条 route、零处不符**。

## 4. 生命周期

| 事项 | 规则 |
|---|---|
| 所有权 | `std::unique_ptr` 建、`shared_ptr<const SharedModel>` 共享；**删拷贝** |
| 只读 | 预测是 `const`；训练只在构造/重建时发生 |
| 重校准 | 区域**重建或分裂**时按新的首末键重新校准 |
| 失效 | 区域的整体回退（校准失败）**按区域记录**，不在单次查询内改变 |
| 重训时机 | **一个模型 / 一个索引版本，无在线学习** |

## 5. 指纹：融合可以，抹掉不行

**约束**：**指纹可以与预测融合计算，但不能把融合得到的成本误记为"哈希消失"。**

**当前实现**：`Prediction` 分成两个字段——

- `consumed`：模型实际处理的字节数 → 喂给 `result.steps`；
- `fp_consumed`：**哈希的续接位置**，`find_impl` 用 `fp.tail(s.substr(pred.fp_consumed))` 收尾。

**两者不可合并**（源码注释明写）：合并会把 `fp_consumed` 清零，于是参考后端"看起来让指纹消失了"。

**LITS 后端报 `fp_consumed = 0`**：它读完整键，所以哈希与模型**没有**融合。要让"哈希是否消失"有**时间**证据（而不只是语义证据），需要另立一个 `M0_separate_hash` 计时臂——**该臂未做**（登记在 `CODE_AUDIT.md` §3）。

## 6. 回退：分三处计数，且不在查询中途换模型

**约束**：回退必须**按活跃区域、记录、查询分别计数**；**区域内映射一旦确定，单次查询内不得临时换模型**。

**当前实现**：`Index::lits_coverage()` **按当前活跃区域**走，带回退原因分项（`admission` / `degenerate` / `boundary` / `unsupported`）；`Index::which_region()` 供基准统计**回退查询占比**。

**两条已经付过代价的口径**：

1. **累计值 ≠ 末态值**：整个门累计的回退率（18.2%／17.0%／7.9%）与**末态**的回退率（9.3%／5.3%／2.2% 区域、11.8%／6.6%／2.9% 记录）**相差约两倍**——多数回退发生在过程中的临时构造上，重建时又校准成功了。**引用回退率必须说它对应哪一份状态。**
2. **非有限值一律拒绝**，不在半途切到另一个后端。

## 7. 扫描：合法组号 + 子块有序**不**自动保证全局扫描正确

**约束**：模型必须核实"组间与子块间的键序依赖"是否成立。

**依赖是真的**：`Region::scan` 按**组号升序**遍历，所以扫描输出字典序**当且仅当**区域内组号随键序非降。M1 只管一个组**内部**的子块，**跨组不保证**；边界目录也只是组内边界。

**验收**：`check_scan_contract` Part 1a 全量相邻键对测保序（三数据集违例 0），**Part 2 是负对照**——用诊断钩子把组号轮转一位（确定、在范围内、故意非保序），要求 Part 1 至少崩掉一项；不崩则门自报失败。

**对 M_team 的要求**：**若未来模型不提供扫描所需的顺序性质，必须明确约定它需满足的条件，或另做辅助有序目录并完整计费；不能默认为任何 predict 实现都可以直接接入。**

**这一条是契约要求，不是建议（2026-09-23 审阅后收紧）**：**保序断言必须与后端无关地跑在同一个受检入口上。**
任何新增后端（含模型组的 M_team）在接入前，都必须与 `Context16` 一样通过
**「全量相邻键对的显式组号保序断言 ＋ 非保序负对照」**。**由「返回合法组号」加「组内子块有序」
推不出跨组全局有序**——M1 只管组内，`Region::scan` 依赖的恰恰是跨组那一段。
**「内容与参考表相等」是功能证据，不能替代这条断言**：它只在被抽到的状态与起点上成立，
而保序是可被单点破坏的性质。

**当前缺口**：**LITS 后端从未跑过保序断言**（`use_lits_` 路径下只有 `check_lits_index` 的内容一致间接约束）。
换模型正是这条最该守的场景。**因此 LITS 现在的身份是「参考后端」，不是「已验收后端」**——
它可以用来回答「换一个映射会怎样」，**但不足以作为新后端接入流程的样板**。

## 8. 边界情形

| 情形 | 语义 | 有无**有触发证明**的用例 |
|---|---|---|
| 空索引 | 组 0，不需要共享表 | 有 |
| 单键（`sorted.size() < 2`） | `boundary(TooFewKeys)` → 组 0 | 有 |
| `G = 1` | 全部映射到组 0 | 有 |
| 前缀关系（键短于区域前缀） | 拒绝 | 有 |
| 域外输入（字节 ≥128、嵌入 NUL） | 拒绝 | 有 |
| `p = 0 / 1 / 31 / 32 / 33 / 121 / 123` | 位置下标是 `i & 31`（掩码取模），所以 `p > 32` **不是越界**，但 `p` 决定**相位** | 有（37 个边界区 / 2,370 键） |

## 9. 模型替换

**约束**：**改变映射必须重建或按有证明的方式迁移记录，不能只换模型指针保留旧位置。**

**当前实现**：换后端时 `preset_ok` 恒假 → 每个区域重新统计、重新规划、重新构造。

**为什么"只换指针"不行**：`model_identity` 是**摘要**（只认 `Model` 这一个类型，折进 `m.kind` 与整个 `m.cumulative`），**不是版本门槛**；而 `key_digest` 的实现在注释里**自述为 helper 而非身份**。

---

## 10. 保留的默认与不做的事

- **保留默认构建 R1。** 跨阶段缓存 **R2 的历史实验不因新后端而自动启用**。
- **新优化不再次将弱摘要、相同数组长度当成键序列身份。**
- **优化 HPT 的训练算法、表参数或概率估计不进入本轮主线**（属模型组）。
- **许可证未决**：LITS 的代码许可仍未解决。**源码哈希一致不能替代许可确认。**

## 11. 交付 M_team 时怎么用这份契约

1. 逐条对照 §0 总表：九项各有"谁看守"——**没有看守的项必须先补门**。
2. 跑 §7 的 2×2：`M_ref × S0/S1` 与 `M_team × S0/S1`，固定数据、外层区域划分与主块预算；各臂按**合法映射**重新构建；训练时间、模型内存与维护**一并计入**。
3. **若 M_team 必须改变组数或区域划分，就不能再称"纯模型消融"**——要另外说明改动。（这一条 E38 已经踩过：LITS 用到组的 1.55×–2.01×，报告**未标注**为非纯模型消融。）
4. **换模型后必须重测**：LITS 接入已经证明同一结构在不同映射下成绩不同（skew／tranco 上点查更快、构建慢 2.4–2.7×）。**"模型替换导致更均衡的记录分布"不代表字节需求或动态寿命分布也更好。**
