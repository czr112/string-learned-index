## 3. P1 —— A1′：只扩大回收触发面，不迁回

**这是架构主线，也是本计划的首选包。**

| 字段 | 内容 |
|---|---|
| **具体函数** | `Region::insert_slow`（`index.hpp:3345`）与 `Region::place_with_ctx`（`:3262`）的回收调用点；当前只对 `first_candidate(g, s)`（**按键序选中的那一个**子块）调 `repack_subblock` |
| **唯一变量** | **新增一个开关**（拟名 `Config::reclaim_widest`，默认 false，四张开关表全登记）：放置失败时，若按序选中的那块整理后仍失败，**改试该组"可回收字节最多"的那个子块**，而不是只试按序选中块 |
| **固定条件** | 发布配置；模型、容量规划、主块预算、组几何、溢出容器**全部不动**；**不迁回**（`overflow_migrate` 保持 false）；不加周期、不加迟滞（E32 已把节流方向实测否掉） |
| **对照** | S0（发布配置） vs S1（S0 + `reclaim_widest`）；同轮、同进程、同一次重复内配对；三臂即够（S0／S1／ART） |
| **正确性风险** | 低——`repack_subblock` 是**原地收紧**，只改 `Entry::offset` 与 `Header::bottom`，不改成员、不改槽序、不重建边界目录。仍需：在 `check_g1_contract` 的 C 部分之后追加一条"多块整理后内容与键序不变"的断言，并断言新分支**真的触发过**（`reclaim_widest_helped > 0`，否则门自报失败） |
| **工作负载** | 长期替换 `same`/`grow` 到 200%（三个语料）——**这正是 E28/E31/E37 用的负载，可与它们对话**；另加一个纯插入负载做对照 |
| **目标指标** | ① 溢出记录数（主）；② **回收促成数**（`subblock_reclaim_helped` 的增量）——这是 E37 归因给出的那个量；③ 完整维护耗时；④ 点查；⑤ 常驻空间；⑥ 尾延迟 p99 |
| **读写空间副作用** | 整理不释放块（只恢复块内可用容量），所以**常驻空间不应下降**；若观察到下降，说明有其他机制被顺带触发，必须查清再解释。分配次数应不变（原地 memmove） |
| **停止条件** | 见 §5。**关键判据**：若溢出降幅与 E37 同量级（−46%～−91%）**且**完整耗时与尾延迟不劣于 S0，则 P1 复现了 E37 的效果**而无需迁移**——E37 的"迁回"贡献被证伪，E37 的结论要据此改写；若溢出降幅远小于 E37，则说明 drain 的效果**确实**来自它对溢出记录逐个求目标子块的那部分，P1 需要相应扩大触发面 |

**为什么这是"扩大触发面"的正确形式**：E37 的 drain 之所以回收了那些子块，是因为它**为每条溢出记录求了目标子块**——也就是说，回收的触发准则是"组内另一个块有空位"，而当前 S0 的准则是"按键序本应落在哪块"（`first_candidate` 与 `put_primary` **共用同一个枚举**，这是有意的、也是 E31 的设计）。P1 把准则从后者换成"最脏的那块"，是**同一个机制的单一变量变化**。

**边界**：E37 已证明 `drain` 的尾延迟代价（p99 六格 1.055–4.469，全 0/5）。P1 **不含迁移**，所以不应有那份代价——**若仍出现，那就是回收本身的代价**，这本身是一个值得记下的结论。

### ✅ P2a 已完成（2026-09-23）——**进入条件不成立，A4 按条件关闭**

**三处疑似的重复工作**：

| 计划怀疑 | 实测 | 判定 |
|---|---|---|
| 每区域重新求 `canonical_group` | **≈ 1.0 次／扫描**，**与区域数无关** | **不存在** |
| 跨区域重复 `locate(start)` | **恰好 2.0 次／扫描**，不随结果增长 | **存在但已是常数**——**不是 R+1** |

**随结果增长的只有三样**（组游标启动、归并比较、结果分配），**三者都是结果强制的**；其中**结果分配恰好 1 条／记录**，已是 E27 的 S1 之后的**下限**。而**每次扫描的固定设置（`locate`／`canonical_group`／`regions`）在 n=1024 时合计每返回记录 < 0.005**——**随 n 增大而消失**。

**周期性的一条计划修正**：计划 §P2a 写「跨区域重复 `locate(start)`」，**实测是 2 次而不是 R+1**——`Index::scan` 收集够 `count` 条就退出，512 个抽样起点绝大多数在**第一个区域内**就收够了。**E32 的 S2（起点缓存）因此也失去了对象。**

**处置：按停止条件未满足关闭 A4，P2b（持续游标）不实施，转向 §6 的下一项。** 本轮**没有做任何计时**，也**不估计加速比**——计数只能定位候选。

| 理由 | 实测 |
|---|---|
| **纯插入上没有总体** | 死区**恰为 0.0**、匹配率 **0.00%**；且槽位拒绝与之同量级或更大，而空洞复用**只释放字节、不产生槽位** |

**两处被推翻的初版说法（留在原处并注明，不留「一直是对的」的印象）**：

1. **「repack 覆盖严格超集」不成立。** 那个结论由**缺失的 `n<2` 守卫**撑起——
   初版的 `fits_repack` 只算算术，不看机制的前置条件，于是**在一个根本不会执行的块上把 repack 算成「覆盖了」**。

   W3 的 **8.79%／1.24%／33.89%**。**挂在它上面的「碎片元数据成本近零」登记一并作废。**

**下一件该测的事（不是空洞表）**：**`repack_subblock` 的 `if (n < 2) return;` 是一行条件，不是机制**，

**两条口径必须先说清**：**（a）发布配置里 `subblock_reclaim` 与 `reclaim_widest` 都是 `false`**，
所以三列匹配率全部是**反事实对照**，`subblock_reclaims` 恒为 0 是**配置导致的零**；

## 7. 停止、采用与记录规则

| 结果 | 处置 |
|---|---|
| 正确性或预算失败 | **停止排名，先修该问题** |
| 机制成立、完整目标成本有可分辨收益、副作用可接受 | 进入最终组合候选 |
| 空间或尾延迟改善但读路径明显变慢 | 作为**明确场景候选**完整报告取舍，不直接进默认 |
| 只有计数改善、时间与空间无可辨收益 | 完成实验并保留**负结果或未分辨**结论 |
| 进入条件不成立 | 记录诊断，**关闭条件分支**并继续其他任务 |
| 多种局部改动分别有效 | **同轮**测试选定组合，**不将各轮比值相乘** |

**每个实验在开始前声明停止条件**；一次架构候选足以回答当前问题时，**停止无依据的横向扩展**。

## 8. 与本计划配套的三条纪律

1. **S0/S1 的"必须相等"清单**取自 `S0_SNAPSHOT.md`：区域数、逻辑组数、主块预算、逻辑映射。任何结构实验都要先证明它们一致——**不能只依赖同一参数名**，因为逻辑组数可能由槽数等物理参数间接推导。
2. **比值只在同一次重复内配对**；报告逐进程中位数、跨进程范围、方向计数与**噪声底**；落在自身噪声底内的变化记为"未观察到明确差异"。
3. **空间是确定性量**，不套时间统计的措辞（噪声底、5/5 胜出）；RSS 单列。
