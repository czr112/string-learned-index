# G5 —— 2×2 跨后端检查：A1′ 的收益属于哪个映射

日期：2026-09-23。run_id **`g5x2`**（计时）＋ **`DIAG`**（计数）。
目录：`validation_e25_20260918`。装置：`bench_lits2x2.cpp`（五臂）／`run_widest.py --phases x2`／`analyze_lits2x2.py`／`diag_lits2x2`。

## 0. 为什么必须做这一轮

G3 把 **A1′**（`subblock_reclaim` ＋ `reclaim_widest`：放置失败时，按序选中的子块整理后仍失败，就改试该组**最脏的其余子块**）测成**本项目迄今最强的结构结果**——维护 0.273–0.733、点查 0.464–0.686、溢出 −76%～−99.4%。

**但那一轮只跑了一个映射：`Context16`（M_old）。**

A1′ 的触发条件是「**按序选中的那块整理后仍然放不下**」。**换一个映射，组内几何与溢出分布都会变**——模型把记录放进哪一组、组里几个子块、哪个子块有垃圾，全部可能不同。**所以在「A1′ 是架构级收益」这句话成立之前，必须在参考映射上重测一遍。**

本轮把 **M_ref（固定 LITS 适配器）** 接进同一个程序、同一个进程、同一次重复，与 M_old 并排：

| 臂 | 映射 | A1′ |
|---|---|---|
| **S0** | Context16 | 否 |
| **WIDE** | Context16 | **是** |
| **S0L** | LitsHpt | 否 |
| **WIDEL** | LitsHpt | **是** |
| **ART** | — | libart 外部臂 |

**四条臂之间的差异全部由 `require_only_switches_differ` 断言**（S0↔WIDE、S0L↔WIDEL、S0↔S0L、WIDE↔WIDEL 四条），**臂塌成同一配置即失败**。

## 1. 协议

- 5 个独立进程 × **5 次重复**（五臂轮转，`reps % 5 == 0` 才能位置平衡；驱动里有一条**断言**位置平衡的检查，不是假设）。
- 比值**只在同一次重复内配对**（同进程、同重复、两个臂）；报每进程重复中位数、跨 5 进程中位数、方向计数 (k/5)、**噪声底 = 五个进程中位数 max÷min**。
- **落在自身噪声底内的变化记为「未观察到明确差异」。**
- 语料 mixed／skew（131,072 键）、tranco（262,144 键）；模式 `same`／`grow`；长期替换到 **200%** 检查点。

## 3. 主结果：A1′ 的收益**几乎全部属于 Context16 这个映射**

**维护＋操作耗时，200% 检查点**：

| skew / same | **0.277** | 5/5 | 1.012 | 1/5 | 1.058 | **−2%** |

**点查**：

| 数据／模式 | M_old `WIDE/S0` | 方向 | **M_ref `WIDEL/S0L`** | 方向 | 判定 |

**「保留比例」＝（1 − WIDEL/S0L）÷（1 − WIDE/S0）。** 它是**两个配对中位数之比**，继承两者的不确定度，**是一个概括、不是一次测量**，不能当作独立观测量引用。

**读法**：

1. **M_old 上 A1′ 是六格全部 5/5 的大幅收益；M_ref 上维护的收益保留比例只有 −2%～36%，点查六格全部落进噪声底。** **「保留比例」是由两个配对中位数推出的概括量，不是参考后端的耗时降幅**——`WIDEL/S0L` 本身的比值是 **0.890–1.012**（其中 skew 两格点估计 1.012／0.993，**方向 1/5 与 3/5，在噪声底内**）。
2. **skew 上点估计甚至略偏负面**（维护 1.012、点查 1.002），方向 1/5 与 2/5 ——**记为未观察到收益**，不说「变差」，因为它也在噪声底内。
3. **只有 tranco 两格在 M_ref 上留下可分辨的维护收益**（0.890／0.904，5/5，噪声底外）。**但这不能读成「LITS 在 tranco 上最弱」——恰恰相反**：`S0L/S0` 的 same 维护 **0.480** 是三个语料里**最低的比值**（§5），即**参考后端在 tranco 上收益最大**。**按指标与语料看，方向并不单一**：tranco 上 `S0L` 的溢出 **192,980** 反而**高于** `S0` 的 **127,330**（§4 的表）。**所以不能说「更好的模型必然让溢出更少」**——映射改变的是**组内几何与触发机会**，**不能预测模型组后续模型的收益**。

**结论：A1′ 不是一个「与映射无关」的架构级收益，它在很大程度上是 Context16 映射下子块碎片的产物。** 在 M_ref 上它基本不产生可分辨的变化。**把 G3 的数字直接写成「本索引的 A1′ 加速」会高估它在参考后端下的价值。**

## 4. 机制：为什么 M_ref 上没得可回收

**诊断构建（`diag_lits2x2`，`-DE25_DIAG`）的逐臂计数，200% 检查点**（计数是确定性的，不套时间统计的措辞）。**原始记录：`results/main/long_lits2x2_same.jsonl`，run_tag `DIAG`，三语料 × 5 重复 × 五臂 × 4 检查点 ＝ 300 条**；计时记录在 `results/main/long_lits2x2_g5x2_{same,grow}.jsonl`（各 1,500 条）：

| 数据 | 臂 | 考察过的块 | `reclaim_widened` | `reclaim_widened_helped` | 溢出 | 常驻 |
|---|---|---:|---:|---:|---:|---:|
| mixed | S0 | 0 | 0 | 0 | 128,533 | 41.13 MB |
| mixed | **WIDE** | **2,123** | 2,017 | 2,013 | **748** | 22.86 MB |
| mixed | S0L | 0 | 0 | 0 | 112,768 | 35.44 MB |
| mixed | **WIDEL** | **273** | 259 | 259 | **89,204** | 32.26 MB |
| skew | **WIDE** | **5,544** | 5,101 | 5,082 | **950** | 22.02 MB |
| skew | S0L | 0 | 0 | 0 | 129,686 | 30.87 MB |
| skew | **WIDEL** | **0** | **0** | **0** | **129,675** | **30.87 MB** |
| tranco | **WIDE** | **3,047** | 2,824 | 2,200 | **1,924** | 24.39 MB |
| tranco | S0L | 0 | 0 | 0 | 192,980 | 37.71 MB |
| tranco | **WIDEL** | **240** | 187 | 127 | **182,535** | 36.85 MB |

**三个计数的单位不同，不能相减或相除**——这一点必须写在表下面，因为这张表很容易被那样读：

- **`考察过的块`**（`reclaim_widened_blocks_examined`）是 `E25_ADD`，**一次加的是「本次搜索里候选块的个数」**；
- **`reclaim_widened`** 是 `E25_INC`，**每重排一个块加 1**；
- **`reclaim_widened_helped`** 是 `E25_INC`，**每次搜索成功时加 1**（每次搜索至多一次，因为成功即 `return`）。

**所以 `考察过的块 − helped` 是「块的个数」减「成功的事件数」，没有意义**；
**`helped / widened` 也是一个混合比**——它是「成功搜索数 ÷ 重排块数」，见下一条。

**机制是直白的：**

1. **`skew` 上 `reclaim_widened` 恒为 0** ——**加宽的那次搜索一次都没有进入**。因为触发它的前提（按序选中的子块整理后仍失败，且**该组还有第二块带垃圾**）在 LITS 的几何下从不成立。WIDEL 与 S0L 的溢出差 11 条、常驻空间**逐位相同**，那 11 条来自 `subblock_reclaim` 那一半，与加宽无关。
2. **mixed 上考察块数 2,123 → 273（7.8× 更少），tranco 上 3,047 → 240（12.7× 更少）** ——机会本身小了一个数量级。
3. **「每成功一次要重排几个块」在 M_ref 上变差。** `helped / widened` **不是「有用块的占比」**（两者单位不同，见上），它的倒数是**每次成功所需的平均重排块数**：
   M_old 的 mixed 是 `2013 / 2017 ≈ 0.998` → **约 1.00 块／成功**（成功几乎总在第一次重排就拿到，因为每次成功最多只记 1）；M_ref 的 tranco 是 `127 / 187 ≈ 0.68` → **约 1.47 块／成功**。
   **也就是说：加宽在 M_ref 上不只是机会更少，每次成功还要多整理约一半的块。**
4. **LITS 让「回收」这件事整体变小**：它把更多记录直接放进主块（S0L 的常驻在 mixed 上比 S0 低 **14%**），于是**溢出更少、碎片更少，A1′ 的对象也就更少**。

**所以 A1′ 与「更好的模型」在功能上是部分替代的**：两者都在减少「放置失败」，一个靠更准的预测，一个靠更宽的整理。**本轮在 mixed 与 skew 上观察到参考后端把 A1′ 的机会吃掉大部分；tranco 不是**（那里 A1′ 仍有可分辨的收益，而参考后端的溢出反而更高）。**这是按语料与指标观察到的现象，不是「更好的模型必然更少溢出」的规律。**

## 6. 对 A1′ 采用决定的影响

`OPTIMIZATION_PLAN_V2.md` §3 把 A1′ 列为「进入最终组合候选」，G5 的组合轮要在两个映射下复核。**复核结果是分裂的：**

| 问题 | 回答 | 依据 |
|---|---|---|
| A1′ 在**发布映射**下成立吗 | **成立，且是本项目最强的结构结果** | §2 同轮复现 G3；六格维护 5/5、点查 5/5 |
| A1′ 在**参考映射**下成立吗 | **基本不成立**——维护剩 5%–36%，点查六格全在噪声底内，skew 上搜索从未进入 | §3、§4 |
| 因此它是「架构级」还是「映射级」 | **映射级。** 它的触发面由 Context16 的子块碎片决定 | §4 的计数 |

**处置**：

- **A1′ 保持非默认**（与 G3 的处置一致），**但它不能被写成「换后端也成立的通用优化」**。
- **若模型组交付的后端在结构上更接近 LITS（放置失败更少），A1′ 的价值应按 M_ref 行预期，而不是 M_old 行。**
- **G3 的结论据此加一条边界**：那组数字的口径是 **Context16 映射**。

## 7. 本轮不能声称的

1. **不能把 M_old 与 M_ref 的比值相乘或相除**得到任何「映射 vs 机制」的联合量。§3 的保留比例是**概括**，已标注。
2. **不能声称 LITS 更好或更差**——§5 只在 `same` 上一致更好、`grow` 的混合字符串上一致更差；且 LITS 是临时后端。
3. **不测尾延迟**：本基准没有逐操作计时装置（与 G3 同一条边界）。
4. **计数器是每臂独立的**：`Counts::reset()` 是 `*this = Counts{}`（整结构体重置），而本基准在**每个臂开始时**调用它，所以 §4 的四个计数都是**该臂自己的**累计值，不是四臂之和。（这一点与 G3 的报告口径不同——那里 `subblock_reclaims` 被描述为进程级累加器；**本轮不是**，因为重置覆盖了整个结构体。两轮的计数不可直接互引。）
5. **skew 上 `WIDEL` 与 `S0L` 的常驻空间逐位相同、溢出差 11 条**——这**不是**「A1′ 无效」的普遍证明，**只是「在这个映射、这个语料上，加宽没有机会」的直接证据**。
