## I1 构建组 == 查询组

**要求**：同一键在相同映射状态下，构建与查找得到同一逻辑组；含未命中新键。

**为什么它不平凡**：两条路径**不是同一个调用**。

```text
Region::canonical_group(...)  ->  model_.predict<false>(suffix, groups_, config_.canonical, ...)   （index.hpp:1450）
Region::predict_for(...)      ->  model_.predict<Hash>(suffix, groups_, mode.route, ...)          （index.hpp:1483）
```

不同函数、不同模板实参、**不同 route**。而发布配置里放置走 `Config::canonical`（默认 `Route::Full`）、查询走 `query_mode`（`Route::Interval`）。

**覆盖**：`check_scan_contract` Part 1a 对**每个已放置键**在键序上逐键断言"查询组 == 放置组"（三数据集，全量）。`check_g1_contract` C 对**缺席键**做同一断言：先问查询路径，再插入，数哪个组 +1——两条 route × 3 数据集 × 1,024 键 = **6,144 个缺席键，零处不符**。

**剩余缺口**：无（就 M0=Context16 后端而言）。LITS 后端下未做同类断言。

## I2 扫描依赖的保序性

**要求**：若扫描依赖组序，分组映射须满足所需字典序；验收＝理论契约检查＋有序键相邻差分。

**依赖是真的**：`Region::scan` 按**组号升序**遍历（`index.hpp:3811` 起），所以扫描输出字典序**当且仅当**区域内 `canonical_group` 随键序非降。M1 只管**一个组内部**的子块，跨组不保证。

**看守**：`check_scan_contract` Part 1a 全量相邻键对测保序（三数据集违例 0／131,008、0／131,008、0／262,016），并且 **Part 2 是负对照**——用诊断钩子 `sar_rotate_groups` 把组号轮转一位（确定、在范围内、故意非保序），要求 Part 1 至少有一项**崩掉**；若不崩，门自报失败。**这是本课题唯一带反向对照的门**，所以它的"通过"不是空的。

**剩余缺口**：**LITS-HPT 后端从未跑过保序断言**——`use_lits_` 路径下 `canonical_group → lits_.predict_group` 的单调性没有直接断言，只有 `check_lits_index` 的内容一致间接约束。**换模型正是这条不变量最该守的场景**，所以这条缺口要写清楚。

## I3 每个活跃键恰好一次；值正确

**看守**：五个门各自与**独立 `std::map` 参考表**逐条比对内容与值：`check_lits_index`（两臂各自比，不互相比）、`check_overflow_store`、`check_freeze`、`check_tag_store`、`check_scan_contract`。

**覆盖**：update／insert／重复插入／upsert 命中与未命中／erase 命中与未命中／删除再插／全量扫描／任意起点扫描。

**剩余缺口**："**恰好**一次"是靠 size ＋ 有序 ＋ 集合相等**推出来的**，没有重复计数这种独立断言。

---

## I4 目录导航不漏记录

**看守**：`check_e11_locate`（＋`san_` 版）断言边界目录的尺寸／顺序／边界最小键、`mismatches == 0`，并要求三类键族非空（边界点、两键之间、首尾之外），另含"溢出里有主块下界之外的记录"这一情形；空中间子块由 `check_e9_multiblock`／`san_check_e31` 覆盖；任意起点与"返回不足 n"由 `check_scan_contract` Part 1c 覆盖。

**剩余缺口**：单块组的 locate 边界未单独驱动（`check_e11_locate` 主要跑多块组）。

---

## I5 块几何合法

**看守**：`san_check_e9_multiblock` 断言表尺寸／偏移基址／槽位范围 1..48／块与基址 64 字节对齐／偏移与块一致／子块等分／每个子块的条目数一致／字节守恒／子块有序／M1 秩序；`san_check_e31` 逐多块组把目录与自身子块的最小键复核；`check_freeze` 覆盖重建路径含"精确容量子块"。

**剩余缺口**："有效区间不重叠"没有独立断言（由偏移单调 ＋ 字节守恒间接保证）；对齐只查 64 字节。

## I6 标签正确

**看守**：`check_tag_store` 断言缺键必然 `found == false`（碰撞必须落到完整比较）、退订与槽位重用后无陈旧标签、标签与句柄同移、三臂与参考一致；`check_lits_fingerprint` 断言标签是**后缀的函数**，且**带负对照**（要求朴素接线在可测比例的键上不一致，否则门自报失效——实测 98.4%／99.56% 不同）。

**剩余缺口**：LITS 臂自身的存储标签没有独立于"后缀标签"的第二套核对（因为适配器 `fp_consumed = 0`，完整键字节不入哈希，所以这条对该后端是弱形式）。

## I7 整理不改记录集合

**看守**：`check_freeze` 在同一计划下建 OLD（C2 关）／CHOSEN（C2 开）／SHIPPED 三份，断言 OLD 与 CHOSEN **逐条内容相同**、SHIPPED 与 CHOSEN 内容与结构计数相同，并在 replace 负载上确实发生压缩（输出 `old/chosen_compactions`）；`san_check_e31` 在四个检查点逐条比对内容与键序，并**断言回收分支真的跑过**（`subblock_reclaims > 0`，源码带 `#error` 防漏宏）；`check_c3` 与 `check_e26_c2` 覆盖各自的触发变体。

---

## I8 定位不跨失效点

**要求**：有限作用域的定位结果不跨越使它失效的修改；变更后重取槽位；测试目录重建、压缩和分裂。

**看守**：`Located` 只在产生它的那次公开操作内有效（设计上的结构性保证，`index.hpp:2828–2846` 写明）；`check_e25_write` 对 V2 的复用路径做了**定向分支非空断言**（NotLocated 回退、前缀重建、区域分裂三类触发点都计数过）。

**剩余缺口**：没有"复用陈旧定位应被拒绝"的**负向用例**——该情形在类型上不可表示（`Located` 不可跨调用传递），所以只能靠设计约束，而没有断言。这一点如实登记。

---

## I9 映射身份

**要求**：模型／前缀／组数变化后不直接沿用旧映射缓存；记录映射版本与受控生命周期；**禁止仅用数组长度作身份**。

**看守**：`check_e20_r2` 覆盖四个 guard case（组数不同／模型不同／键集不同／陈旧上下文）被拒且回退后结构正确；`check_e19_reuse` 覆盖 R1 复用组号的失败回退。

**实现侧**：`RegionDemand` 携带 `prefix / groups / model_digest / key_digest`（`index.hpp:941–967`）；`preset_ok` 要求四者与当前一致才接受预设（`index.hpp:2099–2102`）；`Index` 侧另有源地址与长度（`source_ok`）＋逐区域 `key_digest` 复核。

**注意**：`key_digest` 的实现在注释里**自述为 helper 而非身份**（`index.hpp:951–966`）——"禁止仅用数组长度作身份"这一条由代码满足。

## I10 维护失败的原子性 —— **已知缺口**

**要求**：维护失败不丢记录、不重复发布、**计数不半更新**；验收＝准备—验证—提交；可控失败注入。

**装置**：`check_g1_contract` D 用诊断专用的注入钩子（`-DE25_DIAG`，不新增 Config 开关），在 `compact()` 的两个点各注入一次 `std::bad_alloc`：准备点（收集完成、尚未动数据）与提交点（块已清空、一半记录已重放）。

**结果**：

| 注入点 | 断言 | 结果 |
|---|---|---|
| **准备** | 索引逐字节不变 ＋ 全量扫描与参考表逐条一致 ＋ 该键仍不存在 | **成立**（三数据集） |
| **提交** | ——只能测，不能断言 | **不原子**：丢 mixed 24／skew 173／tranco 34 条，且 `size` 仍报原值 |

**结论**：**"维护失败不丢记录、计数不半更新"在当前设计下不成立**，成立的是更弱的一条——**失败不可达**。`compact()` 提交前有 `repack_budget_fits` 的必要条件检查，`put_primary` 失败还有 `throw std::logic_error("compaction lost capacity")` 兜底，**原子性完全建立在这个前置条件之上，而没有验证与回滚**。

**顺带修掉一处**：`++compactions` 原本在 `compact()` 的**入口**——一次失败的压缩也被计成一次压缩（正是"计数半更新"）。已移到提交成功之后。E25／E30 的计数器**没有跟着移**：它们量的是已经真做过的工作，失败时把那份工作记下来是对的。

**关闭路径**（G2/G3 输入）：要么实现 §6.3 的临时缓冲版本并与原地版对照，要么把"必须持有前置条件"写成显式契约、调用方在 `logic_error` 后重建。**两者都不做，就不能宣称维护是失败安全的。**

## I11 只改值不动布局

**要求**：只改值不改变键布局与空间计数；验收＝值更新控制组前后状态检查。

**此前为什么是缺口**：现有门只比**内容**（`check_lits_index` 的 update_only）或比**两个配置**（`check_freeze` 的 update_only）——**没有**同一个索引在纯值更新前后的前后比较。

**看守**：`check_g1_contract` A：4,096 个活跃键改值，前后各取完整快照并逐项比较（size／region_count／`memory()`／overflow／compaction／`memory_breakdown()` 七个分量／每区域的前缀长与三张表／每区域逐组的 entries+bytes+free+garbage 指纹）。三数据集全部**逐项相同**；同时断言每个被更新的键都能查回新值（非空性）。

---

## I12 扫描的 lower_bound 语义

**要求**：返回满足同一比较器的 `lower_bound` 起点语义，最多 n 条；验收＝独立参考表、完整键值、任意起点与 `n = 0`。

**看守**：`check_scan_contract` Part 1b 全量扫描严格升序且逐条对参考表；Part 1c 起点族（首键／末键／末键+`\x01`／每组最小键／缺席键）× counts `{1,2,16}` 等于参考表截断；Part 1d 在删除、清空中间子块、制造溢出后重做。

**此前缺的是 `n = 0`**：三个扫描门的 count 集都没有 0，只有代码可读。`check_g1_contract` B 补上：14 个起点（含空起点、尾后起点、缺席键）× `n = 0` 返回**空**，× `n ∈ [size+1, size+64]` 逐条等于参考表的 lower_bound 尾部。

## 这份清单之外的边界

- **两个后端不对称**：除 I1（部分）与 I6（弱形式）外，LITS-HPT 后端在 I2／I3／I4／I5／I7 上都只由 `check_lits_index` 的内容一致间接覆盖，没有各自的不变量级断言。
- **并发、持久化、更宽 SIMD 不在本清单内**（任务书明确排除）。
- **字节域**：LITS 适配器拒绝字节 ≥ 128 与嵌入 NUL；M0 的键域承诺更宽。ART 对照限定在无 NUL ASCII 域。
- **门通过的含义**：只支持"**在门的覆盖范围内未观察到违反**"，不等于该不变量在所有输入上成立。
