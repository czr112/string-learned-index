# E26 结果：压缩重放的标签复用，与压缩触发门

日期：2026-09-19。目录：`validation_e25_20260918`（E26 在本轮内完成，沿用 E25 目录）。平台：WSL2 Ubuntu 24.04 + g++ 13.3.0，单核绑定。

**两个改动，逐级归因：**

| 变体 | 改动 |
|---|---|
| **C0** | E25 的默认候选（V1＋V2）＋**现有压缩** |
| **C1** | C0 ＋ **压缩重放复用原标签**（去掉一次重算） |
| **C2** | C1 ＋ **压缩只在组内可回收垃圾 ≥ 待放置记录长度时才跑** |

C1 是**同一批操作里少做工作**，是干净消融。**C2 改变"哪些操作会跑"，是触发策略变更**，不是消融。

---

## 0. 结论摘要

### 0.1 三个问题的答案

**① `compact` 为什么触发，是否反复无收益？**

| 数据 | 负载 | 实际压缩 | **促成该次放置** | 未促成 |
|---|---|---:|---:|---:|
| 混合字符串 | 持续插入 | 531 | **0（0%）** | 531 |
| | 删除后补入 | 1,131 | **34（3.0%）** | 1,097 |
| 重复前缀 | 删除后补入 | 5,103 | **179（3.5%）** | 4,924 |
| 百万域名 | 删除后补入 | 4,065 | **108（2.7%）** | 3,957 |

**表述限定**：未促成记为"**没有促成这一次放置**"，**不等于"这次压缩毫无价值"**——压缩还会跨子块重排记录，那对后续操作可能有价值。本轮的 `check_e26_c2` 显示这种重排在插入负载上**一条溢出都没省下**（见 §0.3）。

**② 压力组里的垃圾有多少？**

`garbage_before` 只统计**被压缩的那些组**，不是全索引总量：插入负载恒为 **0**；替换负载为 **48.6 / 293.0 / 81.0 KB**，而同期复制量是 **11.57 / 85.93 / 5.90 MB**——**垃圾只占复制量的 0.42% / 0.34% / 1.37%**。

**③ 清除垃圾后能多放进多少？**

**不适用**：C1 保持记录放置不变，压缩后能放入的记录数与 C0 **完全相同**。而 C2 走的不是"压缩后试放"，是**在压缩前就判断它能否腾出足够字节**——判据是必要的字节条件，不是对放置成功的预测。

### 0.2 C1：哈希砍掉 2/3 到 19/20，时间只快 0.9%–6.7%

| 数据 | 负载 | C0 总哈希 | 重放哈希被移除 | **移除占比** | **完整耗时 C1/C0** |
|---|---|---:|---:|---:|---:|
| 混合字符串 | 插入 | 9.67 MB | 6.91 MB | **71.5%** | 0.953（4/5） |
| | 替换 | 16.13 MB | 11.03 MB | **68.4%** | 0.954（3/5） |
| 重复前缀 | 插入 | 48.50 MB | 45.88 MB | **94.6%** | 0.930（5/5） |
| | 替换 | 86.49 MB | 81.95 MB | **94.8%** | 0.962（5/5） |
| 百万域名 | 插入 | 3.95 MB | 2.64 MB | **66.8%** | 0.966（3/5） |
| | 替换 | 7.70 MB | 5.63 MB | **73.1%** | 0.938（5/5） |

**这是审阅要的那个分辨**：**哈希量下降 2/3 到 19/20，完整负载只快 0.9%–6.7%**，所以**压缩的主要成本不在哈希**，在它的其他工作——记录收集、字符串复制、重新放置、目录重建。

**注意**：诊断构建的 `fp_hash_bytes` **看不出** C1 的节省，因为它为核对复用而对每条记录重算一次标签——正是 C1 去掉的那份工作。所以节省量由上表的**复制量**给出，时间由计时构建给出。

### 0.3 C2：跳掉"腾不出足够字节"的压缩

**正确性**（`check_e26_c2`）：C0 与 C2 的**内容与按键序**都与参考表**逐条一致**（每数据集 851,968–1,703,936 次元素比对）。C2 可以改变记录在主块／溢出的分布，**不改变索引持有什么**。

**结构代价几乎为零：**

| 数据 | 负载 | C0 压缩 | **C2 压缩** | C0 溢出 | **C2 溢出** |
|---|---|---:|---:|---:|---:|
| 混合字符串 | 插入 | 531 | **0** | 33,125 | **33,125（不变）** |
| 重复前缀 | 插入 | 2,168 | **0** | 33,590 | **33,590（不变）** |
| 百万域名 | 插入 | 1,901 | **0** | 66,934 | **66,934（不变）** |
| 混合字符串 | 替换 | 1,131 | 556 | 12,515 | 12,509（**−6**） |
| 重复前缀 | 替换 | 5,103 | 2,552 | 32,421 | 32,431（+10） |
| 百万域名 | 替换 | 4,065 | 2,255 | 28,971 | 29,013（+42） |

**插入负载上跳掉的压缩一条溢出都没多产生**；替换负载上代价是 **−6 到 +42 条**（相对 2.9 万–3.2 万条溢出）。

**耗时**（25% 检查点）：**C2/C1 = 0.049（重复前缀插入，约 20× 快）／0.362（百万域名插入）／0.531（重复前缀替换）／0.781（百万域名替换）／0.860（混合插入）／0.970（混合替换）**，方向 5/5（混合替换 4/5）。

## 1. 采用的决定

**采用 C1 与 C2**（`compact_reuse_tag` 与 `compact_needs_garbage` 一并启用）。

依据逐条对照审阅给的三项判据：

| 判据 | 本轮证据 |
|---|---|
| **包含维护在内的完整负载收益** | 有：`C2/C1 = 0.049–0.970`，方向 5/5，计时含压缩、分配与复制 |
| **改变溢出分布后的空间与后续查询代价** | 有：空间 **0 到 +7,209 字节（≤0.03%）**；查询 **C2/C0 = 0.82–1.02**，五格更快或持平 |
| **"没有垃圾但重放仍有用"** | 已明确处理：判据不预测重放价值；数据上插入负载的压缩组垃圾恒为 0 且促成 0 次 |

另：**C1** 是纯减法（不动成员、放置、容量、触发、边界维护），比值每格 ≤ 1 且无一致劣化；**C2** 的正确性经内容与键序逐条比对证明。

## 2. 适用边界

1. **C2 是触发策略变更，不是消融**；它与 C0 的**结构不同**（溢出数不同），这正是它有效的原因。
2. **C2 的判据是必要条件的字节测试**，不是对"压缩能否促成放置"的预测——压缩也做跨子块重排，本判据不预测那部分。
3. **`garbage_before` 只覆盖被压缩的组**，不是全索引垃圾；E24 的全局垃圾数字不能替代它。
4. **C1 的哈希节省由复制量给出**，不由诊断构建的哈希计数给出（诊断构建为核对而复算）。
5. **计时只覆盖 `insert_only` 与 `replace` 两种负载**；只改值不触发压缩，未纳入本轮消融。
6. **检查点到 25%**；`50%／100%／200%` 长期替换未测。
7. **单线程、单核绑定**；无 sanitizer。
