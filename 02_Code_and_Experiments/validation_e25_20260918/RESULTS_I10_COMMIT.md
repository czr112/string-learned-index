# I10 提交阶段原子性：实现与验收（`compact_plan_commit`）

日期：2026-09-23。触发：G0–G5 交付审阅 **P0-3**。
目录：`validation_e25_20260918`。装置：`check_i10_commit.cpp`（＋ `san_check_i10_commit`）。
审计（本轮的依据）：`I10_COMMIT_PHASE_AUDIT.md`。

**一句话**：`compact()` 的提交段**不再含有可失败操作**——放置决策与容量检查（连同目录构造）
全部移到了改动组内任何状态**之前**，提交段只剩无分配的写与一次 `noexcept` 的 `swap`。

---

## 0. 改了什么

| 位置 | 改动 |
|---|---|
| `Config` | 新增 **`compact_plan_commit`**，默认 **false**（发布行为逐位不变），四张开关表全登记 |
| `Region::plan_replay`（新） | 在**局部 scratch** 里复现重放的放置决策：既**证明**组装得下这批记录，又**建出**重放将产生的目录。**不写组内任何字节** |
| `Region::append_planned`（新） | 提交段**唯一的写原语**：执行计划已证明可行的追加。**没有容量判断可失败、不分配** |
| `Region::compact` | 改为 `bool`；开关打开时先 `plan_replay`，不通过就**一个字节都没动**地返回 false；提交段用 `append_planned` 与 `dirs_[g].swap(plan_dir)` |

**为什么 `plan_replay` 是精确的、不是估算**：`compact()` 按子块顺序收集记录，而 M1 保证子块按键序排列，
所以 `live` **全局升序**。对升序输入，每次插入都落在某个子块的**尾部**（新键 ≥ 已放置的每一个键），
于是 `insert_into` 内部那套块内排序**从不被走到**，放置退化成逐子块计数。**这就是一次便宜的预演能精确的原因。**

**提交段为什么会抛、以及现在为什么不会**：旧设计在重放**之后**调 `rebuild_dir`，它 `dir.clear()` 再逐个
`push_back` 构造 `std::string` 边界——**旧目录已经销毁、记录已经重放完毕**。现在目录在 `plan_replay`
里就建好了（那时组还完好），提交段只做一次 `vector::swap`，**而 `swap` 是 `noexcept`**。

## 1. 门的五个部分

| 部分 | 内容 | 断言还是报告 |
|---|---|---|
| **P1** | **旧设计**：在重放后的目录重建处注入（**两个注入位置**：目录被留空、以及非空但残缺） | **断言必须变化**——否则门是空的 |
| **P2** | **新设计**：在同一个目录构造处注入，此时它在 prepare 里 | **断言索引逐字节不变 ＋ 全量点查全部命中** |
| **P3** | 开关打开与关闭跑同一条负载 | **断言快照与扫描逐条相同**——计划**不改变行为** |
| **P4** | prepare 点注入（与 G1 的 D 部分连贯） | **断言不变** |
| **P5** | 重放中途注入 | **只报告**：这是修复后**不可能真实发生**的中断 |

**P1 为什么要跑两个注入位置**：在目录的**第一项**上注入，目录被留成**空**，而 `has_dir()` 对空目录返回
`false`、查找会走回退路径——**那是较轻的失败模式**。从**第二项**起目录**非空但残缺**，
`has_dir()` 接受它，`locate_subblock` 会对一份被截断的键表做二分——**那才是可能出错答的那种**。
**只测第一项的门会认证较轻的那一个。**

## 5. 调用方与提交链审计（审阅要求逐项核查）

### 5.1 `compact()` 有两个调用方，都**不分支**返回值

| 位置 | 形式 | `false` 的处置 |
|---|---|---|
| `index.hpp:3595` | `if (worth_compacting(loc.group, s.size())) compact(loc.group);` | **丢弃返回值**，随后重试 `put_primary` |
| `index.hpp:3686` | `if (worth_compacting(g, s.size())) compact(g);` | 同上 |

**这是有定义且正确的处置，理由写在两处调用点的注释里**：`false` 表示计划**证明了组装不下它自己的记录**，
此时**组一个字节都没动**——于是接下来的 `put_primary` 会再次失败、记录进溢出，
**与「压缩跑了但没帮上忙」的后果完全相同**。两者在调用方**故意不可区分**，
因为**调用方要做的事本来就一样**（都不改变后续流程）。

**但不可区分会掩盖诊断**：一个「计划从不被拒」的观察和一个「从不发生」的观察读起来一样。
所以加了计数器 **`compact_plan_rejected`**（`-DE25_DIAG`），把两者分开。
**实测值：三语料 `plan_rejected = 0`、`plan_violation = 0`**（`check_i10_commit` 的 P3 输出，mixed／skew 各 131,071 条、tranco 262,143 条）——**在这套负载上，计划从未拒绝过一次，`append_planned` 的前提也从未被破坏过**。

### 5.2 提交链审计：从第一次改动到函数返回，逐调用核过

| 调用 | 实现 | 分配？ | 可抛？ |
|---|---|---|---|
| `header(g,i).count = 0; .bottom = bb_[g]` | 写预分配的块头 | 否 | 否 |
| `suppress_dir_rebuild = true/false` | 布尔 | 否 | 否 |
| `append_planned(...)` | `h.bottom -= len` → `memcpy(base_of + h.bottom, ...)` → 写 `es[h.count]` 与 `h.tags[h.count]` → `++h.count` | **否**（写的是块内已分配的字节区与已分配的描述符数组） | **否**（只有整数算术与 `memcpy`） |
| `E18_INC` / `E18_ADD` / `E25_INC` | 宏，加一个 `uint64_t` | 否 | 否 |
| `++dir_rebuilds; dir_entries_built += n` | 整数 | 否 | 否 |
| **`dirs_[g].swap(plan_dir)`** | `std::vector::swap` | 否 | **`noexcept`**（`std::allocator`，不传播） |
| `++compactions` / `E30_ADD` | 整数 | 否 | 否 |

**结论：提交段**（`suppress_dir_rebuild = true` 之后到函数返回）**不含任何分配，也不含任何可失败的调用。**
`append_planned` 的前提由 `plan_replay` 建立，并在诊断构建里**被检查而不是被相信**
（越界或超槽位则 `E25_INC(compact_plan_violation)`）。

**边界**：`append_planned` 是**有意**省掉容量判断的——它执行的是计划**已经证明**可行的那次追加。
**这就是「按计划执行」与「边做边判断」的区别**，也是 §5.2 那一列全为「否」的原因。
代价是：**若 `plan_replay` 的算术与 `insert_into` 的算术漂移，越界只会在诊断构建里被计数器抓到**。
这条依赖写在 §6 的边界里。

**边界**：本基准测的仍是**长期替换到 200%**这一种负载形状；纯插入、短期替换与扫描**没做**这个对照。
`p99.9` 与 `max` 的噪声底大，**只报不判**。

## 8. 采用与默认值

1. **这是一次正确性修复，最后才成为默认值。** 开关最初默认 false，**在同轮配对计时证明它不慢之后**才翻转为 true（见 §7 与 §8）；**顺序是有意的**——先证明，再采用。
2. **计划正确的依据是「`live` 全局升序」**，也就是 M1。**M1 已有门**（`check_scan_contract` 的
   Part 1a 全量相邻键对保序），但**这条依赖是新的**：若将来 M1 被放宽，`plan_replay` 会先失效。
   `Result` 里为此留了诊断计数器 `compact_plan_violation`（`-DE25_DIAG`），
   在 `append_planned` 里检查计划的前提是否仍成立。**实测三语料为 0。**
3. **P5 的那条中断在修复后不可能真实发生**（重放循环里没有任何分配或可失败调用），
   **但它仍然是「若发生就会丢记录」**——本报告不把 P5 当成已解决，只把它标成不可达。
   **本轮的结论是「已测的同步失败路径已修复」，不是「抗任意中断」。** 见 §9.1 与边界 §10。
4. **不改任何算法**；`compact()` 的语义、输出与结构**逐位未变**（P3 断言）。
   **尾延迟本轮测了**（§7 的 p99／p99.9，来自源码已有的逐操作分布），**只覆盖长期替换负载**。
