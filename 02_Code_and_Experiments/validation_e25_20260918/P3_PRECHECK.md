# E38/P3 预检：单进程内存

日期：2026-09-22。装置：`precheck_memory.py`。**不是计时，也不是索引的测量**——它回答审阅提出的四个问题。

**为什么要先做这个**：把重复次数从 4 改成 3 修的是**顺序平衡**，**没有证明 OOM 的原因已解决**。OOM 出在 Windows 宿主上，而 WSL 的视图看不到宿主。

## 方法

**进程外观测。** 预检从 `/proc` 读，**没有把分配记账加回干净的计时程序**——那正是唯一会让它的数字不可用的改动。

**观测的是整棵进程树，不是包装进程。** `tools_build.py run_current` 把基准作为子进程启动并等待，所以预检手里的 pid 是包装进程的；只读它会报几 MB 的 Python 而完全看不到这次运行。第一版就是这么错的，已修（`descendants()` 走一遍 `/proc` 求和）。

**规模与范围**：正式数据规模（mixed 131072、tranco 262144），**一次一个进程、一个数据集、一个阶段**，三次重复。

## 结果

| 检查项 | 结果 |
|---|---|
| **并行度** | **串行。** `run_lits.py` 用嵌套 `for` ＋ `subprocess.run(...)`，没有进程池、没有 `&`，每个 `invoke` 阻塞到子进程结束。**同一时刻只有一个基准进程。** |
| **对象生命周期** | 每个臂的 `Index`、它与参考表 `Reference`、`live` 与 `live_set` 都建在**臂循环体内部**，下一次迭代前析构。**三臂索引不同时存活。** |
| **跨重复累积** | **没有。** RSS 在第一个 25% 就到达峰值，之后 50%／75%／100% 三个采样点**完全相同**——后两次重复没有再加任何内存。 |
| **跨运行累积** | **没有。** mixed 同一配置跑两次，峰值**都是 215.6 MiB**（逐位相同）。 |
| **峰值** | mixed 131072：**215.6 MiB**；tranco 262144：**147.6 MiB**。 |
| **归还** | 运行后 `MemAvailable` 不变（**+0.0 GiB**），WSL 侧 `MemFree` 6.78 GB、Swap 2 GB 全空、**无遗留进程**。 |

**宿主的余量**：`MemTotal` **7.5 GiB**、运行前 `MemAvailable` **6.8 GiB**。单进程峰值约占可用内存的 **3%**。

**WSL 内当前占用最高的进程**是 `snapd`（31 MB）、`unattended-upgr`（22 MB）、`systemd-journal`（15 MB）——都是系统守护进程。

## 结论

**这次扫描自身的内存用量是「每进程约 216 MiB、串行、无增长」，它不是把宿主耗尽的原因。** 宿主当时内存低的原因在 WSL 视野之外，本报告**不宣称**知道那是什么。

**三条不能从这份数据推出的说法**（写在这里以免被读出来）：

- **RSS 在对象释放后不立刻下降，不等于泄漏。** 分配器保留高水位是正常的；本报告区分「峰值」与「地板」，而这里地板在后半段等于峰值**是因为负载连续运行、没有空闲间隙**，不是因为累积。
- 预检用的是 `same` 模式。`grow` 的键更长，峰值会高一些；本轮**没有测**，不把 215.6 MiB 当成两模式的界。
- **测的是一个进程**。驱动是串行的，所以这一个进程就是全部并发；但若将来驱动改了并行度，这份预检不覆盖。

## 附：中断与产物登记

**P3 装置与冒烟验证完成后，正式采集曾启动一次；那次运行因宿主内存不足被系统终止。当时尚无完整正式结果。**

- **中断位置**：第一个进程、mixed／same 的第一次调用跑完就被终止。
- **它的产物**：200 条记录写在工作文件 `results/main/lits_adapter_same.jsonl` 里，随后**被删除**。**它不是可追溯的原始数据**，不再被任何分析引用，也不计入任何结论——登记在此，仅此而已。
- **登记为删除而不是保留的理由**：它来自一个**协议已被判定为错**的运行（重复次数是 4，三臂下轮转不平衡）。保留一份协议不正确的中途数据，比删掉它更容易被后来的人当成原始结果。
- **上次删除与本次的区别**：旧驱动在每次启动时**无条件删除**工作文件，这会让一次中断的结果成为下一次运行的牺牲品。新驱动**只清空本次 `run_id` 的工作文件，从不触碰任何已归档文件**，并且**每完成一次调用就归档一次**——中断因此保留现场，而不是丢掉它。
