## 0. 结论

**分支 C 本轮只判了一半，而且两半的判法不同：**

| 目标 | 判定 | 依据 |
|---|---|---|
| **缩到当前活跃数** | **暂不进入原型** | 可回收量真实存在（25%–30%），但**回收不耐久**：回落之后容器以 **42%–98%** 的概率回到自己的历史峰值，而回到旧峰值**必然要重新扩容** |
| **缩到历史峰值** | **尚未判定** | 它回收的正是占 **18%–31%** 的 **Term A**；而**回到旧峰值不需要重新扩容**（容量本来就还在），所以**本轮的 `regrowth` 比值不能否定它**。它的代价是**容器突破历史新高时的重分配**——**本轮没有埋这个计数器**，故**未测**而非已关闭 |

**本轮真正确定下来的是一件事，而它与「关不关闭」无关**：
计划判据里的那个容量差额（`Σ(cap − size)/Σcap`，实测 18.32%–30.99%）**真实存在，但它主要是 `cap − high_water`**，
也就是**容器从未用过的部分**。**它不能再被用来证明「删除之后留下了大量待回收容量」。**

计划 §6 给分支 C 定的判据是**两个量**：`Σ(cap − size)/Σcap` 的差额，**和再增长次数**。
本轮两个量都测到了，而且**它们给出相反的答案**：

| 计划的判据 | 实测 | 读法 |
|---|---|---|
| **活跃数 vs 容器容量的差额** | **18.32%–30.99%**（W1 全部检查点）、**25.71%–29.87%**（W2） | **有对象可回收**——E24 的 22%–30% 落在这个区间内，同一口径 |
| **再增长次数 ÷ 回落次数** | **W1 88.13%–97.83%**、**W2 41.82%–49.48%** | **缩到活跃数不耐久**——容器落下去之后又会回来把这块容量用掉 |

**所以「有对象」这一半是成立的。** 只是**这个对象的构成不是 E24 以为的那样**：
它是增长策略的几何余量（**从未用过**），而**不是**「删除之后留下的保留」（**用过、现在没用**，实测只占 **0.00%–5.26%**）。

**同时被本轮否掉的是 E24 的那句推断**（见 §3.1）：同一口径的 21.28% 在一个**没有任何容器回落过**的检查点上也照样出现。

## 1. 装置与两个负载

只读诊断 `diag_branchc.cpp`（`-DE25_DIAG`，独立诊断构建，**不进入任何正式计时程序**），
在**当前冻结默认配置**上跑，**不打开任何候选开关**，**本轮的冻结开关全部为默认**（发布的 OFF 臂）。

**两个负载缺一不可，而且两个的 `frac` 约定方向相反**（这一点在分析器里咬过我两次，见 §4.2）：

| 负载 | 形状 | 作用 |
|---|---|---|
| **W1 长期替换** | 替换到 200%，活跃数按构造不变 | 与 E24 的口径对上（本轮 **18.32%–30.99%** vs E24 的 22%–30%） |
| **W2 净下降** | 跨键空间**步长 4/2/1** 删除 ＋ 每 4 次删除插 1 条新键 | 让容器真的从峰值回落，使 Term B 被**检验到**而不是顺带出现 |

W2 的两处形状都是被数据逼出来的，不是设计时的选择：

* **必须跨键空间均匀删除**，否则容器**要么被整段抽干、要么完全没动**，
  测出的 Term B 只是「空容器是空的」——同义反复（第一版的实证见下方引注）。
* **必须混入插入。** 纯删除下 `regrowth` 按构造恒为 0，判定规则里「回落之后再增长很少」那半条会变成空洞。

修正后的 W2 确实产生了**部分回落**：回落过的容器占比 3.2%–24.7%，
且 mixed/skew **每一个检查点上都没有归零容器**；tranco 有 **1–4 个**，
**不到其非空容器的 0.3%**——**不足以像第一版那样让 Term B 退化成「空容器是空的」**。

> **第一版的形状（在 N=20,000 的烟测上）**：按排序顺序从头删，容器**要么被整段抽干、要么完全没动**，
> 于是**回落 0.5 时「全部容器」口径的 ΣB = 35 全部来自 2 个归零的容器，而「非空容器」口径 ΣB = 0**。
> **烟测的记录未进入本文任何表格**，正式运行由修正后的 W2 取代。

## 3. 本轮被推翻的三个说法（这一节比数字本身重要）

### 3.1 E24 的推断不成立：「22%–30% ⇒ 记录已减少但容器仍保留」

**同一口径的 21.28% 出现在一个没有任何容器回落过的检查点上**（mixed W1 `before`：plan A+B = 21.28%，**ΣB = 0**）。
一个在「零回落」状态下就存在的比值，**不能作为「记录已减少」的证据**。

E24 的 22%–30% 本身没错，**错的是把它读成留存**。它量到的是**增长策略的几何余量**。

### 3.2 设计文档里的 A/B「可回收性」标注是算术错误

原设计写的是「Term A 是倍增余数，分支 C **不能**回收；Term B **才是**唯一可回收的部分」。
**这是错的**：收缩是**从分配的顶部**拿容量，所以

* 缩到**活跃数**：收 `cap − size = A + B`（＝上表的 plan A+B 栏）
* 缩到**历史峰值**：收 `cap − high_water = A`

**两项都收得到。** A/B 真正区分的不是「可回收性」而是**耐久性**：
A 是这个容器**从未用过**的空间，B 是**用过、现在没用、可能还会要**的空间。
本设计的判据沿用了错误的读法，**本轮已改**（`diag_branchc.cpp` 文件头、`analyze_branchc.py` 文档字符串）。

### 3.3 W1 的「Term B 按构造恒为 0」是**存量推元素**

原设计说：W1 活跃数按构造不变、溢出单调上升，**所以没有容器会落到自己峰值以下**。
**这是从总量不变推出每个元素都不变**——**本项目已经犯过两次的同型错误**，
而**它被本轮自己的数据否掉**：tranco W1 的 ΣB 是 90 / 153 / 259 / 939 条，
且 **mixed W1** 的 203,914 次回落中有 **4,425 次从未被补回**（mixed/skew 的 ΣB 在 1.00 处恰为 0，
但那同样是**测出来**的零，不是按构造的零）。

W1 的 Term B **是测出来小，不是按构造为零**。**本轮已改**（文件头与 W1 段落注释）。

## 4. 本轮修掉的装置缺陷

### 4.1 分析器的标签阈值被自己触发

分析器对 tranco 打印 **「Term B present」**（5.26% 越过 5% 标签线），而结论却把它并入统一的「关闭」。
**这是措辞与判据不一致。** 本轮已改为：**阈值写死在一处**、tranco **单独记录**
（它的 B/cap 是 mixed/skew 的 3–8 倍；**只统计真正回落过的容器（`B>0`）时是 11.15% / 7.90% / 6.35%**），
**不并入一个总的结论**。

### 4.2 两个负载的 `frac` 约定方向相反，分析器读了错误的检查点

W1 的 `frac` 是**替换比例**（递增），W2 的 `frac` 是**剩余活跃比例**（递减）。
任何「取第一行／最后一行」的规则都会让其中一个负载读到**全零的 `before` 行**——
本轮分析器确实这样打印过 `W2 regrow/drop = 0.00%, mostly permanent`。
已改为**按累计计数取最大值**，与 `frac` 约定无关。

**这个缺陷是被对抗性审查按出来的，不是自己发现的。**

  mixed/skew/tranco 仍分别是 3.46→1.94→1.55% / 4.35→2.40→1.90% / 11.15→7.90→6.35%，
  **同样的单调下降、几乎不变的倍数**。常数倍数产生不了趋势，所以趋势是**回落容器自己的性质**。

  它的算式把 `sum_drops`（贯穿整个调度的**流量**）减 `sum_B`（检查点上的**存量**），
  **正是本项目纪律 (ii) 明令禁止的存量/流量混用**。

## 8. 2026-10-10 补测：「缩到历史峰值」那半已判定，不再是"未测"

第 6 节登记表把分支 C 判成两半，其中一栏写的是**「尚未判定（未测，不是已关闭）」**，
并注明「要重新打开需补一个计数器（新峰值事件率），**不需要重跑本轮**」。**该计数器已补，入口已跑完。**

**新结果**：`RESULTS_C2_PEAK_ENTRY.md`（装置 `diag_branchc2.cpp`，是本文装置的副本加计数器，
本轮负载与本轮逐字相同，输出名 `results/main/branchc2_*.jsonl`）。

| 语料 | 负载 | 额外重分配 | 额外复制 | 期末 Term A | 代价/回收 |
|---|---|---:|---:|---:|---:|
| mixed | 替换 200% | 189,191 | 829.9 MB | 4.80 MB | 173× |
| skew | 替换 200% | 234,774 | 1,451.0 MB | 5.26 MB | 276× |
| tranco | 替换 200% | 164,943 | 341.9 MB | 3.92 MB | 87× |
| mixed/skew/tranco | 净下降 | 20,639 / 46,008 / 13,699 | 48.2 / 88.4 / 10.1 MB | 0.46 / 1.09 / 0.37 MB | 105× / 81× / 27× |

**判定：C-2 关闭，理由是成本——它的额外搬移是可回收容量的 27–276 倍。**
结构性原因：两个负载的溢出存量都在增长，容器的峰值持续被刷新，
而「容量 == 峰值」意味着**每一次刷新都是一次分配＋整段复制**；倍增把这个成本摊还掉了，缩容把它按次付清。

**因此第 6 节的这一行应读作：**

| 项 | 更新后的内容 |
|---|---|
| **分支 C（缩到历史峰值）** | **已判定，关闭**（2026-10-10）：Term A 确实可回收（期末 0.37–5.26 MB），但维持它的代价是 27–276 倍的额外复制 |
| **分支 C 整体** | **两条都关闭**：缩到活跃数不耐久（§0 表）；缩到峰值不值（本文第 8 节）。此后要重开需要新的机制设想，不是补测 |
