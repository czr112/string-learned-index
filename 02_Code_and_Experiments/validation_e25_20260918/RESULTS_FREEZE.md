## 2. 默认入口确实等于选定组合（`check_freeze`）

三种配置，各回答一件事：

| 配置 | 是什么 | 用途 |
|---|---|---|
| **OLD** | 五个开关全关的**显式**配置 | 衡量整个组合的变化 |
| **CHOSEN** | 五个开关全开的**显式**配置 | 连接前面各轮实验与最终产物 |
| **SHIPPED** | **不设开关、只设 R1 字段**的 `Config` | 验证默认入口 |

**断言（不是观察）**：`SHIPPED` 的开关串必须等于 `CHOSEN` 的——默认值若被改回，这里直接失败，而不是让产物悄悄回退。同时断言 `SHIPPED` 与 `CHOSEN` 的**内容与结构统计完全相同**，`OLD` 与 `CHOSEN` **内容相同、布局可以不同**（C2 改变的是哪些压缩会跑，这正是它的作用）。

**三个数据集全部通过**，每数据集 851,968–1,703,936 次元素比对。实测 `cfg_shipped = write_fast_locate=1,reuse_locate_ctx=1,compact_reuse_tag=1,compact_needs_garbage=1,scan_reserve_result=1`。

**一次确认运行能核对配置与功能，不能单独证明性能稳定。**

## 3. 各轮测试臂已显式固定（`switches.hpp`）

**这一步是必须的，不是洁癖。** 在此之前，每个门都从 `Config` **默认值**构造基线，再翻转它要研究的开关。默认值一改，门就会在下面悄悄换掉实验条件。

- `baseline_config()` 逐字段写出**本项目新增的全部五个开关**（全关），不读任何默认值；
- `pin_frozen_switches()` 把五个开关钉到发布值，供冻结前写成、依赖默认值的门使用；
- `require_only_switches_differ()` **断言两条臂恰好只在声明的开关上不同**——臂若不慎塌成同一个配置，门**失败**而不是"通过"一次没发生的比较；
- 每个门的输出里直接印出**实际生效配置**。

**已固定**：`check_e25_write`（写门，压缩与扫描固定在关）、`check_e26_c2`（写路径与扫描固定，只变压缩）、`check_scan`（写路径与压缩固定，只变结果构造）、8 个继承门（钉到发布值），以及 `bench_e26`／`bench_scan`。

**`bench_scan` 不固定就会坏**：S0 与 S1 只差 `scan_reserve_result`，默认翻转后两臂会变成同一个配置，对照静默消失。

## 5. 构建闭环的一个洞，已修

**编译失败时 `tools_build.py` 只写 `logs/build_<target>.json`，不动 `build/<target>.built.json`。** 而 `run` 读的是后者——所以**源码已经编译不过的门，仍然执行了上一次成功的二进制并报 `passed`**。本轮真的发生过一次（`check_e8_hetero` 缺 include 却"通过"）。

已修：失败时**一并删除** `build/<target>.built.json` 与 `build/<target>.exe`，失败变成硬停而不是静默回退到旧构建。

## 6a. 长期替换（原任务书阶段三的补测）

完整结果见 **`RESULTS_LONG.md`**，对照是 **C1 vs C2**（判断 C2 自身的长期价值；"最终版本 vs ART"是另一个问题）。

**三条结论：**

1. **空间不趋稳。** 三种数据、两种键模式下溢出与索引字节都**单调增长**；到 200% 周期时混合与重复前缀的**溢出条数接近全部活跃记录**（128,533／131,072 与 127,070／131,072）。**C1 与 C2 的空间逐位相同——C2 不解决空间增长。**
2. **C2 的时间收益依负载而定，不是普遍的。** 替换键变长的负载上全程有效（0.69–0.93、5/5）；替换键等长的负载上 **25%–100% 落在噪声里**（0.98–1.02、方向 1–4/5），**只在 200% 才一致成立**（0.87–0.93、5/5）。
3. **C2 从不一致劣化**（24 格 ≤ 1.02）。**冻结决定不变，但 C2 的边界现在写清楚了。**

**"长期替换下空间趋稳"这个目标没有达到**，且**不在本轮四项改动的射程内**——它指向容量规划与组分布在长时间漂移后的失配，属于已列在候选清单的方向。

## 8. 已知但未做的候选

- **`Index::scan` 的循环条件里重复求值 `locate(start)`**：每扫描多 0.01–1.49 次外层搜索。**本轮测了、记录了、没有改**（阶段四按"一次只改一项"执行）。
- **替换路径**是当前最大缺口。它与压缩的关系已查清：替换下压缩仍跑 556–2,552 次，**垃圾只占复制量 0.3%–1.4%**——剩余的替换成本不在压缩里。
- **空间在长期替换下不趋稳**（见 §6a）：到 200% 周期时溢出条数接近活跃数，**C1 与 C2 相同**。**换组已实测，仅 0.016%–0.046%——分布漂移不是机制**；当前机制是"擦除只还槽位、不还字节，而压缩的触发条件要求某个子块同时有空槽与足够字节"，**尚待 F0–F3 对照确认**。
- **无 sanitizer**；**单线程**；并发、游标复用、反向扫描未测。
