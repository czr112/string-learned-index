# E36 结果：内联标签（B / O8 / T8）——把 tag 从记录里搬到有序条目旁边

日期：2026-09-21。目录：`validation_e25_20260918`（E35 之后）。平台：WSL2 Ubuntu 24.04 + g++ 13.3.0，单核绑定。

**审阅裁定（本轮开工时）**：保持冻结配置，先完成 E35 的三处统计口径修订（已做，见 `RESULTS_E35.md` §7），然后实施一次 B/O/T 内联标签对照。有界迁回再后移一轮。O1 仍不进入默认。

**审阅裁定（本轮收官时，2026-09-21）**：**T 保留为非默认候选，结束这一轮 O1 改造，下一步转向有界迁回。不再追加前缀、预取或专门针对 skew 的搜索方案。** 本报告 §3 按审阅给的措辞与表格重写，§6 记录下一轮的计划。

**一句话结论**：**把过滤标签放进有序条目，确实减少了线性路径对记录存储的访问，并在部分负载下改善了读写表现；但它没有解决二分路径的间接访问成本。** 这个结论足以收尾——**不需要继续追求所有数据集都获益**。**本节初版把 mixed 写成"追平 B"，现已撤回，见 §3。**

## 0. 命名与口径（本轮统一，避免与 E34 混用）

| 名称 | 内容 | 在本轮的角色 |
|---|---|---|
| **B** | E34 的 OFF 配置（冻结版本） | 原始基线 |
| **O4** | **E34 的 O**：`vector<uint32_t>`，**4 B 句柄条目** | **只在 E34 出现，本轮没有重跑它**；作为命名与历史参照 |
| **O8** | B ＋ `overflow_stable_store`，**8 B 条目**，**标签不参与提前过滤** | 本轮对照臂之一 |
| **T8** | O8 ＋ `overflow_inline_tag`，**8 B 条目**，**用内联标签提前过滤** | 本轮被测臂 |

**所以本轮的两条对照各自成立**：**`T8/O8` 隔离标签读取方式**（两臂同为 8 B 条目、同一容器实现，只差标签是否在访问记录前生效）；**`T8/B` 衡量完整方案**（从冻结版本到 T8 的全部变化）。**O4 的 4 B 条目不再参与任何比值**——它与 O8 的差别（条目变宽）在本轮**没有被单独隔离**，见 §4。

**边界（按审阅固定，逐条守住）**：Hybrid 阈值未改、无 SIMD、不缓存前缀、不动分配器；二分仍按**完整字符串**排序，**标签不用于确定字典序**；扫描仍读完整记录、**不按查询标签过滤**；原记录中的标签保留（记录布局未变）；插入、删除、空闲槽复用时标签与句柄**同一个结构体、同一个数组、同一处写入**；**首版没有为追求 5 B 而引入 packed 布局**。

**装置**：`bench_tag.cpp`（由 `bench_prefix.cpp` 派生）一个源两个目标——干净构建供时间、`-DE25_DIAG` 供计数；**四臂 {B, O8, T8, ART} × 4 重复**（四臂四重复让每个臂在每个位置上各出现一次，轮转平衡）；5 独立进程 × 3 数据集 × 2 模式。扫描由 `bench_scan_s4.cpp`（由 `bench_scan_s3.cpp` 派生）另测，四臂 {S2, S2O1, S2OT, ARR}。

**配对声音性（先断言再看比值）**：三臂在同一格上计时的是同一批键、返回的是同一批结果——`queue_hash` 与 `queue_acc` **2880 对比较，0 处不符**。

**四行的定义，逐条写死（免得再被读成别的量）**：

- **线性条目读取** ＝ `ov_tag_entries`，线性扫描看过的有序条目数，每条目一次。
- **线性路径记录读取** ＝ `ov_lin_recs`，**真正落到记录存储上的读**。O8 与三臂的 B 相等（标签只有读了记录才拿得到），T8 中只有标签通过的候选才计入。
- **二分路径记录读取** ＝ `ov_bin_cmps`，二分循环内每步读一次 `(*o)[mid]`。
- **二分后确认读取** ＝ 二分结束后 `lo < size` 时的那一次相等确认。**本轮没有单独计数**，用 `ov_queries_bin` 作**上界**；把同一个上界同时加在 O8 与 T8 的总数上，**只会让 T8 的相对优势显得更小**，所以这个口径对本节的结论是**保守的**。

**这张表就是审阅要的那句解释**：**标签机制有效，但 skew 的总查询仍然慢，原因全在第三列。**

- **B 与 O8 在四列上完全相同**——稳定记录存储没有改变任何一条记录的读取次数，它只改变了"读一次要几次加载"。
- **T8 把线性路径的记录读取压到 3.8%–7.7%（13×–26×）**，但**二分路径一列在 T8 与 O8 上逐位相同**（skew 49,230、百万域名 4,140／6,903）——**标签不能用于定序，所以二分那一段它一点也帮不上**。
- **于是合计的降幅分成两类**：二分占比 0% 的 mixed 降 **92.3%**，二分占 8.7%–14.6% 的百万域名降 **91.4%–93.3%**，而**二分占 94.7% 的 skew 只降 8.6%**。**skew 的读代价几乎全在二分路径上，T8 碰不到它。**

**另外两问（同一检查点、同一队列）：**

**有多少候选在访问记录存储前被标签拒绝**：mixed **92.3%／92.5%**、skew **94.0%／93.8%**、百万域名 **96.0%／96.2%**（分子 78,309／79,044／5,211／5,232／150,480／145,515，分母是上表的"线性条目读取"）。

**三臂看过的条目数完全相同**（mixed 13.80／13.91、skew 0.90／0.91、百万域名 25.50／24.63 条/溢出查询）——**候选集合没有变，变的只是从哪里读标签**。

## 3. 最终判定（按审阅给的措辞）

| 数据 | 当前结论 |
|---|---|
| **mixed** | **T8/B 为 1.019–1.038，观察到约 2%–4% 的额外耗时；是否可视为等效，取决于预先定义的容忍范围与 A/A 波动。本轮不把它写成"追平"。** |
| **百万域名** | 本轮点查 T8/B 为 **0.924–0.946**，且 **5/5 同向**，支持该负载下的优势 |
| **skew** | T8/B 为 **1.181–1.266**，**读路径回归仍明确存在** |
| **维护** | 本轮汇总比值支持维护优势保留（T8/O8 六格 ≤1；T8/B 六格 0.863–0.980）；**逐格方向计数已在上表每一行附上** |
| **默认配置** | **保持不变** |

> **「差异没有显著超过噪声」与「已证明性能等效」不是一回事。** mixed 的结果可以接受为**候选边界**，不必为了归入停止条件 ① 而写成完全恢复。**本节初版写的"mixed 追平 B"撤回。**

**本轮的收尾表述（审阅给定）**：

> **内联标签恢复了稳定记录存储在线性过滤路径上的部分性能，并保留了已测维护收益；二分占主导的负载仍存在读代价，因此保留为场景候选，不进入默认。后续转向降低溢出记录数量，而不继续扩展该容器的读路径补丁。**

**T8 与 O8 都保持非默认；冻结的五个开关、构建路径、模型与主块预算均未改动。**

## 4. 把两句话收紧（审阅指出）

### 4.1 "标签的边际代价为零"

**原写法**：内联标签的边际代价是零。

**问题**：`T8/O8` 在空间与搬动上逐位相同**是真的**（`sizeof(OrderedEntry)==8`，`uint32_t` ＋ `uint8_t` 补齐到 8，**标签住进了那 3 字节填充里**），但那句话**把"相对 O8 的边际"说成了"这套布局的代价"**。

**改成**：

> **相对 O8，启用标签过滤没有增加条目存储字节；相对 O4，完整 T8 布局仍承担条目变宽的空间与搬移代价。**

**后一半有独立测量**：差分门 `check_overflow_store` 在同一配置上给出 **+51,072 字节**（mixed、131,072 键、200%），即 **4 B × 约 12,768 个条目**，`arm_a_memory` 25,467,239 → `arm_b_memory` 25,470,607，而 `handle_moves_total` 528,988、`record_moves_total` 0、比对条数 553,027 **全部不变**；`O8/B` 的常驻空间在 mixed 上是 **1.001–1.010**。

### 4.2 "变宽在时间上低于分辨力"

**原写法**：这个变宽的代价在维护时间上低于本测量的分辨力……与 E34 的 `O/B` 逐格接近。

**问题**：**跨轮接近不足以支持这句**——两轮的二进制不同、平台会话不同，用"和 E34 差不多"去论证"变宽在时间上不可见"是拿另一个实验的结果替本轮没做的实验说话。

**改成**（并撤回归因）：

> **本轮未单独隔离 O4→O8 的时间影响。**

**不为此另跑第四臂**——审阅明确说"不必为补齐这句话另跑第四臂，撤回归因即可"。**条目变宽在时间上值多少，本轮没有测量，本报告不宣称。**

## 5. 正确性门：`check_tag_store`（三数据集全 pass）

按审阅列的五项逐条落地，**每一项都是断言而不是说明**：

| 审阅要检查的 | 门怎么回答 | 实测 |
|---|---|---|
| **标签碰撞后仍完整判等** | 大规模**缺席键**查询必须全部返回 `found == false`——tag 匹配落到完整比较上，假阳性会在这里现形 | 三数据集各 **40,960** 次缺席查询，**全部为 false** |
| **删除、重插、空闲槽复用后没有旧标签残留** | `Region::diag_tag_pairing` 逐条比较**每个有序条目的标签副本与它所指向记录里的标签**，任何不符即失败；操作序列专门制造删除、重插与槽位复用 | 配对检查 **27,532 / 38,932 / 244,716** 条，**0 处不符** |
| **句柄与标签始终成对** | 同一次遍历（两者本就在同一个结构体、同一个数组里，这条是**被验证的不变量**而不是被追的 bug） | 同上 |
| **点查、更新判重、任意起点扫描与参考表一致** | 三臂各自对**独立的 `std::map` 参考**作答，再**互相比对**（含 `Result::source`——开关不得把键在主块与溢出之间挪动） | mixed **389,120** 次点查、skew 389,120、百万域名 **2,826,240**；扫描 **5,120** 次、逐条比对 **245,760** 条记录 |
| **三臂键值内容与溢出记录数一致** | 每批之后比较 `overflow_count()`，扫描输出逐条比 | 溢出计数 **B ＝ O8 ＝ T8**（mixed/skew 2,476／4,285，百万域名 22,772） |

**门的非空性**（否则"没有旧标签"只是"没有执行到那段"）：断言 `ov_tag_entries > 0`、**`ov_tag_reject_pre > 0`**、`ov_linear_recs > 0`——**标签路径真的跑过**，且真的有候选被拒后才走到完整比较。

**`sizeof(OrderedEntry)` 由门报告，不作假设**：**8**（`uint32_t` ＋ `uint8_t` 补齐；不是设想的 5）。

## 6. 收尾与下一轮（E37）：有界迁回（审阅给定，尚未执行）

**决定**：**结束这一轮 O1 改造，下一步转向有界迁回。不再追加前缀、预取或专门针对 skew 的搜索方案。**

**实验底座固定为**：

> **E31 子块整理 ＋ 原有溢出容器。**

这是迁回实验的基线配置，**不改变冻结默认值**；**先不叠加 T8**，避免把容器变化和迁回效果混在一起。

**第一步：可行性诊断（先做，不先做两臂）。**

> **E31 能让新插入成功，不自动证明旧溢出也能迁回**——旧记录的键范围与长度可能不同，所以这一步仍然必要。

用**已有状态**检查真实机会：

- 子块整理后，有多少**已经在溢出区的记录**满足该块的**键范围、空槽与字节**条件？
- 能迁回多少条、多少字节？
- 从溢出容器删除它们，需要**移动多少条目**？

**机会足够时**，才做两臂：

| 变体 | 配置 |
|---|---|
| **R0** | 固定底座，不迁回 |
| **R1** | 同一底座，仅开启迁回 |

**R0／R1 只是本实验的臂名**；**代码里要用明确的迁回名称**，避免与既有的构建优化 **R1** 混淆。

**验收同时看**：迁回量、完整维护耗时、查询、扫描、常驻空间**及峰值**。并把两种实验分开记录：

- **从初始状态运行**：能否**防止**溢出积累？
- **修复已退化快照**：能否以合理成本**恢复**已有布局？

**一条必须写进下一轮的口径**：

> **「每次最多迁回 K 条」不等于维护时间有界。** 原溢出向量即使只删除一条，也可能移动很长的尾部。**工作预算至少要覆盖候选检查、后缀复制和溢出删除的搬移**；**如果只限制候选或成功条数，就如实称为「迁回条数受限」，不要承诺单次维护成本有界。**
