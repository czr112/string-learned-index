## 0. 先纠正一句话：运行中的代码**有**预测模块

此前"我负责的部分没有模型"这个说法不准确。准确的说法是：

- **模型的训练与选型不在本课题的职责内**（属于模型负责人）；
- **但索引内部一直运行着一个表驱动的参考模型**，构建时现场训练、查询时现场预测，索引靠它的输出决定记录落在哪个逻辑组。

所以"原型 vs ART"从来不是"无模型 vs 有模型"，而是"**参考模型 + 本索引结构** vs ART"。方案 §1.1 在 E3 历史源码上核实的结论，在**当前冻结版本上同样成立且更完整**——本文件用当前源码的具体位置、配置与一次真实运行给出。

## 1. 模型是什么（当前源码）

| 项 | 内容 | 位置 |
|---|---|---|
| 种类枚举 | `ModelKind { Context16, Position16, Unigram }` | `index.hpp:588` |
| 实际启用 | `Context16`（`Config` 默认值与 `baseline_config()` 都显式写死） | `index.hpp:605`、`switches.hpp:33` |
| 模型类 | `class Model`：**量化概率上的整数区间运算**。位置标度 `Q = 2^47`、概率质量 `MASS = 2^16`、**16 个上下文行** | `index.hpp:770` 起 |
| 累计表 | `using Table = std::vector<std::array<std::uint32_t, 258>>`（258 = 256 字节 + 2 个哨兵） | 同上 |

| 训练 | `Model::train(first, last, prefix, kind)`，由区域构建调用：`model_.train(sorted, prefix_.size(), config_.model_kind)` | `index.hpp:2036` |
| 预测 | `Model::predict<Hash>(s, groups, route, fp)` → 返回 `{group, …}`，把区间映射到**逻辑组号** | `canonical_group` |
| 映射入口 | `Region::canonical_group(s)` = `model_.predict<false>(s, groups_, config_.canonical, dummy).group` | `index.hpp:1450` |

**三点必须一起说清：**
1. **它是训练出来的，不是空接口**：`bulk_load` 对**每个区域**的**已排序键**、**去掉该区域公共前缀之后的后缀**做统计，生成累计表。输入是真实数据，不是常量表。
2. **它只输出逻辑组号**，不输出物理地址。物理地址由组几何（`sg_`／`bb_`／`off_`）与子块枚举决定。
3. **它与模型负责人要交付的"差异化后缀模型"不是同一个东西**。本索引从未集成后者（任务书 §13 列为尚待实施）。**因此本项目所有数字都是"参考模型下"的条件结果，换模型必须重测**——尤其 E28–E32 那条空间线，它的结论建立在"预测质量决定的组内字节分布"之上。

**结论（对方案 §1.3 的回应，已按 §3.1 更正）**：模型与映射都是**表驱动、按区域训练、输出逻辑组号**。**但「换模型很简单」这个推论不成立**：扫描的正确性**依赖** `canonical_group` 在同一区域内随键序单调不减，而这条性质**没有任何断言在守着**。所以接入新模型的契约里必须写明**保序性**（或有门验证它），否则扫描会静默返回错序或漏键的结果——**门不会失败，因为没有门在看这件事**。换模型同样影响训练成本、模型内存与预测耗时，不只是组内字节分布。

### 3.1 扫描的正确性依赖映射保序——这条依赖此前没有被任何门看着

**依赖在哪**：`Region::scan` 的遍历顺序是**组号升序**（`for (g = first; g < groups_; ++g)`），
组内才做子块与溢出的有序归并。它还有一处起点推进（跳过所有小于 start 的条目）建立在
「组号更小则键更小」之上。外层 `Index::scan` 同样按**区域序**推进。

**失效的样子**（反例，键 → 组号）：

| 键 | 组号 |
|---|---:|
| a | 0 |
| b | 1 |
| c | 0 |
| d | 1 |

组内各自有序（组 0 是 `a,c`，组 1 是 `b,d`），但按组升序扫出来是 **`a,c,b,d`**——
**既错序，又会在 `count` 用尽时漏掉键**（从 `a` 起取 2 条会得到 `a,c`，`b` 永不返回）。
M1 管不到这里：它的范围是**一个组内部**的子块（`index.hpp:1656` 的原话是 a group's sub-blocks），
边界目录也只是组内边界。

**这条性质从哪来、由谁守着**：

- **来源**：模型是条件累计分布上的区间运算。**如果**每行的累计表都是规整的 CDF，那么「键更大则预测排名不小于」
  是**结构性**成立的（单调函数的取整与限幅仍单调），组号由排名映射而来，于是保序。第一轮在 Python 模型上做过
  「整数递推的单调性检查」（研究报告 §14.10，1365 个字节串）——**那是历史原型，不是当前 C++ 代码**。
- **守护**：**当前代码里没有任何断言，也没有任何一个门检查它**。此前的扫描门 `check_scan` 用的是真实模型，
  它在真实数据上恰好保序，所以门通过——**但通过的理由不是门在检查保序**。换模型、改 `derive_groups`、
  改量化或限幅，都可能让扫描静默出错而**所有门仍然通过**。

**本轮补的验收**（按审阅要求）：新增 `check_scan_contract`——

1. 真实冻结配置上**逐相邻键对**检查区域内保序（全量，报检查对数与违例数）；
2. 全量扫描与参考表逐条比对；任意起点 + `count = 1/2/16` 的截断比对；
3. 删除首末与中间记录、清空中间子块、制造溢出之后重做上述比对；
4. **负对照**：用诊断构建里的旋转映射（`(g + 1) % groups_`，确定、在范围内、故意非保序）再建一个索引，
   **要求它的扫描确实出现错序或漏键**——否则说明注入没生效、上面三项检查是空的。

**2026-09-20 实测（`check_scan_contract`，三个数据集，日志 `logs/check_scan_contract_*.log`）：**

| 数据 | 相邻键对（全量） | **保序违例** | 每键可查到 | 起点的键 × count=1/2/16 | 逐条比对记录数 |
|---|---:|---:|---:|---:|---:|
| 混合字符串 | 131,008 | **0** | 131,072 / 131,072 | 7,488 × 3 | 537,673 |
| 重复前缀 | 131,008 | **0** | 131,072 / 131,072 | 1,500 × 3 | 423,599 |
| 百万域名 | 262,016 | **0** | 262,144 / 262,144 | 10,386 × 3 | 985,871 |

（每个数据集都在三个检查点上做：初始、删除首末与中间记录并清空 3 个中间子块之后、制造溢出之后。**全部与独立参考表逐条一致**。）

**负对照生效**：把映射换成旋转（`(g + 1) % groups_`，确定、在范围内、故意非保序）之后，
全量扫描**不再升序**、**不再返回同一多重集**，起点探针 **14–35 处不匹配**、删除后的扫描 **90–145 处漏键**——
**这条依赖是真的会致命**，不是纸面推演。同时 `hook_off_identity` 通过：钩子关掉时结构与扫描输出**逐条相同**
（13.0 万–26.0 万条子块键、1,261–3,708 条目录项、48 个起点探针）。

**结论（三条，分开说）**：
1. **依赖存在且致命**（负对照证明）；
2. **现行参考模型满足它**（全量 0 违例），所以今天**没有观察到扫描错误**；
3. **它此前不受任何门保护**，现在由 `check_scan_contract` 守着——换模型、改 `derive_groups`、改量化或限幅时，这个门会先失败。

**对「接入新模型」的接口含义**：契约里必须写明**保序性**（或有门验证），而不只是「返回 `[0, groups)` 内的组号」。

## 4. 边界与未决

1. **本文件只描述冻结版本**（五个开关默认全开 + R1）。其它开关的配置差异见 `switches.hpp` 的四张表与各轮报告。
2. **不声称本模型与 LITS 或任何论文模型等价**。它是同一族（条件概率 + 区间运算 + 早停思想）的**参考实现**，这一点在任务书 §1.3 里被明确允许（"可以先使用参考模型开发和隔离测试布局"）。
3. **没有测量预测质量**：本项目从未报告误预测分布或组间不均衡度。E8 做"按组需求重分配容量"（溢出降 21.9%–62.1%）本身说明各组需求不均，但**不均里有多少该算模型的账、多少算布局的账，没有拆开**。
4. **"接入差异化后缀模型"未做**，接口契约（方案 §8.1 的 `MappingContract` / `PredictorAdapter`）尚未起草。若要接入，受影响的至少包括：组数（`derive_groups`）、区域前缀、`canonical_group` 的返回域，以及**所有已发布数字的条件前提**。
5. **`group_of()` 是本轮新加的只读访问器**（`index.hpp`，紧邻 `slot_table`／`boundary_dir` 等既有只读暴露），加它是为了让诊断**检查**映射而不是"读代码推断"。它是加法，不改变任何既有行为。
