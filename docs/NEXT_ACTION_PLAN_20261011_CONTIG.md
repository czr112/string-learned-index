## 1. 假说与唯一改动

当前点查的标签筛选逐个子块进行：每进一个子块都要先读它 64 B 的 `Header`（`count` 与偏移 16 起的
`tags[48]`，`tags` 起点 16 B 对齐），然后按 16 槽一批做 SIMD 比较。一个组若有多块，
筛选就要跨多个 64 B 头部行。

假说：把「真实 count + 按原顺序的 8 位标签」连续复制成**每组一块的连续面板**，
可以让筛选只读一个紧凑区间，减少筛选元数据要跨的逻辑 64 B 行数。

首版固定（不试宽度、不改语义）：每块一条 32 B 面板记录，`[0,16)` 放 `count` 与保留位、
`[16,32)` 放 16 个标签；**标签起点 16 B 对齐**；16 槽面板固定 32 B。
面板只把标签与有效范围放热；完整描述符（Entry 数组）与后缀仍留在原块。
空块、最后半批、早命中一律沿用原路径的规则。模型、CRC/指纹、8 位标签、槽数、块预算、
记录次序、溢出策略、`Mode` 全部不变。

## 2. 一次六格入口（计数构建，无计时）

六格：mixed / skew / tranco × Context16 / LITS；`baseline_config(128)` + `pin_frozen_switches`，
C 开、W/S/H 关；普通 `bulk_load`；matrix2 原 rows/queries；标准查询模式（`locate=off`）。

**指标定义（开跑前固定，地址代理，不是实测 cache miss）**

- 一次查询的**原筛选元数据行**：块循环里访问过的每个子块，其 64 B 头部的逻辑行（`Header` 64 B 对齐，
  `tags` 在偏移 16）；同一行重复访问只计一次。
- **面板行**：同一次查询访问到的那些块，其 32 B 面板记录（真实分配地址）覆盖的不同 64 B 行数。
- **冷块位置**：标签筛选幸存、因而需要进入条目/后缀比较的块；报告其个数与不同行数。
- **溢出锚点**：查询进入溢出检索时读的块 0 头部（`overflow_pointer` 所在行），单独报告，
  绝不并入原行数。
- **查询加权减少率** = 1 − Σ面板行 / Σ原行（每条查询等权）。

**目标格 Context16/mixed 必须同时满足**

1. 原筛选元数据行 >4 的查询占比 ≥60%；
2. 查询加权减少率 ≥40%；
3. 全部新增常驻记账（面板容量 + 归属对象）≤5%；
4. 差分全等：逐查询模拟的筛选计数与生产 `Result` 逐项相等；全部语料键与原查询答案与
   interchange oracle 全等；（块序 + 槽序）候选序列在「由面板标签」与「由后缀重算标签」
   两条独立路径上逐项相等。

不满足即停，不改面板宽度/步长/目标格挽救；满足也只支持一个静态原型（下一步），
不授权默认值或集成本身。

## 3. 入口必须证明的实现前提

- 面板标签的语义：生产路径的查询标签等于 `Fingerprint::of(后缀)`；面板复制的是同一函数。
  入口按「全部语料键都能被生产路径命中」+「逐查询筛选计数与模拟全等」两道行为检查来验证这条前提，
  而不是靠注释声明。
- 分组：查询路径的组号由模型给出；入口用 `diag_group`（Route::Full）取组，并由逐查询计数全等
  （`subblocks_visited`/`simd_batches`/`tag_candidates`/`candidate_blocks`/`str_cmps_primary`）
  反向确认两条路走的是同一个组。
- 面板地址真实：面板按组连续、每记录 32 B、起点 16 B 对齐地真实分配，行数按真实地址统计。
