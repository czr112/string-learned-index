# B阶段：物理块定位契约 v0

状态：内部设计定义已落盘，存储/模型接缝实现尚未开始。它不改变现有v1外部接口、S3源码或默认配置。
依据：长期路线B阶段；A阶段结果见`07_Eval_Integration/RESULTS_INTEGRATION_ATTRIBUTION_20261018.md`。

## 1. 参与者与责任

| 部件 | 输入与输出 | 责任 |
|---|---|---|
| 存储层 | 有序唯一完整键、自有前缀和后缀、实际块fence | 定义物理块身份，持有键值，提供字节序比较、标签与扫描游标 |
| 范围导航 | 完整键→所属区域范围 | 包含首尾/缺席/前缀键，不借评测输入fence |
| 编码层 | 已验证区域前缀后的后缀→保序坐标 | 明确EOS/NUL/高位字节及碰撞，不把截断相等当键相等 |
| 模型 | 块fence样本→位置hint/预测范围 | 预测单位为区域内实际物理块号，不返回值或最终命中 |
| 纠错层 | 模型hint、证据与完整fence→可用范围 | 检查界限与覆盖，无法证明时退到安全父范围或精确目录 |
| 查询层 | 已认证范围→真实条目 | 标签仅作过滤，命中须完整键比较 |

精确目录是同布局的独立定位策略，不要求先执行模型。

## 2. 范围和状态

最小定位结果含：区域ID、区域内半开块区间`[begin,end)`、前缀验证状态，以及空集/点查前缀拒绝/候选窗口/精确前驱块状态。
实现时采用能区分这些状态的类型，避免空索引被默认`[0,1)`冒充。只读索引拥有并稳定保存其解释所需的元数据。

- 有效区间满足`begin < end <= region.block_count`，转为全局地址需验证基址加法不溢出。
- S3使用闭区间`[lo,hi]`；新接缝转换为`[lo,hi+1)`，只在边界处转换一次，不混用含义。
- 当前定位定义保证范围包含“完整字节fence的前驱块”（首端夹到0），所以命中键所在块必在范围内。
- 缺席键也必须覆盖这个前驱；仅在训练键上测试最大误差不够。
- 此定义不保证范围内存在第一个`key >= q`：该键可能在后一块。scan必须精确seek并向邻块/邻区域推进。
- 前缀拒绝可证明点查缺席，不能直接使scan返回空。scan起点可能位于本区域之前或区域间隙。

模型/编码/布局身份属于构建元数据。不可变查询不重复计算哈希；未来动态发布的页版本决定模型与块范围是否同一代。

## 3. 模型接入规则

1. 首批实现只接当前分段预测与完整字节目录；布局、区域划分、16槽和CRC保持不变。
2. 模型训练数据是实际物理块fence，标签是块号。队友算法若预测样本排名，fence序列排名即可对应块号，避免额外逻辑组映射。
3. 区域前缀、编码版本、原算法版本、拟合参数、目标单位分别登记。模型保留的任何引用必须由索引稳定拥有。
4. 模型的数值hint不是证书。单调模型和保序坐标可结合等值族、间隙端点构造界；其他模型先使用可验证扩大搜索。
5. 输入超出模型可证明的域时使用明示回退。模型初始化/重建失败不发布半成品。
6. 首轮不搜索模型参数，不改队友算法；相同布局、完整查询及同一纠错规则下再比较算法收益。

## 4. 首个接缝的实现与验收顺序

1. 保留S3旧文件；新版本只提取“范围定位”和“范围内验证”接缝，不同时重写arena、训练器和扫描器。
2. 精确目录先返回单块前驱范围，独立全键有序参考复核区域、块身份及首尾夹取。
3. 当前模型返回保守范围，经同一验证入口查值；对每个探针与完整目录比较覆盖关系。
4. 在类型边界检查空、非法范围、重复bulk_load、失败构建及输入释放后的有效性。
5. 全量语料键/冻结请求及二进制域门，包括空键、EOS、NUL、80/ff、共享前缀、长键、块/区域边界和缺席间隙；新增接缝做ASan/UBSan。
6. scan对独立lower_bound参考逐行比较，含前缀拒绝、刚好落在块间隙、limit=0/大limit及结果跨析构。
7. 无行为差分才做小范围无新优化的A/B，观察接缝是否引入额外工作；未分辨不解释为零成本。

交付是两个可互换的定位实现、一个共同验证入口和可复现验收。B本身不宣称新加速；后续C/D各自只有一个结构候选。
