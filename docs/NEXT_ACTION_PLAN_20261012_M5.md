## 5. M5.2：参数冻结后的三份留出查询

先 tranco 与 mixed，再按采用需要覆盖 skew；不建立全命中率、全状态、全分布矩阵。
静态外部查询每队列固定 100,000 次，所有臂读同一份 `rows.bin` / `queries.bin`。

| 队列 | 固定规则 | 回答的问题 |
|---|---|---|
| 新均匀流 | 90% 命中、10% 缺席；种子 2026101201 | 原有短键导航收益是否延续到新请求 |
| 边界缺席流 | 100% 缺席；种子 2026101202；覆盖区域及组阈值附近、前缀结束、首尾边界 | 完整回退和边界比较是否引入成本或错误 |
| 热点流 | 90% 命中；80% 命中请求落在固定随机选择的 1% 存量键；种子 2026101203 | 更集中访问下是否仍值得开候选 |

边界池根据所有参与臂的边界并集生成，独立参考逐条核实确实缺席及邻近区间。
四方池保持共同支持域；不可构造的区间如实记录覆盖缺口，不用普通随机 miss 冒充。
记录生成规则、实际命中数、边界覆盖数、键长分布及队列哈希；不看时间后重选种子、热点或边界。
这是新查询验证，仍使用既有数据集，不宣称通过了新语料泛化。

复用现有 interchange 写入与 C++ runner 的 `--rows/--queries`；Python 主入口当前只生成均匀流，
本轮用一个小调度脚本直接重放冻结输入，无需改变统一接口或 runner 的计时语义。

## 6. M5.3：有限静态读与双外部基线

首轮四臂固定为 `release / read_compact / ART / HOT`，tranco 为 C 的主格，mixed 为风险格。
两语料各三队列；有主收益且风险未失败，再补 skew 风险。目录只有内部场景验收通过后，
才在 skew 用 `release / directory_skew / ART / HOT` 做独立四臂对照。

测量安排：

1. WSL、同一编译器，全部 C/C++ 目标及 runner 统一 `-O3 -march=x86-64-v3`，
   核查实际编译命令；HOT 的 AVX2/BMI2 需求不能仅由适配器自己的编译参数满足。
2. 固定逻辑核，5 个串行独立测量块 × 4 个位置轮转重复。每重复顺序轮转四臂；
   每次 runner 用 `--repeats=1`，以调度层的重复编号形成配对。
   原入口的“单臂内部重复多次”不能代替这一安排。
3. 采用格使用真实同配置复本检查 A/A：参考与候选分别独立实例，位置轮转；
   复本只增加测量标签，不改变配置。每进程先取配对比值中位数，再汇总 5 个进程。
4. 主指标为完整 `find` 序列耗时，吞吐由同一次耗时换算。HOT 的复制与终止符计入，
   我方的适配包装同样计入。不把内部 v2 的绝对值与外部 v3 拼接。
5. 本轮关闭单次延迟采样（`latency_samples=0`），保留未测状态；不以独立实例 P50/P99 为排名。
   构建耗时、索引记账、保留输入分项报告；ART/HOT 未提供空间则维持 unavailable。
6. 对预期记录全集、缺臂、重复、有效配置、源码/产物身份、队列哈希和结果校验作硬拒绝。
   计时外逐条答案验证为必要条件；checksum 相同仅为辅助。

判定提前固定：令每进程比值为同重复配对后的中位数；F 为同格所有 A/A 进程比值及其倒数的最大值。
候选主目标须同时满足总体中位比值 ≤0.90、至少 4/5 进程更快、收益倍率大于 F。
风险判失败须同时满足总体比值 >1.05、至少 4/5 更慢、慢倍率大于 F。
其它情形记未分辨；F 是观察到的复本波动范围，不是置信区间。

主目标失败或风险明确失败即停止相应扩面；高噪声导致未分辨也收口，不增加重复挽救。
与 ART/HOT 的比值直接由同批原始记录计算，不由旧比值推算。

## 7. M5.4：更新配置与 S 的采用边界

内部更新复用 `bench_combo` 的有效容量计划与逐键交错 erase→insert 日程；活跃键数保持 N。
Context16/same/mixed，N=131,072，为维护/点查主格；Context16/grow/tranco，N=262,144，为扫描风险格。
检查点固定 0%、25%、100%、200%；使用原阈值及原计划，内部统一原 WSL v2 工具链。

1. 四臂 B/W/C/WC 在当前身份上复验。新点查队列以各检查点独立参考生成并冻结，
   验证相同存活键和值，计维护、命中/缺席、空间和扫描16/256/4096。
2. S 的采用主目标固定 **Context16/same/mixed@200% 的完整 scan16**；
   按种子 2026101204 预生成 64 个新起点并冻结，5 进程 × 4 平衡重复，B/S 配对。
   原 17 起点仅保留为状态/机制复现控制，不代替留出队列。
3. 风险保留 mixed@25% 的首批扫描、scan256/4096，以及 grow/tranco@100%/200%。
   边界和空返回用于正确性门；采用计时起点池记录实际返回行数和键字节，完整结果物化与释放计入。
4. 首遍、第一批总耗时和后续遍历分开输出。任何一次停顿保留原值，不能删掉后用稳态均值宣布修复。
5. 只有 S 在 Context16 主目标通过，才做 WC/WCS 的一轮增量组合验收。
   S 相对 WC 的收益与 WCS 相对 B 的扫描风险分别判定，不能彼此抵消。

增量收益沿用 §6 的 ≤0.90、4/5 和真实 A/A 判据；构建/常驻新增分别不超过 10%/5%。
W 的已知扫描取舍限制它的采用类别，即使维护与点查大幅变快，也不能进入通用默认。
若 CWS 不能改善需要的扫描格，保留 WC 的“更新与点查优先”用途，不继续调整归并规则。

`directory_skew` 只做 C16/DDirT 的既定静态与更新后新查询对照，使用各自合法计划及原目录更新日程；
该日程与上述交错替换分开标记。其新统一静态外部阈值为128，与历史 skew 阈值不混称同配置。
不追加 C/W/S、M3 或模型参数搜索。已明确失败的 tranco 通用目标无需重跑来挽救目录。

## 9. M5 之后的结构研发方向

下一轮优先讨论**逻辑组到物理主块的整体组织**：Context16 的静态命中仍访问约
11.31/16.86/2.68 个子块（mixed/skew/tranco，P1 口径），而目录虽降到约1块，却支付额外二分。
这支持更大粒度的布局问题，尚未支持某一种新实现。

M5 完成后只提出一页新候选设计，必须同时写明：具体省去的查询操作、查询加权覆盖率、
新增搜索/同步/空间成本、动态更新与扫描契约、独立入口及停止门槛。
只合并几张表、换摘要宽度、再添边界搜索或缩短 M4 的失败段规则，不能作为新机制依据。
没有这样的证据就结束这条研发预算，把映射集中、主块长尾与查询成本账本交给模型协作设计使用。
有新上游模型交付时，另按接口与正确性 → 同输入结构入口 → 有限 A/B 接入，不重新优化 LITS。
