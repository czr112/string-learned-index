# 基于最新 BM 的长期优化计划

日期：2026-10-18。主对象是用户提供的 BM 模型，benchmark 负责数据接入、负载和公平评测。
本计划接替旧 A–G 路线的当前执行顺序；已经完成的正确性、物理页和维护工作不重做。
工期按单人串行推进估计，约 6–8 个开发周，属于预算，按阶段结果调整。

## 1. 最新证据与当前判断

当前固定 benchmark `003a55bf`、模型 `e8e05411`，见[上游核对](../07_Eval_Integration/UPSTREAM_UPDATE_20261018.md)。

| 对象 | 已完成的证据 | 结论及边界 |
| --- | --- | --- |
| 原 BM + 本项目物理页 | 普通/ASan各13,152,655项，接口各99/99，旧三数据六格3000行计时复核 | 已实际使用原模型，不是自研模型换名 |
| 窗口内完整 fence 纠正 | skew约少22%耗时，mixed未分辨，tranco更新后多19% | 整体策略不采用，原失败永久保留 |
| 同轮自研F5与ART对照 | BM/F5=1.234–1.561；BM/ART=1.079–2.088 | 模型接入正确不等于接入方式有效；通用ART目标未过 |
| 同布局完整目录 | 窗口纠正版与目录六格未分辨；原BM路径在若干真实格有清晰收益 | 要关闭额外纠正机制，不能据此否定模型本身的作用 |
| 局部写槽与换页 | 已有强异常安全、稳定fence、dirty维护、最多两相邻源页及2049行的检查 | 功能基础可复用，真实动态吞吐和完整分配峰值仍缺 |
| 预测前驱括号 | 主格完整fence比较1.118倍，入口已关闭，未计时 | 不重复该候选；payload预测块探测是另一机制，不能混名 |
| 短目录场景消融 | 页内查值tranco/current=0.611、mixed=0.874；skew不适用 | 原结构门失败，根路由在计时外，完整读与完整空间门仍缺 |
| 上游完整BlockLearn最新配置 | 当前物理页只链接原BlockModel；新短目录/预测块优先/cost/adaptive尚未同轮测试 | 必须先补原生完整工厂参照，不能把当前接入的失败等同完整模型失败 |

原证据：[BM首轮结果](../07_Eval_Integration/RESULTS_BM_LATEST_20261018.md)。
本次[真实数据结果](../07_Eval_Integration/RESULTS_BM_REAL_20261018.md)已完成：每类65,536键，
普通/ASan动态语义各6,634,925项、完整读预检各10,817,354项，3000行独立复核通过。

| 真实键类型 | 原BM路径/ART，两态 | 窗口纠正/原BM，两态 | 当前优先处理 |
| --- | ---: | ---: | --- |
| 英文词表 | 1.478–1.496 | 1.164–1.168 | 短键固定路径和验证工作是主要风险 |
| MemeTracker URL | 1.062–1.069（未超AA） | 1.102–1.166 | 保留原路径已接近ART的数值表现，禁止纠正引入倒退 |
| MemeTracker 短语 | 1.114–1.118 | 1.098–1.138 | 检查长尾及前缀下的净定位成本 |

原BM路径对ART是同轮raw的运行后补充直接配对，未相乘中位数、未重跑性能；
它不改变原采用门。窗口纠正在真实数据六格均数值更慢，其中四格形成清晰回归，必须冻结这版通用策略。
因此阶段1优先于新候选编码；短目录是已有证据的候选，先补正式集成口径与完整读门，
不再把已关闭的预测前驱括号列为下一项。其他预测块探测只有完整上游消融/真实工作量支持时才进入。

另见[最新结果口径核对](../07_Eval_Integration/AUDIT_BM_PROGRESS_20261018.md)：短目录现有空间摘要只列codes，
还需统计fence视图、计数副本及prefix容量；完整fence比较还应包含目录/回退步数。
页内查值收益不等于全索引加速。当前`max_error`只改认证标志，调小不会让裸BM拟合窗口收紧。

研究判断：保留“有序物理叶页、原BM预测、精确纠错、局部维护”主线。
近期优先级从继续叠结构机制，改为 **真实数据验证 → 上游完整实现对照 → 减少必要查询步骤 → 静态收口 → 动态成本**。
若长期只能形成空间或特定场景优势，就明确发布这种结果，不无限追求所有场景超过ART。

## 2. 目标、命名与能力边界

必须区分以下实现，报告、配置和源码身份保持一一对应：

| 名称 | 实际含义 | 用途 |
| --- | --- | --- |
| BM-page-base | 上游BlockModel + 本项目物理页，安全的窗口扫描路径 | 当前接入基线 |
| BM-page-window | 同一BM物理页，窗口内精确fence纠正 | 已失败的通用候选，保留作控制 |
| BM-page-next | 今后通过单机制验收的新接入 | 主要研究对象，每轮明确差分 |
| BlockLearn-native | 上游完整工厂，使用其目录、标签、规划和增量组织 | 检查提供模型的原生能力及复用价值 |
| F5 | 冻结自研模型 + 同类物理页与维护 | 内部控制，不冒充BM或Context16 |
| ART / HOT / Context16 | 各自真实工厂与支持能力 | 外部及兼容动态对照；HOT当前失败单列 |

允许按构建数据特征选择BM或精确纠错，不能按语料名、文件路径、已知查询答案选择。
披露模型调用比例、直接目录比例和回退比例；若某配置几乎绕过BM，按真实结构命名，不能把目录收益归功BM。
不开展LITS定向优化，不把当前任务转回自研预测器。生产默认当前仍为Context16。

最终目标分三层，以下均是未来验收条件：

1. **精确语义**：任意字节、空/NUL/高位字节、前缀关系、缺席、0/MAX值、owning scan、更新失败回滚零失配。
2. **通用静态读**：冻结必测格每格完整find耗时/ART<=1.10，且无清晰>5%风险回归；
   进阶目标是在至少两类真实键上<=1.00，并超过双方AA观测带。不能只用均值或一个skew格满足目标。
3. **可用动态配置**：相同当前map下，相对本版本重建只读快照的点查开销<=15%；
   重建工作随变更页增长，根全量复制不被藏到计时外；支持能力、吞吐、扫描及峰值同时披露。

候选的预算默认沿用：新增模型元数据<=基线常驻5%，总常驻增幅<=10%，构建耗时增幅<=20%。
完整堆测量后，空间路线以低于ART为必要条件、<=ART的70%为目标；这是目标，不是现有BM成绩。
若速度目标未过但空间/维护优势稳定，只保留明确场景配置，整体默认采用资格单列判断。

## 3. 数据与实验分层

### 当前真实补测

benchmark原数据准备脚本和锁文件，seed=42，各65,536个唯一键，完整源文件扫描后哈希抽样：

| 键类型 | 原始来源 | 已观察形态 |
| --- | --- | --- |
| english_words | 固定版本英文词表 | 长度中位9B，p95 15B；相邻LCP中位4B |
| memetracker_urls | MemeTracker phrase-cluster 的URL字段 | 长度中位75B，p95 137B；LCP中位32B，含高位字节 |
| memetracker_phrases | 同一MemeTracker原文的短语字段 | 长度中位48B，p95 253B，最大3729B；LCP中位9B |

这是**两份原文、三类键**；URL与短语不能算两个独立来源。原字节、来源哈希、过滤数量和抽样规则都保留。
真实键配合成查询，不代表真实访问日志。65k结果不外推百万级。

### 日常筛选、确认与最终验证

- 日常筛选固定短词、长前缀URL、长尾短语三个真实键类型，加旧tranco/skew风险格；
  先看工作入口，只有一个机制通过才进入完整计时，避免每个想法都扩全矩阵。
- 确认集在候选冻结后另取预登记样本或另一独立来源。不同seed样本可能重叠，不能称为无交集数据；
  若需严格隔离策略开发与验证键，先对原始唯一键做固定哈希分区再抽样。
- 原BM拟合本来就可以读取索引中的键；禁止的是用正式查询/答案调路径、调成本权重或选择更好的轮次。
- 最终补0%/100%命中端点、热点和Zipf，三者分别定义访问分布；skew合成键形态不是Zipf负载。
- 规模先64k，再100k及真实原文允许的更大唯一键集；不复制键制造规模，不修改下载器限制来伪称全库。
  超出预处理接口时使用通用reader/显式转换，并先做RAM、临时盘和原文唯一键数预算。

## 4. 分阶段执行与验收

| 阶段 | 预算 | 主要产物 | 推进条件 |
| --- | --- | --- | --- |
| 0 真实键补测 | 本次已完成 | 三键类型六格、源身份、工作账和完整比较 | 全部普通/sanitizer通过，3000行独立复核，旧失败不改 |
| 1 完整上游参照与短目录收口 | 2–4个工日 | 原生BlockLearn参照、短目录正式内存及完整读规格 | 明确结构差距，短目录的页内证据转为可验收的完整路径 |
| 2 必要查询步骤 | 5–7个工日 | 一个减少定位/验证重复工作的候选 | 正确性、工作入口、完整读收益及风险门均通过 |
| 3 编码与局部策略 | 5–7个工日，仅有证据时进入 | 有上限的局部细分或策略选择 | 模型失辨证据成立，元数据/构建预算受控且净收益成立 |
| 4 静态收口与空间 | 4–6个工日 | 新样本、规模、完整分配、正式只读配置 | 速度/空间/构建/能力边界同时满足，或明确收窄场景 |
| 5 动态维护与根成本 | 1–2周 | 同能力混合矩阵、根成本改进、尾部暂停及峰值 | 当前map读预算、写入正确性和全部维护成本通过 |
| 6 集成与复现 | 3–5个工日 | 少量正式配置、一键复现、最终总表 | 从干净环境重建通过，最终源码重测，不继承实验最好数字 |

### 阶段0：真实键补测（本次已完成）

保持原模型fit(1,7,8,1)、物理页、编译器、ISA和计时二进制不变，只换数据。
复用的二进制逐字节核对哈希，其已验收源码全部归档；不为数据变更无意义重编译。
先做每语料完整动态corpus普通/ASan，再做六格全部实现逐键/scan预检；全部通过后才按固定协议计时。
比较BM-base/BM-window/同布局目录/F5/ART，各自AA，初建与1024次值更新后两态。
HOT固定适配器泄漏未解决，当前不排名；下载和发布失败只影响准备流程，不能改样本或降低数据校验。

已交付 `RESULTS_BM_REAL_20261018.md`、源元数据、输入、原始计时、独立复核。
本轮到此收口，不调参数追加重复。后续短词为主要风险，URL原BM路径为保护格，短语为长尾确认格。

### 阶段1：给最新完整BlockLearn建立可信参照

1. 通过最新benchmark接入上游完整工厂，先检查来源、宏、include与实际链接目标。
   BM-page和BlockLearn-native必须分别命名；保留原生默认参数及额外适配成本。
2. 第一组固定原 `block-residual-delta` 与 `block-residual-delta-shortdir-first`，加F5和ART；
   原生新版本用同一行/查询文件和公共单线程接口，不能拿另一台机器的README数字比较。
3. 对目录和预测优先分别使用 `-shortdir`、`-first`，先小规模正确性和工作入口，
   通过后再完整消融，不先跑全部12个工厂的全笛卡尔积。两项联合收益不能乘两个单项比值推导。
4. cost/adaptive配置留给后续独立一组，不先堆到短目录里：用独立合成数据校准、冻结profile哈希，并核对target/build/ISA。
   首先比较同shortdir-first的旧目标与cost目标，再比较固定残差和自适应标签/顺序。
5. 按实际descriptor区分static/find/insert/update/erase/scan。当前上游完整模型不支持的操作诚实报告，
   不用std::map后备或本项目写层替它偷偷补齐，再称为上游原生动态能力。
6. 核对完整模型的借用输入、KeyStore、标签、delta和目录空间；原生及本项目的生命周期/复制成本都入账。
7. 对已完成的短目录页内候选做正式集成准备：不覆盖冻结原型，移除计数副本、合理预留fence视图、
   完整统计所有动态容量及模型绕过比例。先补缺失的全域/动态生命周期门，再登记完整find比较。
   原五格结构门失败保留；新实验问的是可计算适用条件下的完整收益，不把旧门事后改写为通过。
8. 完整读门以本次真实词表、URL、短语为主要输入，旧tranco为机制阳性对照、skew检查不适用时回退成本。
   预先冻结主格/风险格与目标；包含真实根导航、统一接口、缺席、clean/dirty、ART和模型原路径。
   HOT仍未通过sanitizer则保留缺席排名，不为了矩阵齐全压过失败。

决策：若完整模型明显更好，优先复用被证明的机制；若两者都慢，优先分析共有的预测/验证工作；
若只差特定数据形态，保留差异证据。不能预设一定是接入错误，也不能把本次失败归罪原算法。
这一步最多一个诊断周期，缺少归因证据则标未知，不无限延长模型对接工程。

### 阶段2：先消除额外步骤，再提高拟合复杂度

首先完成短目录的完整读门，只有它及完整上游参照提供证据后才选下一机制。
最新 `locate().predicted` 的预测块payload优先探测仍未验证，可以作为备选：
完整key命中即可返回，未命中仍执行原安全窗口/纠错，避免无条件增加完整fence搜索。
已探测块的标签/key校验不得无意义重复；任何提前返回必须由完整字节相等证明。
预测fence括号加整侧搜索已经在入口否决，不再重做；不再预设进入一个块就一定更快。
两者都保留窗口外、极值、EOS和前缀缺席的纠错，不能把训练radius/certified当全域缺席保证。

先登记以下账本，再决定是否进入计时：

- 根/页内导航次数、模型编码与选段次数、括号成功比例、完整fence比较及逻辑比较字节。
- 进入块数、标签批次、候选lane、完整key验证、回退和分配次数；正确查询不得新增堆分配。
- 命中/缺席、短键/长尾分别列出；工作量计数与正式计时分离，不把比较次数或插桩占比换算成未经证明的纳秒。

同一轮只选一种差分：预测块payload优先、短目录正式集成、或另一项有证据的新机制；不重做已关闭括号。
短目录若要持久化fence视图，
必须记入新增容量，不能逐查询构造临时view向量，也不能漏算前缀视图生命周期。
保留BM-base、失败BM-window、目录、F5和ART；联合版本必须另测交互，不继承单项通过资格。

工作入口目标：在主格减少至少25%的额外定位比较或标签批次，另一类工作无明显放大，元数据在5%预算内。
这只是筛选，完整查询仍须至少10%收益、至少4/5更快且超双方AA；风险格清晰>5%退化即停止通用采用。
连续两个候选入口失败，停止该方向，回到阶段1证据重选一个瓶颈，不扩大参数搜索。

### 阶段3：编码失辨与局部策略，按证据启动

1. 先审计真实数据的同坐标fence簇、逐页最大/分位窗口、额外公共前缀与回退分布；
   合成skew的99.93%歧义不能直接套到真实URL或短语。
2. 只有确认截断编码覆盖了显著慢路径，才做局部前缀细分；优先复用原BM在局部后缀重新拟合，
   先深度1、保留父区间纠错。段数增大不能恢复未读取的字节，不盲目搜索段预算。
   当前裸`BlockModel::fit`的max_error只决定certified，不能靠调小它期待窗口变紧；
   若完整planner因为认证结果改选区域/模型，应把规划变化与单模型拟合分开归因。
3. 若直接目录更合适，选择只依据构建时的可计算特征及预算，不依据语料名。
   必须与原BM和完整目录同布局比较，并披露模型绕过比例。
4. 有证据后再接成本选择：按物理页实际工作单位转换tag batches、完整验证和容量成本。
   当前BM按fence训练，不能直接沿用上游按record拟合的 `average_tag_batches` 作为实际扫描成本。
5. 参数/策略开发集和确认集分开；预算、分裂阈值、规划重跑触发条件先冻结。
   元数据>5%、构建>20%或完整查询没有净收益，则关闭该具体机制。

### 阶段4：静态泛化、完整空间与构建账本

候选通过筛选后，才在另一预登记样本/独立来源上确认；补一次规模变化与0%/100%命中端点。
对热点/Zipf分开报告，暖态和驱逐缓冲后首遍分开；没有硬件证据不叫严格冷缓存。
模型、完整目录、自研控制及ART的最终版本同轮重测，不能把历史倍率相乘。

完整分配测量单独构建/进程：覆盖C++ new/delete（数组、对齐、sized形式）及C malloc/calloc/realloc/free。
先用已知分配释放序列验收追踪器，避免追踪器自己递归或漏掉外部库。
分别记录bulk-load、query、insert、scan、compact的常驻、临时缓冲和峰值；输入/查询/参照map排除在索引账外。
报告请求字节、分配器可见量、RSS/HWM及仍未知部分；自计容量不能冒充完整堆。

交付一个明确结论：通用只读配置、场景配置、或停止该结构候选。
