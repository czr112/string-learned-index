## 1. 当前状态和需要修正的判断

### 1.1 已经获得的成果

- 已实现页级 `extract_split`、`apply_drop`、`block_for`；三个切分点的独立 Page 测试通过。
- 历史 `split_at_block` 微基准在两个样本上观察到约 60.7%/73.5% 的耗时下降，说明避免逐行物化字符串有研究价值。
- 索引层的 `rebuild_by_split` 接线已经回滚；既有 factory 仍走原页重建路径。263,469 项语义检查支持的主要是既有路径，不是新接线完整验收。
- 页核仍保留新增 API 和 scan reserve；相对 f4e79bf 有 67 行新增。当前源码不能描述成“全部与 S0 逐字节一致”。
- 尚无新接线的完整写入、纯吞吐、查询、空间和异常安全通过结果。历史 29/32 写门、查询 10 通过/5 回退/17 未定及外部比较须标明版本，不能作为新候选的验收。

### 1.2 哨兵报错的源码解释

失败脚本 `u3_wire3.sh` 执行了以下组合：

1. `staged` 只保存新上半页；原下半页继续留在 `target`。
2. 调用 `prepare_root(target, pages_.end(), staged, ...)`。
3. 现有 `prepare_root` 的语义是**排除 target，再加入 staged**。

因此，新根会漏掉仍保留的下半页。target 是首个哨兵页时，新根失去空 lower，直接报 `root sentinel`；target 是普通页时，仍可能生成漏页的根，查询路由将与 `pages_` 不一致。

现有检查也不支持“两个空键导致 root sentinel”的解释：`std::map` 不允许两个相同键；`FlatRoot` 在绑定为空或第一个 lower 非空时抛 `root sentinel`，重复/非递增 lower 则抛 `root bounds`。应保留根的严格约束，不能通过放宽检查掩盖漏页。

**哨兵回落可以缩小首次候选的适用范围，但不能修复普通页的漏绑定问题。** 哨兵页也可能重复分裂；“只有一页”不意味着“只发生一次”，更不能用 1/32 页估计时间损失。

| 项 | 源码事实 | 对下一轮的要求 |

### 1.4 成本和查询证据的有效范围

U1b 支持“在所测插入序列里，触发整页重建的插入很贵”。但它只执行 `kind==insert`，跳过 update/erase；替换轨迹因此被改成增长序列。77% 等份额也包含触发该事件的整次插入耗时，不是重建函数的排他耗时。它没有进一步分出 page_full、arena_short、prefix_change，不能把全部 75.5%–95.6% 都算作“页满切分可消除成本”。

U2 程序实际调用 `find_counted`，没有调用报告声称的公共 `find_base`；探针取初始键集及合成 miss，也没有复用五格正式回退的正确分组。目录步数增加 0.4%–3.9% 不能换算成相同百分点的查询耗时。五格已确认回退继续有效，不能据此降级成测量问题。

微基准计入初始 Page 构造，旧路径按 1,024 行分半，新路径按第 68 块切分；不包含新键插入、根发布、dirty/resident 记账。当前文件仍调用已移除的 `split_at_block`，不能直接视为新两阶段 API 的重测结果。旧记录保留，后续使用固定历史源码复现，或建立身份不同的新实验。

## 4. G1：先写分裂事务契约（2 天）

### 4.1 路由不变量

分裂前，页区间为 `[L,H)`，L 是页表 lower，H 是下一页 lower 或正无穷。L 可以是哨兵空串，它不必等于页内当前最小 live key。

分裂后必须满足：

- 页表含 `[L,M)` 的 lower 和 `[M,H)` 的 upper；`L < M < H`，末页不要求有限 H。
- lower 保留原 L；若 L 为空，空 lower 仍存在且位于首项。真正的数据键 `""` 仍按合法键处理。
- root 的 `(lower, Page*)` 集合与 pages_ **一一对应**，严格递增，引用都有效；检查数量相等不够，还要逐绑定一致。
- 所有原键及新键按 unsigned-byte 字典序恰好落在一页，值不变，插入成功后 size 只增加一次。

明确选择一种根构建语义：保留 target 并增加 upper，或排除 target 并提供完整的 lower+upper 替代。首版建议保留下半页对象时使用“保留 target、增加 upper”的契约，不再把仅 upper 的 staged 传给原有替换型 helper。

### 4.2 第一版的适用范围

先支持“非哨兵页、prefix 匹配、按 live 行数接近中位的块边界、两边非空且均有空间、新键属于 upper”的情况。lower 暂时保持原对象，upper 在旁路完成插入，利于证明异常安全。

- 切分后两边 live 行数拟要求各占旧页的 25%–75%，先登记再测试，避免按新键所在块切出极端小页而导致反复分裂。
- 新键落 lower、边界不可用、含未处理空块、prefix 改变、upper 无容量等，全部在修改源页前转旧路径，并计原因。
- 哨兵暂时走旧路径属于范围限制；必须专门测反复命中哨兵，不能宣称只付一次代价。
- 若这一范围覆盖率不足以支持整体收益，应在实现前停止或重新论证。扩展到左右任意插入或哨兵不是无预算的补丁。

### 4.3 准备与提交严格分开

| 步骤 | 可抛阶段的工作 | 对可见旧状态的要求 |
|---|---|---|
| A 判断 | 查重、区间/prefix/容量检查、选择 M、检查 M 无冲突 | 原键、值、路由不变 |
| B 页准备 | 构建 upper、插入新键、准备 lower model；对齐模型参数 | 不修改 lower blocks/arena/fence |
| C 索引准备 | 准备 map 节点、根绑定、需要的 dirty 节点、精确内存与版本差值 | 所有会分配的对象都已就绪 |
| D 提交 | lower drop、相同 allocator 的节点转移、root swap、计数/版本/账本更新 | 提交区域不分配、不抛出、不调用用户代码 |
| E 回收 | 按已证明的生命周期释放旧 root/暂存 | 无悬空 Page*、fence 或模型 prefix view |

同 allocator 节点转移、比较器、BlockModel 移动赋值等“不抛”的前提必须逐项验证；必要时编译期断言。候选仅单线程，不额外宣称并发原子性。

失败后原键值、root/pages 绑定、size、账本和可继续操作性都保持约定；允许变化的诊断计数单列。generation 若允许跳号必须预先约定，否则只能在提交时增加。不能发生 lower 已缩短后再分配 map 节点的顺序。

### 4.4 模型、fence 和内存契约

1. 初版结构候选保持原训练口径 `fit(fences,1,7,8,1)`，模型升级另立实验。记录实际 block_size、encoding_bytes、segment 等身份，训练 fence 数与物理块序使用同一单位。
2. 新 arena 重定位 entry 时，同步处理需要存活的稳定 fence 字节；删除块首键不等于可以删除其边界。空块按显式规则保留边界或在准备阶段处理，不能读取无效 `entries[0]`。
3. lower model 借用旧 arena 时，旧字节必须持续存活；任何未来压实都需要重新绑定或重建模型。
4. 明确 lower 保留的 arena/capacity 是空间债务。不要为保持速度而把它从 requested bytes 中排除，也不要事后引入未计时的 compact。
5. 首版不同时改变 prefix 压缩、BM 参数、根结构和分裂策略；若保留旧 prefix 导致上半页空间变化，记录它，不能借旧“空间零代价”结论免责。

**G1 放行物**：状态转换说明、所有权/借用表、适用条件、账本公式、错误返回和 fallback 表。无法完成这些定义，就不进入第五次接线。

## 5. G2：一次完整实现与最小反例（3–4 天）

先建立能暴露根丢页的最小反例，再实现事务入口。执行顺序：

1. 单页哨兵、三页索引两类夹具，分别触发首/中/末页分裂；断言分裂后 root 与 map 逐绑定一致。
2. 通过独立实验 factory 接入；冻结 BM0/BM1-frozen，不同时补丁修改所有 Index 头。
3. 先对保留 target 的根契约、两阶段 Page API、提交账本分别做路径验证，再组合。
4. 运行下面的边界矩阵，使用事件计数证明新分支真正执行。只跑旧路径通过不能增加新路径通过数。
5. 任何正确性错误先停止计时。只允许一次有明确根因的修正；满 4 天仍不通过则关闭本轮接入。

| 维度 | 必须覆盖 |
|---|---|
| 页位置 | 首哨兵、中间、末页；连续多次命中同一范围 |
| 新键位置 | 小于首 live key、恰在边界、边界两侧、末尾；duplicate |
| 数据内容 | 真正空键、NUL、高位字节、长公共前缀、不同 prefix、长后缀 |
| 页状态 | 全满、稀疏、有空块、删除过首键、arena 刚好够/差一字节 |
| 分裂位置 | 首个合法边界、中位、末个合法边界；极端不平衡必须回落 |
| 后续操作 | 两侧 find/absent、update、erase、重插、scan 跨 M、compact |

单元“恰好命中一侧”须直接验证 `has(lower) XOR has(upper)`，即使双命中的两个值不同也要失败；然后独立核对值。公开完整 scan 与 oracle 一致，不能只对两个 page 的 scan 拼接做检查。

## 6. G3：异常安全与空间验收（2–4 天）

按新路径一次成功预运行中的真实分配序号逐点注入，至少覆盖 upper arena/blocks/fences、两模型拟合、根绑定、map/dirty 节点；每一失败点检查旧状态、重试成功、继续 1,000 次插入/删除、销毁零泄漏。

先跑最小夹具的 sanitizer，再跑 words/URLs/phrases 和 byte fixture 的受影响路径。允许不变旧路径复用既有证据，但新增路径不能借用旧 263,469 项通过。ASan/UBSan/泄漏检查、公共 contract、差分和 find 零分配分别列出结果。

空间要看三条曲线：

- **单次维护峰值**：旧 lower 全容量 + 新 upper + 模型/根/staged/临时结构；所有申请纳入。
- **终态**：连续 1/10/100 次有效分裂后的 requested bytes、live-key 数与占用率，不只看一次分裂。
- **回收后**：可单列显式 compact 后状态，但 compact 的时间/峰值计入；不得用回收后数值替代操作终态。

共同门：终态相对 BM1-frozen 和 BM0 均 ≤1.05；维护峰值均 ≤1.10；构建峰值与 RSS 单列。root/map/dirty 自报与外部账本一致，size 和每页行数守恒。若空间超门，只能登记取舍或停止，不自动增大预算。

## 7. G4：验证当前两阶段实现的真实成本（2 天）

### 7.1 新微基准

建立新的两阶段 benchmark，历史数字单列：

- 从同样的源页、同样的新键和相同切分边界开始；源页准备在独立计时段，不能混入维护单价。
- 先在相同分区下比较“字符串物化+重建”与“提取+插入+提交”；再比较候选实际策略与旧策略，区分机制和分区策略影响。
- 新路径包括模型拟合、upper 插入、根准备/发布、node/dirty/resident 更新、释放；旧路径包含同样边界的完整工作。
- 多个随机页、三语料、长短后缀、不同占用，平衡臂顺序；单页 40 次重复不能代表独立样本。

只测 Page 提取可以作为组件结果，但不能叫完整页维护门通过，更不能把两个语料近似耗时称为“不随键长变化的结构下限”。

### 7.2 整体收益预测

使用真实完整轨迹计算：

`可节省写耗时 ≈ Σ(事件类别的写耗时份额 × 该类实际适用比例 × 该类实测节省率) − 新增开销`

适用比例按实际事件时间加权；单列 sentinel、prefix、lower 插入、稀疏块、空间不足等 fallback。候选可能改变后续事件频率，最终仍以完整重放为准。

如果仅覆盖 page_full，不得乘上包含 arena_short/prefix_change 的全部重建份额。替换负载必须包含原 update/erase；插入收益和所有写请求收益分别呈现。

**进入正式确认的门**：同等有效维护单价预计降低 ≥25%，完整写耗时预计降低 ≥15%，纯混合吞吐预计提升 ≥10%，并且 G3 已通过。预测只决定是否值得确认，正式通过依赖 G5。

## 8. G5：端到端性能和查询收口（3–4 天）

### 8.1 扩表顺序

先 4 格诊断（G0 的四格），再 10 格风险矩阵，最后只冻结一个版本做现有 32 格及独立确认。10 格由五个既有查询回退格、三个 95/5 均匀替换写门失败格、两个 URLs 80/20 替换观察胜出格组成；不得每修一行都跑完整矩阵。

使用新候选/BM1-frozen 的直接配对比。最终四/五臂按真实臂数平衡顺序，不能通过新候选/BM0 与旧历史比例相减来宣称增量。

试跑 4 个进程只用于找工具和路径问题；正式固定 16 个独立进程，每进程 8 个配对重复。动态重复从同一初态新建/重放；终态查询批量校准至少 40ms。oracle/组件计时、单操作延迟、纯吞吐分开，pure A/A 两次数据和结果校验均落盘。

每指标/每臂独立 A/A 质检；进程内重复先聚合，进程间 log 比 t 区间 df=n−1。旧写门 29/32 的历史算术统计保留，不能与新 log 比拼接。正式多格“全部通过”预登记比较族，采用同时区间或已冻结的多重校正；未定不算通过。

### 8.2 查询是独立硬门

继续以正式正确分组报告的五个确认回退为风险格：words 80/20 均匀增长、URLs 95/5 均匀增长、URLs 80/20 热点增长、words_indep 80/20 均匀增长、words_indep 80/20 热点增长。

从实际 adapter 的 `find_base` 采集窗口、fallback、真实块访问、边界和完整比较；沿用 manifest 热区和最终存活集。对同终态 snapshot 与动态版分别测量。目录步数只是一个诊断指标，不能取代完整查询时间。

若 split 候选通过写门但五格查询仍超门，结论只能是写路径研究成果。查询机制只能在同布局因果证据成立后另立最多一个候选；不得把查询修复偷偷并进本轮容量改造，造成无法归因。

### 8.3 正式门

| 指标 | 接受条件 |
|---|---|
| 正确性/异常 | G3 全部通过，公开入口新路径确实触发 |
| 完整写请求 | 目标域新/BM1 CI 上界 ≤0.85；非目标关键操作上界 ≤1.05 |
| 纯混合吞吐 | 目标域新/BM1 CI 下界 ≥1.10，且自身 A/A 通过 |
| 完整查询 | 新/BM0、新/BM1 在声明支持范围上界均 ≤1.05；终态与交错混合 find 分开过门 |
| 空间 | 终态 ≤1.05、维护峰值 ≤1.10，含 retained arena/capacity |
| 既有成果 | 原 29 个写门通过格按最终版本复核；另外 3 格和 17 个查询未定不能消失 |

只通过部分预登记场景就限定范围；不得看到结果后删格改成全域成功。

## 9. G6：相对 baseline 的价值与长期维护（3–5 天，条件阶段）

只有 G5 至少一个完整场景通过才进入。

### 9.1 外部价值

保持原 mixed+scan 组，同时建立点操作组：从相同请求序列去掉 scan 后独立审计并哈希。ART 的扫描从头遍历下界的实现局限写在混合表旁，不用扫描混合成绩宣布普遍胜过 ART。

相对 Context16 的建议价值门沿用此前计划：纯吞吐 CI 下界 ≥1.10 且空间/读不回退，或终态空间 ≤0.80×Context16、吞吐下界 ≥1/1.10 且读/维护预算满足。用未参与调参的新 seed 和真实独立样本确认。旧中位吞吐比 0.584 与 ART 写耗时 3.87–16.84 倍仍为历史参照，不得声称本次已经缩小。

### 9.2 长期分裂债务

至少包括：反复向最左区间写入（哨兵回落）、反复向同一普通页区间写入、均匀增长、完整 2:1:1 真键替换、删除 50% 后回填与跨页 scan。

记录新/旧路径次数及耗时、页占用分布、root 页数、live/retained arena 字节、数组 capacity、模型/fence 引用、分裂放大、compact 时间和 p99。按键所属块切分会改变占用率，必须检查连续分裂是否制造小页和扩大根。

完整周转计划最少 3 次、最多 10 次；同时设置 1,000 万操作上限，事前确认预算够完成 3 次，否则标覆盖不足。不主动 compact 和预登记触发 compact 两种策略分别测，维护成本不能放计时区外。

稳定性建议门：同 live 数下 bytes/live-key 在第 3–10 周转不持续增加超过 10%；维护 p99 相对 BM1 不恶化 >10%，并报告绝对暂停。事件不足只报 max 和样本量。

### 9.3 规模放行

依次完成当前 100k words 同协议验收、250k 实际活跃键、百万实际活跃键，每阶先 4 格。真实语料不足则停止在该范围，不能重复或加后缀伪造规模。输入池、初始 live、终态 live 分开记；先估算多臂峰值，不能将换页影响当算法收益。

任何一级价值、查询、空间或维护门失败，停止下一规模。HOT、接口改造、通用根重写和多模型选择保持独立后置事项。

## 10. G7：最终交付与止损（1–2 天）

交付逐格性能/空间表、路由和异常验收表、分裂适用与 fallback 表、长期债务表、版本/证据索引与干净目录复现入口。报告明确四种状态：组件可行、索引正确、端到端获益、具有外部价值；不能由第一种直接跳到第四种。

允许三种结束方式：限定场景的实验配置；可复用的无字符串分裂组件与失败边界；停止当前结构支线。没有通过默认替换门就保持 Context16，不能为了结束项目而自动切换。

若正确接入后主要受 arena/prefix 非满页重建限制，或空间债务使门无法兼顾，应结束本候选。此前提出的“稳定 BM 基页+有界 delta”只能另立设计研究：必须先证明 BM 空间/场景价值和完整成本预算；不能作为本轮第五、第六次失败后的自动续命。

## 11. 时间、文件与执行纪律

| 阶段 | 工作日 | 阶段结束必须有的决定 |
|---|---:|---|
| G0 冻结和适用成本 | 1 | 哪类事件能被覆盖，旧证据哪里受限 |
| G1 事务契约 | 2 | 根/页/模型/账本的完整状态转换是否可证明 |
| G2 单次实现 | 3–4 | 最小反例与边界矩阵通过，或停止接线 |
| G3 异常和空间 | 2–4 | 新路径是否可安全继续，空间是否在预算内 |
| G4 成本验证 | 2 | 两阶段完整路径是否值得端到端确认 |
| G5 写/读/吞吐 | 3–4 | 冻结候选是否通过明确目标域 |
| G6 价值/长期/规模 | 3–5 | 是否有独立确认的适用价值 |
| G7 收口 | 1–2 | 可复现成果或明确停止报告 |

顺序执行合计 **17–24 个有效工作日**；条件阶段未放行时提前结束，不要求把预算全部用完。

拟新增一份事务协议、一份正式候选 factory、一份公开入口分裂门和一个遵循 README §4 的 runner。runner 使用真实源闭包/模型/adapter/二进制 SHA、`.partial` 原子发布、运行前后校验、新结果目录；所有失败记录保留。不得继续用 `"u3"` 占位身份或以文本替换脚本在测量时改核心。

每周更新单一台账：阶段、父版本、实现次数、已用时间、适用率、完整性能门、证据与下一决定。到阶段预算不通过即停止或按已登记条件转研究收口，不能以“只剩最后一个特例”重置预算。
