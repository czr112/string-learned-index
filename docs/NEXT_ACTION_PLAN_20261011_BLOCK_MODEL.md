# 下一阶段：新模型进入现有索引，分离模型与结构的效果

日期：2026-10-11。状态：已核对本地源码与上一轮结果；本文件是执行计划，尚未实现新后端或启动实验。

## 1. 决策

优先做 BlockLearn 的模型级接入，主比较为同一套 Index 下的 Context16 与新后端。
上一轮是完整 BlockLearn 索引与我方索引的系统对照，并未完成 RegionModel 替换。
不做 LITS 定向优化；LITS 只保留既有实现和安全修复。残差标签、delta、模型参数搜索均不进入第一版。
M4 写后扫描归并顺延；GD/M2/H/Q/PFX2 等已关闭机制不重开。

目标是判断新映射能否减少组负载长尾、主块探测和溢出，并转化为完整操作的净收益。
不预设新模型一定更快，也不把独立 BlockLearn 的内存优势归因于模型。

## 4. P0/P1：最小接入设计

### 4.1 采用“确定的保序排名 → 逻辑组”，暂不移植候选窗口查找

第一版建议命名 BlockLinearRank，明确它是来源于 BlockModel 的适配变体，不冒充原完整 BlockLearn。
拟复用 9-bit 保序编码、同坐标不拆段、分段线性拟合、限幅和取整；训练目标使用区域内排名。
具体起点：fit 的 block_size=1（坐标成为排名），encoding_bytes=7、segment_budget=8；不搜索参数。
预测中心 p 经受检整数算术映射 g=min(G-1, floor(p*G/N))；N=0/1、G=1 单独定义。
参数及公式须在任何性能运行前写进契约和身份记录；若接口分析证明不适用，先修订设计并说明原因，不能看计时择优。

原窗口半径证书保留为诊断数据，不能复用“误差≤1块”作为这个排名变体的正确性保证。
正确性来自：记录按照同一映射放置和读取、完整键验真、区域内全域保序。误差和碰撞影响布局与性能。
不从裁剪后的窗口中点反推预测中心；应暴露或最小抽取原中心预测运算，并记录来源差分。

必须审计编码单调性、非负斜率、段间输出边界、间隙/域外坐标、浮点有限性和取整范围。
有限样例检查不能替代这些不变量；保留原模型测试并补独立映射门。
前缀不匹配走 Index 已定义的拒绝/重建/扫描起点路径，不能静默截错后缀。
不要只在查询时临时换回 Context16：若构建已经用了新组号，这种回退会漏键。
如必须回退，应在区域构建时决定该区域全生命周期使用的后端，并报告区域/键/查询覆盖率。

### 4.2 受影响的接入面

- canonical_group 与 predict_for 共用新后端；构建放置、插入、erase、update、scan 起点一致。
- predict_for 明确区分 consumed 与 fp_consumed。第一版 fp_consumed=0，完整后缀沿既有指纹路径处理；不一起改 CRC 或标签。
- 新后端拥有前缀字节，或只借用有明确稳定生命周期的区域所有权；验证复制、移动、输入销毁及异常路径。
- 需求统计、普通构建和 BuildContext/preset 都绑定模型类型、参数、训练身份和映射；不能套用 Context16 的 group_ids。
- 初始可显式拒绝尚不支持的 preset/R1 入口，但必须标记功能范围；正式采用前补齐实际使用入口，不能静默退化。
- region 重建/分裂重训并重放全部活跃记录；compact 若不改映射则不重训。先生成有效新状态，再提交。
- memory_breakdown 包含模型、前缀、对象、容量余量和训练峰值；若第一版仍持有参考模型，照实计入。

## 5. P2：正确性和结构诊断

正确性以独立 unsigned-byte 有序参考为准：完整键值集合、缺席查询、覆盖更新、删除重插、跨区域和任意起点扫描。
边界含空键、NUL、0x80/0xff、4096 字节键、长公共前缀、编码碰撞、段边界/间隙、训练集之外新键。
真实触发分裂、前缀变化重建、溢出、compact，记录触发数；训练输入释放后重扫，移动对象后复查。
检查存量键和新键混合排序后的组号单调性，加入非保序映射负对照，证明门能抓到错序/漏查。
ASan/UBSan 无诊断才通过；若发生异常失败，独立参考确认已有索引未半更新。

一次三语料入口记录：

- 新模型区域/键/查询覆盖率、回退原因；段数、编码碰撞、排名误差分布。
- 组记录数与后缀字节量的 P50/P95/P99/max、空组比例、子块数与溢出量。
- 查询主块探测、标签拒绝、完整比较字节、溢出探测，分别统计命中/未命中。
- 单次拟合与完整构建的成本分别记录；内存分为持有输入、主存储、模型及峰值。

若几乎全回退、容量不可接受或映射造成明显集中，先报告具体瓶颈，不直接启动八臂大矩阵。
入口只解释机制，不能把计数减少折算成加速比；只要正确可用且存在合理收益空间，允许一次完整 A/B。

## 6. P3：有限 A/B 与采用标准

主目标固定为 mixed 完整点查耗时，skew/tranco 为风险格；该选择服务于长键组负载改进假设，不因后续结果更换。
主对照只有 Context16 与 BlockLinearRank；LITS 不进入开发迭代，最终必要时列为历史参照。
两边使用相同区域输入、组数推导、容量算法、指纹、查询、操作序列及配置。基础配置沿本轮默认，C/W/S/M3 固定 OFF。
模型改变记录分组，实际布局不可能保持逐字节相同；这应称“同输入、同结构策略”的比较，而非相同物理状态。

复用现有小型 A/B 装置：5 个串行独立进程 × 4 平衡重复、固定逻辑核、B0/B1 与 N0/N1 复本；比值先在重复内形成，再按进程汇总。
计时无诊断计数，预热规则一致；完整构建包含训练和分配。A/A 散布沿既有规则预注册，禁止看结果修改公式。
分析器先用固定小记录检验缺格、缺字段、配对重复、身份不符、失败样本；不扩建通用评测平台。

速度采用的拟定门槛：主目标 N/B≤0.90、至少4/5进程同向，且收益超过 A/A 散布；风险格可分辨变慢>5%则不作为通用读配置。
构建增量≤10%、常驻增量≤5%为常规预算，峰值单列；超过预算保留测量，但不能按速度收益掩盖成本。
若主要收益是空间，单独按空间取舍评估（拟定常驻下降≥20%，读/扫描/更新无可分辨>5%回归）；不能改口声称达成速度目标。

扫描风险先看完整物化 scan16/256；更新风险复用 existing same/grow 替换日程、点查及 scan256 检查点。
grow 是键长增长、存活数保持 N；周期语义沿旧装置，不误称为存活键数翻倍。
性能尾延迟与吞吐分别报告，不要求名次一致；必要条件已失败时不为排名扩大矩阵。

## 7. 后续结构方向与长期收口

1. 新映射减少组长尾且端到端获益：集成新后端，再测实际采用配置与 ART/HOT；冻结参数后用留出未命中/热点查询确认泛化。
2. 新映射改善负载但净收益不足：据完整查询和工作量判断是否有独立结构瓶颈；每次只选一项，不能凭微基准继续优化预测器。
3. 映射集中于相同编码或构建困难：整理反例与量化反馈给模型负责人；发消息需用户另行授权。当前不改其学习算法或追加搜索。
4. 第一轮接入收口后恢复模型无关的 M4 有序段归并。优先在 Context16 验入口；新后端已可用则作为第二后端验证，LITS 不作为推进条件。
5. 残差标签只在新后端下证实完整比较仍主导后另立候选；delta 只在既有更新结构出现明确瓶颈时讨论。两者不随模型接入一起搬入。

长期产物是一个经验证、接口可替换的索引版本及明确场景配置，而不是不断增加默认关闭开关。
新模型不获收益时保留 Context16，模型级接入作为明确结果收口，结构优化仍可沿 M4 推进。
