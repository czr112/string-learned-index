## F6B：准备真实动态轨迹和分配账本

1. 固定三语料，95/5与80/20读写、均匀/集中写、固定键数替换/增长，共24格。
   先明确写比例分母、insert/update/erase组成、替换是否含两次primitive、集中区间与新键生成，
   并把完整可重放操作流及逐步答案/最终map身份冻结，之后才运行时间测量。
   不以重复已有键冒充增长；生成键遵循公共字节比较且HOT共同域不含NUL。
2. 每条轨迹对照std::map，验证最终全量find、完整scan、缺席update/erase及重复insert，
   同样覆盖F5裸核心、v1 bridge和动态Context16/ART/HOT。保留各基线能力/适配成本说明。
   所有普通/sanitizer门通过才计时。HOT不支持NUL仍明确排除在公共域之外，F5全字节门单独保留。
3. 针对变更页拓扑后的当前map，重建D1快照，补完整find必要读门；同一初始数据不能代替相同最终map。
   沿用>1.15、>=4/5更慢且超双AA带的停止条件，不因混合吞吐变快就接受读退化。
4. 完整分配峰值单独构建/进程计量，不污染计时二进制。覆盖C++ new/delete（含数组、对齐、sized形式）
   和C malloc/calloc/realloc/free，以及各外部库的分配入口；用已知分配/释放序列先验收追踪器。
   输入/操作流预先加载，区分构建、读、写、scan、compact的索引常驻、临时缓冲与峰值；
   辅以mallinfo2/RSS/HWM并披露剩余未知，不能把仅C malloc link-wrap称作完整C++峰值。
5. F5自计仍排除树节点链接、分配器元数据和内部scratch；根仍每次换页O(页数)复制。
   单列根prepare尝试/完成/发布、项复制/键字节、页重建行/字节、dirty集合、页数增长和所有失败。
