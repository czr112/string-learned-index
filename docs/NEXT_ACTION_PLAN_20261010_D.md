绑核失败不得静默继续并输出可比较计时；记录 CPU、编译参数、构建身份和校准值。

诊断分两种构建：

2. 阶段计时版：复用已有计时宏，只在计数无法区分的目标环节补最少时钟；记录空计时器校准与原始值。

发布路径的最终 A/B 使用关闭计数和阶段时钟的构建。诊断时钟只用来定位，不宣称收益。
诊断字段缺失或宏未生效时编译/分析必须失败；用小规模手算案例核对计数，不能把缺字段当零。

## 4. 第二步：记录更新增量与检查点附近的工作

统计范围只包索引的 erase/insert 调用；数据生成、参考容器、构建和校验不进入写路径计数或时间。
每个检查点记录两种口径：

- 区间增量：0→25%、25%→200%，分别记录删除和插入的操作数与阶段增量。
- 局部窗口：每个检查点最后 8,192 个替换周期。在原日程中设置快照边界，不额外更新索引。
  此窗口用于区分早期转换成本与检查点附近残余成本；窗口结果不能与区间总量混为同一分母。

核心记录：

| 环节 | 必须记录的工作与去向 |
|---|---|
| 区域内检索 | 模型/定位次数，主块与子块探测，标签候选/拒绝，完整比较次数及字节，主块/溢出命中与未命中 |
| 放置 | 首次尝试与重试次数，探测子块数，槽位/字节/秩限制的拒绝原因，主块成功和最终落溢出 |
| reclaim/widen | 调用、实际回收/扩宽、搬移记录与字节、重试成功/失败，失败后重复检查的工作 |
| 删除 | 主块/溢出去向，搜索比较，记录搬移及字节；与插入计数分开 |
| 重建与分裂 | 次数、触发原因、`all()` 记录数、重放/复制字节与阶段耗时 |

先复用现有字段，仅补影响候选判断的缺项；不扩成全量 profiler。
统一输出每次 insert、每次 erase 和每个替换周期的分母；区分插入初次尝试、重试与重建重放。
重建嵌套记录不混入普通放置成功率；调用次数和返回结果交叉核对。
嵌套计时仅对父项取比，不能相加；接近校准地板的环节记为不可分辨，负校正值不当作零成本。
计时扰动若改变排序，只保留计数事实，不给出精确时间占比。

## 5. 第三步：入口判定，只选择一个候选

完成上述 8 格后先判定，再写优化代码。进入实现必须同时满足：

1. 在 W 的局部窗口仍有重复/无效工作，能够指认具体函数、循环或重复状态计算。
2. 该工作在目标负载中持续出现，有可分辨的成本依据；计数多本身不能证明时间大。
3. 提出有界改动，说明如何省掉这份工作以及如何维持查找、秩序、容量与失效不变式。
4. 明确一个主要收益指标、目标格子和风险格子；在候选计时前固定，不能事后挑格。

按证据择一：

- 检索/放置重复定位：先核对已有 `reuse_locate_ctx` 的覆盖，避免重新实现已有优化；只有未覆盖工作才立项。
- 放置失败后重复遍历：只有拒绝条件或位置上下文可安全复用，且 reclaim/widen/repack 后能正确失效，才做局部复用候选。
- 重建占主导：先指认一次可省的物化、复制或重放；不能因重建贵就扩大到模型或区域划分重构。
- 溢出搬移占主导：核对 W 后实际残余成本及 O1 已有读/扫描取舍；不足以支持净收益就记负结果。

本轮诊断最多做一次针对目标环节的补充核验；入口不成立就收口，转现有候选清单，不能无限追查宿主机噪声。
产出 `RESULTS_WRITE_RESIDUAL_20261010.md`：8 格工作表、时间限制、首选对象或负结果、下一步有界差分。

- 候选关闭时跑受影响的既有组合回归，确认默认路径一致。

门失败先修实现，不能用性能结果抵消正确性失败。
