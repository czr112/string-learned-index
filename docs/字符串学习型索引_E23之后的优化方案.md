**字符串学习型索引：E23 之后的优化方向与实施方案**

适用版本：冻结的 R1 默认实现。E24–E28 是本方案建议的后续编号，尚不是已经完成的实验。

本方案依据原始《学习型索引(1).docx》、本地保留的早期源码、已上传报告，以及你在对话中提供的 E21–E23 结果制定。E21–E23 的完整源码与原始记录未在本次环境中提供，因此相关数字引用你的报告；下文明确区分已经报告的现象与需要核实的实现假设。本文没有新增性能测量。

**核心决定：保留模型与 R1 构建，优先优化更新的定位路径和局部维护，再改善范围扫描。**

你的第二项任务是索引结构、增删查改接口和工程优化。最适合继续形成研究主线的问题是：在预测模型与逻辑分组保持不变时，怎样通过物理布局维护，延缓更新造成的溢出与碎片积累，并控制维护代价。先消除可以确认的重复工作，再验证这条主线。模型算法改进仍由模型负责人处理。

**1. 为什么作出这个选择**

| 已有证据 | 能支持的判断 | 不能据此断言的事 |
|---|---|---|
| E21 混合点查中，S 比有序数组耗时低 34.9%–45.0%，比当前 ART 耗时高 12.3%–48.8% | 现有结构有点查价值，但尚未达到当前 ART 的水平 | 差距主要由模型预测造成；任意 ART 都更快 |
| E21 构建改造后，完整构建比原 S 降低约 42%–47%，查询变化接近噪声 | 构建这条线已经有明确成果，可以阶段性收尾 | 继续削减一次预测就一定值得 |
| E22 只改值耗时也是 ART 的 1.24–2.77 倍，布局没有变化 | 更新的基本定位与写入路径值得单独检查 | 这部分慢是重建或容量回退造成的 |
| E22 替换成本为 ART 的 5.73–8.56 倍，skew 空间比从 0.86 升到 1.02 | 更新维护是突出的短板，空间优势会随某些负载消失 | 全部增长都是垃圾字节，或释放容器容量就能解决 |
| E22 三类负载均未触发容量回退 | 已测负载中主要压力表现为溢出增长 | 其他插入分布也不会触发回退 |
| E23 扫描相对有序数组为 1.28–2.34 倍，三个进程方向一致 | 扫描访问路径需要独立优化 | ART 扫描排名已确定；差距全部来自模型 |

上表各行保留原实验轮次，不能拿跨轮绝对耗时相减，也不能拼成一个“综合加速比”。Tranco 本项目实际测试规模为 262,144 键，不写成已经测试百万键。

任务优先级如下：

| 顺序 | 工作 | 主要目的 | 暂时不扩展的内容 |
|---|---|---|---|
| P0 | 更新路径与空间诊断 | 分清重复定位、碎片、真实容量不足和容器保留 | 不再泛泛收集一大批无关计数 |
| P1 | 统一增删改的定位内核 | 让已有 SIMD、标签过滤和 Hybrid 查找覆盖写操作 | 不改模型、不改记录布局 |
| P2 | 证据支持的一种组级维护 | 在原预算内利用可回收空间，或释放无用保留容量 | 不同时做全局重建、多种新分配器和后台线程 |
| P3 | 范围扫描的顺序访问路径 | 减少空组遍历、重复定位和结果物化 | 不复制一份完整有序索引来掩盖扫描成本 |
| P4 | 条件性的点查硬件优化 | 在新诊断支持时处理路由、访存或预测开销 | 不默认升级 AVX2、不重复启动 R2 构建优化 |

P1 是成本较低的工程机会；P2 是更适合承接你课题创新点的结构研究。若 P0 发现 P1 已在最新版中落实，直接跳过，不为了形成一轮实验而重写。

**2. E24：用一轮有限诊断决定改哪里，预计 1–2 个有效工作日**

这轮只回答三件事：写操作有没有重复做定位；增长的空间具体在哪里；原预算内还有多少真实可行的回收机会。

**2.1 核对增删改是否走了同样高效的查找路径。**

本地早期 `validation_e3_20260906/index.hpp` 中，`find_impl` 有指纹筛选；`update` 和 `erase` 则直接循环做完整字符串比较；`insert` 先调用 `find`，随后再次计算组号和指纹。这是已经读到的早期实现事实，不代表 E23 仍保留这些行为。

对最新版只需检查下列调用链，并在独立诊断构建中记录每次操作的计数：

| 操作 | 需要核对的问题 | 对应计数 |
|---|---|---|
| 只改值 | 是否重复找键；是否绕过标签过滤；是否用了与 find 不同的溢出策略 | 外层定位、模型预测、指纹计算、子块访问、完整比较与逻辑比较字节 |
| 删除 | 找到位置以后，花在移动描述符与释放字符串上的工作是多少 | 定位计数、移动条目数、实际复制字节、分配/释放次数 |
| 插入新键 | 判重与放置是否重复预测；失败后是否盲目重试 | 预测次数、主块尝试、容量失败类型、压缩次数 |
| 删除后插入 | 时间高在删除、插入，还是维护事件 | 两段操作计数和维护事件；正式比较仍计完整周期 |

计数按主块命中、溢出命中、未命中分开。但不要把分别运行的三种负载耗时当成同一条混合负载的时间分解。重建、前缀变化等慢路径单列，不要求所有情况下都只预测一次。

优先看已有调用链与确定性计数；必要时做整批采样剖析。不要为每一次字符串比较打时间戳，避免仪器成本盖过实际工作。

**2.2 把空间账本拆成互不重复的组成。**

主块的分解应满足：

`主块分配字节 = 块头/标签 + 预留描述符区 + 活跃后缀 + 垃圾后缀 + 未用后缀区 + 对齐余量`

标签如果已经位于块头中，只计一次。未用槽位已包含在预留描述符区中，不能又加一份。垃圾后缀是删除后仍占据块内位置的旧字符串字节，不包含空闲字节。

溢出区单列：容器对象、记录数组容量、有效记录数、外部字符串分配、未使用记录容量。`std::string` 的内联短字符串已经包含在记录对象里，不再按 `capacity()+1` 重复计算堆空间；具体工具链下无法可靠分离时，要保留“估算”标识，并与独立分配诊断交叉核对。

模型、共享前缀、路由、容量表、新增位图等另列。常驻空间、维护时临时峰值、进程 RSS 是不同口径，分别报告。

在 E22 的 0%/5%/10%/25% 检查点记录这些分项。后续只对“删除后补入”增加 50%/100%/200% 累计替换周期：活跃记录数维持约 N，判断空间是否趋稳。先保持 N 不变，避免同时扩大工作集和改变更新比例。

**2.3 计算可行回收机会，不能只看空闲总量。**

对每组分别问：

- 是否有空槽？清掉垃圾之后是否有足够后缀字节？
- 空槽、字节是否在同一个可接收该键的子块？
- 放进去是否仍满足子块之间的键序？
- 空闲是否来自其他逻辑组？若是，首版组内维护不能直接使用。

用当前布局的真实几何参数作一次诊断性试放，得到“按指定算法实际可以迁回的条目数和后缀字节”，不要把聚合空闲量命名为可实现收益，也不宣称它是最优装箱答案。

**诊断后的决策规则：**

| 主要观测 | 下一步 |
|---|---|
| 更新/删除绕过了已有快速查找，或插入重复定位 | 先做 E25 的统一定位 |
| 垃圾字节多，而且压缩后同一合法子块确实能承接插入/溢出 | 选择压缩或压缩加迁回 |
| 活跃溢出不多，记录数组保留容量很大 | 选择延迟收缩容器 |
| 活跃溢出持续增长，合法位置确实没有槽位/字节 | 组内压缩不是解法，暂缓此分支，转向后续区域容量维护 |
| 空间并未明显浪费，慢主要来自描述符移动/溢出插删 | 先核对写入算法；只有计数支持时再研究有界增量区 |

E24 的交付是一张明确的“现象—对应代码—计数—选择”表，不是又一份没有决定的性能报告。

**3. E25：一个键定位一次，再完成读写，预计 2–3 天；若最新版已做到则跳过**

目标是复用已经验证的查找机制，包括主块 SIMD 标签过滤、精确键比较、当前溢出策略及子块查找开关。复用代码不意味着必须让每个点查都构造一个庞大的通用对象；用内联函数和编译期需求裁剪，避免为只读路径增加额外字段搬运。

建议的内部接口示意，名称可按现有代码调整：

```cpp
enum class Where { Missing, Primary, Overflow };

struct Located {
    Where where;
    uint32_t region, group, subblock, slot;
    // 仅在本次操作内有效；内部可携带后缀视图和已计算标签。
};

// 示意接口，不是已经完成的补丁。
Located locate_for_write(std::string_view key);
bool update_at(const Located&, uint64_t new_value);
bool erase_at(const Located&);
bool insert_prepared(/* 本次判重结果、组号、标签、key、value */);
```

具体行为：

1. `update`：一次查找得到确切槽位，再写固定宽度的值；记录数、组几何、溢出数和空间不变。
2. `erase`：用同一定位机制找到记录，再做必要的描述符移动、标签同步、后缀垃圾记账和边界更新。
3. `insert`：判重后复用已经算出的组号和标签。若压缩改变了槽位，需要重新求物理插入位置，但在模型与前缀不变时不必重新预测逻辑组。
4. `upsert`：根据一次定位的结果执行写值或插入，避免先完整 update、失败后再完整 insert 查找。语义继续保持“插入/更新”可区分。

位置结果只在同一次公开 API 调用内部有效；重建、压缩、删除移动、容器扩容后不能沿用旧指针或旧槽号。区域发生前缀变化或分裂时，必须重新使用相应的新映射。

不能通过“已知新键一定不存在，所以取消判重”让原型占基线便宜。若另测内部已知不存在入口，双方要有相同前置条件，并与通用接口分开。

验收只针对实际改变的风险：主块/溢出中的更新和删除、标签碰撞、跨 16 槽的 SIMD 批次、重复键、未命中、删除再插、压缩后位置失效。完整键值与扫描结果必须与参考容器一致。

本轮先比较冻结 R1 与仅改定位的新版本，再在同轮加入 ART。如果诊断计数下降但端到端没有明确改善，就保留为可选实现或撤回；不把“预测少了一次”当作性能结论。

**4. E26：固定映射的组级维护，是建议的研究主线，预计 3–5 天**

把一个逻辑组看成一个小存储单元：模型仍把同一个键送到同一个组，组内可以整理后缀、利用已有槽位或回收无用容器容量。首版不改前缀、模型、逻辑组数、组号映射，也不扩大主块预算。

一次只选择 E24 支持的一个分支，最多做三种变体，不同时实现所有维护办法。

**分支 A：只压缩垃圾。** 保持主块成员不变，重新打包活跃后缀，修正偏移，恢复连续可用空间。它释放的是块内可用空间；主块仍分配着，不能因此宣称常驻内存下降。压缩后能否少进溢出，要用后续同一操作序列验证。

**分支 B：压缩后迁回溢出。** 首版采用保守算法：保留全部原主块记录，只把溢出记录放入满足键序和容量约束的空位。具体步骤：

1. 读取该组主块的有序记录和有序溢出记录；在临时状态中保留旧主块成员。
2. 清掉临时主块中的垃圾，为溢出候选寻找合法的子块区间。结合相邻非空子块边界判断，不能把“这个子块空”当作能装任意键。
3. 只有槽位与后缀字节同时足够时才迁入；不驱逐原主块记录来换取表面上的迁回数量。
4. 更新标签、偏移、计数，以及已经启用的子块范围目录；校验主块与溢出互斥、并集不变、值不变、组内顺序不变。
5. 临时状态成功后再提交；失败保持旧状态。未能迁回的记录继续留在溢出区。

准备阶段完成可能失败的分配、复制和目录构造，提交阶段避免再分配。若维护是在单键操作已经成功后触发，维护准备失败应保留“单键操作已完成、布局尚未整理”的有效状态，不能误报该键操作失败。这里的失败原子性是单线程接口要求，不是并发事务保证。

这种保守方法不承诺最大回收量，但能避免简单贪心装入一个长字符串、反而挤出许多原主块记录的情况。完整的跨子块重新划分可作为后续候选，不混入第一版。

**分支 C：缩减溢出容器的保留容量。** 仅在活跃记录下降后，容器仍占着过量容量时采用。需要测实际分配容量和后续再次增长的分配次数，不能假设调用 `shrink_to_fit` 就一定释放了某个确定数量的字节，更不能把容器释放等同于 RSS 立即下降。

当前多块布局用区域内连续空间及偏移表寻址。首版固定各组和子块几何，使用组级临时缓冲并在校验后写回原地址，避免为了维护一个组而搬动整个区域。复制回写、边界更新和临时峰值全部计费。如果最新版布局无法支持这种实现，先明确改为区域级维护并计入完整成本，不把区域复制伪装成 O(1) 的“组指针交换”。

提交设计首先服务单线程语义；后续并发负责人需要另外接入同步发布、读者验证和内存回收。临时副本并不自动提供并发安全。

**4.1 什么时候整理。**

首版只使用写操作已经需要更新的轻量统计，例如垃圾字节、空槽数、溢出记录数、上次维护以来的更新次数。不要为触发策略给每个查询增加昂贵计数器。

示意条件是：

`出现空间压力 AND 存在合法回收机会 AND 超过最小维护间隔 AND 满足临时空间预算`

在插入失败或若干次更新后检查；不要每次删除都立即做压缩和收缩。采用触发高水位、解除低水位与冷却间隔，避免删一个、缩一次、插一个、又扩一次。具体阈值先在调试/验证序列选择，再冻结后测试，不能根据测试结果逐数据集反复挑选。

至少记录维护尝试、成功、无收益拒绝、延后、复制字节与单次事件时间。“无收益”后必须等待足够状态变化再试，避免每次插入都付一次失败的整理成本。

已有压缩路径优先复用，不重新发明一套做同样工作的函数。若现有 `compact` 已自动迁回溢出，本轮应研究触发与作用范围，不将已有功能写成新实现。

**4.2 怎样知道维护划算。**

对照应从相同初始逻辑状态独立开始，使用相同后续操作：

| 变体 | 内容 | 回答的问题 |
|---|---|---|
| M0 | 当前维护规则 | 真实基线 |
| M1 | 选中的整理原语，按简单固定周期触发 | 整理本身能带来什么 |
| M2 | 相同原语，按状态条件触发 | 选择时机是否减少无用维护 |

如果要单独证明迁回效果，改用 M0 / 只压缩 / 压缩加迁回，先固定触发策略。两种问题分轮回答，不做一次包含所有组合的大网格。

主结果是完整工作负载的耗时，包含规则检查、整理、迁回、目录维护和分配。辅助结果才是溢出率、垃圾量、搬移量及空间。不得只在离线整理完成后计查询，然后把整理成本漏掉。

可以画出维护前后“累计耗时差随后续操作数变化”的曲线。如果维护后节省了每次访问，但在整个测试周期内仍不能回本，应如实判为当前负载不合算。一次维护的最坏观测暂停也要单列；搬移字节受限不等于严格的延迟上界。

**4.3 什么时候停止这个方向。**

以下情形不继续盲调阈值：合法空位很少；溢出主要是活跃记录的真实容量需求；频繁回收后很快又溢出；整理总成本超过其后续收益；只有隐藏维护时间才看见优势。

此时下一层才是“区域内重新分配容量并保留需求布局”，或对更新频繁的组预留余量。两者均需同预算评估：保留余量会牺牲初始装载率，不能宣称静态空间最紧凑和动态维护最便宜同时无代价成立。暂不把模型重训加入这轮，以免无法区分布局作用。

**5. E27：独立改善范围扫描，预计 2–3 天**

目标是减少扫描自身的多余工作，同时保护点查。E23 已说明扫描比有序数组慢，但尚未把原因定位到某一项；有序数组的连续遍历本来就是强对照，不预设最后必须超过它。

首轮检查四个量：起点定位次数、访问空组/空子块数量、合并时的比较次数、输出键复制与分配量。

**5.1 起点只定位一次，随后维护游标。**

概念上使用 `lower_bound(start)` 初始化，再由 `next()` 保留区域号、组号、子块号、主块位置与溢出位置。主块记录在已经验证的键序不变量下形成有序流，与溢出有序流作归并。不能为每个返回键重新调用点查，也不应先取出整个区域排序后只返回少量结果。

如果当前实现已经如此，不重写游标，只优化诊断发现的额外工作。扫描起点允许不存在；不能把点查得到的组号当成完整的 lower_bound 答案。空子块、已删除边界、组末尾、区域末尾必须按现有正确语义推进。

**5.2 用非空位图跳过空组，必要时再加入子块位图。**

每个逻辑组用一位表示“主块或溢出至少有一条活跃记录”。对 G 个组，原始位图需要约 G/8 字节，另有对象、对齐及可能的层级目录成本。最后一个记录被删除时清位，首个记录插入时置位。

必须把仅含溢出的组标为非空；不能只看主块计数。子块位图先只用于主块流，不能据此跳过整个组的溢出。更新开销和空间必须进入结果。

若空组访问本来极少，跳过此项。E9 的空组分布只是动机，不能直接代替当前 E23 状态的诊断。

**5.3 减少完整键物化的中间副本。**

对需要返回拥有所有权的完整键的 API，尝试直接在输出字符串中一次准备空间并追加“共享前缀 + 后缀”，避免不必要的中间字符串。保留返回键值、顺序与生命周期语义。

可增加不物化的内部访问接口帮助归因，但原型返回视图、基线返回完整字符串的计时不能放在同一排名。正式扫描仍让双方返回同样的完整结果。

先只测冻结版与新增一个组件的版本，成功后再叠加下一项。保留 E23 的初始/插入 25%/替换 25% 状态，以及长度 16/128/1024；实际返回不足指定长度时同时报告返回数。还要复核更新成本与点查，不能只测扫描。

子块范围定位在 E11/E13 已研究过，其收益不是普遍成立的；本轮可以按既有开关诊断，但不将“重新打开它”写成新机制。

**6. 模型预测究竟占多少：做一次有边界的诊断，不先动模型**

更新路径的预测调用次数应在 E24 一起记录。若后续仍要专门解释 S 与 ART 的点查差距，可以加入：

- 对同一混合查询序列采样，观察外层路由、模型、指纹、主块、溢出相关代码的样本分布；若硬件计数可用，再看 cycles、instructions、分支失误与缓存失效。
- 单独执行模型预测并保留结果，测其数量级；再测完整查询。两者缓存与流水线状态不同，不能把前者直接当作后者中可精确扣掉的一块。
- 必要时使用预先记录组号的诊断变体，观察“用数组读取替代预测”后的整条路径。该变体改变缓存、依赖链和访存，且普通查询没有预知组号，因此它不是可部署方案，也不是模型成本的精确测量。

若预测被证明确实突出，你仍可在索引职责内减少重复调用、避免后缀复制、复用本次预测已经产生的信息。改变模型表达与训练则交给模型负责人，共同约定接口后单独比较。

其他工程优化由证据触发：如果主要是内存等待，才尝试预取；如果主要是外层比较，才继续路由选型；如果子块访问多，才评估已有范围定位的条件启用。当前统一 `x86-64-v2` 基线已有的 SIMD 路径继续保留，不将 AVX2/AVX-512 扩展混入同一硬件预算下的对照。

**7. 从哪些 baseline 借鉴，哪些部分属于你的工作**

| 来源 | 有依据的借鉴点 | 在你的方案中的用途 | 边界 |
|---|---|---|---|
| ART | 按实际占用使用不同节点大小，紧凑的键/指针表示，Node16 可用 SIMD 搜索 | 借鉴小结构快速定位与容量随状态调整的原则 | 不照搬整棵 ART；不把节点自适应称为原创 |
| ALEX | 为更新保留空间、局部扩缩容及基于成本的维护选择 | 帮助设计维护触发、预留余量和包含维护的评估 | 它主要处理数值键，不能直接把其槽位模型当作字符串字节预算 |
| LITS | 有序紧凑叶、哈希筛选与扫描迭代；更新先定位再修改 | 参考统一定位、减少碎小节点访问和有序扫描组织 | 模型与混合子树机制不是本轮要复现的内容 |
| B+ 树实现 | 叶内有序数据、迭代接口、局部搜索与存储布局取舍 | 参考 lower_bound 与持续迭代接口设计 | 连续有序数组仍保留为扫描对照 |

这些来源的支持分别见 [ART 原论文](https://db.in.tum.de/~leis/papers/ART.pdf)、[ALEX 原论文](https://jiayuasu.github.io/files/paper/alex-sigmod2020.pdf)、[LITS 扩展论文](https://arxiv.org/pdf/2407.11556) 和 [STX B+ Tree 作者文档](https://panthema.net/2007/stx-btree/)。本次主要核对 ART 第 III 节、ALEX 第 4.3–4.4 节、LITS 第 3.1 与 3.3 节；没有据此保证原型能取得论文中的性能。

适合尝试形成贡献的表述是：**在固定字符串模型与逻辑分组下，结合槽位、后缀字节和键序三种约束，设计受预算限制的物理布局维护，并评估其对更新退化的缓解作用。**

这目前是研究假设。统一定位、位图、SIMD、压缩、延迟收缩本身都是已有工程思想。要主张研究创新，还需与已有维护方法比较，说明组合中的具体新机制和适用边界，而不是用“实现由自己写”替代新颖性论证。

**8. 实验怎么做，才不会再次被测量口径误导**

**固定起点。** 冻结 R1 为对照；模型、数据、编译参数、查询语义、种子与初始规划保持一致。先做单组件对照，再测最终组合，ART 在当前轮重新运行。不乘历史比值，不沿用旧轮 ART 绝对耗时。

ART 比较继续限定在当前适配器已经通过检查的无 NUL ASCII 键域，固定 libart 版本、键所有权和值表示。原型针对嵌入 NUL、高位字节的功能测试另列，不能扩展 ART 的适配范围后直接沿用旧正确性结论。扫描中 ART 仍不进正式排名，除非之后单独提供并验证语义匹配、代价合理的实现。

**分开三种构建。** 正式计时关闭诊断计数器与分配包装；计数诊断记录执行工作；内存诊断记录已覆盖分配接口下的请求字节。算法本身必须使用的维护统计和触发检查仍留在计时程序中，不能当成“诊断开销”删掉。

**动态计时覆盖维护。** 索引操作、触发检查、整理、分配和同步更新元数据均计入；输入生成、参考容器与答案核对放在区间外。若维护由单独调用完成，其时间必须纳入同一完整工作负载，不能只报前台操作。

**每次重放从独立状态开始。** 动态测试不能在已经改变的索引上重复同一批操作并称为重复实验。各方案使用同一操作序列、相同初始键值与明确的合法操作前提。

**正式负载限定规模。**

| 用途 | 负载 |
|---|---|
| 不变量控制 | 只更新已有键的固定宽度值 |
| 沿用比较 | E22 的邻近插入、删除后补入，到 25% |
| 长期维护 | 活跃记录数近似不变，累计替换到 50%/100%/200% |
| 检查未覆盖路径 | 明确构造能触发前缀变化、区域分裂的输入，并用事件计数确认；先做小规模正确性，再决定是否扩大计时 |
| 受影响读路径 | 同一混合点查序列；扫描沿用 E23 语义 |

每个检查点同时保留固定查询序列和固定命中比例的查询，两者分开报告；答案与命中标签按当前真实状态生成。偏斜插入的生成规则必须固定，不将只插尾端无意混成均匀增长。

**重复与统计。** 初筛采用少量独立进程；只有明显有价值的候选进入确认。确认前固定运行数量，例如 5 个独立进程、分至少两个运行时段、每进程 5 个配对重复；这只是最小计划，不自动代表统计充分。随机或平衡方案顺序，每次从等价状态重放，预热规则一致。

以单次重复的 `候选耗时 / 对照耗时` 作配对比值；先按进程汇总，再报告跨进程中位数、范围与同向进程数。若给区间，要尊重同进程批次相关性，不能把全部批次当作独立样本。预先规定分析办法，不持续重跑直到出现有利结果。

E23 比值离散的最坏情况很大。若结果只差几个百分点且仍在噪声内，结论写“未分辨”，保留旧默认；需要时换安静机器复核，不用堆更多同环境批次掩盖问题。

**尾延迟。** 主计时使用整批计时；维护事件时长单独记录。若测单操作 P99，使用另外的采样延迟模式并报告样本量与打点影响，避免让 ns 级操作全面承担时钟开销；样本不足不宣称可靠 P99.9。各阶段 P99 不能相加。

**空间与正确性。** 新元数据、临时缓冲和保留容量全部入账。差分验证覆盖值、存在性、扫描顺序及完整结果，不只比校验和。专项检查包括中间空子块、仅溢出组、目录边界删除、长后缀、槽位与字节错配、重复插入、失败后旧状态不变。适用工具链有 ASan/UBSan 时用于新维护路径；工具不可用时记录限制，不把已有固定种子门当作内存安全证明。

**9. 什么算成功，什么情况下不合并**

| 方向 | 必须看到的机制证据 | 采纳条件 | 退出/保留可选的条件 |
|---|---|---|---|
| 统一定位 | 不必要预测、完整比较或重复搜索减少 | 写操作完整耗时有可区分收益，点查无明确退化 | 只是代码统一，成本没有改善或只读路径变慢 |
| 组级维护 | 合法回收量兑现，垃圾/溢出/保留容量中的目标项下降 | 包含维护的总成本有收益，或明确以可接受时间代价换空间 | 整理不能回本、尾部暂停过高、无空间却反复尝试 |
| 扫描路径 | 空访问、重复定位或复制减少 | 相同返回语义下更快，新增更新成本和空间可接受 | 只有无物化诊断变体快，正式扫描不变 |

项目管理上可以把“目标负载的完整耗时下降约 10%”作为优先保留的工程目标，把“长时替换后的空间增长受到控制”作为维护目标；它们不是预测结果，也不是统计显著性的替代品。对点查可预先约定 5% 的实用退化容忍界，但若噪声不足以验证这一界限，就不能声称没有回归。

达到这些目标后再看与 ART 的差距缩小了多少。没有全面超过 ART 也可以形成有效成果：需要清楚回答在哪些字符串分布、更新模式和扫描比例下，本结构有意义。
