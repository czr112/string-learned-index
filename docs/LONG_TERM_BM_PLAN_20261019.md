# BM下一阶段详细长期计划

日期：2026-10-19。本文是当前执行计划，接替[10月18日计划](LONG_TERM_BM_PLAN_20261018.md)的后续顺序。
起点为[最新结果复核](../07_Eval_Integration/AUDIT_BM_NEXT_PLAN_20261019.md)，而非沿用旧总表的“根入口通过”。
本次完成了结果核对、原数据重算和单格精确复验；下述新的实现与性能实验尚未执行。
剩余工作预算约3–5个开发周，按单人串行估算；阶段不过门就停止或缩小，不承诺把所有条件分支都做完。

| 有限动态正确性 | 2数据×2读写比各20k操作，四格失配0 | 均匀find+insert增长；只有两格sanitizer，无全操作吞吐排名 |

| 16键分块根原型 | 路由正确、复制量算式有潜力 | 标签错位后真实短键路由约1.99–2.06倍；原入口通过结论撤回，未集成 |
| 干净复现 | 同ELF；本次两次原始输出的确定性字段一致 | 旧“差28”可由Number精度重现，但旧stdout丢失；未从零重建全部依赖/整轮 |

当前可继续工作的核心是**原BM + 现有物理页 + 按页构建 + FlatRoot**。
生产默认仍Context16。空间结果可作为有边界的研究结论，不能自动升级成默认配置。
新计划不把“复制量算式少”写成“真实写入更快”，也不把“未分辨”写成“严格相同”。

## 2. 剩余目标与判断标准

1. **先让结果可信**：执行路径身份、输入、原始整数、预算方向、模型/adapter版本和失败记录均可核对。
2. **形成完整的BM动态取舍表**：在相同操作流和当前map下，给出查询、写入、维护、暂停、常驻及峰值。
   对照ART和Context16只使用双方都真实支持的操作；上游native的insert子集另列。
3. **只优化实测瓶颈**：根确有足够成本才做新根。若主要成本在叶页重建，优先保留FlatRoot继续评估，
   不因已写过根原型就把集成视为必做项。
4. **交付等级分开**：组件证据、显式实验场景、生产采用各有独立结论。
   通用静态采用仍沿用完整find/ART≤1.10及风险格要求，不为已有负面结果事后放宽。

固定口径：

| 指标 | 定义与门槛 |
| --- | --- |
| 动态读预算 | `elapsed(dynamic)/elapsed(same-final-map snapshot)≤1.15`；直接逐轮配对，不倒数汇总中位数 |
| 空间必要条件/目标 | 有效常驻requested<ART；目标≤0.70 ART。保留输入必须计入，失败格逐格公开 |
| 构建组合 | requested峰值≤ART、未插桩构建中位耗时≤1.20 ART；构造和适配器转换全部入账 |
| 新根的优先级触发 | 至少一个登记场景中，根准备/发布占结构写时间≥10%，或其临时量占结构写峰值≥10%；须在诊断轮测得 |
| 新根研究目标 | 工作量下降≥25%只是必要线索；还需实测结构写耗时降低≥10%或结构写峰值降低≥20%，完整读预算仍通过 |
| 明确性能收益 | 默认≥4/5进程同向且幅度超过本轮双方AA观测带；AA不是置信区间 |
| 正确性 | 逐操作、终态全键值、owning scan、空/NUL/高位字节、0/MAX值及回滚零失配 |

新根触发和收益阈值是本计划给未来实验的新登记条件，不追改旧根实验的绝对5%门。
构建中位数仍只是观察量；若用它做性能排名，要另有配对及噪声控制。

## 4. P0：先把测量与证据链收口

已完成的审计不用重做。下一实现单元仅修评测与身份，不改模型算法。

1. 用单一arm描述表绑定`label / 实际实现 / 对象ID / 调用函数`，AA必须指向同一对象。
   在计时前用可区分的路径计数确认真实调用，防止两个答案相同的路径被错标后仍过checksum门。
   复核器检查这些字段，不只检查标签集合和结果相等；NDEBUG下仍必须执行必要检查。
2. 校验和跨工具用十六进制或十进制字符串；保留原始stdout/stderr，Python整数做权威比较。
   不让uint64经过JavaScript Number或浮点表格。时间、RSS等非确定字段不得混入语义相等检查。
3. 将正式读预算改成dynamic/snapshot；保留原值及原始直接配对。
   终态行数必须等于`初始数+成功新插入−成功删除`，去掉`or True`等失效断言；逐键值与scan独立核对。
4. 找回与旧SHA一致的规格/验证器版本。可从Git/blob或冻结副本追溯；找不到就如实标不可恢复。
   发布新的验证器身份和审计结果，不覆盖旧raw/decision/verification、不补写旧哈希。
   规格冻结后只读，执行结果放独立报告；本轮所有新增工具一起冻结。
5. 核对当前总表的每一列来自哪轮、哪臂、哪种计量。候选/参照/自研控制分别命名，跨轮数值不相乘。

验收：故意交换两个arm、改变一位64位校验和、删掉终态键时，新检查均能拒绝；正确记录可精确通过。
修复后只在新目录发布验证，不为了掩盖旧错误补跑一组“更好看”的性能。

## 5. P1：量清根是不是值得优化

先使用现有FlatRoot，不把旧字符串分块原型接进Index。

- 复用冻结的words/URL 95/5和80/20轨迹，另取固定分布、固定初始占用率的一组规模梯度。
  用32/64/128页为基础，来源允许时补256页；改变规模时保持键形态及每页写压力可比。
  官方真实数据采样器上限为100k，不能悄悄改上限或重复键来称百万规模；已有合成/其他来源大样本独立标注。
- 每次结构写分开记录：源页读出、页内排序/复制、BM拟合、arena建立、根prepare、提交、旧根/旧页释放。
  记录实际当前页数、受影响页数、克隆块数、复制key字节、allocator请求以及相邻页合并影响。
- 实测根准备和回收时间，区分“平均复制条目/初始页数”与“每次发布复制当前整根”。
  解释原1.50–1.52比值中的页数增长，不把它解释为每次冗余复制1.5份当前根。
- 成本诊断可插桩，吞吐比较用未插桩二进制；oracle、逐操作校验和计时器开销不混入正式混合吞吐。
  暂停采样另跑，不能把包含std::map校验的单进程max当作纯维护延迟。

验收：所有维护事件可对回trace和最终map；准备、发布和回收都在总成本中，无工作移到计时外。
决策：根达到触发条件才进入P2；未达到就暂停根优化，保留FlatRoot进入P3。
该诊断最多3日，不把进一步扩评测工程当作主要产出。

## 6. P2：只做一个另行登记的新根机制

候选方向是**保留现有digest快速辨识的共享分块根**；固定16项作为初始设计，
不继续用已失败的两级纯完整字符串比较来代表低开销COW，也不在16/32/64间搜索最优参数。
真正需要比较的是发布、分配和回收，而不是`块首数+16`的公式。

1. 独立实验类型保留FlatRoot对照；先登记数据、顺序、重复、实际算法和适用范围。
   如果要限定大根，只能按预先固定的页数/构建特征选择；另取确认样本，不能按语料名或已知答案开关。
2. 绑定真实页指针；明确谁拥有边界key、块、摘要和前缀。共享块不得指向已回收页或变化后的arena。
   单页替换、分裂、两邻页合并、删除空页、块边界变化及全局prefix变化都必须覆盖；
   若prefix变化需要全量回退重建，其频率、时间和峰值全部入账。
3. prepare阶段完成所有可能失败的分配，commit保持一致发布；失败保留旧索引完整可读。
   覆盖新块、块首数组、摘要、key复制、根准备以及提交前的注入失败点，核对页/根/dirty归属及释放。
4. 账本同时记录块首索引、引用计数/指针数组、共享活块、被替换块、暂存旧根和回收。
   顶层复制仍可能是O(页数/16)，不得声称已经变成O(log页数)的路径复制。
5. 先与FlatRoot做完整find同轮比较，包含页/模型/完整键校验；
   通过后再做同最终map的动态/快照读预算，以及真实结构写/峰值比较。
   两方均带同对象AA，五独立进程，顺序预登记；容量追踪程序与计时程序分开。

停止条件：正确性/所有权失败先修，原失败保留；无真实写入或峰值收益则关闭具体候选。
本计划最多允许这一个新根候选；它未过门就保留FlatRoot，不再叠第二层目录或改门救结果。

## 7. P3：有限全操作动态对照

固定words与URL，95/5、80/20两档，先均匀目标，分别做增长和固定键数替换，共8格。
初始轨迹预算沿用20,000 primitive操作；只要唯一键池充足就固定该数，不按结果改变长度。

| 项 | 冻结要求 |
| --- | --- |
| 对象 | 当前有界构建BM+FlatRoot；P2通过时另加新根候选；固定项目ART；同contract重编的Context16 |
| 读写分母 | 一次find/insert/update/erase各算一次primitive；替换的erase+insert算两次写，不能算一次 |
| 增长 | 写入成功insert:update:erase目标2:1:1；公布各类实际成功/缺席/重复数与净增长 |
| 固定键数替换 | 成功update:erase:insert目标2:1:1；erase/insert成对，配对后规模回到初始；过程中的缺口语义单列 |
| 查询 | 目标90%命中，按当时map生成并冻结；额外0%/100%端点另列，不改变主轨迹 |
| 失败尝试 | 重复insert、缺席update/erase在语义门单独覆盖；计时若加入则事前固定比例并公开实际数 |
| 构建 | adapter转换、bulk_load、临时量全部计入；每个对象有独立实例，复用同一不可变输入/trace |
| 维护 | compact固定在trace规定边界，时间计入总批次；同时保留含/不含维护的分项，不能只选较好一项 |

先逐操作独立oracle、终态全量键值/scan，8格均做普通及ASan/UBSan/LSan；通过后才计时。
活动页重建继续限制为最多两相邻源页、单次≤2049活行；纯值update不得新增dirty或根发布，
干净compact应无重建。最终map相同的差分实例必须逐项验证这些维护不变量。
正式计时回放完全相同的冻结流，不在热区跑oracle；先验收过的expected结果用于回放后核对。
5进程×6轮的预登记平衡顺序，每个比较对象附同对象AA。记录完整混合批次吞吐，
另在诊断程序拆出find、页内写、重建、根发布与compact；不把计时器主导的单次测量当正式吞吐。

每格发布：mixed ops/s、读/写实际组成、成功操作数、维护次数、暂停p50/p95/p99/max、
常驻/临时/峰值、最终map快照读预算、构建成本及相对ART/Context16的同轮直接比较。
即使动态/快照≤1.15，也不能据此称BM比ART更快；空间收益与吞吐代价都要列出。

P4入口：8格零失配、读预算通过、维护边界正确，且至少一个登记场景有可复现的空间/峰值或吞吐净收益。
如果只有空间优势，标“空间优先实验场景”并明确吞吐代价，不升级为通用速度配置。

## 8. P4：有条件扩24格与规模边界

矩阵为words/URL/phrases × 95/5、80/20 × 均匀/集中写 × 增长/替换。
集中写规则固定为80%写目标落在10%的有序页区间，区间由固定seed选择；记录受影响页和覆盖范围。
热点规则是合成负载，不称真实访问日志。更新后的区间边界和新键来源也必须在生成器中固定。

仍保留短语风险格，不以三类平均值掩盖其0.731空间目标失败。
增补tranco短键风险格及长key/空/NUL/高位字节的语义门，不把它们混进24格总数。
百万唯一键或更大真实数据要另找有来源、有足够唯一键的输入、单独登记，不从100k外推。

只有前8格支持继续时才一次冻结这24格；不逐格边看结果边改参数。
如果集中写导致重建、compact或根回收失控，先交付失败格与范围，关闭该场景。
HOT必须修复原适配器泄漏并重新验收后才能恢复排名；其缺席不阻塞其余基线。

## 9. P5：全依赖复现与最终配置

- 新目录、无历史.o或.a：从固定源码重编BM库、benchmark组件、ART和最终adapter，记录完整依赖及工具链SHA。
  不把“重新链接两个历史静态库”当作全部依赖干净重建。不删除旧build来腾出同名目录。
- 正式包装自身重过公共contract、所有权/异常安全、必测语义和sanitizer；实验driver通过不替代正式adapter验收。
- 逐确定性字段精确比较，时钟/RSS/地址等观察量独列。跨目录ELF不同不自动意味着语义失败，
  同路径ELF相同也不能替代全输入语义验证；路径宏与编译规范化另列。
- 性能只要求新轮结论在其AA观测带及预登记预算下可重现，不要求纳秒计时逐字相同。
- 最终最多保留：兼容默认Context16、明确边界的BM实验场景、确实通过动态门的BM配置。
  原生native支持子集和自研F5单列。各配置附来源、能力、选择条件、失败格、复现命令及全部成本。

最终结论可以是：通用采用、限定场景、仅组件证据，或停止具体候选。
本计划没有预设BM一定超过ART；默认采用必须独立满足现有通用门，不能从空间账本推导。

## 10. 立即执行顺序与停止规则

下一次工作先完成P0的新身份复核器，再做P1成本分解；不要直接集成旧分块原型，也不要先跑24格。
上游若有更新，先只读检查差异，当前正在验证的固定快照不覆盖；有关数据/代码变化另开身份。

- 验证或sanitizer失败：留存原始失败，修明确问题；不得据失败轮作成功排名。
- 两次合理尝试仍无实测净收益：关闭具体机制，转已有FlatRoot或明确空间场景；不靠追加重复救结果。
- 每个诊断单元最多2–3日；每阶段交一份结果、判定和下一步，不无限扩评测设施。
- 若只有空间优势、动态开销不可接受：交付空间/构建成果与边界，结束通用动态替代目标。
- 无并发写、事务或持久化支线；并发find只有单独证明生命周期和无lazy写后才另立任务。
