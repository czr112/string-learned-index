# BM下一轮详细长期计划：统一候选、公平对照、降低叶页重建成本

日期：2026-10-20；起点`35f566e`工作树。主对象仍是用户提供的BlockModel，
当前固定模型3894c767、benchmark003a55bf；后续研发与实验显式选择BM。
本文接替[上一轮P0–P5计划](LONG_TERM_BM_PLAN_20261019.md)，依据[本次原始记录复核](../07_Eval_Integration/AUDIT_BM_P0_P5_20261020.md)。
本次完成了审计和规划，以下新factory、轨迹、结构候选与性能轮尚未实现或执行。

## 1. 当前证据与下一轮要回答的问题

| 已有证据 | 可以使用的结论 | 仍需补齐 |
| --- | --- | --- |
| 原BM及完整上游参照、失败查询族 | 模型实际接入，失败机制保持关闭 | 不重做旧候选，不切回自研预测器 |
| 空间/构建两seed与100k词表 | 常驻约0.427–0.731 ART、峰值约0.437–0.756 ART；按页转换有效 | 最新统一factory的同轮全成本、读延迟取舍 |
| P3/P4轨迹零失配 | find+insert、find+update在这些轨迹上正确，值更新零重建 | erase、删后插新键、扫描负载；新语义必须另验 |
| P4集中组观察更便宜 | 仅能描述其自身轨迹 | 实际hot写8.3%–10.1%、新插入更少、命中率不同，因果结论撤回 |
| P1根prepare占批次2.8%–7.4% | 目前将根优化后移合理 | 叶页构造和约一半other的分解；非通用规模定律 |
| P5依赖重建与100/100 | 该次旧包装的公共接口通过 | 包装仍全量复制+window查询，与有界构建/base候选不是一个入口 |

下一轮要回答三个问题：

1. 同一个正式BM实验factory，在同一工作负载下，相对ART/Context16的空间、读写吞吐和尾暂停是什么取舍？
2. 增长触发重建主要因为页满、块槽满、arena字节不足还是前缀变化？复制、拟合、分配各占多少？
3. 一个有针对性的叶页改动能否带来实测增长收益，同时保持查询、内存、所有权与异常安全？

旧P0–P5中已经可靠的结果不重跑；下一轮只补上与这三个问题直接相关的入口。
F5仅在需要内部控制时单列，LITS不进入优化主线，旧分块根继续关闭。

## 2. 目标、门槛与预算

下一轮预算约4–6个开发周，单人串行估算，按阶段证据停止或缩小。
这是研究预算，不预先承诺BM通用超过ART。

| 顺序 | 主要工作 | 预算 | 交付 |
| --- | --- | ---: | --- |
| R0 | 统一BM实验factory及接口身份 | 1–2日 | bounded构建+find_base+FlatRoot，同一入口普通/sanitizer/contract通过 |
| R1 | 少量公平轨迹与外部配对基线 | 3–4日 | 先4个增长格，BM/ART/Context16同轮；修正热点及成功率，加入真正键替换 |
| R2 | 叶页重建触发与子阶段成本 | 2–3日 | 原因位图、时间/请求字节/重写量分账，选定一个候选或停止 |
| R3 | 一个单机制叶页候选 | 4–6日 | 差分实现、回滚与所有权、同轮收益及读/空间门 |
| R4 | 新样本、真实语义矩阵与规模确认 | 3–5日 | 条件扩24格，扫描/缺席风险格，规模只到可核验边界 |
| R5 | 同一候选全链重建与成果收口 | 2–3日 | 全依赖与正式factory同轮复验、明确场景与失败格 |

R0–R2最多约两周，必须产出明确对照或结构决策，不能长期停留在评测设施。
若R2没有支持某个改动的成本证据，跳过R3，交付外部取舍表，不为了走完计划强做结构。
若R3失败，最多允许另行登记一次替代尝试，总诊断/候选预算不扩大；不叠加两个未单独过门的机制。

未来实验统一判据：

| 指标 | 定义 |
| --- | --- |
| 结构正确性 | 每步和终态独立oracle一致；空/NUL/高位字节、前缀、0/MAX值、缺席及回滚零失配 |
| 动态读预算 | dynamic/same-final-map snapshot≤1.15，直接逐轮配对；不把未分辨说成等价 |
| 候选读回归 | 相对冻结R0基线完整find不出现明确>5%回归，另保留通用find/ART≤1.10门 |
| 候选增长目标 | 相同成功/重复/失败次数下，成功新插入成本目标降低≥15%，且至少两类真实键、≥4/5进程同向并超过AA带 |
| 总批次 | 报纯索引混合吞吐，不能只给成功插入的较好分项；主风险格无明确>5%整体回归 |
| 空间预算 | requested常驻≤R0的1.05；原已达0.70 ART的主场景仍需保持该目标；失败格逐格列出 |
| 空间替代成果 | 若没有速度收益但重建峰值下降≥20%，只按空间组件报告，不称增长加速 |
| 构建预算 | 相对R0不出现明确>20%构建回归，全部adapter转换计入；旧ART组合门单独保留 |

AA是双方同对象重复的观测带，不是置信区间。计时结果、空间目标、采用资格分别判断，不用跨轮比值相乘。

## 3. R0：把“当前BM”固定为一个实际对象

新实验factory基于现`bm_bounded_adapter.hpp`：直接接收contract rows，
按页转换，外部find调用find_base，保留原BM、2048行页、15/16槽布局与FlatRoot。
用清楚的新名字注册实验入口，不覆盖旧`make_bm_page_index`的历史身份，不改变原项目常规运行行为。

- Descriptor与identity同时记录模型commit、核心/adapter SHA、build_mode、lookup_mode、root_mode及能力。
  不使用`p5-fresh-core`之类占位版本代替哈希；factory/计时臂/实际对象从同一描述表绑定。
- 公共contract、三类真实语料全行/缺席/owning scan、边界字节与回滚门均通过普通及ASan/UBSan/LSan。
  scan结果在索引销毁后仍有效；查询零分配声明通过分配账本验证。
- 新factory和现有bounded/base核心作差分：页边界、fences、模型输入/参数、查询答案与维护计数一致。
  接口包装若造成明确>5%完整find回归，先定位包装，不把它归因到模型。
- 新建目录重编实际链接的依赖并运行这个factory；记录完整命令和退出码，验收失败必须退出失败。
  同一个入口用于语义、性能、分配与最终复现，插桩版本另列，不混用旧包装成绩。

交付`R0统一候选说明+manifest+公共/语料/差分门`，从此所有新结果指向此身份。

## 4. R1：先取得少量可比较的真实结果

第一组仅words、URL × 95/5、80/20的均匀增长，共4格；
BM统一factory、固定项目ART、同contract重编的Context16使用完全相同的初始map和操作流。
先语义，再纯索引计时，先回答增长代价及查询/内存取舍，再扩大场景。

### 4.1 轨迹必须验证实际发生了什么

每份轨迹公布：kind次数、成功新插入、重复、成功/缺席update与erase、动态命中率、净增长、扫描返回行数。
独立解析ops文件验收这些量，不能只检查生成器参数写了“80%热点”或“90%命中”。

增长先保留纯insert作为可解释的结构诊断；另立真正键替换：
写primitive按update:erase:insert=2:1:1，erase与不同新键insert配对。
一次替换是两次写；配对后键数恢复，中间缺口的语义公开，不承诺原子事务。
旧纯update格保留为低成本控制，统一改名value_update，不再叫键集合replacement。

热点采用与索引实现无关的**冻结源键序范围**：10%的源键区间承担80%的写，
实际BM受影响页数单列，不能用BM的页划分给其它索引定义不同负载。
均匀/集中一对共享初始map、操作kind顺序、成功新键数、重复数、查询命中数和扫描长度。
键目标随局部性改变，其长度/LCP分布及实际成功率也须公开。

先预留热/冷新键池，再生成共享初始map；每次成功insert取尚未出现的新键，不能用有放回抽样填足次数。
容量检查要求`hot_new_pool≥0.8×成功insert数`，原64k/4:1随机切分可能无法支撑20k操作的热点增长。
默认目标20k primitive；池不足时在冻结前统一调整初始划分或整轮长度并记录，禁止运行后追加重复插入补数。
每次find按当时map生成预定命中/缺席，不能从完整源池抽键后把不存在的键仍算“命中”。

### 4.2 校验、吞吐和诊断分开

- 语义回放逐操作跑oracle，校验最终键值、全量scan、维护不变量；性能回放不在计时区维护std::map。
- 性能计完整操作批次，回放后核对准确返回码/值/拥有的scan输出及字符串化校验和。
  构建、compact、扫描buffer分配/释放都单列；compact如在trace中规定，就计入总批次。
- 起始三对象各自附AA，共6臂，5独立进程、预登记6轮平衡顺序、CPU/ISA/flags固定。
  新候选加入时重新冻结包含双方AA的顺序，不边看结果边追加轮数。
- 公布mixed ops/s和实际写组成；单次暂停分位在独立诊断程序采集，不把逐操作计时器开销当纯写代价。
- 成功新插入成本用独立、无oracle且新键全部成功的插入批次测量；不从混合总时长减去估计查询时间，
  也不把混入重复尝试的write_ns直接除以成功数。混合批次仍是端到端收益的权威。
- 点查覆盖90%主负载及0%/100%命中端点；owning scan先做17/128行的有限对照，再决定是否值得单列扫描场景。
  ART scan的适配开销与其原生/适配能力必须披露，不泛化为整个ART算法家族结论。

R1输出完整同轮BM/ART/Context16取舍表。若当前BM已经没有可接受的目标场景，则缩小后续研究，不扩全矩阵救排名。

## 5. R2：把增长成本细分到可修改的位置

保留FlatRoot及原BlockModel，不投入新根、增量读链或已失败查询机制。

1. try_insert记录原因位图与固定优先原因：PageFull、BlockFull、ArenaExhausted、PrefixMismatch、Empty。
   同时记录页live、目标块活槽、剩余arena、申请suffix长度及多原因并发情况，避免错误归因。
2. 分段记录：旧页scan/行物化、插入/排序、part临时Row复制、prefix/fence生成、arena/slots写入、
   BlockModel::fit、根prepare、提交、旧Page与旧Root回收、dirty维护；未归类时间也必须列出。
   现P1的reclaim只包旧根，不能继续把它当作全部回收成本。
3. 对成功页内插入、失败尝试、触发重建的插入分别给成本；最终每次成功新插入、每次重建及整批时间都要能对账。
   计时器间隙和插桩开销另列，R1未插桩批次是性能权威。
4. 复用独立allocation trace记索引有效常驻、构建/写入/compact峰值和输出buffer。
   共享输入排除、借用输入计入；RSS只作全进程旁证；模型、arena、map/set节点和释放归零都入账。
5. 控制同一键形态的规模与初始占用率。官方真实采样器当前上限100k：
   65k/100k是真实确认，已有262k其它来源/合成输入另列，不能从100k宣称百万级。

验收：主场景的时间段/复制字节/分配/触发次数有原始记录，不能再把约一半other笼统称“页构造”。
诊断最多3日；只选择一个有测量支持的候选，否则停止结构改动，交付取舍表。

## 6. R3：一个单机制叶页候选

### 首选A：重建时消除part行字符串副本

当前路径先把旧页物化为rows，再复制成part，Page随后再次把suffix写入自有arena。
拟用**仅在构造期间存活的行视图/范围**消除part的逐key字符串复制，保持Page自持有最终数据。
只有复制/临时行分配占增长成本≥15%，或该副本占重建请求峰值≥20%时才实现。

- 原BM fit算法与参数、fence顺序、15/16槽、页大小、FlatRoot和find_base保持不变。
  候选预期减少每次重建成本，**不预期减少重建次数**。
- 旧页/输入rows必须活到新Page复制完成；模型前缀与训练view只能借用新Page自有稳定arena，
  不能在构造后引用临时RowView、旧Page或销毁的行buffer。
- 差分核对页/块布局、完整fences、payload/值、模型输入、查询Work与维护事件；持久requested常驻应相同。
  覆盖单页重建、2049行分裂、两邻页合并、空页和临时buffer销毁后的读/scan。
- 所有可能抛异常的准备先完成，注入各分配失败点，旧索引可读且dirty/根归属不变；
  仍最多两相邻源页、单次≤2049活行；纯值update无dirty/根发布，干净compact无重建。
- 通过普通及sanitizer后，在冻结R0基线上做同轮A/B及外部参照；不以减少的malloc次数代替实际增长收益。

### 有条件的替代B：arena预留与写余量匹配

若ArenaExhausted占重建≥50%、而A成本不足触发，则不实现A，另登记一个B：
保持16槽与原模型不变，仅把现有`bytes/32`字节余量调整为一组固定的`bytes/16`余量。
先静态预算每格额外常驻和峰值，超空间预算则不进入实现；不搜索多个余量选最好成绩。
预期减少arena不足触发的重建，必须用实际原因计数证明，不能把槽满或前缀失败归到本机制。

A、B不叠加。本轮最多把一个过门候选带入R4；任何替代都保留前次失败、独立规格和身份。
候选须同时满足第2节的增长目标、完整读预算、常驻/峰值和回滚要求。
若只有重建微基准变快、总批次没有净改善，则作为组件结果，不宣称系统加速。

## 7. R4：通过筛选后才扩展确认

主矩阵为words/URL/phrases × 95/5、80/20 × 均匀/正确的集中写 × 增长/真正键替换，共24格。
每格均公布真实kind和成功率；纯值更新是额外控制，不能代替删后插新键的格。
主矩阵scan权重可为0，但必须明确命名为点查/写入矩阵。
另登记小组扫描混合负载：scan占全部primitive的1%，17/128行限额，成功返回行数、分配/回收与吞吐同时报告。

- 矩阵先过全语义和ASan/UBSan/LSan，再计时；正式结果保留完整读预算和外部同能力对照。
- 开发用当前固定样本；确认在实现冻结后取未用于选参数的新seed，报告与旧样本交集，不能称独立来源。
  同seed较大样本的包含关系也公布；真实来源不足就标未覆盖，不重复填充。
- 规模至少确认可用的65k/100k；若引入新大来源，先来源锁定、唯一键与字节过滤审计，再谈更大规模。
- 缺席密集、长key、前缀变化、删除密集/反复更替、热点迁移、compact频率作为有限风险格，
  每项由前阶段证据决定，不能同时铺成无边界组合。
- phrases的0.70空间目标失败继续公开；若候选令原已达标主格跌出目标，不靠三类平均掩盖。
- 真实访问日志属于单独扩展：只有来源/权限/规模明确、负载可冻结时才加，不阻塞本轮合成负载结论。

HOT原适配器泄漏仍独立处理，未普通/sanitizer重新验收前不排名，不替换另一个HOT包装冒充已修。
24格如果没有有价值的新候选，就交付当前基线的完整取舍表，不为了增加格数继续跑。

## 8. R5：同一个候选的最终交付

从新目录、固定源码重建实际使用的模型库、benchmark组件、ART/Context16及BM实验factory，
保留全部命令、来源、库/二进制SHA及退出码；不吞失败，不复用历史.o/.a，不删除原结果。
对这个**同一factory**重过公共contract、三语料语义、回滚、sanitizer、分配及关键性能格。
跨目录二进制不必逐字节相同，但语义确定字段必须以精确整数/字符串一致；时间与RSS不要求逐字相同。

最终最多保留一个明确的BM实验候选及冻结基线，公布：
模型/adapter身份、所有权、支持操作、空间/构建/读写/scan/维护/尾暂停、失败格、数据源和复现命令。
完整数据和验证脚本一起冻结，报告与规格分开保存。

结论按三层交付：组件改进、明确取舍的空间/维护场景、或达到通用门的配置。
没有任何一项从“contract通过”“单次零失配”直接升级成“通用采用”。
全项目默认的切换是最后的配置决策；后续研发和实验始终显式使用给定BM，Context16作为既有参照。

## 9. 下一次执行顺序与停止条件

先R0统一候选，接着只做R1四个公平增长格；R2决定R3是否值得实施。
优先改叶页复制/分配或有证据的arena余量，不重开预测括号、payload、局部细分、cost/adaptive或分块根。

- 每个结构候选一次只改一个机制。两次合理尝试仍无端到端净收益，就关闭增长优化支线。
- 发现口径问题只补与当前决策直接相关的检查，时间盒内收口，不重新建立一套评测平台。
- 若查询/动态均不能达到通用门，保留已证的空间/构建组件成果及明确代价，结束通用替代目标。
- 并发写、事务、持久化不进入本轮；并发find需要独立证明生命周期与无lazy写后另立任务。
