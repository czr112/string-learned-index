日期：2026-10-11。H 已按原判据关闭，不换洞策略或负载重试。

## 1. 问题与范围

转回静态点查。外层 C 已有收益，当前优先减少 C 之后的主块探测。
matrix2 同输入诊断显示 tranco 每查询仍访问 2.91 / 2.53 个主块；普通子块目录虽能
降到一个，完整边界字符串比较使耗时反而为顺序探测的 1.156 / 1.094。
Q 拟将每个多块组的边界摘要放到连续数组，完整边界留在现有目录中，只在摘要相等时比较。
这与外层区域 C 是两个导航层，不将 C 的收益当作 Q 的证据。

固定 Context16/LitsHpt、普通 bulk_load、冻结容量与映射、原 matrix2 的 rows/queries。
C 开启；W/S/H 关闭。目标 tranco，mixed/skew 为风险格。源码基准：
index.hpp SHA-256 640660a32f1fd1476d0d889d541c007883e5597d70e476524e3bcf2556ec8aa1。

## 2. 有界入口诊断（先执行）

六格一次计数，关闭计时。以现有 boundary_dir 的实际边界建立不可变诊断摘要。
摘要固定为后缀前 8 字节、按无符号字节保序、短串补零；相等一律完整比较，含 NUL。
不试其他宽度、共同前缀跳过、标签表或自适应阈值。

逐查询与独立 unsigned-byte upper_bound 对照，核对 found/value 与 interchange oracle。
报告顺序/普通目录的主块与比较次数、摘要二分探测数、完整回退比例、未命中情况及新增空间。
空间按 8 字节/边界 + 4 字节/组起始偏移（含末端）+ 每区域两个 vector 对象计；
诊断复制的冷键单列，不宣称现有字符串目录可以删除。

每后端单独筛选：tranco 原查询平均主块访问 >2，摘要使目录完整比较减少至少 50%，
新增逻辑空间不超过当前索引记账的 5%，才支持静态原型。任一条件不足就收口该后端；
不从计数估算净加速比，不把未命中队列冒充完整查询队列。

## 3. 若入口成立：一个静态原型

在结果目录生成由上述哈希约束的独立 index.hpp 副本，补摘要数组和实验查询选项。
主索引源码、Config 默认值、适配器与既有输出不动。原型借用已有冷目录，静态构建后
生成摘要；不允许更新后继续使用。比较同一结构上 C+顺序、C+顺序重复、C+普通目录、C+Q。
5 独立进程 × 4 位置轮转重复；同重复配对，保留重复基线散布。计数构建与计时构建分开。
散布底预先定义为五个进程各自 S1/S0 配对中位数的 max/min。目标的 1/(Q/S0) 中位数
须超过该底，风险的 (Q/S0) 中位数若超过该底且至少 4/5 变慢，则判回归。
真实运行路由、模型、摘要、过滤与完整比较；禁止预存查询区域或候选块答案。

门覆盖逐语料键/查询及空键、NUL、高位字节、短串补零碰撞、长公共前缀、空目录和空子块。
ASan/UBSan 必须通过。tranco 耗时 Q/顺序超出重复基线散布且至少 4/5 同向，
mixed/skew 无超出散布的回归，才进入动态集成；否则记录负结果或未分辨并收口。
