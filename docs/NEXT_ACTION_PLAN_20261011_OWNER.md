## 1. 假说与唯一改动

每个 `Region` 现在**无条件**训练并常驻一份 Context16 参考表（`Model::cumulative`，
16 × 258 × u32 = 16,512 B，外加 vector 对象 24 B）。而查询与放置两条路径都按后端分派：
`predict_for`（查询）与 `canonical_group`（放置）在 `use_lits_` 为真时走共享 HPT 表，
**不读** `model_`。

假说：对**映射由 LITS 负责**的区域，这份参考表在查询/更新/扫描上从不被读取，
因此可以不训练、不常驻——前提是「有效映射、校准结果、拒绝域、回退覆盖」全部不变，
并且把仍需要参考答案的**诊断**改成独立的参考对象（其时间与空间另列）。

首版只讨论「LITS 区域是否可以不常驻参考表」这一问题；不试表的形状/精度/替换，
不改模型算法、概率表、组映射与 LITS 准入规则。

## 2. 一次六格入口（计数构建，无计时）

六格：mixed / skew / tranco × Context16 / LITS；`baseline_config(128)` + `pin_frozen_switches`，
C 开、W/S/H 关；普通 `bulk_load`；标准查询模式。

**开跑前固定的判据**

1. **审计完整**：`model_` 的每一个消费者都要有行号与分类（查询/更新/扫描路径、
   构建与 R1/preset 路径、参考诊断、失败路径、记账），且查询/更新/扫描路径上
   LITS 区域的 `model_` 读取为**零**。
2. **行为零读取（目标格 LITS/tranco）**：重放全部原查询与全部语料键期间，
   `Model::predict`（即 Context16 表入口）的计数增量必须**恰好等于**落在回退区域
   （`use_lits_ == false`）的查找数——一个可被证伪的恒等式，而不是「应该不会读」。
   同一恒等式在**构建期**（`bulk_load` 期间）也要成立。
3. **回退覆盖如实**：回退区域/键/查询的数量单独报告，且它们**不计入**可省字节。
4. **可省字节**：目标格的理论上限 = Σ(LITS 区域 `model_` 常驻字节)；报告占该格
   `index_bytes` 的比例，并列出仍然引用 `model_` 的接口（供原型阶段处理）。
5. **基线差分**：全部语料键与原查询答案与 interchange oracle 全等（本轮不改任何东西，
   这是装置自检）。
6. 若恒等式在任一格不成立、或存在查询/更新/扫描路径上的 `model_` 读取，
   即停：不建原型。

入口通过只支持**一个原型**（隔离副本：LITS 区域不训练/不常驻参考表 + 诊断改用独立参考对象），
不授权默认值或集成本身。

## 3. 原型阶段要回答的（不在本轮）

- 实测常驻节省是否达到「理论可省参考表字节」的 **≥90%**（覆盖区域、对齐、分配器开销都算）；
- 完整构建若无可分辨改善，仅按空间候选评价；构建出现可分辨 >5% 回归即停止；
- 点查/更新/扫描无新增可分辨 >5% 回归；Context16 控制臂不允许变化；
- preset/R1 路径的 `model_digest` 与参考诊断如何取得独立参考对象（其成本另列）。
