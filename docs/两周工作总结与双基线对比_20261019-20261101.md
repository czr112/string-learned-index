# 两周工作总结与双基线对比

**周期：2026-10-19—2026-11-01。** 本文按主题汇总模型接入、结构优化、工程正确性与评测建设；10月18日的接入工作仅作为背景。最新性能表只使用11月1日同一轮Linux结果，不与历史实验拼接。

近两周的主要进展，是把协作开发的 **BlockModel/TX8模型与结构组合** 接入、定位、维护与验证链路进一步对齐：完成多项隔离结构候选，修复构造和所有权问题，并形成覆盖五类语料、点查及动态负载的双基线比较。当前结果呈现明显的语料与负载差异，尚不能概括为所有场景优于ART或HOT。默认仍为Context16，隔离候选没有自动进入默认配置。

## 一、主要工作及取舍

### 1. 模型接入与定位路径对齐

- 明确了Context16、LITS-HPT和BlockModel的接口与训练目标。LITS允许区域回退Context16；TX8包含模型、事务页、根路由、纠错和适配器，不是仅替换模型的对照。
- BlockModel固定为`3894c767338a865d2920ba5e21283827fea1d803`。本周期后段的来源核对未发现新版本，因而工作集中于现有模型与结构的协同。Model16是同一模型的16段参数版本，不是Context16或新的上游算法。
- 10月19日审计把预测窗宽度、编码碰撞和纠错工作分开：URL类键存在明显的七符号同坐标现象，但不能将其他语料的成本一概归因于此。后续坚持完整字节fence和精确验证，不把训练样本半径当作所有缺席键的证明。
- 完成TX8、Model16 base及corrected的独立工厂包装。corrected调用既有精确纠错入口，没有另造模型；Model16包装仅支持构建、查询和扫描，写操作明确不支持。小型接口、身份漂移负对照和独立oracle验证已完成。
- 当前五实现面板是完整索引／适配组合的比较；Model16三路径是同对象定位消融。两种问题分别报告，不把结构差异解释为模型本身的单独贡献。

### 2. 从块再平衡推进到事务拆页与有界容量维护

- 10月20—25日将增长插入的重建来源进一步定位到满块，形成页内块再平衡，并补齐实际factory、负载、空间和查询分组核对。期间发现的入口不一致、悬空引用和统计口径问题已更正，早期摘要中的百分比不直接用作当前结论。
- 10月29—30日形成TX事务拆页：在旁路准备页、map节点和root，再进入不分配、不抛异常的提交区；修正容量增加或减少时的resident计量，保留完整separator与模型训练坐标。32条冻结轨迹、分配失败注入及空间保护门形成了可复核证据。
- 后续bounded-fence先确定精确前驱再访问payload，suffix方案减少维护选择器工作而保持查询、空间和K个后缀更新不变。grouped-map虽减少部分维护写入，却增加查询解码；terminal比较省略回报有限，均保持隔离。
- fixed-1/32 slack在冻结full32普通与sanitizer验证中，将每数组目的对象数从**1,245,633降至862,022，减少30.7965%**；拆分数组分配调用从**30,522降至12,074，减少60.4416%**。查询与既定空间门保持，7个无收益组合也保留。别名输入的冷路径失败回滚覆盖随后补齐。

上述是特定冻结机制实验的源级工作量与请求字节证据，不是等幅墙钟加速。fixed-1/32、suffix等仍是隔离候选；本次最新双基线表使用固定TX8包，**没有把slack候选的工作量减少算作TX8已实现的性能收益**。旧ordinal-map在长期删除压力下的反例、未通过门的方案和回滚记录均保留。

### 3. 正确性与工程修复

- 统一实际编译源码、descriptor及manifest身份，并增加漂移拒绝；历史结果保留原身份，不回填当前哈希。
- 修正MinGW下Region按值传递Config时触发的对齐栈存储问题。五个记录案例在修复版两个合法栈位置逐项重放通过；这支持限定正确性修复，不等于旧失败负载已有修复后性能数据。
- 修复既有Region构造失败的对齐存储泄漏：使用局部RAII owner，成功后才移交既有析构函数。四个旧泄漏负控复现；112次失败注入、23,668项构造／生命周期检查通过，独立审阅未发现阻断性源码问题。临时Config、LITS共享表释放后的维护及最终销毁均有覆盖。
- 预备混合运行库探针的旧堆错误仍未完全归因。已识别动态DLL分配不全部经过EXE跟踪器，但没有据此认定原错误必然只是测试工具问题；构造测试也不证明整个Index的强事务回滚。
- HOT使用稳定所有权适配器及独立迭代器补丁。原版33键删除在UBSan下仍触发`ctz(0)`，因此不进入有效性能排名；HOT-patched同一回归通过。另行准备的Windows移植补丁及helper验证是不同工作，不能与本轮Linux的HOT-patched混称同一版本。

### 4. benchmark协议、语料与证据链

补齐了数据来源、共同键域、负载配方、独立oracle、接口验收、源码闭包、编译选项、日志和suite完整性核对。上游工具固定为`94ead07a45af7cb5dd33a2a708683ec2ba4411b6`；动态轮的额外补丁只保存运行日志，C++ runner字节保持不变。

mixed/skew是项目合成键集合；skew描述共同前缀等键形态，不等于热点查询。Tranco来自榜单前段，words与URLs有锁定来源和抽样记录；访问序列由生成器合成，不是真实流量重放。真实来源、合成负载、结构机制驱动和统一suite各自标记，避免混用。

## 二、最新双基线比较的条件与完成范围

最新轮使用Linux、GCC/G++13.3.0、`x86-64-v3`、`-O3 -UNDEBUG`，串行构建和运行。五个实现是Context16、LITS（含回退）、TX8、ART、HOT-patched。同一比较单元共享数据和操作身份，先经独立正确性验证再计时。

五类语料为mixed、skew、Tranco、english words和MemeTracker URLs。第一阶段每份**4,096键**，第二阶段每份**16,384键**，这是本轮最大规模；历史65k／100k机制实验不计入本轮性能覆盖。

完整轮次合计**1,300个执行单元＝325＋325×3**：第一阶段125个点查单元加200个动态单元；第二阶段175个点查／扫描单元加150个其他动态单元，各完成三个独立进程。它不是1,300种独立场景，也不是每格1,300个统计样本。已完成suite未记录意外实现失败；早期中断的第二阶段12个单元保留但不进入汇总。同对象Model16消融另行报告。

URLs共同域从65,536个唯一键中**过滤420个**，采用ASCII、无NUL、长度不超过220字节的共同视图，为生成缺失键后缀留出空间；所有实现使用同一视图。原始URL中有超过HOT-patched长度域及LITS字节域的键，完整原始URL面板没有被这张共同域结果替代。

## 四、结果应如何使用

1. **结论强度。** 没有隔离系统负载、显式绑核或统一额外预热；主suite执行顺序固定，计时前验证可能影响缓存。三个进程的范围不等于置信区间，不能视为论文级排名。Model16消融有自己的预热和顺序设置，不能与主suite直接拼接。
2. **内存口径。** 各实现自报包含项不同，ART和HOT的总索引内存不可用；适配器拥有字节不等于完整索引字节。本文不按自报值排名，不把未取得的内存写成0，也不把请求字节当RSS。
3. **尾延迟。** 点查P50/P99来自独立、确定性分散抽样，第一阶段每进程最多200次、第二阶段最多500次，含计时器开销；P99尤其受样本量限制。混合负载没有尾延迟结果，吞吐不能换算为单操作尾延迟。
4. **能力与版本。** LITS允许Context16回退；Model16不支持动态写入；HOT-patched不是原版HOT。Windows移植helper通过不等于完整Windows HOT组合通过；本轮Linux结果也不补成Windows成绩。公共接口断言数受可选参数测试影响，不能仅凭计数比较覆盖完整性。
5. **历史证据。** 原Windows探索失败、旧运行库探针、中断轮和无效消融初版均保留。旧统计资格失败不被改写，也不拿来否定这轮已完成探索的事实；它们对应不同协议与结论强度。

## 五、后续联合优化重点

- 以当前同轮结果为起点，优先分解TX8读插／纯插入的页维护、事务准备、目录发布和模型重建成本；对fixed-1/32候选保持明确来源，只有同条件复核后才讨论其墙钟贡献。
- 联合检查BlockModel输出窗口、完整字节纠错与物理布局。Model16不同语料的正负观察都保留，不将某条路径固定当作所有语料的最优入口；定位子成本时避免同时改模型、结构和测量方案。
- 继续统一源码身份、成本口径与完整接口覆盖，针对构造、分裂和重建分别说明异常保证；新证据使用新身份，不覆盖历史结果。
- 在预先固定的多规模、更多独立进程、不同数据种子和共同域／完整域计划中确认趋势；将适配操作与原生能力、吞吐与尾延迟、空间与分配流量分开报告。当前最大16k不能外推到大规模或生产负载。

本周期已经形成可复核的工程与实验基础，也明确暴露了不同负载下的差距。后续工作围绕协作开发的模型与结构组合继续联合定位和验证；本文不代表默认切换、所有候选采用或全部目标完成。
