# BM 下一轮详细计划：可信验收（2026-10-23 → 约 10–15 个工作日）

**本轮只做规划，不执行。** 候选与生产代码在本轮内不修改；默认继续为 Context16。
条件研究最多 +5 日，总预算不超过 20 日。

## 0. 本轮要回答的问题

块内再平衡在增长语义下有 −40%～−59% 的观察收益，但它有**未验收的三类风险**：

1. **异常安全**：块分裂在分配失败时会丢键（见 §2.1）；
2. **空间**：现有"delta = 0"是在**重新构建**的同一 map 上测的，不是增量运行空间；
3. **性能证据**：计时回路内含正确性校验，且前几轮多为单进程，缺 AA 控制与配对轮转。

本轮的判断顺序固定为：**正确性（含异常回滚）→ 空间 → 性能 → 合规负载 → 泛化**。
前一项未过，不进入下一项，也不做"先看性能再补安全"的倒序。

## 2. 修复异常安全（1–2 日）

### 2.1 已定位的缺陷（必须最先修）

`bm_n1_page_core.hpp` 的分裂路径当前顺序是：

```cpp
Block tail; ...;                       // 复制后半 8 个 entry 到 tail
block.count=8;                         // ← 原块已被改写：后 8 个键从原块"消失"
stable_fences_.insert(...);            // ← 可能抛 bad_alloc
blocks_.insert(...);                   // ← 可能抛 bad_alloc
```

`block.count=8` 之后、`blocks_.insert` 之前若抛异常，**后 8 个键既不在原块也不在新块**，
`size_` 仍是原值 → 结构损坏且不可回滚。这正是"分裂分配失败后旧键丢失"。

### 2.2 修复要求

- **先分配、后改写**：把 `tail`、新 fence 元素、`blocks_` 所需容量全部准备好
  （`reserve` + 局部临时），确认无异常后再改动原块；
- 或采用"**先插入后切换**"：新建一个包含两半的临时数组，全部构造成功后再整体替换；
- 逐个覆盖三类分配失败注入：**目录数组**（`blocks_`/`stable_fences_` 扩容）、
  **块内 entry**、**字符串/arena**；
- 失败后必须满足：旧键值完整、`size_` 与 `sum(block.count)` 一致、
  `verify()` 通过、后续查询与插入仍可继续；
- ASan/UBSan/LSan 在失败注入版本上零报告。

### 2.3 门（预登记）

| 检查 | 判据 |
|---|---|
| 失败后键集 | 注入点前后全键读回逐一相同 |
| 计数守恒 | `size_ == sum(block.count)`，`blocks_.size() == stable_fences_.size()` |
| 可继续性 | 注入失败后继续执行 1,000 次插入/删除，终态与无注入轨迹一致（允许失败那次不同） |
| sanitizer | 三类注入 × 三语料，零报告 |

**未通过则不进入 §3–§6。**

## 3. 统一入口与空间核验（2–3 日）

### 3.1 正式 factory

- 新增 `make_bm_split_experiment_index`（与 `make_bm_experiment_index` 并列，不覆盖旧名），
  参数 `lookup=base`，payload＝再平衡候选；
- Descriptor 必须记录：model commit、核心 bundle SHA、adapter SHA、`build_mode=bounded-per-page`、

- 跑 R0 那套门：公共 contract、三语料全行/缺席/边界/跨销毁 scan、差分（页边界、fences、
  模型输入与参数、查询答案、维护计数）、`find` 零分配、包装 ≤5%（AA 带内）。

### 3.2 空间账本（判据已定）

- **口径**：在实际增长轨迹上，记录
  `请求字节常驻`（页 + 根 + 目录 + 模型 + fence + string heap，含 adapter 自身）与
  **进程峰值**；不使用"重新构建后的空间"替代增量运行空间；
- **门**：常驻请求字节 ≤ 同轨迹 BM 基线的 **1.05 倍**；
- 峰值单独报告（不设门，但需解释增量来源）；
- 对现有 diff 给出解释：块目录增量理论约 8 B/块；若实测远超，必须定位到具体容器扩容。

### 3.3 完成标准

完整请求字节账本 + 一份"增量来源解释"；据此**重新判断空间门是否通过**。
未通过则按预登记停止点：只登记**一个**容量或目录机制，最多两次尝试，不做参数搜索。

## 4. 公平性能验收（2–3 日）

| 项 | 设计 |
|---|---|
| 计时与校验分离 | 两条路径：`verify` 版（逐操作对照 `std::map`）只用于正确性；**计时版不含校验**（预言机在计时外或按批校验） |
| 平衡轮转 | BM 基线、候选、ART、Context16 四臂 + 各自 AA 臂；五进程 × 六 Williams 行 |
| 指标 | ①纯成功插入 µs/次（剔除重复与失败）②混合吞吐（按登记比例）③完整查询 µs/次 ④`dynamic/snapshot` |
| 门 | 收益：两类真实键的主增长格 ≥15%，五进程至少 4 个同向且在 AA 带外；查询：无清晰 >5% 回退；读预算 ≤1.15 |

同时报告：每次插入的触发分布（页满/槽满/arena）、重建次数、根发布次数，
以便把收益归因到机制而不是测量差异。

## 5. 合规负载验证（2–3 日）

| 要求 | 具体做法 |
|---|---|
| 真键替换 2:1:1 | 按**成功操作**计比例；erase 与不同新键 insert 配对；活跃键数守恒 |
| 热点 | 80% 写目标落在**源键序** 10% 区间（与索引页划分无关）；实测比例须达登记值，偏差要解释 |
| 扫描 | limit=16 与 limit=128 两档，占比固定并公布 |
| 一致性 | 各臂的初态、命中率、成功率、失败原因逐项公开且相同 |
| 判据 | 若替换/扫描语义无收益，明确记为"该场景无效"，不并入增长格结论 |

## 6. 泛化与收口（2–3 日）

- 复验 65k（三类键）、100k 词表与**一个独立样本**（新采样种子）；
- 全部经**同一正式入口**重跑，出一份取舍表：场景 / 收益 / 代价 / 已过门 / 未过门；
- 明确写出：哪些场景有效、代价多少、哪些门仍未通过、以及"不替代 ART"的结论是否仍成立。

## 7. 预登记判据（本轮全部适用）

1. **正确性先过门**：异常回滚未通过，不进入性能采用判断。
2. **空间据实判断**：常驻请求字节 ≤ 同轨迹 BM 基线 **1.05×**；不得用重建后空间替代增量空间。
3. **收益保留原门槛**：两类真实键主增长格 ≥**15%**，五进程至少 4 个同向且超出 AA 噪声。
4. **查询守门**：完整查询无清晰 >5% 回退；同终态 `dynamic/snapshot ≤ 1.15`。
5. **失败有停止点**：空间明显超预算时，只登记**一个**容量或目录机制，最多两次尝试，不叠加参数搜索。

## 8. 本轮不做

- 250k 与百万规模（后置，需先确认数据来源）；
- HOT（适配器泄漏未修，不参与排名）；
- 新模型机制、参数搜索、根结构改动；
- 默认采用变更（Context16 不变）；
- 把"增长 15%"写进任何通用结论。
