# R 收口后的 BM 长期计划：先确认单页重建，再决定局部修复

日期：2026-10-20；依据 `02e8a09` 收口状态与[本次原始记录复核](../07_Eval_Integration/AUDIT_BM_R_CLOSEOUT_20261020.md)。
本文接替 [R0–R5 计划](LONG_TERM_BM_PLAN_20261020.md)，新工作编号为 **N0–N6**。
本次已完成记录审计和本计划；**N 系列性能运行、原因插桩和新结构均未执行**。

## 1. 方向与最终交付

继续优化用户提供的 **BlockModel**，保留原模型算法和固定快照；不切回自研预测器或 LITS。
Context16 保持默认。BM 页只读/动态继续显式选择，不以组件过门代替通用采用。
R3 `split_from` 支线保持停止；预测括号、payload 探测、局部细分、cost/adaptive、分块根保持关闭。

下一轮必须交付：

1. **正式取舍表**：同一 BM factory、ART、Context16 在同一字节轨迹上的纯索引吞吐、完整读、成功写入成本、尾暂停、请求字节和峰值；失败格也列出。
2. **一个结构决定**：若成本证据充分，实现并检验一个新机制；否则明确“不实现”。不为了完成阶段而强做候选。
3. **真实能力边界**：真正删旧键插新键、删除/扫描负载、合规热点和可核验规模；给出 BM 省空间的实际代价。

历史按页构建的空间/峰值收益保留。R1 含 oracle、R2 未拆全重建、R3 微实验不构成上限，
故不沿用“查询全面持平”“重建几乎全是分裂”“差距已定位到页编码”等因果表述。

## 2. 排期、依赖和停止点

单人串行主线约 **15–22 个工作日**；允许一次另外登记的替代候选，最多增加 4 日，
总预算封顶 **26 个工作日，约 4–6 周**。以下是工作预算，不是已有成果或后台自动执行的承诺。
替代候选与文末 HOT 独立支线共用主线之外的剩余预算，不能叠加突破 26 日；时间不足时优先完成 BM 取舍交付。

| --- | ---: | --- | --- |

不另建通用评测平台，不扩参数网格。到期仍无法判定时写“证据不足”，跳过结构实现，进入有限场景测量。

## 4. N1：四格纯索引对照与真正的重建原因

### 4.1 先完成最小干净外部对照

主格固定为 **words / URLs × 95/5 / 80/20 均匀增长**，复用 R1 四份冻结 SIBROW1/SIBOPS1；
初始 52,428 行，每格 20,000 操作，find 命中率 90%，成功插入 999/3,999、重复 1，
三臂共享同一个初始 map 和操作字节。新结果采用新输出目录，不覆盖 R1。

| 测量 | 方法 | 用途 |
| --- | --- | --- |
| 语义回放 | 独立进程逐步对照参考表，终态全键/有序 scan 对比 | 确认操作结果、值、计数和终态，而非性能 |
| 混合吞吐 | 计时区只执行索引操作和预先固定的最小结果消费；无 oracle、日志或内存自计 | 正式的完整批次耗时与 ops/s |
| 纯成功插入 | 从冻结轨迹生成独立的成功插入序列，保持插入顺序；构建初态后整批计时 | 成功新插入 ns/次；明确是另一工作负载，不从混合耗时中相减推算 |
| 完整读 | 初态/终态上的现存键和真正缺席键，队列固定 | BM0/ART/C16 以及 dynamic/同终态 snapshot 预算 |
| 暂停分布 | 独立的逐操作计时诊断，区分页内、单页重建、二分裂和失败 | p50/p95/p99/max；不能冒充无插桩吞吐 |
| 空间 | 独立 allocation_trace 进程 | owned+adapter+retained 请求字节、构建/动态峰值；scan 输出单列 |

混合吞吐不再逐操作启动计时器。计时后的结果校验必须实际消费返回值、检测错误，避免编译器删除工作；
校验内容和顺序对三臂相同。对于 scan，返回 owning rows 的分配属于接口代价，不能扣除。
纯成功插入序列删除原来的重复操作并保存独立 SHA，重复插入另列语义/风险测试。

配对要求：

- **5 个依次启动的独立进程**，不并发跑性能；每个进程内平衡 BM0、BM0_AA、ART、Context16 的位置及前驱。
  四臂采用完整 Williams 四序列，做两轮完整循环；每臂每次重建相同初态，并立即做等量只读预热。
- 构建与校验在混合计时之外；所有臂都遵守同一预热、初态、操作流和结果消费规则。
  每次重放使用新实例，不能重复往已经变大的索引插相同的键。
- 每个进程先计算同格配对比值，再报告五进程中位数、全部过程值和方向数。AA 是观测噪声带，不是置信区间。
  噪声覆盖目标收益时报告未分辨；最多一次有记录的测量修正，不通过追加重复挑出通过结果。
- 尾部按条件事件报告样本数；不足以支撑 p99 时不作稳定性结论。以独立初态重放增加预定样本，不能悄悄改变增长率。
- `uint64` 校验和保持精确十进制/十六进制；拒绝经过浮点 Number 往返。每一结果行记录 factory、参数和实际源码身份。

### 4.2 原因统计必须在原分支决策点记录

诊断构建只增加统计，不改原分支顺序/决策，也不计入正式性能臂。记录：

1. 重复键、成功页内插入、单页重建、二分裂、失败/回滚。
2. 首个实际触发原因：`PageFull`、`BlockFull`、`ArenaExhausted`、`PrefixMismatch`、`EmptyPage`。
   同时记录条件位图，避免槽满与 arena 不足同时出现时丢失信息。
3. 每原因的成功写入数、重建数、重写行/后缀字节、涉及页数、请求分配字节和完整耗时。
   检查 `页数增量=split−coalesce`、`成功新插入=页内+重建`，bulk 初始计数先取差。
4. 插入位置、块占用、页行数、arena 可用字节，以及首次满页分裂后的后续重建次数。
   冷启动第一次分裂与之后的单页重建分开，不能仅由总页数推断原因。

只报事件比例不够：**356/381 是次数，不是可节省时间比例**。
必须知道槽满/arena/前缀中的哪一类，按时间和重写字节占比最大。

### 4.3 覆盖完整写路径，保留未解释项

按互斥的粗阶段计时，避免在每个字符或槽位上放计时器：

`路由/重复查找 → 页内尝试 → scan恢复整页 → rows插入/整理 → part构造 → Page构建 → root准备/提交 → 旧页/旧根/临时对象析构`。

Page 构建再分为：边界/前缀及字节统计、reserve、编码循环（tag+后缀追加，交织部分合并报告）、
fences/digests/训练视图、**原 BlockModel::fit**。所有权与分配按阶段打资源标签，不能把包含在阶段中的分配时间再重复相加。
诊断记账/`peak` 自计单列；两次 `find` 与后续目录定位的重复工作单列；不把未解释 residual 全称为插入或编码。

至少对两类键建立计时闭合，未解释部分目标 ≤10%；未达到就不得对这部分选候选。
计时闭合和仪器开销用带/不带诊断的成对批次检查；不从不同进程的独立复制微实验推出上限。
无法准确拆开的交织循环保持联合标签，不为了漂亮占比重写被测算法。

**N1 决策**：已有正式取舍表；能按成本支持一个机制则进入 N2。否则跳过 N2/N3，完成 N4/N5 的有限场景边界。

## 5. N2：只登记一个新机制

优先研究的问题改为：**非满页的局部资源不足，是否真的需要重新编码整页？**
这与已停止的“两份临时复制消除”有不同的触发条件、修改范围和收益指标，必须新登记。
下表是选择规则，不是三个都要实现的任务。

| N1 证据 | 可登记的唯一机制 | 登记前必须证明 |
| --- | --- | --- |
| 非满页 `BlockFull` 的可避免编码/物化成本占比足够 | **页内有界块分裂**：只重新分配目标块的槽与必要目录元数据，未变键的 arena 字节及 tags 不重编码；必要时仍用原 BM 重拟合 | 保持稳定 fence/前缀字节与全键纠错；块序号改变后模型必须重拟合或重新证明，不能直接沿用旧窗口 |
| `ArenaExhausted` 主导，槽位仍够 | **稳定字节存储的局部扩展**，单独作为 arena 机制 | 新存储寻址的常驻/完整 find 成本可过门；所有借用视图寿命正确，追加失败不破坏旧页 |
| 真正 `PageFull` 的时间主导 | 一种固定的、考虑块/字节余量的分裂策略 | 更早分裂确实降低完整写成本；页数/根/模型及空间增量全部入账，不预设“更早一定更少” |
| `fit` 主导且训练输入确有不变子集 | 单独的原模型拟合复用 | 字节、顺序、目标秩、前缀和块边界/数量完全符合复用条件；不符合则调用原模型；预先量出适用率 |
| 重复 seek / scan 恢复等其他路径主导 | 重新登记该单一路径的结构/接口改动，或停止 | 不附带编码、根、余量等第二项改动；只有可避免成本足够大才实施 |

若各原因分散、共同可避免成本不足，或需要同时改多个机制才能凑门，直接停止结构支线。
根成本、回收成本和复制成本不能因旧报告措辞而预先排除或宣布主导，选择以 N1 的正确范围为准。
FlatRoot 继续保留；规模后出现新证据也只能登记新的根问题，不能自动启用旧分块原型。

候选登记必须写清：主因、适用率、可避免的时间比例 `f`、预计减少比例 `r`、新增成本 `h`，
用 `f×r−h` 给出**有依据的预测区间**，而非理论实测上限；预测净收益中心目标 ≥20%，给 15% 实测门留余量。
若连乐观假设都不到 15%，不实现。若归因不可靠，不拿“未知”当成可节省时间。

禁止无证据地把“重建一半”写成总成本减半；两半页的前缀/块数/训练秩往往都会变。
优先方案也不能复用仍借用旧 arena 的视图再释放原页。旧数据存储、stable_fences、模型前缀的生存期必须逐项列出。

登记产物：`BM_N2_<mechanism>_SPEC_*.md`，包含修改文件、固定参数、测试格、失败注入点、预期分配与停止判据。
登记后才能改页编码；登记由本任务按证据完成，不额外等待重复口头许可。

## 6. N3：实现、验真和研究门

### 6.1 正确性及所有权

- 在独立显式候选中实现；BM0 源文件身份冻结，旧正式 factory 保留。不把候选改动偷偷写进对照。
- words/URLs/phrases/tranco 及边界字节：全行读回、真正缺席、前缀键、空键/NUL/高位字节、页边界、连续触发修复、删后插新键、owning scan。
- 结构差分按语义不变量验证：页键范围与排序、活跃行集合、完整字节、稳定 fences、模型训练输入/目标秩及窗口纠错。
  候选合法改变块数时，不能要求模型参数与旧页机械相同；须重新验模型训练和安全纠错。
- 所有分配可能失败的阶段先准备、再无抛出提交；dirty 标记失败、局部存储/块目录/模型分配失败、根准备失败逐项注入。
  索引仍能读回旧 map，无悬空借用、双重释放或半提交；干净 compact 不做无谓重建。
- ASan/UBSan/LSan 覆盖所有被改的路径，至少 words+长 URL；若碰字符串所有权/前缀则增加 phrases，不能沿用旧 sanitizer 冒充新候选。
- 保持单次触及 ≤2 个源页、≤2049 行的既有上界；局部修复另记实际重写槽/字节数。纯 value update 不新增根发布/页重建。

### 6.2 性能与空间门，预先冻结

| 指标 | 研究门 |
| --- | --- |
| 成功增长插入 | words、URLs 的 **80/20 两个主格均比 BM0 降 ≥15%**，每格 ≥4/5 进程同向且超出 AA 噪声；95/5 两格无清晰 >5% 回退 |
| 完整混合批次 | 四格无清晰 >5% 回退；单列 ART/C16，不以每次重建更快代替端到端收益 |
| 完整 find | 初态/终态固定命中+真正缺席队列，相对 BM0 无清晰 >5% 回退；宽 AA 只判未分辨，不能宣称证明 ≤5% |
| 动态读预算 | 同一最终 map 的 dynamic / fresh snapshot 直接配对 ≤1.15；命中/缺席分列；不是历史其他候选的预算 |
| 内存 | requested resident ≤1.05×BM0，且原本 ≤0.70 ART 的主样本保持该门；所有页、目录、模型、保留输入和适配器计入 |
| 峰值与构建 | build ≤1.20×BM0；动态/构建 requested peak 无 >5% 增量，或在登记时明确峰值换时间的场景门并据实降级 |
| 暂停 | 条件样本量足够时 p99 无清晰 >10% 恶化；最大重写范围和最坏恢复路径符合登记上界 |

N3 不能在看到结果后把“插入时间门”换成“峰值门”来救候选。
若以 ≥20% 峰值降低作为独立组件目标，必须在 N2 预先选择该目标；过门也只算空间组件成果，不算写入优化。
单格收益不足以代表两种键；只过一格最多留为明确的研究记录，不合并进通用 BM 实验配置。
未过门则撤销候选的采用资格，保存失败证据，不改 BM0、默认或旧记录。

**采用与研究严格分开**：降低 15% 只说明局部机制有效。
原带校验同格插入观察约为 ART 的 11.5–13.9 倍；即便小幅改进，也远不足以证明通用竞争力。
通用资格仍须完整读和预登记混合负载均达到同轮 ART ≤1.10 等原目标，并完整通过语义/内存门；任何格失败都据实列出。
没有预先定义并通过场景门时，统一标 `experiment_only`，不自动修改 Context16 默认。

## 7. N4：补上真实删插、扫描和合规热点

不把值更新叫“键替换”。先完成少量独立负载，不直接扩成旧 24 格。

| 负载 | 格数/组成 | 约束 |
| --- | --- | --- |
| 均匀增长 | N1 的 4 格 | 复用冻结定义；候选需要在同轮重测，不能拼接旧基线 |
| 真正键替换 | 4 格：words/URLs ×95/5、80/20 | 写操作 `update:erase:insert=2:1:1`；删旧键、插真实缺席新键，期末活跃数不变 |
| 合规热点 | 4 格：两类型 ×80/20×增长/键替换 | 与已登记均匀控制共享初始 map、操作数、成功率和查询命中率；生成后验证实际热点比例 |
| 删除/扫描混合 | 4 格：两类型 ×scan limit 16/128 | find79%、update10%、erase5%、insert5%、scan1%；每批末全量读回/有序 scan 校验 |

合计 **16 个主格**。phrases/tranco 如需风险确认，只额外登记两个 80/20 增长风险格，不自动开新全矩阵。
若 N3 未产生候选，BM0/ART/C16 仍完成这些能力边界；没有通过语义门的臂不参与该格性能排名。

真键替换的生成器维护参考活跃集合；每次 update/erase 应命中、insert 应缺席，
失败操作另列，不靠重复插入降低写成本。95/5 的 1,000 写为 500 update+250 erase+250 insert，
80/20 的 4,000 写为 2,000+1,000+1,000。检查实际计数、净增长、删除/新增集合和最终键值摘要。
扫描返回完整 owning rows；计时后的 oracle 比较实际输出，不只比较行数。
删除留下的 arena 垃圾、空块/空页与是否调用 compact 必须声明；维护时间摊入同一服务工作量，不能在计时外免费整理。

热点预登记为**固定字节序键域的 10% 范围承担 80% 写入**，增长和替换分别统计所有写及成功新插入。
先检查热区真实 held-out 键容量；例如 80/20 增长需要约 3,200 个不同热区新键，容量不足就生成一组
均匀/集中共同使用的新初始分割并另记身份，不能退化成重复插入，也不能静默扩大热区。
重放后实际比例应在登记容差内（目标 80%±2 个百分点），并验证值更新/删除/插入各自比例。
若无法满足，热点格标未执行/不合规，其他格继续。
初始 map、成功率、命中率相同仍不自动隔离所有影响；热区键长/前缀分布不同必须报告，
没有进一步匹配时只称“该集中负载观察”，不称局部性单独造成了加速。

## 8. N5：新样本和规模，分开数据协议与结构结论

1. **100k**：复用已登记的真实 100k 词表；补增长/键替换的有限动态格。
   之前的 100k 空间结果不代表 100k 动态吞吐。URLs/phrases 有足量可核验唯一键时再列各自 100k。
2. **250k 入口**：从 benchmark 来源的真实原始语料检查可用唯一键、字节编码、去重/排序和版权/访问条件；
   单独登记规模抽样协议和 seed，形成新的 dataset/trace 身份。
3. **1M 条件扩展**：250k 语义、资源与超时门通过，且实际原始语料足够，才对 words/URLs 中满足条件者运行百万格。
   不用 suffix 拼接、重复键或合成扩充冒充 benchmark 百万真实键。
4. 当前官方 sampler 上限 100k；扩展 loader/抽样是新的明确协议，不能把新样本改称官方原 100k 协议的自然延伸。
   不足百万的语料明确标不可执行，不为填表下载未经需要的巨大数据。

规模阶段使用固定 80/20 增长与键替换两负载、单一登记 seed；只有主结论需要确认时再用一个独立 seed。
先做单进程资源/语义预检，再跑五进程配对。预先登记内存和单格超时预算，超出后停止该规模并保留原因。
报告页数、模型数、原因占比、每次重写字节、根准备时间及峰值；不能将 64k 的根 3%–8% 外推到百万。
若根在新规模变成主要成本，单独登记问题；本轮不顺势恢复被否决的 chunked root。
