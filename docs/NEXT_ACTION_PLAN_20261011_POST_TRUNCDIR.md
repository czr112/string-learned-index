# 截断目录之后：先补正确性，再限额诊断，回到结构优化

日期：2026-10-11。计划基于本地 `main@3f8f016`、TRUNCDIR 结果及本次源码核查。
本次已完成最小字节序反例验证；下列修复、读路径诊断、原型和计时均待执行。

## 1. 决策与当前证据

**优先顺序：P0 目录字节序修复 → P1 一次读路径诊断 → 有充分依据才给一个读路径原型；否则恢复 M4 有序段归并 → 冻结可用配置并做必要外部复测。**

默认后端继续为 Context16。BlockLinearRank 及两种等深目录均保持默认关闭。
不做 LITS 适配优化；不搜索模型、摘要宽度、段数或阈值；不同时叠加参考表释放、指纹替换等候选。

## 2. 本次核查对旧建议的三项修正

1. **先处理已复现的正确性缺陷。** 两种目录在 signed-char 构建下使用有符号字节比较。
   四个键、四个组即可出现组号逆序；WSL/MinGW 各复现 128/256 失配。
   详见 [核查记录](../07_Eval_Integration/AUDIT_DEPTH_DIR_ORDER_20261011.md)。
2. **按真实路径诊断。** `bench_depth_dir.cpp` 的 qmode 最后一项为 false，即 `Mode::locate=false`。
   上一轮 C16 实际是模型预测后顺序标签探测，不是“模型预测＋子块目录二分”。
   诊断中应断言该模式及 `locate_probes==0`，避免优化一条并未计时的路径。
3. **计入指纹工作及完整查询。** C16 的预测与指纹累积融合；DDirT 的 `fp_consumed=0`，
   目录搜索后仍要沿现有路径对整个后缀计算指纹。二者总指纹字节未必不同，但重复读取、依赖顺序不同。
   `Result.steps` 的两个后端含义不同，不能简单相减当作分段耗时。

## 3. P0：字节序修复与有效验收（第一个执行批次）

范围：`model/equal_depth_dir.hpp` 的不同字节比较；两种目录的现有验收门及其构建登记。
这是契约修复，不是新的性能候选，不改变默认后端和截断规则。

执行顺序：

1. 将已复现的最小反例纳入会失败的正式门；确认当前源码确实触发非零失败。
2. 使用显式 unsigned-byte 比较修复生产搜索，保留当前长度相等/前缀结束规则。
   不通过全局 `-funsigned-char` 隐藏问题。
3. 两种目录分别对独立整数/字节序参考验证：组号范围、阈值计数、单调性和任意查询区间不变量。
   强制同一区域存在多组且搜索跨过 `7f/80`，检查实际阈值数与分支触发数。
4. 扩展至完整 Index：空键、NUL、`7f/80/ff`、共享前缀、重复阈值与长键；全部 find 键值、
   任意起点 scan 的顺序及完整行对照独立参考。包含删除重插、更新、重建/分裂、输入释放后的复查。
   训练放置与查询互相比对不能替代独立参考。
5. 对新语义套件跑 WSL 正常构建与 ASan/UBSan；重跑受影响的目录门、扫描门及集成契约门。
   原有三语料用于 ASCII 差分检查，不因修一个比较立即重跑完整性能矩阵。

通过：独立参考零失配、单调性零违例，正向分支与故意破坏字节序的负对照均触发；sanitizer 无诊断。
未通过则停留在 P0。不得以“候选默认关闭”跳过已知契约问题。

交付：修复、回归门、`RESULTS_DEPTH_DIR_ORDER_FIX_*`、新源码身份。
历史计时保留旧身份；manifest 必须覆盖实际变更的模型头，不能只更新未变的 index.hpp 哈希。

## 4. P1：一次完整读路径入口诊断（不接计时）

本阶段只回答：目录把组分布改善之后，额外查询工作来自哪里，是否还有值得实现的单一结构机制。
tranco 为诊断重点，mixed/skew 为机制对照；**诊断重点不改变目录候选原来的 mixed 速度采用主目标**。

固定装置：

- C16 与修复后的 DDirT；旧完整目录只在需要核对截断等价时使用，不扩展性能臂。
- 复用 `bench_depth_dir.cpp` 的生成器、区域规则、容量规则、frozen threshold、qmode 及随机种子。
  mixed/skew 各 131,072 键，tranco 262,144 键。
- 静态 20,000 探针、种子 20261011、miss_percent=10；按实际命中分层，独立参考核实生成的缺席键确实缺席。
  同一查询列表两臂重放一次即可计数，保存 probe hash。不得只扫全体存量键代替该性能队列。
- 更新后按原 bench 的批量擦除再插入及 25%/50%/100%/200% 检查点构造状态，
  最终探针种子 20261012。该日程保持活跃 N；它与 M4 的逐键替换日程各自复用，不能混称同一负载。
- 开关完全相同，只有后端不同。模型会改变分组和物理布局，应称“同输入、同结构策略”，不称逐字节同状态。

| 路段 | 记录内容 | 可以回答的问题 |
| --- | --- | --- |
| 外层区域导航 | 实际比较步、完整比较次数/逻辑字节 | 后端切换是否伴随区域边界变化 |
| C16 预测 / DDirT 搜索 | 模型步、目录二分步、比较长度、相同前缀、结束原因 | 减少主块探测前付出了多少额外搜索工作 |
| 指纹 | 融合输入字节、tail 输入字节、目录已读位置重合 | 是否存在可以独立消除的重复读取；不改变标签算法 |
| 主块 | subblocks_visited、SIMD 批次、标签候选、完整比较次数/逻辑字节 | 少访问块是否同时减少有效比较 |
| 溢出 | 进入次数、记录探测、完整比较 | 静态与更新后收益是否来自不同位置 |

按静态/更新后、命中/缺席、区域与键长保存数量、总和与分布；说明每个计数的分母。
逻辑比较字节不是缓存未命中或物理访存量；没有 PMU 不作分支误预测、缓存停顿的定量归因。
复用 E12/E25 计数，必要新增点限定在诊断宏或隔离副本中。影子计算必须与实际组号/答案一致；
生产 find 必须真实执行。不开带计数的计时，也不以若干整段时长相减充当阶段成本。

交付：`diag_depth_dir_read_path`、原始计数、`RESULTS_DEPTH_DIR_READ_PATH_*`，含一张“少做什么/多做什么/未知什么”的表。

### P1 结束时的强制选择

- 能提出一个可部署的结构改变，指出可消除操作、适用查询比例、新增工作和内存上限，并用影子执行验证答案与净工作减少：
  写一页候选设计，冻结参数和采用条件后，只允许一个原型。
- 只能确认“二分有固定成本”，或机会需要多项改动、参数搜索、特殊语料判断才成立：目录读优化在本阶段收口，转 M4。
- 若证据主要指向融合指纹等模型内部算法改造，单列为研究问题，本阶段不顺带实施；优先推进模型无关的 M4。

一次诊断、至多一个原型；主目标失败或风险明确回归即停止，不连续增加目录后端挽救原候选。

## 5. 有条件的目录原型与 A/B

只在 P1 满足入口时执行。原型在隔离副本中实现；新逻辑默认关闭，先通过独立语义门、生命周期与 sanitizer。
主对照固定 C16/候选；修复后的 DDirT/候选可作为机制对照，不能用相对 DDirT 变快替代主目标。

复用现有 5 进程 × 4 重复、位置轮转、重复内配对；本轮内部沿用 WSL `-O3 -march=x86-64-v2 -static`。
不混用 MinGW 性能数。主目标仍为 mixed 完整静态 find 耗时：候选/C16 ≤0.90、至少 4/5 同向，且越过预登记散布范围。
风险格任一可分辨慢 >5% 不作通用读配置；构建增量 ≤10%、常驻增量 ≤5%，峰值单列。
扫描16/256与既有替换后点查列为风险；主目标失败不扩展外部矩阵。

实际 `run_depth_dir_ab.py` 的 F 是各进程配对比值中位数的 max/min，**不是独立 A/A，也不是置信区间**。
沿用时按这个实际含义报告，不能写成做了未执行的 A/A。若候选需要不同装置，必须在运行前单独冻结规则。
必要的装置修补仅限输入完整性：当前字典聚合会覆盖重复记录，缺对只被计数；新运行前须对预定 5×4 全集、
重复/缺臂、必填字段、身份和 checksum 作硬拒绝。用少量固定坏记录验证，不建新评测平台，不改旧记录。

## 6. 下一项结构主线：M4 有序段归并

P1 无足够机会或唯一目录原型结束后恢复；不与目录优化并行叠加。
技术规则承接 [M4 计划](NEXT_ACTION_PLAN_20261011_MERGE.md) §3–§7，但后端和当前身份以本节为准：

- Context16 先验入口；正确性完成后的 DDirT 仅作第二后端的迁移验证。取消旧计划中的 LITS 开发/验收前置要求。
- 目标 Context16/grow/tranco，N=262,144，100% 与 200% 更新检查点；C/W/S 同开，额外候选关闭。
  风险保留 Context16 的 same/mixed@25%/200% 及 0% 控制，scan16/256/4096。
- 同一后端 A/B 共用输入、容量计划和结构状态。不同后端分别生成各自有效计划，不跨映射强行复用组号或 preset。
- 一个主块剩余连续段实际输出长度 ≥4，且末键严格小于溢出当前首键时整段输出；证明失败该块回到逐条归并。
  每块只试一次、不二分找较短段、不缓存跨调用地址；对侧已耗尽时不记新收益。
- 入口两个目标检查点均要求：≥50% 输出来自上述有效段；扣除成功/失败边界证明后净比较减少 ≥30%；
  与独立参考逐行一致。任一不满足即关闭机制，直接配置收口。
- 通过才做单个隔离原型。主指标是 200% 后完整 scan256 物化及释放，包含首遍；门槛 ≤0.90、至少4/5同向并超过散布。
  原 M4 的 A0/A1/B0/B1 控制与首遍/首批风险保持，内部统一使用本计划 v2 工具链，新数字不与旧 v3 绝对值拼接。

交付：`RESULTS_MERGE_ENTRY_*`；入口通过再交付原型、门与 A/B。失败不增加生产开关。

## 7. 配置收口与外部对照

1. 整理默认 Context16、已验证的紧凑外层导航场景、更新扫描场景和目录 skew 场景。
   按当前集成身份分别验收，旧单项收益不相乘，不把候选组合假定为已经通过。
2. 只对内部通过且准备交付的配置做 ART/HOT 对照；统一 `-march=x86-64-v3`、输入、查询、适配成本和身份。
   外部工具链与内部 v2 分开报告；不得据目录对 C16 的比例推算超过 ART/HOT。
3. 参数冻结后做有限留出验证：新均匀查询、边界缺席查询、热点查询；完整 API 不支持的操作明确标记。
4. 参考表释放排在上述机制之后：目前估计约 1–2 MB，需验证后端回退、重建和 preset 生命周期。
   它是独立空间候选，不能解释 tranco 当前的时间回归，也不为它重开 LITS 适配。
5. 每个执行轮结束更新 RESULTS、状态与 README；生产源码实际变化才重钉相关 adapter/diagnostic identity，
   生成新快照（沿现有 s 后顺延）、检查差异并提交同步到唯一主仓库。

本阶段完成标准：已知字节序缺陷关闭；目录读路径有明确继续/停止判定；M4 有入口或最终结论；
保留的配置给出边界和对照证据。以减少用户可见操作成本和可用配置为终点，不以新增开关数量为产出。
