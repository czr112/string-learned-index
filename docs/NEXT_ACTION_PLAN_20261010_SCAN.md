# 下一轮行动计划：定位并尝试消除 WIDE 的扫描代价

日期：2026-10-10。状态：已完成代码与证据复核；以下实验尚未执行。
本文件接续已经收口的 `NEXT_ACTION_PLAN_20261010.md`，规定下一轮顺序。

## 1. 行动方向与优先级

**首选方向：在 WIDE 更新后的索引状态上，诊断扫描起点定位，并在证据支持时实现一个最小改动。**
目的：保住已有维护、点查和空间收益，减少已经复现的扫描代价。
不是重新证明 WIDE 有效，也不是立即修改默认配置。

| 方向 | 当前证据 | 下一步处置 |
|---|---|---|
| WIDE 扫描路径 | grow/tranco scan256 已独立复现约 2.9–3.6 倍回归；same/mixed/LITS 在 25% 的 scan16 有约 7.3 倍回归 | 最高优先级，一轮有界诊断，证据支持才改一个环节 |
| 残余主块检索／放置 | E3 指向此处，但测的是发布配置；不能沿用该占比解释 WIDE 后的状态 | 扫描轮收口后，作为下一项入口诊断 |
| 导航摘要宽度、外部协议扩建 | C 已有集成与外部记录；当前无宽度选择的新证据 | 暂不开展 |
| 低活跃回收、C-2、泛化分配优化 | 三项入口已关闭 | 不重复 |
| O1／稳定溢出容器 | 历史有点查与扫描代价；未证明 WIDE 后还有足够可省时间 | 不加入本轮 |

优先级依据：WIDE 已得到规模明显的收益，同时暴露了明确的读侧代价；修复这个代价比叠加第三个结构因素更容易归因。
当前 W、C、WC 均保持默认关闭，场景候选身份不变。

## 2. 复核后必须调整的两点

### 2.1 现有扫描计数不能直接排除遍历成本

`bench_combo.cpp` 只在每臂构建前 reset 计数器，检查点读取的是累计值：
维护中可能调用的扫描、此前检查点、三档计时扫描、三档校验扫描混在一起。
`analyze_scandiag.py` 又只读取 200% 检查点，因此不能解释 25% 的 mixed/LITS 尖峰。

另外，`scan_result_allocs` 按代码路径累加 1 或 2，实际表示字符串构造路径的估计次数，
并非 allocator 调用计数；短字符串优化、输出 vector、两条物化路径的单位成本均未被它测量。

所以旧结果只说明“已有累计计数没有给出充分解释”，不能推出“扫描算法没有多做工作”或“已经排除分配”。
旧计时回归仍成立；本轮纠正的是机制归因强度。

### 2.2 起始游标推进是候选原因，尚非已确定瓶颈

当前 `Region::scan` 在起始组中从主块第一条开始逐项比较，并对溢出容器从位置 0 线性推进。
WIDE 改变主块与溢出的记录分布，可能改变这两种推进的工作量和单位成本。
`scan256` 与 `scan4096` 的回归差异支持检查固定启动成本，但不足以证明该机制。

历史 A4 关闭的是每区域／每组游标重复重建；此次检查的是同一组内寻找 lower_bound 的逐项推进。
二者不同，不重开 A4 的旧结论，也不引入长期持有的扫描游标。

## 3. 阶段 A：一次有界入口诊断

### 3.1 固定负载与状态

复用组合轮的初始键、容量计划、逐键交错替换序列及扫描起点，禁止换负载来挑收益。
诊断先运行以下三格，保留四臂 B/W/C/WC，后端间不合并比值：

| 后端 | 模式／语料 | 规模 | 重点检查点 |
|---|---|---:|---|
| Context16 | grow/tranco | 262,144 | 0、25、50、100、200%，重点 200% |
| LITS | grow/tranco | 262,144 | 同上 |
| LITS | same/mixed | 131,072 | 同上，必须保留 25% 尖峰，不能只看 200% |

扫描长度保持 16/256/4096。每格先做 1 进程 × 4 重复的计数诊断；不把诊断构建耗时当性能结果。
保留每个起点的记录，避免中位数隐藏一个极端起点；空起点、存在键、缺席键、末键之后的零结果探针分别列出。
额外边界探针只用于诊断和正确性，不混入历史扫描时间的对照队列。

### 3.2 计数的边界

在独立诊断构建中添加以下计数，不影响发布路径：

- 主块起点推进：比较次数、跳过记录数、起点阶段经过的子块数。
- 溢出起点推进：比较次数、跳过记录数。
- 输出阶段：主块／溢出各自输出条数与完整键输出字节数。
- 保留既有 regions/groups/blocks/merge/locate 计数，但改为扫描阶段增量。

每个 `scan(start, limit)` 调用前后取快照；计时重放与答案校验各自取增量，按 limit、检查点、起点和臂输出。
维护计数另存，不能为了扫描清零而丢掉 widening 分支执行证据。
若复用 `lower_bound_pos`，须在实际比较点计数，不能用 log2(n) 推算比较次数。

每次诊断扫描逐行对照独立参考表。至少验证：
实际输出条数等于期望值，主块输出＋溢出输出等于返回条数，所有增量非负。
JSON 中二进制探针使用可靠转义或只记录 probe_id，不能原样输出控制字节。
给一个确定内容与起点的小案例手算推进数，核验新计数器确实记录目标循环。

### 3.3 进入候选实现的判据

只有同时满足以下条件，才进入阶段 B：

1. 正确性通过，WIDE 分支实际执行；`NOT EXERCISED` 单列，不算通过。
2. 分相位计数揭示可省的起点定位工作，并能指出具体主块侧或溢出侧。
3. 起点／状态的分布与回归相符，且所选路径具有已验证的排序前提。

计数只能支持实现一次可检验的候选，不能换算成时间占比，也不能据此宣称已经解释回归。
真正的验证是阶段 C 的同状态、同队列、干净构建 A/B。

若新计数不支持该入口，最多追加一次有界区分：在原扫描逐条产出位置增加诊断消费方式，
跳过结果字符串物化，但逐条验证后缀、前缀、键序和值；比较原输出与诊断消费方式下的 W/B。
此对照仅区分物化路径与遍历读取的可能影响，不是可部署 API，不将其速度当候选收益。
必须通过运行时消费与答案校验防止编译器删掉工作。

如果这次区分仍不能定位可修环节，记录“机制未决，停止本轮”。
不得把诊断失败称为“已证明结构性代价”，不得无界追查缓存、PMU、分配器或扫参数。

## 4. 阶段 B：只实现一个候选

候选暂记 S：缩短扫描起点定位。具体改法由阶段 A 选择，不提前承诺加速。

- 若主块推进是对象：利用已排序的描述符进行 lower_bound，必要时利用现有子块边界跳过。
  必须验证空子块、相同前缀和跨子块顺序；不能启用整套点查目录来同时改变其他路径。
- 若溢出推进是对象：复用容器已有 `lower_bound_pos(s)`，只替换扫描启动的线性循环。
- 两侧都有机会时先选择证据最充分的一侧；另一侧登记后续项，不能一起修改后再归因。

首版不新增持久目录或额外键缓存，不改模型映射、区域划分、回收预算、主块容量、输出 API。
使用默认关闭的开关隔离，在 Config、基线、冻结配置、开关摘要、差异检查白名单中登记完整。
不打开 `scan_cache_start`、O1 或其他旧开关来遮蔽本候选的效果。

正确性门覆盖：

- 空索引、limit=0、起点在首键前／正好命中／两键间／末键后、跨组与跨区域。
- 空键、NUL、高位字节、4096 长键、公共前缀、主块与溢出同时有结果。
- 删除重插、重复键更新、空子块位于组中间、repack 后 offset 变化、区域分裂与重建。
- 两后端与 W/WC；逐条比较旧路径、候选路径及独立参考表的键和值。
- 小数据集穷举每个扫描起点及多个 limit；保留排序契约的负控制，不能让错误排序也通过。
- 专门构造非零起点且发生跳过的案例，证明 S 的分支真实执行。

正确性及 ASan/UBSan 通过后，才运行干净性能构建。
相关现有扫描契约门、组合门、导航门按受影响路径复跑；扩展后端覆盖，不能将旧门默认后端当两后端都已验证。

## 5. 阶段 C：先定向 A/B，再扩到六格

### 5.1 定向试验

先保持导航关闭，以四臂 B、B+S、W、W+S 跑阶段 A 的三格。
这能同时回答 S 是否缩小 WIDE 的代价，以及它是否只是对所有配置相同的扫描优化。

复用 5 独立进程 × 4 重复、臂位置轮转、同重复配对；固定原扫描起点与替换序列。
计数／时钟诊断构建不参与正式计时，答案校验在计时外。
每个检查点同表列维护、命中、未命中、scan16/256/4096、总空间及主块／溢出状态。

核心比值全部直接配对：

- (W+S)/W：修复自身的增量效果。
- (B+S)/B：基线状态上的效果。
- W/B 与 (W+S)/(B+S)：两臂采用相同扫描算法时，WIDE 的相对代价是否缩小。
- (W+S)/B：最终配置相对现有发布配置的总效果。

同时报告绝对耗时与差值，不用历史倍率连乘，也不要求“必须恢复到 1.0”才承认部分改善。
静态检查点 W/B 在 S 状态相同的对照下应是同结构；作为装置负控制，不能把其抖动称为 WIDE 收益。

### 5.2 完整回归验证

定向试验有可分辨收益后，扩到两后端 × same/grow × 三语料 × 五检查点。
臂为 B、W、W+S、C、WC、WC+S；同轮验证修复与导航的交互。
重点比值：(WC+S)/WC、(WC+S)/C、(WC+S)/B，以及 W+S/W。
输出表继续保留维护／点查／扫描／空间，不因目标是扫描而省略写侧验收。
重用现有方向与噪声判据，并报告逐进程范围；未分辨不等于性能等效。

若源码再次变化，旧结果不再绑定新身份：先重跑受影响门，再使用新输出名重测。
本轮不自动升默认；静态 ART/HOT 入口不能证明更新后扫描修复，不以重跑该入口代替内部验收。

## 6. 收口规则

| 结果 | 处置 |
|---|---|
| 正确性失败、排序前提失败、分支未执行、固定配置不符 | 停止性能解释，修门／装置或放弃具体改法 |
| 起点定位计数有可省工作，但 S 的干净 A/B 未分辨或回归 | 关闭本候选；计数减少不算性能成功 |
| S 改善定向扫描，但完整轮损害维护／点查／空间或其他扫描 | 明记取舍，保留场景候选或关闭 S，不能宣称消除通用代价 |
| S 缩小扫描代价但 WIDE 相对基线仍慢 | 报告剩余代价；W/WC 继续为场景候选 |
| 同轮保留既有收益并未再观察到可分辨扫描回归 | 记为完成的修复候选；默认变更须另作决定 |
| 有界诊断未定位机制 | 记未决并停止扫描轮；保留现有取舍，转阶段 D |

扫描轮限定为“一轮计数诊断＋至多一次诊断区分＋一个候选的定向与完整验收”。
不做摘要宽度／目录阈值／分配器的参数矩阵来挽救候选。

## 7. 阶段 D：收口后转残余主块检索／放置

先保留 same/mixed 与 grow/tranco；仅在覆盖不足时补 skew。

必要时复用 E3 的校准方法分段计时；嵌套时间不相加，低于时钟地板的项不排名。

这一阶段的交付是“在 WIDE 后的状态上选出一个仍有可省工作的主导环节”，
不是复述 E3 在发布配置上的百分比。入口成立才制定下一项结构候选，入口不成立保留负结果。
不从“搬移字节很多”直接跳到 O1，也不重开已关闭的收缩／低活跃／泛化分配分支。
