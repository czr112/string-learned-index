 **实验底座固定为「E31 子块整理 ＋ 原有溢出容器」**（迁回实验的基线配置，**不改冻结默认值**；**先不叠加 T8**，避免把容器变化与迁回效果混在一起）。**先做可行性诊断**：用已有状态查"**已经在溢出区**的记录里有多少满足该块的**键范围、空槽与字节**条件、能迁回多少条／多少字节、从溢出容器删除它们要移动多少条目"——**E31 能让新插入成功，不自动证明旧溢出也能迁回**（旧记录的范围与长度可能不同）。**机会足够才做两臂 R0（不迁回）／R1（仅开启迁回）**，代码里用明确的迁回名称，避免与既有构建优化 R1 混淆。**验收**：迁回量、完整维护耗时、查询、扫描、常驻空间**及峰值**，并把"**从初始状态运行（能否防止溢出积累）**"与"**修复已退化快照（能否以合理成本恢复布局）**"分开记录。**一条必须随数字读的口径**：**「每次最多迁回 K 条」不等于维护时间有界**——原溢出向量即使只删一条也可能移动很长的尾部；**工作预算至少要覆盖候选检查、后缀复制与溢出删除搬移**，**只限制候选或成功条数时只能称「迁回条数受限」，不得承诺单次维护成本有界**。**E24（2026-09-18，诊断轮，不计时）**给出了下一阶段的依据：**增删改走的是慢路径**——按命中来源分组，`update`／`erase` 做 **34×–93×** 于 `find` 的全字符串比较（溢出命中 41×–130×，**未命中最高 34,155×**），且**这个代价与负载无关**（只改值与初始状态逐位相同，替换后反有升有降）；**垃圾只在替换后出现**（0 → 2.36／1.78／0.65 MB），主块账本恒等式 12 格全部成立；**按键序的合法迁回在 12 个格子里 11 个为 0**，而**有溢出的组里 90%+ 同时有空槽和空字节**（组级判据几乎没有分辨力），**总空闲的 98%–99.6% 还躺在没有溢出记录的组里**——组内维护用不到。据此定：**E25 = 分离验证"快速定位"与"消除重复查找"**（V0 冻结 R1／V1 更新删除复用高效定位／V2 再复用本次定位的组号·标签·判重结果；调用计数与 0/5/10/25% 检查点并入本轮）；**E26 方向待定**——**排除迁回不等于已证明压缩划算**，要看 E25 顺手测的"压力子块里到底有多少可回收垃圾"。详见 `02_Code_and_Experiments/validation_e24_20260918/RESULTS_E24.md`。
