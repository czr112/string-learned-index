## 2. 必须保留的性能不确定性

重算方法与原判据相同：每进程取六个同重复比值的中位，再取五进程中位；
A/A 底为五个控制比值的 max/min；回归要求中位 >1.05、至少 4/5 更慢且超过该底。
24 项的底在 **1.0752–1.6118**，以下格子虽未触发回归判据，也不能称为性能等效。

| 格子 / 阶段 | ON/OFF 耗时中位 | 更慢进程 | A/A 底 | 原判定 |
|---|---:|---:|---:|---|
| mixed / Context16 / scan | 1.1105 | 4/5 | 1.1684 | 未分辨 |
| mixed / LITS / query | 1.1206 | 4/5 | 1.1934 | 未分辨 |
| mixed / LITS / update | 1.2398 | 3/5 | 1.3361 | 未分辨 |
| mixed / LITS / scan | 1.1989 | 4/5 | 1.4813 | 未分辨 |
| skew / LITS / build | 1.0847 | 5/5 | 1.1522 | 未分辨 |

这些结果既不推翻原预注册判定，也不足以支持默认开启。M5 必须把风险格列为采用条件，
不能在采用表里把 `any_regression=false` 写成“零回归”。
本轮 scan 计时实际调用的是 200 个起点的 **Region::scan、limit=64**；
它不构成完整 Index 跨区域扫描、写后 scan256 或首批停顿的验收。

## 3. 新发现的验收缺口

### 3.1 `gate_split` 没有证明分裂发生

`diagnostics/owner_proto.cpp` 的所谓分裂门先只向 ON 对象插入 400 个键，随后遍历**全部当前区域**：
每个 LITS 且无表的区域都增加 `split_new_regions`，最后又加上区域总数增量。
所以 `61/0`、`63/0`、`128/0` 不是新建区域数，不能从中推断分裂被触发。
`gate_split` 只检查 `split_lits_with_table == 0`，没有要求 `Index::splits` 增长。

同时，OFF 对象没有执行这 400 次插入；后续的删除和 40 个区域局部扫描也不是在相同逻辑状态上比较。
这些扫描相等仅说明采样窗口没有暴露差异，不能充当插入、分裂和重建后的完整正确性门。
本次确认的是**验收证据不足**，不是已经发现生产索引答错。

补验应使用相同更新序列的 OFF/ON 对象与独立有序参考，明确记录 splits/rebuilds 的增量，
并在真实分裂与前缀重建后检查全键/值、跨区域扫描及新区域的模型所有权。
分裂、成功 LITS、回退区域三种分支都应各有正触发证据，不能以零违规代替执行。

### 3.2 M4 不能原样复用当前 `scan_consume()`

生产 `Region::scan()` 在 `scan_ordered_start=true` 时已走两级有序起点搜索；
`Region::scan_consume()` 仍无条件线性推进起点。两者可能输出相同答案，但工作路径不同。
历史 S 关闭时的 consume 结果保留原有效范围；新一轮固定 S 开启后，要先在隔离装置中同步起点逻辑，
核对游标落点和遍历轨迹，才可使用 consume 解释归并机制。

### 3.3 M3 的兼容边界依然存在

LITS 成功区域在 ON 时收到非空 preset 会显式抛错，`group_of()` 也会拒绝无表参考查询。
这是限定了候选适用接口，不是已经支持 R1/preset 与所有参考诊断。
`bulk_load_with_plan` 和提供有效 preset 也不是同一件事：前者可以不带参考上下文。
M4 继承既有显式容量计划，但双方 M3 固定 OFF，防止把所有权变化混进扫描实验。

### 3.4 适配器历史连续性

上一轮共用适配器曾被整文件重写事故破坏，旧文本无法逐字节恢复，现版是按完好接口重建的。
既有 100/100、101/101 验收支持相应行为检查，不能证明新旧适配器性能等价。
旧四方二进制与结果保留为历史证据；M5 使用重建版重编译，在结果身份中同时绑定适配器源文件哈希。

## 4. 下一阶段顺序

1. 一次 M3 生命周期正确性补验；补测显式拒绝契约，保持默认 OFF。只补覆盖，不重跑整轮性能矩阵。
2. 校准 M4 的两种扫描产出路径，固定 C/W/S 和原更新序列，执行一次块级归并入口。
3. 原入口成立才做一个原型；完整 scan256 达到 ≥10% 净收益且风险通过才集成。
4. M4 成功或失败都收口到 M5：固定可用配置，有限新查询验证，最后做 ART/HOT 同身份复测。

具体步骤、统计口径与停止条件见 [下一阶段计划](../docs/NEXT_ACTION_PLAN_20261011_MERGE.md)。
