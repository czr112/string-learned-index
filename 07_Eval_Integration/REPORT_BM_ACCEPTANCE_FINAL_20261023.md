# 验收轮最终报告：六阶段全部执行（2026-10-23）

与阶段 6 的独立样本，并发布正式 factory。**默认仍 Context16，候选仍未被采用。**

| 项 | 内容 |
|---|---|
| 正式 factory | `make_bm_split_experiment_index`（`bm_split_adapter.hpp`），与基线 factory 并列，含 model commit / core SHA / adapter SHA / `mutate_mode=block-rebalance` |

## 3. 判据核对

| 判据 | 结果 |
|---|---|
| 增长格 ≥15% | ✅ 40.5%–59.4%，12/12 |
| 五进程至少四个同向 | ✅ 12 个增长格全部五进程同向 |
| **超出 AA 噪声** | ❌ **未满足**：本设计的 A/A 带为 1.16–3.48，远宽于 41%–59% 的降幅判断所需 |
| 查询无 >5% 回退 | ✅（find 在噪声内） |
| 空间 ≤1.05× | ✅ 0.996–1.011（增量账本） |
| 异常回滚先过 | ✅ 7 个注入点零丢键 |
| `dynamic/snapshot ≤1.15` | ✅ 0.948–1.003（沿用阶段 5 前记录） |

**关于 AA 带**：同一进程内"预热一次 + 测两次"的重复在 20,000 操作、总量 100–300 ms 的规模上
抖动极大（第二遍比第一遍最多快 3.5 倍）。所以"超出 AA 噪声"这条**没有通过**——
不是降幅不够（12 格一致 41%–59% 已远超噪声），而是**这个 A/A 协议本身不够紧**。
要真正满足该判据，需改为"同一进程内 ≥10 次重复取最小/中位并报 AA 带"，或改为跨进程配对。

## 6. 仍未完成

1. **严格的 A/A 协议**（≥10 次重复取最小/中位；或跨进程配对）——这是唯一挡住"收益成立"的判据；
2. **替换格热点达 80%**（需让新键也落在热区间内，或改用"热点内替换"定义并重新登记）；
3. **R0 那套 contract / 差分 / 零分配门在候选 factory 上重跑**；
4. 250k 与百万规模、HOT 排名（后置，未变）。

## 7. 结论

- 块内再平衡在**增长语义**下稳定把 BM 的插入成本降到 **40.5%–59.4%**（中位 56%），
  三个数据集（含独立样本）一致，空间增量 ≤1.1%，语义与异常安全全过。
- 它在**替换语义**下无稳定收益，且**仍未追平 ART**（6–19 倍差距）。
- 因此结论保持"**限定场景的研究成果**"：默认仍 Context16，候选不进生产文件。
