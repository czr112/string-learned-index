## 3. 修订后的执行顺序

| 优先级 | 任务 | 完成标志 |
|---|---|---|
| **1** | 补齐真实源码身份、有界构建与正式 factory 验收 | core/adapter 绑定**真实哈希**；contract、差分、零分配、异常路径**对应同一候选**；`bulk_load` 不再复制全部输入 |
| **2** | 修正轨迹生成器并增加**执行前审计** | 增长**无重复**；真实语料键替换的成功操作 **2:1:1**；活跃数守恒；冷/热两组命中率与成功操作量匹配 |
| **3** | 在修正轨迹上补**真实空间计量** | 覆盖构建与分裂临时空间；核验常驻 ≤1.05、峰值预算 |
| **4** | 校准 A/A 并完成核心性能与读预算验收 | 增长收益、查询回退、**整段混合吞吐**均有明确判定 |
| **5** | 扩展独立样本、扫描与**当前版本**的 100k 复验 | 同一实现、同一入口、同一统计协议形成最终取舍表 |

### 3.1 测量协议（预登记，不得事后挑选）

1. **统计量固定**：以**配对比值 + 中位数 + 不确定区间**为主要判断；最小值仅作辅助观察；
2. **保留全部重复记录**，不在看到结果后再选择"最小值还是中位数"；
3. **四臂顺序用完整平衡循环**，建议 **8 个进程块**；
4. **同时输出整段混合吞吐**——逐操作计时汇总不能替代它；
5. 先用少量核心单元确认测量方法有效，再扩到全部负载。

### 3.2 热点生成的前置检查

生成前必须检查**热区内可用的新键数量**；容量不足时在登记阶段成对调整冷/热轨迹长度或真实保留池，
避免"增长进行到一半后热点比例下降"（本轮 80/20 增长格 39% 即此原因）。

## 4. 范围与预算

- 工作量按 **1–2 周**安排，沿用原总预算上限与提前停止条件；
- **保留**强保证与精确容量机制；
- **后置**：250k、百万规模、HOT 排名、新页机制；
- 默认仍 **Context16**；候选不进生产文件。

## 5. 当前最准确的结论

> 候选已有**明显的写请求耗时改善观察**（增长方向 40.5%–59.4%），**空间实现也取得进展**；
> 但**合规成功增长、完整空间预算、读性能与吞吐**尚需闭合验收。
