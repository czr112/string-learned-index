# N 系列报告复核：增长收益观察保留，尚不能认定五门全过

日期：2026-10-23；核对的 HEAD 为 `0d1a7de`。
本次读取研究报告、原始 N3/N4/N5 记录、生成器和候选源码，新增一个分配失败探针；
未修改候选、基线、默认配置或历史性能数据，未新增性能运行。
候选四份来源文件与现有 manifest SHA 完全相符。

**结论：块满归因与增长收益观察有价值，但“空间零代价、失败注入通过、五门全过”没有成立。
异常回滚已经复现失败，实际增长记录也显示明显内存增加。候选应保持待补验的实验状态。**

## 1. 已复现的回滚缺陷，优先修复

[bm_n1_page_core.hpp](diagnostics/bm_n1_page_core.hpp) 的 `try_insert` 在第 378 行先执行 `block.count=8`，
随后第 381–383 行依次向 `stable_fences_`、`blocks_`、`fences_` 插入。
这些操作可能分配并抛异常；此时旧块已经丢掉一半可见槽位，路径没有恢复旧状态。
外层 `Index::insert` 的 catch 只清 dirty 标记，也未恢复旧页。

最小探针直接使用原候选 Page：装载 1,024 行；向同块插入一键使其达到 16 槽；
再在下一次普通 new 上抛 `std::bad_alloc`，触发块分裂分配失败。

```json
{
  "threw_bad_alloc": true,
  "old_rows": 1024,
  "missing_old_rows_after_failure": 8,
  "verify_ok": false,
  "verify_error": "slot cardinality",
  "rollback_preserved": false
}
```

不是仅凭代码推测：异常后原有 **8 个键读回失败**，`verify()` 同时失败。
探针源码、输出与二进制保存在 [bm_n_series_review_20261023](results/bm_n_series_review_20261023/)。
探针返回 0 表示成功复现缺陷，**不表示回滚验收通过**。

现有 [gate_bm_n3.cpp](diagnostics/gate_bm_n3.cpp) 只有正常增删改和 `verify()`，未调用故障注入，
不能将“正常回放零失配”改称“失败回滚通过”。当前普通路径通过的语料/sanitizer 记录保留其原范围。

修复要求：所有可能抛异常的准备先完成，再提交块数/目录/计数；覆盖每个分配失败点，
并检查旧 map、旧值、计数及结构不变量。修改后使用新身份，不能把旧报告数字改称修复版成绩。

## 2. “空间零代价”与实际性能记录冲突

从 N3 四份原始 JSONL 按臂重算中位数：

| 65k 格 | 基线 `index_bytes` | 候选 `index_bytes` | 自计内存增加 |
| --- | ---: | ---: | ---: |
| words 95/5 | 1,586,704 | 2,520,741 | **58.9%** |
| words 80/20 | 见复核 JSON | 见复核 JSON | **43.4%** |
| URLs 95/5 | 见复核 JSON | 见复核 JSON | **18.2%** |
| URLs 80/20 | 见复核 JSON | 见复核 JSON | **13.7%** |

N4 均匀增长同样增加约 12.7%–58.8%；100k 增长四格增加约 7.1%–45.2%。
这些是实现的逻辑自计，不是完整 requested 字节账本，但已不能支持“增量路径空间零代价”。

九组空间小测试的 `delta=0` 只覆盖自身状态。特别是同终态 map 的 fresh rebuild 会重置增量块布局，
不能代表实际增量布局的内存；该程序也未报告分裂触发次数。
应在**实际性能轨迹同一时刻、同一键值集合**上测量 resident 和动态峰值，并用现有 allocation_trace 计入分配器/节点/适配器。

候选当前 `SplitAdapter::bulk_load` 还会全量复制 `physical` rows，而 BM0 使用 bounded 构建。
构建峰值未对齐；不能把旧 bounded 构建的峰值收益自动赋给此候选。
正常分裂中还有 `fences_.push_back`，报告“只动 blocks/stable_fences”与实际代码不完全一致。

## 3. 性能有改进观察，正式门仍缺

N3 的 40.8%–58.8% 降幅可以从原始数据重算，但当前驱动在计时区内执行 `oracle.find`、
`oracle.emplace` 和校验；不是纯索引成功插入成本或完整混合吞吐。
五次运行是固定顺序的独立单臂进程，没有 Williams 轮转或 AA 臂。

查询也不能表述为“全部在 ±10% 内”：words 80/20 的候选/基线 find 中位数为
`0.829/0.707≈1.172`，观察上升约 **17.2%**。没有 AA 证据不能证明其通过 ≤5% 回归门，
也不能仅从一组中位数确定统计显著性；须按原计划补完整读及 dynamic/同终态 snapshot 预算。

相对 ART 必须同格、同轮相除，不能把旧 R1 或 N3 的基线差距与 N4 的候选差距拼接：

| 轮次 | 候选写均值 / ART（现有带校验记录） |
| --- | ---: |
| N3 65k 均匀增长，5 次/臂中位数 | **5.285–6.174** |
| N4 65k 均匀增长，单次/格 | **3.677–4.807** |
| N4 65k 热点增长，单次/格 | **3.857–6.869** |
| N5 100k 词表增长，单次/格 | **2.118–3.839** |

因此“最好也只到 3.7–4.8 ART”“增长统一为 3.7–4.8 ART”都不是全部已测格的准确范围。
范围不同不能作为规模趋势或普遍稳定性的证明。100k 目前只测词表，尚无 URL/短语同规模结论。

另外，分裂中的两个 vector 中间插入需要移动后续块/目录，可能重新分配；局部搬运 8 个 entry 是常数，
完整操作不能概括为恒定 `O(16)`。

## 4. N4/N5 实际语义与登记不同

驱动报告所有操作结果零失配，说明索引正确处理了**实际生成流**；生成流本身未满足全部登记要求。

- **增长含大量重复插入**：N4 words 80/20 热点中，4,000 次尝试只有 **1,339 次新插入、2,661 次重复**；
  均匀对照有 3,448 次新插入。成功率与初态不一致，不能把热点/均匀差异归因为局部性。
- **查询命中率未对齐**：上述两格实测约 81.5%/74.4%，并非共享 90% 命中率。
- **替换不是严格恒活跃数成功流**：同一热点替换格 1,000 次 erase 仅 **955 次成功**、1,000 次 insert 全成功，
  因而净增长 **45**；2,000 次 update 仅 1,884 次成功。`2:1:1` 只是尝试数比例。
  全局 shuffle 及反复从初始集合选键，导致删除/更新操作落到已删除键。
- **新增键使用合成后缀**：替换插入 `old_key + '~n/i'`，不是从真实 held-out 键池取新键；键长与前缀分布也改变。
- **热点与扫描口径**：替换热点实际约 61%–62%，未达到登记的 80%±2 个百分点；
  每格是 20,000 find/write 加 400 scan，共 **20,400** 次操作，scan 占 1.96%、limit16。
  不是计划中的四个独立扫描风险格和 limit16/128 对照。
- **替换 `write_us` 是混合均值**：分母为 insert+update+erase 尝试数，不是成功插入单项。
  单次观测 −22.6%～+23.6% 只能写“未建立稳定收益”，不能直接称为已测 AA 噪声带或证明机制在严格真键替换上无效。

报告可以保留“已生成 16 格、各臂对该流零失配”；不能据此宣布合规热点/真键替换负载已完成。

## 5. 门禁状态及下一顺序

| 项目 | 当前可认定状态 |
| --- | --- |
| 直接触发计数与块满机制 | 有证据支持，值得保留 |
| 正常路径语料检查 | 三语料记录零失配；本次没有重新运行这些全量门 |
| sanitizer | 已记录 words 格；不外推到未运行的长键/异常路径 |
| 异常回滚 | **新探针已复现失败，须修复** |
| 空间 | **不能认定通过；真实增量轨迹自计内存明显增加，完整账本未测** |
| 纯索引性能、AA、完整读/动态预算 | 未完成；现有带校验降幅是观察证据 |
| 合规热点、严格真键替换、长扫描 | 尚未完成，保存现有负载结果 |
| 正式 factory 与同入口复现 | 报告已明确未做，N6未完整完成 |
| 通用采用 | 未通过，Context16 默认不变 |

建议下一步按顺序只做：**修复分裂异常安全 → 实际增长轨迹空间账本 → 同一正式入口的干净配对与完整读门 → 合规删插/热点**。
在此之前不扩大到百万规模、不叠加第二种机制。R3 的复制小实验也仍不是严格收益上限，
不能把“省掉注定不达标的实现”作为已验证经验继续传播。

可引用的修订摘要：

> 页内块再平衡在现有带校验增长轨迹中呈现明显收益；候选仍慢于 ART，
> 并存在已复现的分配失败回滚缺陷及实际增量内存增加。
> 纯索引性能、完整空间和正式入口验收仍待完成，因此保持实验状态，默认继续使用 Context16。
