## 2. 两处明确的负载缺口

### 2.1 "均匀替换"的更新/删除仍从冷区取键

生成器在替换分支里把候选池拆成 `cold_upd` / `cold_era`，非热点分支只从这两个**冷区**池取样：

```python
key = rng.choice(hot_upd) if use_hot else rng.choice(cold_upd or upd_pool)
```

因此"均匀替换"实际是"**冷区替换**"，不是全范围均匀。
**修法**：非热点分支应直接从**全体** `upd_pool` / `era_pool` 均匀抽，而不是从 `cold_*`。

### 2.2 冷热两组初始数据不同

为让热点配额可达，生成器按局部性使用了不同的保留比例：

| 语义 | 均匀 | 热点 |
|---|---|---|
| 增长 | 保留 4/5 → **初始 52,428 键** | 保留 1/2 → **初始 32,768 键** |
| 替换 | 保留 9/10 | 保留 3/4 |

这违反"均匀/热点必须共享同一初始 map"的配对要求——**冷热对比混入了初始规模差异**。
**修法**（登记阶段二选一，不得事后挑选）：

1. **统一保留比例**（两者都用 1/2），代价是均匀增长的写入键池变大，需重新核对均匀性；
2. **成对缩短写请求量**：保持 4/5 保留，把热点格的写请求降到热区可供给的量
   （80/20 热点增长约 3,200 → 需 ≤ 2,616/0.8 ≈ 3,270，成对降到 3,200 与对称冷格）。
