# U3 接线第三阻：根哨兵（sentinel）页不能参与切分

日期：2026-10-29。按解法 A'（在键所属块处切分、插入只落在局部的上半页）接线，运行期三语料一致报
`root sentinel`，已回滚。

## 现象与根因

`FlatRoot` 的构造要求 **第一个绑定的 lower key 必须为空**（哨兵页）：

```cpp
if(bindings_.empty()||!bindings_[0].lower.empty())throw std::invalid_argument("root sentinel");
```

切分哨兵页（键为空、`prefix` 也为空的那一页）时，上半个新页的 key 由
`prefix + 首个移出块的首后缀` 得到；当该后缀也为空时会得到**空 key**，
于是 `pages_` 里出现第二个空键绑定，排序后哨兵不再是唯一的第一项 → 抛 `root sentinel`。

这也解释了为什么三语料都在同一处失败：**每个索引都有且只有一个哨兵页**，
而增长轨迹的前若干次满页分裂必然命中它。

## 结论：切分路径必须显式处理哨兵页

三条可行约束（下一轮择一实现）：

1. **哨兵页不切分**：`if(target==pages_.begin())` 时回落到旧路径（scan + 重建）；
   代价是哨兵页的分裂仍走贵路径，但只影响每索引一次；
2. **切分后保证上半页非空键**：若 `upper_key.empty()`，把切分点右移到首个非空后缀块；
3. **允许空键但改根**：让 `FlatRoot` 接受"第一个绑定为空即可"而不是"唯一"，属于根语义改动，不作首选。

**推荐 1**，改动最小（一个分支），并且不影响收益的量级（哨兵页只占 1/32 页）。
