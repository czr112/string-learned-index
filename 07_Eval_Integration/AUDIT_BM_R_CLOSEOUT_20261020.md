# R 收口后复核：保留成果，修正下一轮的因果依据

日期：2026-10-20；仓库起点 `02e8a093831db25ef72354304a28e51d3433cf33`。
本次读取 R0–R3 原始 JSON、四份冻结字节轨迹与驱动/页核心；没有重新跑性能，没有改索引。
下一轮执行入口是 [R 收口后的 N 系列长期计划](../docs/LONG_TERM_BM_PLAN_20261020_AFTER_R.md)。

## 1. 可以保留的结论

- Context16 保持默认；研发对象继续为用户提供的 BlockModel，BM 页只读/动态均显式选择。
- 按页构建消除全量输入转换，历史同轮常驻请求字节约 0.427–0.731 ART，构建峰值约 0.437–0.756 ART，峰值比旧全量复制低 53%–57%。这些证据仍绑定各自空间轮，不能与 R1 自计字节拼成最新同轮排名。
- 新实验 factory 已接入 bounded 构建、base 查询、FlatRoot。初版公共验收 100/100，三语料各 263,121 项零失配；words sanitizer 通过。R0 收尾又验证了答案差分和查询普通 `operator new` 计数。
- R1 三臂共用冻结初始 map 和操作流，12 份保存记录均报告零失配。本次从四份轨迹独立重建计数，逐项符合三臂结果；这是轨迹/统计复核，不是重新运行索引的正确性测试。
- R3 未实施 `split_from`，停止决定继续有效。五项旧查询/根机制继续关闭；不因本次证据限定自动重开任何候选。

## 2. R1 是带校验的初步时延，不是正式吞吐排名

`bench_bm_r1_growth.cpp` 在 `Clock::now()` 之后执行 `oracle.find`，插入计时还包含 `oracle.emplace`、计数和校验。
每臂每格仅一次，按 BM→ART→Context16 固定顺序运行，未做进程配对。
`write_us` 的分母是所有插入尝试（含一次重复），不是成功插入单独计时。

以下只把保存值按**同一格**相除，越小越好：

| 格 | BM find / ART | BM insert / ART | BM insert / Context16 |
| --- | ---: | ---: | ---: |
| words 95/5 | 1.034 | 12.254 | 10.429 |
| words 80/20 | 1.217 | 11.496 | 8.620 |
| URLs 95/5 | 1.009 | 13.563 | 12.144 |
| URLs 80/20 | 1.124 | 13.881 | 10.749 |

因此原“ART 的 6–13 倍”应改为“带校验观察约 **11.5–13.9 ART**”；不能把不同格的区间端点交叉相除。
“查询持平”也应改为“部分格接近，观察比值 1.009–1.217；尚无严格的同轮配对结论”。
BM 增长慢的信号很强，精确差距、纯操作成本、混合吞吐和尾部暂停仍需 N1 测量。

## 3. 多数重建不是二分裂

R2 四格均为 26→51 页，但重建为 102/381 次。
在其 insert-only 驱动下没有 compact/coalesce；源码 `pieces = rows.size()>2048 ? 2 : 1`，每次二分裂恰增加一页。
据此可以推导：

| 格 | 重建 | 增加页数＝二分裂数 | 单页重建数 | 单页重建占比 |
| --- | ---: | ---: | ---: | ---: |
| words/URLs 95/5 | 102 | 25 | 77 | 75.5% |
| words/URLs 80/20 | 381 | 25 | 356 | 93.4% |

这是由记录和源码不变量推导的事件类型，**不是历史决策点直接计数**。
单页重建还不能细分为槽满、arena 不足、前缀变化或空页；须补直接原因计数和各原因的时间/重写字节。
“几乎每次重建都把满页拆成两个”与这组记录不符，不能据此优先做更早分裂。

## 4. R2 的计时范围不足以归因到页编码

| 保存指标 | 实际范围 | 可以说明什么 |
| --- | --- | --- |
| `write_ns=batch_ns-find_ns` | 包含插入侧 oracle、分支/循环和计时成本 | 该驱动的剩余时间；不是纯索引写入时间 |
| `page_ns`，占上述分母 42.0%–47.1% | `part` 拷贝、Page 构造、staged map 分配、空间自计/peak 及循环中临时对象析构 | 重建中的这一整段占比较大；不能区分编码、拟合、分配和记账 |
| 重建前 `core->scan` | 在 `page_ns` 开始之前，恢复完整字符串并构造 rows；随后还插入新行 | 真实重建开销的一部分，目前藏在 residual 中 |
| `root_ns`，3.0%–8.0% | 根准备范围 | 该小规模驱动下暂不优先改根；不是所有规模的根成本上限 |
| `reclaim_ns`，0.14%–0.33% | 仅 `root_.swap` 和旧根 `reset` | **不是旧页总回收**；旧页在更早的 `staged.erase(replacement)` 处析构，未被此 timer 覆盖 |

此外，`Index::insert` 先调用一次 `core->find`，`Page::try_insert` 再查一次；二者随后还有块定位。
重复查找、scan 恢复整页、旧页析构和记账均需要进入成本闭合；目前不能断言“剩余一半都是正常插入”，
也不能断言“主要差距已经定位到 tag/CRC/arena/fence”。这些只是候选解释，拟合占比同样尚未测定。

## 5. R3 的 9%–13% 是量级参考，不能证明严格上限

`bench_bm_r3_sizing.cpp` 用平均重写行数，从初始语料等距抽样一小组键；随后反复对同一组
`joined`/`part` 执行 `assign`。首轮后容器容量及多数 string 容量可以复用。
它没有重放每次实际页的键/字节分布，没有覆盖真实 `scan` 的前缀+后缀恢复和临时对象生命周期，
也没有消除真实索引中的复制后测净收益。将其 `copy_ns` 除以**另一进程 R2 的含校验 `write_ns`**，得到 9.0%–12.8%。

该实验既不是移除成本的严格上界，也不是严格下界；不能用它从 `page_ns` 直接扣掉约 10 个百分点，
再把余额分派给 tag/CRC 等子阶段。`split_from` 登记还涉及整块元数据/编码复用，超出了两次 `assign` 的模拟范围。
保留停止支线的工程决定，但改成“现有证据不足以支持投入”，不写成“数学上不可能通过 15% 门”。
“只重建一半就减半”与“更早分裂必定减少重建”也没有被这些记录证明。

## 6. R0 收尾的准确边界

- 196,713 项/语料主要比较答案、内存数值和插入结果；维护计数只读了裸 core。
  没有逐项比较 adapter 的 fences、训练输入/参数与所有维护计数；不把它称为完整结构差分。
- 零分配门重载的是普通标量 `operator new`；没有同轮拦截 malloc/new[]/aligned new。
  保存为“该 find 循环普通 new 计数为零”，最终请求字节仍用现有完整追踪器验证。
- 最终 wrapper/core 中位数为 **1.053/1.061/1.074**，AA 带为 **1.102/1.105/1.079**。
  “在 AA 带内”表示没有分辨出回归，**不表示已证明 ≤5% 或等价**。
- 初版 R0 manifest 的 adapter SHA 为 `0428cacd…`；当前枚举分派版本为 `f5723259…`。
  现有 `BM_CORE_BUNDLE_SHA256` 由单个 index 头的哈希再哈希而来，未覆盖 Page/Root/model 等依赖闭包。
  下一次计时前冻结实际文件清单并对当前入口跑一次公共验收；沿用既有追踪器和验收器，不新造框架。

## 7. 对下一阶段目标的影响

以带校验 R1 同格比值作**算术示例**，若要达到 ART 同等插入成本，需要减少约 **91.3%–92.8%** 时间。
若将 R2 的 `page_ns` 整段设为零，按原分母计算的加速也只有 **1.72–1.89 倍**。
两项都不是纯索引性能预测，不能跨轮相乘；它们说明“候选降低 15%”只是一条局部研究门，离通用替代还很远。

下一轮以“空间受限场景能否接受读写取舍”为可交付结果；纯索引配对测试是判断依据。
只有直接成本证据支持的新单机制才登记实现，不继续复制小优化、根优化或参数遍历。
R 系列可以保持收口；其中未完成的配对吞吐、原因拆分和真实删插/扫描作为 N 系列的新交付，不能标成已经完成。
