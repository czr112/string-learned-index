## 0. 结论

**目标格 Context16/mixed 的四条入口条件有一条不成立——「原筛选元数据行 >4 的查询占比」。

实测 3,133/10,000 = **31.3%**，要求 ≥60%。

按计划 §2「不满足即停」：**不建原型、不做 A/B、不改目标格、不改判据措辞挽救。**
其余三条在目标格上都成立（减少率 43.8% ≥40%、常驻 2.95% ≤5%、差分全等），
但入口条件是合取，缺一条即为否。

这个负结果不是「面板没用」，而是「**面板帮不到这个语料上典型的查询**」：
mixed/Context16 的每查询平均块数确实高达 12.04，但那是尾部拉起来的——
68.7% 的查询只访问 ≤4 个头部，19.2% 的查询访问 >16 个（直方图见 §2）。
入口条件问的正是「典型查询会不会受益」，答案是不会。

## 1. 装置与口径

- 六格：mixed / skew / tranco × Context16 / LITS；`baseline_config(128)` + `pin_frozen_switches`，
  C 开、W/S/H 关；普通 `bulk_load`；matrix2 原 rows/queries；标准查询模式（`locate=off`）。
- 面板按计划真实布局：每组连续、每块 32 B（`[0,16)` count+保留、`[16,32)` 16 个标签）、
  标签起点 16 B 对齐；真实分配后用**真实地址**统计逻辑行（16 B 对齐违规 0）。
  完整描述符与后缀不进面板。这是地址布局代理，**不是实测 cache miss**，本轮也**没有计时**。
- 逐查询重放：设备从面板重放生产的块循环——`count`、16 槽批、按 `count` 截断的活掩码、
  车道顺序、比较前的长度检查、命中即停——并把五个筛选计数（`subblocks_visited` / `simd_batches` /
  `tag_candidates` / `candidate_blocks` / `str_cmps_primary`）与同一索引、同一查询的生产 `Result`
  逐项比对；标签同时从「面板副本」与「由存储后缀重算 `Fingerprint::of`」两条独立来源枚举并逐车道比对。
- **跨轮交叉核对**：本轮的每查询无访问块均值与 PFX2 报告（另一装置、另一轮）的
  「子块头访问/查询」六格全部四位一致——12.04 / 16.24 / 18.11 / 27.62 / 2.91 / 2.53。

## 4. 这个负结果说什么、不说什么

**说什么**：在这三个语料的标准查询模式下，多块访问是**重尾**而不是普遍现象。
面板的算术是对的——只要一次查询真的跨过多个块，把 2 条 32 B 记录放进一条 64 B 行就是
接近 50% 的筛选元数据行下降（skew 两格 45.7%/47.4%）——但目标格上多数查询根本不跨块，
面板对它们既没有收益也不构成损失，于是「占比」这条门槛不成立。

**不说什么**：不否定面板在重尾查询上的价值，也不否定「筛选元数据」这个方向；
本轮没有证明或否证任何计时效果（无计时）。**本轮也没有为了挽救而**：换目标格
（skew 两格四条全过、tranco 两格 lines 也不过）、改占比定义（例如只统计 >4 头的查询内部的减少率）、
或重定义「头部」口径。

留给后续的可复用结论：设备已经把生产的筛选语义（批、掩码、车道序、长度检查、命中即停、
以及「生产标签 == `Fingerprint::of(后缀)`」这条前提）在六格上逐查询证明到位；
若未来要按**重尾子集**预注册一个新候选（例如只对 >16 块的长组启用面板），
那是另一份计划页、另一套权重与目标格，不能借用本轮的通过格。

## 5. 未测与限制

- 无计时；面板宽度/步长（24/32/48 B、8/16 B 对齐）、`locate=on` 分支、固定地址模式、
  动态写入后的面板同步、溢出检索本身，全部未测。
- 「逻辑行」是地址代理，不等于 cache miss、也不等于时间；冷块只统计了候选条目所在行。
- 溢出锚点按计划单独报告（466 / 563 / 1,015 / 913 / 0 / 0），没有并入原行数。

## 6. 关闭声明与下一步

M2「跨子块连续标签面板」作为本轮的候选在**入口**关闭：不建原型、不做 A/B、不改判据。
关闭范围仅限「整组连续 32 B 面板 + 16 槽批筛选」这一形态在**标准查询模式、全查询等权**下的目标；
重尾子集候选、以及长期路线 M3（模型所有权 / 参考表空间）与 M4（写后扫描块级归并）都不受其影响。

生产源码、默认开关、适配器与既有原始结果均未改动；`index.hpp` 640660a3… 未动，四份适配 manifest 无需同步。
