# 阶段3审计：真实键的失辨、窗口宽度与回退分布（登记）

2026-10-19，起点`eb41d23`工作树。依据[最新长期计划](../docs/LONG_TERM_BM_PLAN_20261018.md)阶段3第1条：
“先审计真实数据的同坐标fence簇、逐页最大/分位窗口、额外公共前缀与回退分布；
合成skew的99.93%歧义不能直接套到真实URL或短语”。本轮**只计数、不计时、不建候选**。

## 1. 审计口径

按BM叶页的真实构造逐页重建（2048行/页、占位15、页前缀=首尾公共前缀、
`BlockModel::fit(fences,1,7,8,1)`），对每页：

- **窗口宽度**：每个fence与每个真实键的`locate().window`宽度（块数），报均值/中位/p95/最大；
- **预测精度**：`predicted`是否等于该键所在块；窗口是否覆盖所在块（覆盖失败即必须走窗外交错）；
- **缺席覆盖**：每十条查询里的缺席键，其真实前驱块是否落在窗口内（否则走整侧搜索）；
- **同坐标簇**：7字节码相等的连续fence组成的run：占比、run长度分位、簇内**超出7字节的额外公共前缀**长度分位。

判定“是否存在值得动编码的结构性失辨”（登记）：

- `ambiguity_material`＝簇占比≥10% **且** 簇内额外公共前缀中位≥2字节；
- `window_is_wide`＝键级窗口均值≥8块（即窗内二分≥3步）；
- `encoding_refinement_justified`＝存在同时满足两者的真实格。

## 2. 不做

不建候选、不改模型参数/编码宽度/段数、不计时、不做外部排名；不把合成skew的歧义率外推到真实键。
