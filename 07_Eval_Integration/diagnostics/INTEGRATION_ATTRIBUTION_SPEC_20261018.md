# A阶段：集成成本归因，冻结的执行定义

基点main@2fb74ca；旧S3 c的7.75%失败判定保留。当前阶段只归因，不更改生产或只读核心。

1. 读取S3实际二进制，对比查询入口、CRC、标签循环及调用；机器码静态计数不当作周期比例。
2. 2×2：旧/新核心 × 普通/带构建状态检查包装。每个核心的两种包装共享同一对象；两核心均采用独立heap core + shared_ptr。
3. 第五标签是同一new_checked实例的A/A；第六臂是真实正式工厂，代码/空状态检查完全不变。
   最后一臂与控制仍混合了独立翻译单元、函数/数据布局、unique/shared所有权和不同实例，不能把其差额单独归给其中一项。
4. 主格skew/100k，然后tranco/mixed的100k风险格。原S3 c输入哈希、编译器、O3/C++17/x86-64-v3冻结。
5. 5进程×6次Williams顺序（0/1/5/2/4/3平移），每臂立即等量预热，计时2遍100k完整查询；所有查询通过v1虚接口。
6. 每进程在计时外检查全部语料键和100k请求。另一个独立进程检查逐查询工作量、数值/字节fence包含关系及CRC工具一致。
7. 同重复配对，先每进程再5进程中位数；F取new_AA/new_checked的对称观测带。
   回归：>5%、≥4/5更慢且超F；收益：<0.95、≥4/5更快且超F。不按结果追加重复。
8. 构建状态检查只有在两个核心上都产生清晰回归且实际接口残差不明显时，才是有支持的归因方向；不据此直接删检查。
9. 未复现/未分辨不撤销S3判定；源代码没有多余工作证据则不修改核心，按计划收口为未解释集成成本。
10. 本轮不链接ART/HOT、不产生外部排名；S3原装置的全部实例/内存环境未被原样复制，结论范围限于上述控制。
