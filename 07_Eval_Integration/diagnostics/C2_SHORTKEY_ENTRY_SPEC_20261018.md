# C2短键固定路径入口（计时前登记）

起点`49183a4`（E2完成）。主格固定为tranco/64k；mixed与skew为风险格。不新增布局、不改编码宽度/16槽几何/哈希算法，
不重开C1的完整切点融合导航。本轮只做**入口诊断**，不建候选、不改默认。

## 1. 要回答的两个问题

E2已把差距定位到“两端点共有的固定每查询成本”（100%命中1.358、0%命中1.353，均0/5更快）。
本轮问：这份固定成本花在哪，是否有任何一步能被**证明**省掉？

1. **完整工作账本**：把一次点查拆成区域导航→前缀校验→簇表查找→段搜索→窗口→CRC/标签/块进入→完整键比较，
   逐项计数（含memcmp实际比较字节），只报计数，不换算成时间。
2. **相位计时**：在同一份实现上用三段真实调用做差：
   `region`＝只做区域导航；`window`＝导航+前缀+簇表+段搜索（不含块内验证）；`full`＝完整点查。
   三者都执行真工作，不跳过语义，因此相减得到“窗口选择”和“块内验证”的实测代价。
   另加`directory`（同布局精确目录，完整点查）作策略对照，ART/HOT作外部参照。

## 2. 判据（预登记）

- 相位分解给出各段的**同轮配对比值**（相对`full`），5进程×6次Williams行，A/A带取`region_AA/region`。
- 主要问题：`window`与`region`相对`full`的差额是否足以支撑一个可证明覆盖的新候选。
- 若**没有任何一段**能在保持完整键区间可认证的前提下被省掉，或省掉后主格不足10%耗时下降：
  按计划§C-3“只有证明可以省去实质工作且完整键区间可认证，才建立一个导航原型”，**关闭C2方向**，
  记“短键差距为分散固定成本，当前布局无可证明的单步省除法”，转入F局部页更新。
- 若`directory`在同布局完整查询上清晰快于`learned`（主格≥10%、≥4/5同向、超A/A带），
  则下一步是“短范围先精确定位”的构建期数据规则候选（不是按语料名选择）。
- 不追加重复挽救；不把计数换算成分段时间；跨轮比值不相乘。
