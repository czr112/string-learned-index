# D1簇内前缀辨识：入口与候选执行定义

起点9e83148，保持B布局/区域/16槽/标签及CRC、外层导航不变，不修改旧源或队友算法，不做LITS适配。
唯一机制：原7符号坐标中，完整fence前驱跨度>3的等值簇，验证其额外公共前缀后，再读取后续7个9-bit符号。
只做一层，不搜索全局编码宽度或块大小。沿用原S3分段拟合/间隙与碰撞证书，预测目标仍是区域内实际块号。

簇的fence范围[first,last]对应安全父范围[max(0,first-1),last]，包含缺席键在首fence之前的前驱。
局部模型仅在原坐标精确命中簇、完整局部前缀相等时使用；前缀不符或局部证书仍>3块时，父范围完整字节目录纠正。
局部前缀和模型由索引自持有。EOS/NUL/高位字节沿用保序9-bit编码；numeric hint不替代完整键比较。
不匹配簇时使用原模型；目录控制不执行簇查找。scan沿用原精确seek与有序推进。

入口先于完整find实现/计时：8份S3冻结输入、独立完整行前驱、全键/块边界/缺席邻居与公共字节域。
skew/10k与100k同时要求：覆盖≥80%请求、≥80%被覆盖请求由局部≤3块模型直接定位、预计实际进入块减少≥50%。
预计进入块按有无命中与真实物理块位置计算，先与旧find的实际计数逐请求对账；不是性能承诺。
全部四份数据的新自持有元数据含对象/vector容量/前缀/局部模型，须≤B静态记账5%。
入口失败停止D1，不实现完整候选；通过才接公共验证入口，做共用v1验收及四份O2/ASan/UBSan完整门。

候选通过正确性后仅一轮完整查询A/B，主目标skew/full的10k和100k，风险mixed/tranco full两队列及tranco/64k两队列。
6标签：B learned、其同实例A/A、B wide_directory、B directory、D1、D1同实例A/A。
同一v1虚接口与unique_ptr包装/状态检查；5进程×6 Williams行(0,1,5,2,4,3平移)，位置和有向前驱平衡。
每臂即时等量完整预热，200k操作；g++13.3.0 O3/C++17/x86-64-v3，无LTO/NDEBUG，绑可用CPU，自行编译依赖。
同重复候选/各控制比值，每进程中位再取5进程中位。F取B和D1同实例A/A对称带的较大者。
skew两格相对B learned和旧wide_directory均须至少10%耗时下降、≥4/5同向且超F，才能宣称新的场景收益。
任何风险格>5%、≥4/5同向且超F的回归阻止通用采用；未分辨不证明零成本。
不追加重复挽救失败，不把少查块或不同轮比值相乘当成加速。原S3 7.8%失败及生产默认保持不变。
