# U1 第二半：插入时间的归属——**页重建占 75.5%–95.6%**，块分裂只占 0.3%–9.5%

日期：2026-10-29。承接 [U0/U1 第一半](RESULTS_BM_U0_U1_20261029.md)（"维护路径占 80–89%"）。
本轮用页内计数器把慢路径**拆到触发来源**，结果改变了优化对象。

## 方法

逐次计时成功插入，用计数器差分判桶（不额外插桩）：

- `block_splits` 增 → **块内再平衡**（候选机制）；
- `rebuilds` 增 → **整页重建**（页满 / arena 不足 / 前缀变化）；
- 都不增 → **页内槽写**。

## 判读：优化对象被纠正

1. **块内再平衡（候选机制）只占插入时间 0.3%–9.5%**——
   它把"单页重建"换成了 O(16) 的块操作，**这部分已经基本榨干**（单价 2–4 µs，接近一次查询）。
2. **真正的成本是整页重建：75.5%–95.6%**，单价 140–334 µs，每次重写约 1,600 行
   （45,466/28、142,134/116），URL 因键长更贵（334 µs）。
3. 因此上一半的"维护路径占 80–89%"应更精确地表述为：
   **整页重建占 75.5%–95.6%，块分裂占 0.3%–9.5%，页内写占 4.0%–16.6%**。
4. **页满重建的触发器只有一个**：页达到 2,048 行。要再降写耗时，必须降低
   "每次页满重写 ~1,600 行"的成本，而不是继续优化块。

## 对 U3 的直接影响

- 立项门仍通过（页重建占 75%–96%，把它降 25% → 总写耗时降 19%–24%，≥15%）；
- **但机制对象要换**：应做**"页分裂时不重编码全部行"**——
  把原页已编码的块按边界切成两半、只重建跨界块，而不是重新 encode 1,600 行；
- 这正是早期被否掉的 `split_from` 方向，但**当时否决依据是错的**
  （当时算的是"字符串复制 9%–13%"，而真实成本是"整页重编码 140–334 µs"）。
  现在有正确的成本依据，值得作为 U3 的**唯一候选**重新登记。
