# 差分门：候选与基线在构建期逐字段相同，变更后答案一致

日期：2026-10-24。闭合[优先级 1](RESULTS_BM_P1_FACTORY_20261023.md) 遗留的"逐字段差分"项。

## 做法

同一份 rows 上分别构造基线（`bm_bounded_page::Index`）与候选（`bm_n1_page::Index`），比较：

**构建期（必须完全相同）**
- 页数、`memory_bytes()`、`fence_keys()` 全量逐条、`verify()` 的检查计数；
- 每个键的 `find_base` 与 `find`（窗口路径）答案，且两侧都对照 `std::map` 预言机。

**变更后（只允许维护计数分化，答案必须一致）**
- 同 800 次插入，两侧返回值逐次比对；
- 全键读回一致；
- 记录重建次数、页内插入数、重写行数。

## 结果（三语料）

| 语料 | 检查项 | 失配 | 页数 | 重建 | 页内插入 | 重写行数 | 终态 scan |
|---|---:|---:|---|---:|---:|---:|---:|
| english_words | 395,652 | **0** | 64 / 64 | 32 / 32 | 768 / 768 | 65,568 / 65,568 | 66,336 |
| memetracker_urls | 395,652 | **0** | 64 / 64 | 32 / 32 | 768 / 768 | 65,568 / 65,568 | 66,336 |
| memetracker_phrases | 395,652 | **0** | 64 / 64 | 32 / 32 | 768 / 768 | 65,568 / 65,568 | 66,336 |

（每格 395,652 项检查：全部行 × 4 项、全部围栏、`verify()`、800 次插入一致性、全键读回。）

**构建期完全一致**：页数、内存、围栏逐条相同，`verify()` 计数相同，
说明候选没有改变页布局、模型输入或分区，只改了"块满时怎么做"。

## 一处必须说明的局限

本门的 800 次插入用的是"源键 + 后缀"的构造方式，**很少命中同一个块**，
因此**没有触发块分裂**（两侧重建次数都是 32＝页满分裂）。所以这一轮验证的是：

- 构建期结构完全等价 ✅
- 未触发新路径时行为完全等价 ✅
- **但没有**验证"触发块分裂后与基线的答案一致性"——那部分由
  [三语料语义门](RESULTS_BM_P3_SPACE_20261024.md)（263,822 项、含 600 插入）和
  [N4 十六格](RESULTS_BM_N4_20261022.md)覆盖，那里确实发生了块分裂。

要把差分门做到"分裂路径也逐字段对比"，需要构造**密集落在同一块**的插入序列
（例如对同一源键做连续后缀插入），这是下一轮的具体做法。
