# U3 接线第二阻：顺序冲突——下半页在切分前仍是"满页"

日期：2026-10-29。接线跑通到运行期，但三语料都在同一处失败，已回滚接线。

## 现象

```
split insert into the lower half was rejected
```

（三语料一致。）`rebuild_by_split` 里我按"先插入、后 prepare_root"的顺序写，
但插入目标是**尚未 `apply_drop` 的下半页**——它此刻仍是 2,048 行，
`try_insert` 直接返回 `Page::Insert::rebuild`（页满），于是抛错。

## 根因：三个约束互相冲突

| 约束 | 要求 |
|---|---|
| 强异常保证 | `prepare_root` 之前不能改动活页 |
| 下半页插入 | 必须在下半页**变空之后**（2,048 → 约 1,024 行）才能成功 |
| `apply_drop` 是 noexcept | 它必须在下半页插入之前或之后，但不能倒过来 |

现有三条路径都不满足：

1. **先插入后 prepare_root** → 下半页还是满的，插入被拒（本轮失败点）；
2. **先 prepare_root 后插入** → `prepare_root` 成功、`apply_drop` 完成，但随后的插入若抛异常
   （块分裂要分配），下半页已瘦身、root 还是旧的 → 不一致；
3. **在副本上插入** → `Page` 拷贝被删除，不可用。

## 可行的两个解法（下一轮择一）

**A. 预插入到上半页 + 下半页用"预留即无抛"路径**
- 若键属于上半页：`extract_split` 之后直接插入上半页（它是局部对象，安全）；
- 若键属于下半页：先 `apply_drop`，再用一条**已预留**的插入路径——即在 `apply_drop` 里
  顺带把下半页目标块的 arena/块容量预留好（`reserve` 放在 `extract_split` 阶段，属可抛区）。
  这样 `apply_drop` 之后的下半页插入不再分配 → 可视为 no-throw。

**B. 允许窄窗口并回滚**
- `apply_drop` 后插入，失败则把键从未完成状态移除并复原 `regions_[0].count`/`size_`；
- 实现简单，但破坏"无回滚"的项目惯例，不推荐。

**推荐 A**：把"下半页插入所需的容量"当成 `extract_split` 的一部分预先算好
（目标块若已满 16 槽，则在 `extract_split` 里先给下半页该块预留一个槽位，或在切分点选择上
保证下半页的末块未满）。
