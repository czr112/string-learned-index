# U3 第 0 步：重建成本里模型拟合只占 **3.7%–3.8%** → `split_half` 方向成立

日期：2026-10-29。执行 [U3 规格](U3_SPEC_PAGE_SPLIT_20261029.md) 的第 0 步（决定是否值得实现）。

## 测量

公共 API 探针：分别计时"构造一个 N 行的页"与"同规模块边界上的 `BlockModel::fit`"。

| 指标 | words | urls |
|---|---:|---:|
| `Page(512 行)` | 10.6 µs | 14.3 µs |
| `Page(1,024 行)` | 20.1 µs | 27.3 µs |
| **`Page(2,048 行)`** | **71.1 µs** | **69.1 µs** |
| `BlockModel::fit`（103 个 fence） | 2.73 µs | 2.54 µs |
| **拟合占 2,048 行页构造** | **3.8%** | **3.7%** |

## 判读

1. **模型拟合只占 3.7%–3.8%**——U1b 里 140–334 µs 的重建成本**不在拟合上**。
2. 页构造本身约 **70 µs/2,048 行**，其余成本在
   **arena 后缀写入、块切分、tag/CRC、fence/digest、以及重建路径里 `scan()` 出 2,048 个 `std::string`**。
   后者尤其重：整页扫描要把 2,048 行物化成字符串，正是 `split_half` 要消除的部分。
3. 因此"页分裂不重编码"的**收益上限远大于 15%**：目标是省掉 scan + arena 重写 + 块重切，
   只保留"搬块元数据 + 压实字节"。

## 决策：**GO**（进入 U3 第 1–2 步）

规格里的停止线是"若拟合占一半以上则不实施"——实测 3.7%，**远低于停止线**，
所以 `split_half` 值得实现。

预计收益（保守）：重建单价 140–334 µs 中，若只省掉 scan（约 40–60 µs）与 arena 重写（约 20–30 µs），
即可降 **≥25%**，对应**总写耗时 −19%–24%**，满足立项门。

## 下一步（U3 第 1–2 步）

1. `Page::split_half(src, blk_lo, blk_hi, …)`：只搬选中块的 `entries/tags`、arena 压实并重写偏移、
   fence 由块首 entry 构造；跨界导致前缀变短时回落整页重建；
2. `Index::rebuild` 在 `rows.size()>2048` 时改走它，两半构造成功后才释放旧页（强异常保证）；
3. 门：语义/不变量/异常/差分/空间/查询回退全部沿用，收益门为**重建单价 −25%**。
