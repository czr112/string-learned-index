## 0. 判定

**截断本身成立，但候选仍未达到采用门槛，继续保持默认关闭。**

- **截断把等深目录从“更大”变成“更小更快”**：目录 arena 在 mixed/skew/tranco 上分别
  2,121,557 → **225,478 B**（−89.4%）、1,799,334 → **332,242 B**（−81.5%）、
  264,219 → **113,421 B**（−57.1%，tranco 是 262,144 键口径）。
- **机制对照（DDir vs DDirT）给出明确方向**：截断让 mixed 静态点查 **0.856（5/5）**、
  skew **0.894（5/5）**、tranco **1.006（2/5，未分辨）**；即“更小的 arena 换更快的查找”在
  mixed/skew 成立，tranco 本来 arena 就小（0.87 KB/区域），截断自然无增量。
- **但对 Context16，主目标没到**：mixed 静态 **1.037（1/5，噪声底 1.219）→ 未分辨（不达标）**；
  tranco 静态 **1.240（0/5，噪声底 1.166）→ 可分辨回归**。按计划 §6 的采用规则
  （主目标 mixed ≤0.90、风险格可分辨变慢 >5% 则不作通用读配置），**不设默认**。
- **场景结论**：skew 是稳健收益（静态 **0.830**、更新后 **0.697**，5/5，均超噪声底）；
  维护在三语料上全部更快（**0.491 / 0.409 / 0.708**，5/5，可分辨）；skew 的更新后点查也因此受益。
- **预算**：模型成分相对全索引只增 **+0.5%–0.7%**（未截断版本在 mixed 上是 +5.6%，超预算）；
  目录 arena 已不再是内存问题。全索引常驻在同装置上比 C16 **小 22%–35%**（含布局效应，见 §6）。
- **边界**：本轮没有 ART/HOT 对照、没有扫描/尾延迟、没有释放 C16 参考表（那是另一个空间候选）、
  没有换规则或加参数。tranco 的回归不是 arena 造成的，下一轮若继续，先做入口诊断再动代码。

## 1. 候选与规则（冻结，无自由度）

新增 `ModelBackend::EqualDepthDirTrunc`（臂名 `DDirT`）：与 `EqualDepthDir` 同一份等深排名目录，
只是每个阈值 `t_j` 存成 **“比紧邻左键大的最短前缀”**——`c = lcp(x_{r_j-1}, s_j)`，
`c < |s_j|` 时存 `s_j[0..c+1)`，否则（重复键run的边界）退回完整 `s_j`。规则与证明见
`TRUNCDIR_ENTRY_DESIGN.md` §2–§3（引理 A 逐键路由等价、B 单调、C 任意查询的区间不变量）。
默认配置仍是 `Context16`：`model_backend` 不指名它时，构建/查询/更新路径与上一轮逐位一致。

## 6. 内存与预算（同一装置的逐臂中位数）

| 量 | mixed | skew | tranco（262,144 键） |
| --- | ---: | ---: | ---: |
| 目录 arena：DDir → DDirT | 2,121,557 → **225,478 B** | 1,799,334 → **332,242 B** | 264,219 → **113,421 B** |
| `memory_breakdown().model`：C16 → DDirT | 1,056,768 → 1,367,250 B | 1,056,768 → 1,469,662 B | 2,113,536 → 2,314,509 B |
| 模型成分增量（相对全索引） | +0.54% | +0.70% | +0.49% |
| 全索引 `index_bytes`：C16 → DDirT | 57,485,011 → 44,625,261 B（−22.4%） | 59,336,518 → 43,893,442 B（−26.0%） | 40,693,510 → 26,524,865 B（−34.8%） |

两点必须分开说：**目录本身只增加 225–332 KB**（相对 C16 的参考表 1,056,768 B 反而更小），
但 DDirT 仍会保留那张 C16 参考表（`lits_skip_reference_table` 是 LITS 专用，本轮未扩展），所以
“模型成分”反而变大；**全索引的 −22%…−35% 是布局效应与模型成分的合计**——等深分组消除了
溢出并缩小了块，不能把整个差额记在模型或目录头上。上一轮未截断版本的 mixed 模型增量
（+2.21 MB ≈ +5.6%）在本轮降到 +0.54%，**常驻预算由此通过**。

## 7. 采用判定（按预登记，不换目标、不加重复）

- **主目标未通过**：mixed 静态 1.037（1/5）既不到 0.90，也没有超过噪声底的方向证据；
  tranco 静态 1.240（0/5）是可分辨回归。→ **`EqualDepthDirTrunc` 保持默认关闭**。
- **候选自身的问题已回答**：截断在 mixed/skew 上严格优于未截断形态（0.856 / 0.894，
  5/5），tranco 上中性（1.006），同时把目录内存压到 1/9–1/2。上一轮“未截断 arena 缓存不友好”
  的假设由本轮机制对照直接证实；tranco 的差距另有原因。
- **场景结论**：skew 可用的静态/更新/维护收益（0.830 / 0.697 / 0.409，均 5/5、超噪声底）；
  维护在三语料全部更快。这仍是“按场景保留”，不是默认。
- **禁用读法**：不得把“全索引小 22%–35%”当成目录的纯空间收益；不得把 skew 的收益外推到
  mixed/tranco；不得以本轮证据宣称超过 ART/HOT（本轮没测）。
