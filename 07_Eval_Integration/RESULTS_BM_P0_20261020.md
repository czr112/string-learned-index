# P0 修正：臂身份、校验和精度、预算方向

日期：2026-10-20；执行入口[新长期计划](../docs/LONG_TERM_BM_PLAN_20261019.md)，依据
[复核](../07_Eval_Integration/AUDIT_BM_NEXT_PLAN_20261019.md)。本轮只做 P0，不动模型/索引/旧测量。

## 三项修正与结果

### 1. 分块根：臂标签与真实路径不一致，原通过判定确认撤回

旧驱动用`pass(arm>=2)`选路径，而标签是`flat/chunked/flat_AA/chunked_AA`，因此`chunked`臂实际跑的是
flat 同对象 AA。新驱动`bench_bm_root_chunk_v2.cpp`改成`pass(arm==1||arm==3)`（标签与路径一一对应），
以新身份重编并重跑 3 格 × 5 进程 × 6 轮：

| 输入 | 修正后 chunked/flat | 结论 |
|---|---:|---|
| tranco/64k | **1.968** | 短键路由约慢 2 倍 |
| skew/131k | 0.884 | 长前缀格数值更快，但救不回三格门 |
| tranco/262k | **1.924** | 短键路由约慢 2 倍 |

登记条件是三格均`|chunked/flat−1|≤0.05`，**`entry_gate_passed=false`**。这与审计从旧记录重算的
2.063/0.873/1.992 一致（数值差异来自重新运行）。旧轮`bm_root_chunk_20261019`保持冻结，
其"入口通过"结论**撤回**；分块根**不进入集成**，FlatRoot 保留。

### 2. 动态读预算：按登记方向重算

旧判读用了`snapshot/dynamic≤1.15`，登记方向应为`dynamic/snapshot≤1.15`。从原480条记录直接配对重算：

| 轨迹 | dynamic/snapshot | ≤1.15 |
|---|---:|---|
| words 95/5 | 0.981 | 是 |
| words 80/20 | 0.970 | 是 |
| URL 95/5 | 0.948 | 是 |
| URL 80/20 | 1.003 | 是 |

四格仍在预算内；方向错误没有改变数值判定，但旧`snapshot/dynamic`表述作废。
旧 runner 里带`or True`的终态行数断言也在此登记为必须在下一正式版本换成独立不变量检查。

### 3. 干净重建的"校验和差28"不成立

用原重建二进制、原输入，跑两次并保存原始 stdout，**按十进制字符串精确比较**：

| 来源 | checksum |
|---|---|
| 历史记录（capacity.json） | 507521454403758928 |
| 本次运行 0 | 507521454403758928 |
| 本次运行 1 | 507521454403758928 |

三者完全相等。旧比较里的`507521454403758900`是 JSON Number（双精度）往返的结果，
**不是索引行为差异**。后续校验和一律保存原始输出并以十进制字符串或十六进制比较。

### 4. 版本漂移披露

以下文件与其当轮`identity.json`不再逐字节一致（本会话其后有过编辑）：
`verify_bm_dynamic_entry.py`、`BM_DYNAMIC_READ_SPEC_20261019.md`、`BM_ROOT_SCALE_SPEC_20261019.md`、
`BM_ROOT_CHUNK_SPEC_20261019.md`、`verify_bm_root_chunk.py`。
处理：**不补写旧哈希、不篡改冻结身份**；本轮以新驱动/新结果目录发布，旧记录标注"规格/复核脚本已漂移，
原始计时 driver 源码仍匹配"。无法从 Git 恢复的按不可恢复披露。

## 对计划的影响

- 根不是当前可用的优化方向：分块根在短键上约慢 2 倍，FlatRoot 保留；
  只有另行登记的新根机制通过真实成本与完整查询门才集成。
- 读预算结论维持，但表述与方向已更正。
- 校验和不确定性解除，索引在同等输入下确认确定性。

## 下一步（P1）

按计划分离测量**根复制、页重建与回收**的真实成本：给 `Index` 的发布路径加分段计时与计数器
（根准备/发布、页构造、旧页销毁、dirty 集合），在固定页数上分别报告，而不是用条目数推算时间。
只有确认根是主要成本，才进入 P2 的新根机制。

## 边界

- 本轮是**修正与重算**，不是新性能结论：分块根仍是诊断类型，没有集成、没有写吞吐。
- 根比值的重新测量用 3 格 × 5 进程，与旧轮同协议。
- 干净重建仍是"同一重建二进制 + 一格"，不是整轮性能复现。
