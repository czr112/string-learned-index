# BM完整点查同轮比较：固定协议

前置：BM_PAGE_SPEC的O2/ASan动态语义全部通过，真实BM调用与上游源身份已确认。
六策略：BM_base、BM（窗口内/补集精确纠正）、directory、冻结F5、ART、HOT，各自同实例AA，共12臂。
前3策略共用同一个BM页索引，仅定位方式不同；F5保持原冻结叶页/自研模型；ART/HOT固定原工厂源码。
查询循环统一通过string-index/v1虚接口，不为外部基线叠额外虚调用包装。
BM/F5只读view借用实验owner；bulk_load/维护由owner完成，不能把view本身字节当索引空间。

沿用E2的三份行/查询身份和F5的clean/dirty两态，六格。dirty固定1024次既有值update，seed=0xf2a20261018。
所有实现拥有同一当前map，逐键/逐查询及owning scan核对；每10条查询追加~f2/miss并证明缺席。
全部六格普通O3及ASan/UBSan预检后才计时；ART/HOT普通和sanitized从固定源码分别新建并通过共用验收。
自计空间排除元数据未知部分，不把它等同完整堆；本轮没有新的完整分配峰值或混合读写排名。

固定5进程×12轮×12臂×6格=4320计时行，单CPU0，O3、march=x86-64-v3，无LTO。
Williams顺序[0,1,11,2,10,3,9,4,8,5,7,6]，每repeat/process旋转；各臂共用shuffle(seed=0x12345f2+repeat)。
先每臂一次完整不计时预热。每轮对所有臂校验同一顺序下完整答案checksum。
每进程取12个配对耗时比的中位数，再取5进程中位数，双方AA取各进程对称最大观测带。

BM优化收益门：mixed/skew的clean/dirty四格均BM/BM_base<=0.90、>=4/5更快且超双方AA带；
tranco两态不能有BM/BM_base>1.05、>=4/5更慢且超AA带的回归。未分辨不叫通过，不追加重复挽救。
外部比较直接报告BM/ART、BM/HOT、BM/F5及BM/directory，至少5%和>=4/5并超AA带才称清晰差异。
BM/ART每格<=1.10是通用读场景必要目标；单格失败不能用平均值掩盖。
BM为用户指定的模型研究主线；某个纠正策略失败只关闭该策略采用，不自动退回自研模型继续优化。
所有失败、版本、输入、命令、二进制、实际工作账和源码保留；不跨轮相乘推导外部排名。
