# 阶段4：BM/ART分配、常驻与峰值账本（运行前登记）

2026-10-19；模型3894c767，benchmark003a55bf，沿用三真实样本与tranco64，各65,536键。
只测 BM-page-base、原生 block-residual-delta-shortdir-first、现有项目ART适配器。
上游原生ART适配器有不同输入/字节约束，本轮不替换历史ART参照。不改模型、布局、参数或默认。

## 先验收测量器

Linux glibc专用独立测量程序，以可替换C++ new/delete（数组、sized、aligned、nothrow）
及进程导出的malloc/calloc/realloc/free拦截请求；直接使用__libc分配后端，固定静态指针表避免递归分配。
记录请求字节、malloc_usable_size、对象数、累计分配/释放、各阶段共同存活峰值及入口种类。
测试包含已知尺寸序列、零尺寸、共享C库/libstdc++边界、realloc迁移/失败/零尺寸、对齐及释放归零。
任何计数、覆盖或跟踪表溢出均停止，不出空间排名。追踪器表不计入索引，表尺寸单列。
该覆盖不是OS全部内存：glibc内部隐藏分配、显式mmap及未拦截的C对齐分配仍需披露。
实际目标源码不得直接使用这些绕过入口；mallinfo2和RSS/HWM作旁证，不把它们与请求字节混称。

## 正确性与独立进程

新增BM-base薄适配器调用冻结core的find_base，其他操作真实转发；所有TU使用同一新contract。
同一个保持输入生命周期的公共接口验收；新普通与ASan/UBSan/LSan二进制覆盖三臂四格，
逐行、约90%命中全查询、全scan、scan结果在索引/输入销毁后仍有效。失配或sanitizer失败先停。
跟踪器不与ASan合用；跟踪和未插桩构建使用相同目标源码/flags/库，分配拦截仅测量程序启用。
跟踪程序也重新验证答案。每臂每输入独立进程，三次容量确认；不把插桩耗时当性能结果。

## 阶段与输入

读入rows单独标为input；读取/转换临时缓冲结束后，实际live须等于vector/key容量请求量。
oracle、queries、日志与追踪器不计入索引。原生借用完整rows，**有效常驻与峰值加input实际存活量**；
BM-page和ART拥有所需内容，不把仍为校验保存的调用方rows计入它们的有效索引总量。
分别记录build、完整find、owning scan的请求/usable常驻与共同峰值。scan返回缓冲独立标记，
核对其live量与实际返回vector/key容量，释放后归零；索引销毁后其全部跟踪请求/对象归零。
build峰值包含构造、bulk_load的临时行复制、拟合、根和容器扩容，不移动到测量外。
full find不得新增候选BM堆分配；参照臂如有分配如实记录，不静默扣除。
全进程RSS/HWM包含输入、oracle、tracker和运行时，只报告观测，不用HWM相减冒充索引峰值。

## 构建时间及判读

未插桩二进制各格五独立进程，三臂循环轮换顺序，单CPU；仅构造+bulk_load计时，随后验证答案。
不测/不排名查询或scan吞吐；旧查询失败结论不变。构建中位数和各进程原数均保留，非显著性证明。
容量主判据为有效requested常驻/ART，必要条件<1.00，目标≤0.70；usable同列，不用平均掩盖失败格。
空间场景入口还需build有效requested峰值不超过ART（≤1.00），构建中位耗时≤ART的1.20；
未达上述组合则不能称为完整可用场景，保留单项权衡，进入后续维护只能按明确研究条件单列。
