# F4M 只维护需回收页：实现前登记

F4单因素归因未过预登记门，组合收益不冒充单机制；本轮不增加计时或路由候选。
修复F3已知维护欠账：显式compact遍历/重建所有页。独立新类型复用冻结F3叶页和树路由，原F3/F4源码/证据不改。

- 新增写侧 dirty 集合，成员为稳定 std::map 迭代器，不改变叶页/Node字段及点查函数，不在读路径探测 dirty。
  成功原地insert/erase标记回收需求；纯值update、重复insert及缺席写均不标记。新建/重建后的页干净。
- compact只从dirty集合取页，允许按F3规则吸收一个邻页。新页和路由准备后再无分配发布，
  先从dirty移除将被替换/删除的旧页，再销毁旧节点，避免悬空迭代器。空dirty时O(1)返回。
  相邻干净页可因合并被重建，不能声称每个重建页都曾被写。
- dirty记录首次标记可能分配，必须发生在原地修改前；标记失败、重建失败、部分分裂失败均保持原map、页版本和dirty集合。
  额外分配属于写成本，不声称免费。自报空间仍不含两种树节点链接/分配器元数据。
- 检查：无写/纯值更新compact零目标零重建；8192键单页删除只重建2047活行，未触及页版本不变；
  多次compact幂等、dirty标记失败、首次插入导致部分分裂失败、已有dirty的compact失败、跨页合并删除dirty迭代器、
  全删至单空哨兵、随机混合与三份真实语料、owning scan。独立std::map及普通/ASan/UBSan均零失配。
- 明列compact调用/目标页数、重建行数、相邻源页上限和dirty标记/清除数量；检查常驻账本一致。

通过仅说明维护工作不再无条件随全库增长，不撤销F3读门失败，不发布动态吞吐/维护延迟/完整峰值或采用结论。
