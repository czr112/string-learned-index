起点`c240526`（E1完成）。D1四份实现头文件、B核心、原S3包、生产动态Index、Context16默认与LITS全部不改。
本轮只扩大测量范围并补空间口径；不新增算法收益，不重开C1，不搜索参数，不为三份语料改算法。

1. E1的100k请求只覆盖部分工作集（tranco/full仅29.07%的不同键）。**无放回全库命中遍读**下，D1相对ART/HOT的

2. 短键（tranco/64k）与长前缀（skew）在**100%命中**与**0%命中**两端点上的差距分别有多大？

3. 暖态遍读与“驱逐缓冲后首遍”差多少？首遍单列，不称严格冷缓存。
4. ART/HOT的内部空间到底多少？补完整分配请求字节与峰值，避免把“未知”长期当作空间优势。

## 3. 测量模式（分开报告，不跨模式比较）

- `gate`：建4个对象，六臂各自对**全部行与全部查询**逐一核对presence/value；只做正确性，不计时。
- `warm`：每臂即时一次不计时全遍预热，随后6次计时全遍；每repeat用同一确定性置换，六臂同时收到，
  臂序按Williams行`{0,1,5,2,4,3}`平移。
- `first`：每轮按平移顺序**重建**该臂对象后立即一次计时全遍（不预热、不预先查询该对象）。
- `evicted`：四个对象建好后，每臂在**256MiB写入扫描**后立即一次计时全遍；共6轮。

5个独立进程；`taskset`绑同一CPU；每进程内先做门与预热，再计时。
驱逐一词只表示“被我们的写入扫描挤出”，页缓存、TLB与分支预测仍可能残留，故不称冷缓存。
计时循环内仍计算校验和；同一(模式,repeat,进程)下**六臂校验和必须相等**，否则判装置失败。

## 4. 判据

清晰差异＝比值≤0.95或≥1.05，且≥4/5个进程同向，且超过同格双A/A（`prototype_AA/prototype`、
`integrated_AA/integrated`）的对称观测带。未分辨不证明相等。
通用“每格≤ART的1.10倍”门已在E1失败（两个tranco/64k单元），E2不能撤销该判定；
E2只按单元记录读数并给出**证据支持的场景**，不把任何单格收益解释成通用追平。
任何一格出现正确性失配即停止该格，不追加重复挽救。

## 5. 空间账本（独立构建）

`ledger_e2_allocation`每次只建一个对象，读入行后记录基线，构建后记录：
glibc `mallinfo2`的in-use与mmap增量、`/proc/self/status`的`VmHWM`峰值与`VmRSS`、
以及`-Wl,--wrap=malloc,calloc,realloc,free`统计的**精确分配请求字节**与峰值。
wrap只作用于本轮链接的.o与静态归档，因此对libart这类C实现可完整归因；对走`operator new`的C++实现，
wrap近似0，改以`mallinfo2`增量报告，并在结果中标注该差异。
`VmHWM`含读入行与构建瞬态，是进程峰值上界，不是索引峰值；分配器slab/元数据仍未完全分离。
