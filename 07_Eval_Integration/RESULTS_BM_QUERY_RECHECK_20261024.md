## 分组已独立核验

热区为 manifest 的源键排名闭区间 `hot_range=[lo,hi]`，排名来自完整源键池。hit 从重放后存活集取，miss 必须在终态缺席；真实源键缺席和合成缺席分别测量。各组最多 2,000 个不同键，无放回抽样，短组使用全体。

| 查询组 | 定义 |
|---|---|
| live_hot / live_nonhot | 终态存活、分别位于真实热区内/外 |
| absent_hot / absent_nonhot | 真实源键但终态缺席，分别位于热区内/外 |
| synthetic_absent | 原轨迹出现过、终态确认缺席的合成查询键，不赋予源排名 |
| mixed90（主指标） | 1,800 个终态命中键 + 200 个合成缺席键 |

“非热区”不是“冷缓存”。本轮测预热后的固定终态查询集，包含新插入的存活键；它与原始混合轨迹里交错执行的 find 是两个通道。

Python 生成终态与查询文件，C++ 用独立 map 完整重放，对照检查返回值、scan、四状态全量终态及每条查询答案。全部 33 条真实/控制输入通过 ASan/UBSan/泄漏检查；字节边界夹具也通过。三个负对照——已删除键误标 hit、源排名误标、非热键误标 hot——均被明确拒绝。

独立核验器再检查输入哈希、源排名/存活状态、控制范围、全部 64 位校验和、进程覆盖及区间计算，结果通过：**528 个进程块、25,600 个计时批次、338,816 条分组查询条目**。组间键可重叠，计时批次和重复遍历不扩充独立样本数，每格仍为 n=16。

## 计时与判据

组内批量计时，循环无 map、无逐操作时钟和路径统计；每个状态两遍构成 A/A，采用 Williams 四状态轮转及第二遍反向。每格先校准并冻结遍历次数，目标约 40ms，最大 8,192,000 次查询/批。全部样本保留，不取最小值或删除慢进程。

每个进程先平均两次 log 耗时，再计算同进程配对 log 比；采用 `t(0.975,15)` 得到 95% 区间并指数变换。区间是**点态** 95%，不宣称全部组同时具有 95% 覆盖。

- 候选/BM：上界 ≤1.05 通过，下界 >1.05 回退，跨门为未定。
- 新增 A/A 质量门：参与比较的两状态，其第二遍/第一遍的 95% 区间都须位于 `[1/1.05,1.05]`；否则记“测量未定”，并保留性能区间。
- 候选动态/自身同终态快照另有 ≤1.15 的预算，不能替代相对 BM 的 ≤1.05 门。

正式批次实际耗时最小/中位/最大为 **34.29/54.42/142.35ms**。校准后批长变化原样保留，未因此挑选重复。

## 快照预算、旧混合通道与已有写收益

- 候选动态/自身快照的 mixed90：**20 格通过、12 格 A/A 质量未定**；性能区间本身均在 1.15 预算内。这个对照与候选/BM 的 5% 门分别评价。
- 原 32 格混合轨迹 find 另做既有记录重分析：仅看新的配对性能区间为 **26 通过、6 跨门**；按本轮新增 A/A 质量门则 **32 格均测量未定**。旧 A/A 采用重新构建/重放，与本轮同对象批次定义不同，因此该重分析只作辅助，不能代替新的完整混合测量。
- 写收益没有重新计时，只从已入库原始记录按正确 df 重算：**29/32 满足 ≥15% 的配对区间门（增长16/16、替换13/16）**。完整正确区间另存，未与新查询 log 比的统计口径混用。
- 写门与新终态查询主门的交集为 **7 格**，再加候选动态/自身快照质量及预算门为 **4 格**。这是部分门的交集，不是采用资格清单；新 v3 的请求字节复验、完整混合查询等仍有边界。

独立词表源池与主词表各 65,536 个不同键，交集 **9,230** 个（约 14.08%），不是同一键集换序；它仍是同类词表来源的额外抽样，不代表新键类型。

## 停止、修订及剩余工作

第一轮在 6 格后，于仅 49 键的 absent_hot 校准中达到 4,096 遍上限。协议修订为总查询次数上限（2,000×4,096），其他计时及判据不变；第二轮全部完整重跑，查询/终态文件哈希与第一轮相同。第一轮原始数据和冻结源码完整保留，未合并 n 或挑选更快样本。

本轮没有修改索引核心，也没有追加尝试 A。历史 9%–21% 继续撤回，预留容量机制仍未验证。新结论是：**部分增长格的终态查询确有超过 5% 的回退，查询通用采用门未满足**。

后续若继续优化，应先在已确认回退格收集同查询集的定位、纠错、块访问等工作量，与 BM 及同终态快照对照，再另行登记候选；不能从数组地址变化直接推断回退原因。100k URLs 未覆盖，新负载空间证据与完整混合查询仍需按场景补齐，S5 保持后置。Context16 继续默认。
