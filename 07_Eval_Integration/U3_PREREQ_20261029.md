## 已核对到的类结构

```cpp
class Page {
    struct Fence {std::uint32_t offset,length;};
    std::vector<Fence> stable_fences_;      // 每块一条（块首后缀的 arena 区间）
    std::vector<char> arena_;               // 所有后缀字节
    std::vector<Block> blocks_;             // 每块 ≤16 个 entry（offset/length/value + tag）
    std::vector<Region> regions_;           // 每 2,048 行一个 region（前缀 + 块区间）
    std::vector<std::string> fences_;       // 每 region 一条完整 fence 键
    std::vector<std::uint64_t> digests_;    // 与 fences_ 对齐
    std::size_t fence_prefix_=0, size_=0, region_keys_=0;
    blocklearn::BlockModel bm_;             // 前缀视图借用 arena 里的 fence 字节
};
```

## `split_half` 必须同时维护的六项

| 成员 | 处理方式 | 风险 |
|---|---|---|
| `blocks_` | 把 `[b_split, count)` 移出（`std::move` 区块数组） | 低 |
| `stable_fences_` | 同区间一并移出 | 低 |
| `arena_` | **必须压实**：新页只保留其 entry 用到的字节，并**重写每个 entry 的 offset** | **高（易错）** |
| `regions_` | 新页一个 region：同前缀、`first=0`、`count=移出的块数` | 低 |
| `fences_`/`digests_` | 新页各一条（由首个块首后缀构造） | 中（`fence_prefix_` 语义未完全确认） |
| `bm_` | **必须重拟合**（前缀视图借用 arena 的 fence 字节） | 中（拟合只占 3.7%，重拟合可接受） |

## 两个未决问题（下一轮动手前必须先确认）

1. **`digests_` 与 `fences_` 的对应关系**：构造期按 `fences_` 逐个生成；
   分裂后新页的 `digests_` 是否只需一条、还是必须与块一一对应？
   → 需读构造期那两行（约 200–210 行）确认，写错会导致 `locate` 走错块。
2. **`fence_prefix_`**：构造期设为两个 fence 的公共前缀长度，`digests_` 用它对键做切片；
   分裂后单 fence 的页该取 0 还是沿用原值？→ 必须与构造期一致，否则 digest 计算错位。

## 结论

- `split_half` 的难点**不在搬块**，而在 `arena_` 压实后**重写所有 entry 的 offset** 与
  `digests_/fence_prefix_` 的一致性；
- 这两个未决问题各读一行源码即可解决，但**必须先解决再写代码**，否则会重复此前
  "块数组/fence 数组对齐错误"的回滚；
- 本轮到此为止，下一步是：读构造期 `fences_`/`digests_`/`fence_prefix_` 三处赋值 → 写 `split_half` → 过门。

## 两个未决问题：已确认（读构造期源码所得）

```cpp
187:  fences_.push_back(rows[first].key);                  // 每 region 一条完整 fence 键
198:  stable_fences_.push_back({b.entries[0].offset, b.entries[0].length});  // 每块一条
203:  if(!fences_.empty()) fence_prefix_ = common_prefix(fences_.front(), fences_.back());
204:  for(const auto& f : fences_) digests_.push_back(digest8(std::string_view(f).substr(fence_prefix_)));
```

由此：

1. **`digests_` 与 `fences_` 一一对应，且都按 region 计**（不是按块）。
   分裂后新页只有 **1 个 region** → `fences_` 一条、`digests_` 一条。
2. **`fence_prefix_`**：单 fence 时 `common_prefix(f, f)` 返回 `f` 本身（全长），
   所以 `digest8(f.substr(f.size())) = digest8("")`。新页照此设置即可，
   即 `fence_prefix_ = fences_[0].size()`，`digests_ = {digest8("")}`。

**结论：两个问题都不阻塞实现**，`split_half` 需要维护的六项现在都有确定做法：

| 成员 | 新页取值 |
|---|---|
| `regions_` | 1 个：`prefix` 沿用原页、`first=0`、`count=移出块数` |
| `fences_` | 1 条：`prefix + 首个移出块的首后缀` |
| `fence_prefix_` | 上面那条 fence 的长度 |
| `digests_` | 1 条：`digest8("")` |
| `stable_fences_` | 随块一起移出（每块一条） |
| `arena_` | 压实 + **重写每个 entry 的 offset** |
| `bm_` | 用新页的块边界重新 `fit`（占 3.7%，可接受） |
