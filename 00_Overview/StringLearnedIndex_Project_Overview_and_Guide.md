## 1 任务定位与当前结论

你负责的核心任务是实现内存索引结构：承接分层字符串模型的位置预测，把预测结果变成实际数据布局和查找路径，并在增删改、重排和后续并发接入时维持正确性。这里沿用原课题中"单独的索引部分"的任务定位；它直接落实第二项创新，也需要与字符串模型负责人配合。

原文两条主线分别是共享前缀压缩与差异化后缀学习，以及预测驱动的数据重排与预取。当前已做成**可运行的单线程原型**，**功能评估已完整**（见下）。

**当前冻结版本**：

> **构建**：轻量统计 → 容量规划 → 直接构造 + R1（构造内部复用组号）—— **自 E20 起未变**
> **写路径**：复用高效搜索（V1）＋ 复用本次定位的组号·标签·判重结果（V2）
> **维护**：压缩重放复用标签（C1）＋ 压缩只在腾得出足够字节时跑（C2）

## 2 基础知识与论文阅读入口

先掌握四件事：索引是帮助找到记录的辅助结构；有序索引还要支持区间扫描；学习模型只能预测位置，最终仍须精确核对键；缓存友好意味着减少真实内存访问，不能只看模型计算量。完整报告第 2 节对应课件中的必要基础，第 3 节汇总 24 项文献或工作及入口。

| 阅读阶段 | 论文或工作 | 要解决的问题 |
| --- | --- | --- |
| 先理解结构 | ART、HOT | 路径压缩、节点组织、树高和字符串比较 |
| 理解学习索引 | RMI、PGM | 预测位置之后怎样纠错与保证查找正确 |
| 理解动态维护 | ALEX、LIPP | 插入空间、预测冲突、重建与结构调整 |
| 精读直接参照 | LITS、LIT+／LIT-MT | 字符串模型怎样和布局协同；已有优化边界 |
| 理解压缩与比较 | SIndex、RSS、HOPE | 公共前缀、后缀比较和保序压缩的代价 |
| 核对布局相关工作 | CARMI、Bigtable 学习索引、LINE | 预测块、按模型布局、预取和维护开销 |
| 设计可信实验 | GRE、TLI、RoBin | 公平基线、更新负载、分布变化与退化 |
| 按需补读 | DILI、SALI、LIVAK、LISK 等 | 分布驱动布局、节点演化及变长键近邻工作 |

推荐按 ART → RMI／PGM → ALEX／LIPP → LITS → CARMI／LINE → GRE／TLI 的顺序进入主线。课件中完美哈希与 FairHash 等内容作为背景补充，不必与 LITS 投入相同的精读时间。

精读时固定回答五个问题：键在哪里存？模型预测什么？预测不准怎么办？插入后怎样保持一致？收益是否抵得过额外空间与维护？完整报告第 4–5 节已将这些问题对应到论文和源码。

阅读深度有区别。R15、LIVAK、LISK 等仍有摘要或出版信息级核对项；R18 的期刊记录与仓库说明也不能直接视为全文技术逐项对应。所有状态沿用原报告，不能把 24 项都写成已全文精读。

## 3 原型结构与主要接口

一次查找先按字典序定位区域，验证该区域的共享前缀，再用后缀模型预测数据组。组号一旦确定，就可以停止继续细化模型区间。随后利用指纹筛选候选，最终完整比较字符串；放不进主块的记录由所属组的溢出区保存。**预测不代替精确核对。**

当前主块按 64 字节对齐，块头占 64 字节，固定 16 个条目各占 16 字节，其余空间存后缀。512、1024、2048 字节块对应 192、704、1728 字节后缀空间。因此"条目槽不足"和"后缀字节不足"是两个不同问题。

**主要接口**（`validation_e25_20260918/index.hpp`，**冻结版本**）：

| 类别 | 接口 |
| --- | --- |
| **构建** | `bulk_load(pairs)`；`demand_profile(pairs)` / `demand_profile_ctx(pairs)` 产出每组的 `GroupStats` 供容量规划 |
| **点查** | `find(key, Mode)`、`find_known(region, key, Mode)`、`locate(key)` |
| **范围扫描** | `scan(start, count)` —— 从第一个 `key >= start` 起按键序返回至多 `count` 条完整键值对 |
| **更新** | `insert`、`update`、`erase`、`upsert`、`rebuild(region, data)`、`rebuild_all()` |
| **观测** | `size()`、`region_count()`、`memory()`、`memory_breakdown()`、`overflow_count()`、`compaction_count()`、`structure_version()` |
| **配置** | `Config{region_keys, offset_directory, multiblock, reuse_group_ids}` ＋ 冻结的五项：`write_fast_locate`／`reuse_locate_ctx`／`compact_reuse_tag`／`compact_needs_garbage`／`scan_reserve_result`（**默认全开**） |
| **查询模式** | `Mode{fingerprint, simd, locate}` —— 这三个开关对应 E5／E6／E13 判定为"**保留为可选组件、不作默认**"的三项 |

`memory_breakdown()` **已经**把空间拆成 `blocks / model / prefix / overflow / tables / directory / self`（外层另有 `regions_self / fences`），`GroupStats` **已经**记录 `garbage_bytes / free_bytes / free_entries`。**下一步的空间分解诊断可以建立在这两处已有核算之上**，不必从零造。

同步重建会暂停当前操作；它不是后台重建，也不是并发安全发布。硬件 CRC 已使用，SIMD 批量标签比较在 E25 里已用于写路径。

**必须一起读的边界**：

1. **单机、单线程、共享主机**；并发、游标复用、反向扫描、并发更新**均未测**。
2. **没有 sanitizer**：早期轮次工具链缺 ASan/UBSan，**内存安全检查是待补项**。
3. **"通过正确性门"限于该轮覆盖**，不等于任意输入正确。**E9 引入、E11 修复过一个静默丢键的扫描缺陷**——这类问题正是靠后续轮次的门才暴露的。
4. **绝对耗时不可跨轮拼接**；结论建立在同轮比值上。
5. **空间是容量估计，不是 RSS**；分配器开销与字符串内联存储是否计入**以该轮口径为准**。
6. LITS 接入保留了诊断与失败证据，因内存安全检查未通过而**未纳入正式计时**。

## 5 冻结与下一步

**2026-09-20 冻结**：E24 诊断 → E25（写路径）→ E26（维护）→ E27（扫描）四项改造，**只组合各自有同轮证据支持的部分**。

| 改动 | 同轮证据 | 是否启用 |
|---|---|---|
| **V1** 写路径复用高效搜索 | 只改值快 **1.85×–3.06×**，9 个 (数据, 负载) 格 **9 格同向** | **默认启用** |
| **V2** 复用本次定位的组号·标签·判重结果 | `V2÷V0` 在 9/9 格同向；插入再快 3%–14% | **默认启用** |
| **C1** 压缩重放复用标签 | 哈希砍掉 67%–95%，时间只快 0.9%–6.7% → **压缩的成本不在哈希** | **默认启用** |
| **C2** 压缩只在腾得出足够字节时跑 | `C2/C1 = 0.049–0.970`；插入负载 **0 条额外溢出**；空间代价 ≤0.03%；查询 0.82–1.02 | **默认启用** |
| **S1** 扫描结果预留后原地追加 | 扫描降 **6%–24%**，27 格全同向 | **默认启用** |

**未动**：构建路径仍是 **R1**、模型、逻辑映射、主块预算。

**长期替换（50%／100%／200%）——原定测试已补**：**空间不趋稳**，到 200% 周期时溢出条数接近全部活跃记录；**C1 与 C2 的空间逐位相同**，即 **C2 解决的是时间、不是空间**。**C2 的时间收益依负载而定**（变长键负载全程 0.69–0.93；等长键负载前 100% 落在噪声里、200% 才 0.87–0.93），**但从不一致劣化**（24 格 ≤ 1.02）。**"长期替换下空间趋稳"这个目标没有达到**，且不在本轮四项改动的射程内。

**最终版本的位置**（全部同轮测量）：**持续插入在重复前缀上快于 ART 约 2.06×，混合字符串与百万域名上仍慢 1.14×／1.69×；替换仍是短板（1.86×／3.74×／5.95×）；扫描仍慢于有序数组 1.30×–2.23；构建仍慢于 ART。** **本报告不声称全面超过 ART。**

**冻结之后（E28–E38 与 G0–G5）——这一段的每一条都写在 `RESULTS_SUMMARY.md` §7 与 `validation_e25_20260918/` 里：**

- **E28–E31**：长期替换的空间不趋稳，**原因是子块内部的字节碎片**；放宽压缩触发能恢复空间但**回不了本**（1.45×–6.02× 慢）；判据实测后机制被许可，E31 实现 `subblock_reclaim`（**默认关闭**）。

### 如何构建与验证

**一切构建与运行必须经该轮目录下的 `tools_build.py`**——它编译到唯一临时产物、成功后原子改名，并把"源码哈希＋编译命令＋可执行哈希"写入构建记录；`run` 会先核对可执行哈希，不一致即拒绝运行。

```bash
cd 02_Code_and_Experiments/validation_e23_20260918

# 构建并运行一个数据集
python3 tools_build.py bench_e23 mixed 131072
python3 tools_build.py run bench_e23 mixed 131072

# 正确性门（继承门，固定种子）
python3 tools_build.py check check_e8_hetero check_e9_multiblock
python3 tools_build.py run check_e8_hetero

# 整轮扫描与出表
python3 run_e23.py
```
